# 数据库设计方案 - 当前状态

> 更新时间：2026-05-19

## 已确认的设计决策

1. **菜品重名 + 标签**：`dish.name` 允许重复，通过 `dish_tag` + `dish_tag_rel` 标签体系区分同名菜品，业务层保证"菜名+标签组合"唯一
2. **餐序时间排序**：`meal_type.default_time (HH:mm)` 替代数字排序，`meal_record.meal_time` 存实际用餐时间，按时间自然排序
3. **6 固定餐序 + 加餐**：早餐 07:30、上午餐 10:00、中餐 12:00、下午餐 15:00、晚餐 18:30、宵夜 21:30，加餐由用户选时间
4. **source 字段**：所有表统一 `preset/user` 区分，用户只能编辑 `source='user'`
5. **#复制 标签**：预置 `dish_tag (name='#复制', source='preset')` 一行，导入功能写入；UI 用 TertiaryContainer 浅橙底区分
6. **分类与人群相关 4 张表前置到 MVP**（2026-05-18 决定）：
   - `food_category` / `ingredient_category` / `crowd_type` / `crowd_ingredient`
   - 驱动食材选择 DialogFragment 的左侧分类导航 + 右侧食材列表（含人群推荐角标）
7. **新增字段**（2026-05-18）：
   - `ingredient.pinyin`、`ingredient.image_path` + 拼音索引
   - `food_category.crowd_type_id`（可空外键）、`sort_order`、`icon` + 父子索引
8. **微量元素**：放一期实施，后续单独开专题讨论
