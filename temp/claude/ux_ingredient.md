## 一、盘点：当前一条「找/加/建/看」食材各要几步

- **找一个已有食材**：进「食材」页默认落在「最近」Tab → 若不在最近，要么①切到「常规/营养/…」Tab再点左侧分类树逐层展开 → 点分类 → 网格里找；要么②点顶栏搜索框输字 → 下拉结果里点一条 → **跳到该食材所属常规分类并高亮**（`jumpToIngredient`，体验不错）。
- **入库（在手食材）**：管理模式下，搜索下拉里对某项点「入库」即默认 1 份入库（A8 已做，好）；或点食材开详情 → 底部份数区选份数「入库」。
- **建自建食材**：顶栏「＋」→ 全屏表单，必填=名称+营养大类（大类已按名自动预选）；下面还有：二级名称、默认单位、图片、其它分类、5 个详情文本域、11 个营养数值、调养建议区。表单很长。
- **看详情**：点任意食材卡 → 底部弹层（占屏 65%）四区：做法 / 忌口宜忌 / 属性 / 处理与保存+来源。

整体骨架成熟、A 系列打磨（A8 入库默认1份、A10 组合入口）已落地。剩余问题集中在**空态缺失、搜索下拉遮挡、长表单默认值仍偏多、详情信息密度、若干一致性细节**。

## 二、改进项（高价值低风险在前）

### [🔴][风险 低][体量 S] 补齐所有食材网格的「空态」
**现状**：`IngredientPickerScreen.kt` 网格（第 277-326 行）在 `ui.ingredients` 为空时**什么都不显示**——一片空白。「最近」Tab 新用户没记过菜=空白；「库存」Tab 没入库任何东西=空白（仅底部一行灰字"从现有食材中添加入库"，网格区仍空）；「家庭」Tab 没建过自建食材=空白；搜索无结果时下拉不弹、网格也不动，用户不知道是"没搜到"还是"没生效"。
**痛点**：空白页让人以为出错/加载中，且没有"下一步该做什么"的引导——违背苹果"永远给用户下一步"。
**建议**：给网格加统一空态组件（emoji + 一行主文案 + 一行操作引导），分 Tab 文案：
- 最近："还没有最近用过的食材／记一餐后这里会显示常用食材"。
- 库存（非选择模式）："冰箱还是空的／去搜索或分类里把家里有的食材『入库』"，带一个「去添加」按钮直接聚焦搜索框。
- 家庭："还没有自建食材／点右上角＋添加你家常用的食材"，带「＋添加食材」按钮（复用顶栏＋逻辑）。
- 搜索无结果（`keyword` 非空且 `searchResults` 空）：在下拉位置显示"没找到『xxx』／换个词，或点＋直接新建『xxx』"——**把关键词带进新建入口**（预填名称）。
**落地提示**：纯 UI，新增一个 `IngredientEmptyState` Composable，在网格 `items` 为空的分支渲染；VM 无需改。无迁移。**安全项，可无人值守直接做**。

### [🔴][风险 低][体量 S] 搜索无结果时给出「＋ 新建『关键词』」直达
**现状**：`setKeyword`（VM 210-222 行）搜到结果才弹下拉；搜不到时 `searchResults` 为空，下拉收起，用户输了一个库里没有的食材名后**只能自己清空、再去顶栏＋、再重新手打一遍名字**。家庭记菜高频场景=经常要记库里没有的家常食材。

### [🟡][风险 低][体量 S] 顶栏搜索下拉会遮住主分类 Chip 与网格，且不透明反馈
**现状**：`SearchResultsPanel`（Screen 623-677 行）以 `tonalElevation=4dp` 的 `Surface` 紧贴顶栏**插在布局流里**（不是浮层），`heightIn(max=320dp)`。它一出现就把下面的主分类 FilterChip 行和网格**整体往下挤/挡住**；点结果跳转后才收起。搜索防抖期间（`DEBOUNCE_MS`）无任何"搜索中"指示。
**痛点**：下拉挤压布局产生跳动；搜索时静默，慢网/大库时像卡住。
**建议**：①下拉改为悬浮在网格之上（用 `Box` 叠加或 `Popup`），不挤压 Chip 行——苹果搜索建议一贯是覆盖非顶开。②防抖/查询期间在下拉顶部显示一行细 `LinearProgressIndicator` 或"搜索中…"占位。③结果条目当前左侧 emoji 用的是 `ing.emoji.ifBlank{"🥗"}`，而网格卡用的是 `foodEmojiForName(name)` 兜底——两处兜底不一致，统一走 `foodEmojiForName`。
**落地提示**：纯 UI 结构调整（Screen 内 `Column` → 用 `Box` 承载网格+浮层）。②③零风险。①改布局需**真机确认叠加层不挡底部选择栏**。①标**需真机验证**，②③安全项。

### [🟡][风险 中][体量 M] 自建食材表单太长，把低频区默认折叠、只露必填
**现状**：`IngredientEditorDialog`（Editor 199-334 行）一次性平铺展开：基础信息（名/二级名/单位/图片）→ 营养大类（必选）→ 其它分类 → **详情说明5个文本域** → **营养素11个数值框** → **调养建议区**。对"家里新加一个食材"的高频场景，真正必填只有**名称+营养大类**（大类还自动预选），其余全是低频/可后补。当前长表单让人一进来就被一大坨输入框吓到。
**痛点**：违背苹果"默认只露高频、低频收纳"。5 个详情域、11 个营养框、调养区对家庭日常记菜是**极低频**，却和必填项同层平铺。
**建议**：改成**渐进式**：
- 顶部只保留"基础信息（名称、营养大类已预选、可选图片）"直接可见 + 一个大「保存」——**填名字就能存**。
- "详情说明""营养素（每100g）""调养建议"三块折叠进可展开的 `InsetGroup`/"更多信息（选填）"分区，默认收起，标题右侧带 `›`。想填的人点开填。
- 营养素区标题已提示"选填"，但 11 个框铺开视觉负担大；折叠后既保留能力又不吓人。
**落地提示**：`IngredientEditorDialog` 内把后三个 `EditorSection` 包进一个 `expanded` 状态的可折叠容器（复用已有的苹果风 `InsetGroup` 或简单 `AnimatedVisibility`）。不改 VM/保存逻辑、不改 DB。属体验重排，**建议改完真机走一遍新增/编辑两条路径确认折叠态下保存字段无丢失**（编辑既有食材时折叠区要能带出已填内容）。**需真机验证**。

### [🟡][风险 低][体量 S] 详情弹层：信息密度与"来源/免责"占位过重
**现状**：`IngredientDetailSheet`（264-207 行）四区顺序=①做法 ②忌口宜忌 ③属性 ④处理与保存，然后固定追加"来源：预设/用户创建""默认单位"两行 + 分隔线 + "以上建议仅作为日常饮食记录参考"。对一个**没填任何详情的预设/自建食材**，弹层里几乎只剩"来源/默认单位/免责语"三行，显得空且啰嗦；而"来源"对家庭用户价值很低（卡片左上角已有"预设/自建"徽章，重复）。
**痛点**：高频看的是"这东西能做什么菜/忌不忌口"，"来源"是最低价值信息却每次占两行且总在最下。免责语每张详情都重复。
**建议**：①"来源"从详情正文移除（卡片徽章已表达），或降级为极小灰字并入底部。②"默认单位"仅自建食材且已设置时才显示。③免责语保留但字号/色更弱（红线要求保留免责，不删，只弱化）。④四区顺序对"家庭记菜"可考虑把 **③属性（品类/营养/应季标签）提到②之前**——属性是"这是什么"，比"忌口"更基础；但慢病用户可能更关心忌口，此项**建议保持现状或做成可配置，先不动顺序**，只做①②③减负。
**落地提示**：`IngredientDetailSheet` 内调整第 200-206 行的固定行渲染条件。纯 UI。**安全项**（②③零风险；顺序不动）。

### [⚪][风险 低][体量 S] 一致性细节收敛
**现状/建议**（都属苹果式克制的小抛光，纯 UI、安全项，可批量做）：
1. **入库反馈用 Toast**：搜索下拉入库后弹 `Toast`（Screen 161 行）。苹果一般不用系统 Toast，倾向就地状态变化（按钮"入库"→"出库"即时切换已足够表达）。可去掉 Toast 或改成更轻的 inline 提示，避免每次入库都弹一条系统吐司。
2. **`AlertDialog` vs 苹果 `ActionSheet`**：删除食材/删除分类用居中 `AlertDialog`（Screen 463/545 行）；破坏性操作苹果更常用底部 `ActionSheet`（项目已有自建 `ActionSheet`/`SheetAction` 组件，红色破坏项）。可把删除类确认迁到 `ActionSheet` 与全局风格统一。红线："软删只删 source='user'"逻辑不变。
3. **食材卡"预设/自建"徽章 + 右上建议角标 + 左上来源**同时出现时角标偏多**：一张卡最多可能左上来源徽章、右上建议角标、居中选中钩、右下长按更多——四角都有装饰，略吵。可评估把"预设"徽章弱化（自建才显徽章，预设不显，减少视觉噪音，因为库里大多是预设）。
4. **"二级名称"文案**：详情里显示"二级名称：xx"（Sheet 133 行），而卡片显示 `(别名)`。术语在表单/详情叫"二级名称"、在展示叫"别名/括号"，可统一口径。
**落地提示**：均为 UI 微调，逐条独立、互不依赖。**安全项，可无人值守**（迁 ActionSheet 那条建议真机瞄一眼底部叠加正常）。

### [⚪][风险 低][体量 S] 分类树"当前路径"高亮与展开态提示
**现状**：左侧分类树（Screen 184-251 行）`CategoryItem` 按 `selected` 高亮，有 `hasChildren`/`expanded` 状态。`jumpToIngredient` 会沿祖先链展开（好）。但普通逐层点选时，深层分类被选中后，用户不一定看得清自己在哪条路径下（尤其营养/调养这类多级）。

**建议**：可在网格顶部加一行极简"面包屑/当前分类名"（如"常规 › 蔬菜 › 叶菜"），让用户知道当前网格是哪个分类的结果；或选中项祖先链也做浅底色。属锦上添花。
**落地提示**：VM 已能从 `allCategories` + `selectedCategoryId` 推祖先链。纯 UI 加一行。**安全项**，低优先。

## 四、建议优先落地 Top 5

1. **🔴 网格空态补齐**（S，安全）——覆盖最近/库存/家庭/搜索无结果四种空白，消除"以为出错"的首屏体验，收益面最广。
2. **🔴 搜索无结果 →「＋新建『关键词』」直达**（S，安全）——家庭记菜高频痛点，砍掉"清空重打名字"这一步。
3. **🟡 自建食材表单折叠低频区、只露必填**（M，需真机）——把"填个名字就能存"变成默认路径，长表单不再劝退，最贴合苹果"少操作"。
