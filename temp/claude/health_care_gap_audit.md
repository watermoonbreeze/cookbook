# 健康安全数据审计：只填营养、漏配 care 忌口的高风险食材

> 只读审计，**未改动任何代码/数据**。结论仅供参考·非医嘱；凡数值阈值均标"惯例口径"，不当权威标准。
> 生成日期：2026-07-20

---

## ① 审计范围与方法

**数据源（seed）**
- `shared/src/commonMain/resources/seed/ingredient_nutrition.json` —— 502 条食材营养（每 100g，含 sodium/gi/purine/cholesterol/fat 等）
- `shared/src/commonMain/resources/seed/ingredient_care_rules.json` —— 480 条食材→人群/慢病的 care 规则（21 个 care_* 分类）

**判级引擎（读懂机制，决定"漏配=误判绿"）**
`IngredientCrowdCare.kt` 对每个食材固定评 **4 类数据驱动人群**：高血压(钠)/糖尿病(GI)/高血脂(饱和脂+胆固醇)/痛风(嘌呤)。阈值来自 `NutrientLevelFilter.kt`：
- 钠：LOW ≤120 / HIGH ≥600 mg（惯例）
- GI：LOW ≤55 / HIGH ≥70（FAO/WHO）
- 嘌呤：LOW ≤25 / HIGH ≥150 mg（惯例·非国标）
- 饱和脂：LOW ≤1.5 / HIGH ≥5.0 g（惯例；**注：seed 只有 total fat，无 saturatedFatG → 高血脂几乎只靠胆固醇判**）
- 胆固醇：LOW ≤50 / HIGH ≥150 mg（惯例）

**关键机制（误判绿的根因）**
1. **无 care 规则时纯按数值判**：数值不高 → 判 `FIT`(绿/宜)。care 规则只做**单向压制**（AVOID→红、LIMIT→黄），能把"数据判绿但临床该忌"的食材纠回来——**没规则就压不住**。
2. **痛风兜底只在 purine 为 null 时生效**（`matchHighPurineFoods` 关键词）；一旦录了**偏低/中等**的实测嘌呤值，就按该值判级，**不再触发关键词兜底** → "录了低值反而判绿"的隐患。
3. 引擎已能把 **数据 HIGH 的项判红**（如 purine≥150、钠≥600）——这类即便漏 care 规则，UI 仍显红，**风险较低**；真正危险的是 **数据 LOW/MID(绿/黄) 但机制上应 limit/avoid** 的项。

**方法**：取"有营养但 care 规则里完全无记录"的 351 个食材，按上面阈值算出 4 条判级，再对照临床启发式（酒精/内脏/加工腌制/高 GI 主食/高胆固醇蛋类等）筛出**误判偏绿**者。

**先说结论（免误伤）**：**酒精类全部已配 care 规则**（料酒/啤酒/葡萄酒/白酒/黄酒/米酒/清酒/酒酿 均在 care 中），本次无酒精漏配。漏配集中在 **内脏 / 加工腌制 / 高 GI 精制主食 / 高胆固醇蛋类 / 中嘌呤肉海鲜**。

## ③ 按慢病分组的补漏建议（汇总）

- **痛风(care_gout)**：avoid ← 全部动物内脏(A)、高嘌呤海味/腊禽(E)；limit ← 中嘌呤肉海鲜(F)、植物高嘌呤(干香菇/茶树菇/腐竹/青豆)。血制品(猪血/鸭血)**保持可食**，勿误列。
- **高血脂(care_hyperlipidemia)**：avoid ← 内脏(A)、黄油、腊味/加工肉、猪头肉；limit ← 高胆固醇蛋类(鹅蛋/茶叶蛋/鸡毛蛋)、淡奶油/奶油奶酪/硬奶酪。
- **高血压(care_hypertension)**：avoid ← 咸腊禽畜、加工肉、干海味(虾米/小鱼干/鲍鱼)、腌菜酱(C)；limit ← 硬奶酪、鱼丸/鱼豆腐/料理包/自热米饭等高钠加工品。
- **糖尿病(care_diabetes)**：limit ← 高 GI 精制主食/甜食(D)；桂圆干可 avoid。
- **冠心病(care_coronary)**：与高血脂高度重叠 ← 内脏 avoid、黄油 avoid、腊味 avoid。
- **（可选延伸，非本审计 4 类）** 脂肪肝 ← 黄油/腊味/内脏 avoid；CKD ← 内脏(高磷)avoid、加工肉avoid——这些**不在数据驱动 4 类内**，纯靠 care 规则，可一并补但需谨慎。

## ④ 需联网权威核准后再补的条目（🔴 单列）

1. **鸡毛蛋(毛鸡蛋)** —— 除高胆固醇外，是否有卫生/激素类忌口口径，需权威依据；勿凭印象加 avoid。
2. **鱼油** —— 胆固醇高(521)但富含 Omega-3(对血脂常为有益)，"高血脂 limit 还是 recommend"存在机制矛盾，须核准。
3. **各类嘌呤"低/中/高"临界**（25/150）本就**无国标**（现代码已标"惯例·非国标"）——凡新加痛风 avoid/limit 的**分级依据**仍标"惯例·非国标"，不宣称权威阈值。
4. **植物高嘌呤（干香菇214/茶树菇150/腐竹160/青豆150/黑豆137/毛豆75）** 痛风该 avoid 还是仅 limit：学界对"植物嘌呤致痛风风险低于动物源"有共识倾向，**是否放宽到 limit** 建议核准后定，别一刀切 avoid。
5. **蛋白肉/鱼豆腐/料理包等复合加工品**的营养系估算值，其忌口定性建议核准配方后再定。
6. 凡最终落地的 care 规则，**收尾须把权威来源加进"我的·数据来源"页**（`androidApp/.../ui/reference/DataSourceReference.kt`）——项目硬规则。

## ⑤ 给主 agent 的下一步建议

**可直接按惯例补（🟢，低争议，建议优先落地）**
- A 组内脏 → 痛风 avoid + 高血脂 avoid/limit（血制品除外）
- C 组咸腊/加工肉/干海味/腌菜酱 → 高血压 avoid（+腊味高血脂 avoid）
- D 组高 GI 精制主食 → 糖尿病 limit
- E 组高嘌呤动物源(鱼/腊禽/干海味) → 痛风 avoid
- 高胆固醇蛋类(鹅蛋/茶叶蛋) → 高血脂 limit；黄油 → 高血脂/冠心病 avoid

**须联网核准后再补（🔴）**：鸡毛蛋、鱼油、植物高嘌呤 avoid-vs-limit 的尺度、复合加工品定性（见④）。

**落地技术要点（防踩坑）**
- 本改动**只加 care JSON 数据、不改表结构** → 依项目经验属"纯数据 seed"，**无需 `.sqm` 迁移**；但 care 规则按 seed 逻辑生效，需确认 seed 是否需 `SEED_LOGIC_VERSION`/指纹机制让老库重跑（老用户拿不到新规则）。
- care 规则**按食材名精确匹配**（`HealthCondition.fromCareName` + 名匹配）：注意 seed 里存在"火腿"有规则但"火腿罐头/帕尔马火腿"是独立名、不继承——补规则要**逐个具体名**补齐，别以为父名覆盖。
- 引擎对 purine=null 才走关键词兜底：给内脏补 care avoid 后，即使其嘌呤实测值偏低(MID)也会被 care **单向压制成红**，正是本审计要修的核心路径。
- **勿误伤**：猪血/鸭血/牛血(低嘌呤)、植物性调味香料、低 GI 蔬菜等本就该判绿，别为"看着像肉/加工"就加 avoid。

**规模提示**：漏配总量 351，其中真正"高风险误偏绿"约 60–80 项（A/B/C/D 核心）。建议**分病种分批**补（先痛风内脏+高血压腌腊两批，各带引用完整性/按名断言单测），别一次性大改。
