# 端侧AI能做的远不止显示内容！它是APP的"本地大脑"，能执行几乎所有本地操作

你的这个问题问到了**端侧AI最核心的价值**：它不是一个只能聊天的"展示工具"，而是一个能**深度集成到APP业务逻辑中、自主完成本地操作的智能代理**。它能做的事情远超你的想象，而且所有操作都在用户设备本地完成，完全不需要联网。

## 一、先澄清一个关键误解
**端侧模型本身不能直接读写数据库或操作硬件**，但它可以生成**精确的指令**，由你的APP代码执行这些指令。这是一个"**模型思考，代码执行**"的闭环：

```
┌─────────────┐     生成指令     ┌─────────────┐
│  本地模型   │ ─────────────→ │  APP执行层   │
└─────────────┘                └─────────────┘
       ↑                            │
       │  返回执行结果               │  执行操作
       │                            ↓
┌─────────────┐                ┌─────────────┐
│  推理决策   │ ←───────────── │  本地资源    │
└─────────────┘                │(SQLite/文件/设备)│
                               └─────────────┘
```

这种架构的优势：
- **绝对安全**：模型永远不能执行任意代码，只能调用你预定义的安全函数
- **完全可控**：你可以精确控制模型能做什么、不能做什么
- **性能最优**：复杂计算由原生代码完成，模型只负责决策
- **易于调试**：所有操作都有明确的日志和审计轨迹

## 三、具体实现方法：以SQLite操作为例

这是你的记菜单APP中最常用的操作，我将给你一个完整的实现示例，展示如何让本地模型安全地读写SQLite数据库。

### 第1步：定义工具函数接口
首先定义模型可以调用的所有工具函数，这是安全控制的关键：

```kotlin
// 工具函数定义
data class ToolCall(
    val name: String,
    val parameters: Map<String, Any>
)

// 工具函数注册表
object ToolRegistry {
    private val tools = mutableMapOf<String, (Map<String, Any>) -> Any>()

    init {
        // 注册SQL查询工具
        register("query_database", ::queryDatabase)
        // 注册插入数据工具
        register("insert_meal_record", ::insertMealRecord)
        // 注册更新数据工具
        register("update_user_profile", ::updateUserProfile)
    }

    fun register(name: String, function: (Map<String, Any>) -> Any) {
        tools[name] = function
    }

    fun execute(toolCall: ToolCall): Any {
        val function = tools[toolCall.name] 
            ?: throw IllegalArgumentException("未知工具：${toolCall.name}")
        return function(toolCall.parameters)
    }
}
```

### 第2步：实现SQLite工具函数
实现具体的数据库操作函数：

```kotlin
// 执行SQL查询
private fun queryDatabase(params: Map<String, Any>): Any {
    val sql = params["sql"] as String
    val args = params["args"] as? List<Any> ?: emptyList()

    // 安全检查：只允许SELECT语句，禁止修改数据
    if (!sql.trim().startsWith("SELECT", ignoreCase = true)) {
        throw SecurityException("只允许执行SELECT查询")
    }

    // 执行查询
    val db = AppDatabase.getInstance(context).readableDatabase
    val cursor = db.rawQuery(sql, args.toTypedArray())
    
    // 将结果转换为List<Map>
    val result = mutableListOf<Map<String, Any>>()
    while (cursor.moveToNext()) {
        val row = mutableMapOf<String, Any>()
        for (i in 0 until cursor.columnCount) {
            row[cursor.getColumnName(i)] = cursor.getString(i)
        }
        result.add(row)
    }
    cursor.close()
    
    return result
}

// 插入用餐记录
private fun insertMealRecord(params: Map<String, Any>): Any {
    val dishName = params["dish_name"] as String
    val calories = params["calories"] as Int
    val purine = params["purine"] as Int
    val mealType = params["meal_type"] as String
    val date = params["date"] as String

    val db = AppDatabase.getInstance(context).writableDatabase
    val values = ContentValues().apply {
        put("dish_name", dishName)
        put("calories", calories)
        put("purine", purine)
        put("meal_type", mealType)
        put("date", date)
    }

    val id = db.insert("meal_records", null, values)
    return mapOf("success" to true, "id" to id)
}
```

### 第4步：修改推理循环，支持工具调用
修改`MenuRecommender.kt`，添加工具调用的处理逻辑：

```kotlin
fun chat(userMessage: String, maxTurns: Int = 5): String {
    var conversationHistory = ""
    var currentTurn = 0

    while (currentTurn < maxTurns) {
        currentTurn++
        
        // 构建提示词
        val prompt = "$SYSTEM_PROMPT\n\n$conversationHistory\n用户：$userMessage\n助手："
        
        // 运行模型推理
        val inputIds = tokenizer.encode(prompt)
        val inputs = mapOf("input_ids" to arrayOf(inputIds))
        val outputs = ortSession.run(inputs)
        val response = tokenizer.decode(outputs["output_ids"] as Array<LongArray>[0])
        
        // 检查是否需要调用工具
        if (response.contains("") && response.contains("")) {
            // 提取工具调用
            val toolCallStr = response.substring(
                response.indexOf("") + "".length,
                response.indexOf("")
            )
            
            // 解析工具调用
            val toolCalls = gson.fromJson(toolCallStr, Array<ToolCall>::class.java)
            
            // 执行工具调用
            val toolResults = mutableListOf<Any>()
            for (toolCall in toolCalls) {
                try {
                    val result = ToolRegistry.execute(toolCall)
                    toolResults.add(mapOf("success" to true, "result" to result))
                } catch (e: Exception) {
                    toolResults.add(mapOf("success" to false, "error" to e.message))
                }
            }
            
            // 将工具结果添加到对话历史
            conversationHistory += "用户：$userMessage\n助手：$response\n工具结果：${gson.toJson(toolResults)}\n"
            
            // 继续下一轮推理
            continue
        }
        
        // 不需要调用工具，直接返回结果
        return response
    }
    
    return "抱歉，我无法完成你的请求，请稍后再试。"
}
```

## 五、安全与权限控制（绝对不能省）
端侧AI虽然强大，但也带来了安全风险，必须建立严格的安全控制机制：

### 1. 白名单机制
- 模型只能调用你预先定义的工具函数
- 禁止模型执行任意代码或系统命令
- 对SQL语句进行严格的语法检查和权限控制

### 2. 敏感操作确认
- 所有涉及数据修改或删除的操作，必须经过用户确认
- 敏感操作（如删除所有数据）需要额外的密码验证

### 3. 数据隔离
- 模型只能访问APP自己的私有数据
- 禁止模型访问其他APP的数据或系统敏感数据

### 4. 审计日志
- 记录所有模型的工具调用和执行结果
- 便于调试和问题排查

## 六、端侧AI的局限性与最佳实践

### 局限性
- 模型的推理能力有限，不适合做非常复杂的数学计算或逻辑推理
- 模型可能会生成错误的指令，需要有完善的错误处理机制
- 模型的知识是固化的，无法获取实时信息

### 最佳实践
- **"模型思考，代码执行"**：把精确的计算和操作交给代码，模型只负责决策
- **"简单本地，复杂在线"**：简单的操作由本地模型完成，复杂的操作由在线模型兜底
- **"分层安全"**：建立多层安全防护机制，确保用户数据安全
- **"渐进式增强"**：先从最简单的功能开始，逐步扩展模型的能力
