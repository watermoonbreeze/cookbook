# 06 · 约定与红线

> 这册讲什么：改动前必守的**踩坑红线、质量门禁、工程约定**——避免返工/编译失败/数据破坏。
> 服务用途：审核 ✅ ｜ 反查（现象是否命中已知坑）✅
> 装什么：红线索引（分类）+ 三门禁 + 规范指针。
> 不装什么：红线全文（**单一真相源在项目根 `CLAUDE.md` 踩坑红线 + `.ai-context/docs/experience/06_问题与踩坑.md`**，本册只做分类索引，勿复制正文）。

## 三门禁（改动必过）

| 门禁 | 触发 | 角色 |
|---|---|---|
| **UI/交互设计** | 新页面/弹框/布局或交互改动/配色视觉 | 编码前先 Apple-UX 设计师产出交互规范（仅复用 §九 已确立范式的同类小改可免） |
| **代码质量审查** | 一批编码+构建+单测通过后 | Google 质量管理工程师审查，阻断项必修复复验（小改可免） |
| **文案** | 界面文字/文案/审校 | Apple 文案/运营策划师（`copywriter`），守健康免责红线 |

## 红线分类索引（正文见 `CLAUDE.md` / `experience/06`）

- **SQLDelight/迁移**：改表结构必同步加 `N.sqm`（名=最大N+1）；加列一次改全（CREATE+ALTER+insert/update+调用点+领域模型）；无 UPSERT（用 INSERT OR IGNORE + UPDATE 两步同事务）；WHERE 不支持 REPLACE/TRIM；单测走 Schema.create 不跑迁移链→推演旧库升级；ALTER 对已有列崩→幂等；DB 恢复须原子+回滚。
- **Seed**：大批量改用脚本+引用完整性校验+`:shared:testDebugUnitTest`；未知食材/分类/单位名 seeder 静默跳过→只用已存在名；seedDishes 对已存在菜"补齐式"重挂缺失配料+回填空用量(`fillDishIngredientQuantityIfNull`)；seed **逻辑**变更要 `SEED_LOGIC_VERSION`+1（内容变更靠指纹自动 reseed）。
- **健康数据免责**：营养/慢病/评级/忌口守"仅供参考·非医嘱"，禁"降压/治疗/达标"医疗断言；嘌呤三级无国标标"非国标·惯例"、GI 用 FAO/WHO、钠钾用膳食指南/DRIs；数据标 ref+verified/pending，禁编造出处；**对外文案温和化(不显性标"三高痛风"病名·用"健康管理/慢病家庭"·D-09)**。（详见 [20](20_健康与算法逻辑（专属）.md) + `feature/膳食参考依据`）
- **库存/推荐**：忌口/限量只作用非调料主料；库存推荐"主料齐即可"；忌口菜保留+排末+标红；rotate 按可接受候选算避免翻罚分末批；同名多 id 按名扩展兼容。
- **餐次分类(v28)**：`dish_meal_slot` 纯新表零迁移；`MealSlotMatcher` 降默认推断器(`defaultSlotsFor` 恒非空兜底正餐)；`seedDishMealSlots` 回填只补空+`SEED_LOGIC_VERSION` v6；数据扩充**只用已有食材**(营养已覆盖零编造·引用完整性单测)；`DishMini.mealSlots` 已含兜底恒非空。
- **个人忌口(v29)**：`food_category` **无 code 列→按分类名映射 id**(缺失静默跳过)；个人忌口**对所有食材角色生效(含调料·含即命中)**·`personalAvoidIngredientIds` 单独字段·不套用 seasoning/主料门槛(区别于健康忌口)；`listByCategories` 空列表返全部→**空守卫**。
- **多人关注(零schema)**：`is_focus` 单选→多选(去 `clearAllFocus`·`toggleFocus` 约束≥1·**读判写事务化**)；查看指针存偏好 JSON·`resolveViewing` 收口(失效自愈)；**1人零变化门禁**(size≥2 才显切换器·三处一致)；老库指针空→回退关注集合首位=旧 pickFocus。
- **Compose/UI**：Material3 **1.1.2** 无 `SelectableDates`/`SegmentedButton`/`HorizontalDivider`（用 Divider/自绘/确认回调校验）；`LaunchedEffect` key 用整对象非仅 id；`scrollToItem` 同帧 layoutInfo 旧→snapshotFlow 等布局；`stateIn(WhileSubscribed)` 无订阅 `.value` 冻结（勿做 toggle 判定）；VM 重建整 state 丢粘性字段用 `.copy`；多 init 并发写回用最新 `_state.value`。
- **存储/权限/系统栏**：数据放 app 专属目录(零权限)；图片存相对文件名+EXIF 摆正(androidx.exifinterface)；沉浸式 edge-to-edge 无底栏页加 `navigationBarsPadding`、嵌套 Scaffold 勿重复；系统栏色需 Compose 主题显式设 statusBarColor；db 在外部专属目录非 `databases/`；Git Bash adb 访问 `/sdcard` 加 `MSYS_NO_PATHCONV=1`。
- **工程**：AppLogger.d 无 release 门控且写文件→排查埋点用完删；改 data class 字段顺序后全仓改位置参数构造；删死导入用 Edit+Grep 确认；shared 用 `android.util.Log` 须 `unitTests.isReturnDefaultValues=true`。

## 工程约定

### 可观测性收口红线（OBS-NEXT）

- `OBS-NEXT-A/B` 当前仅记录为 `AUTOMATED_GATES_PASS`；`Runtime` 必须保持 `PENDING_DEVICE_VERIFICATION`，自动化证据不得替代真机证据。
- 真机验证由用户决定在末期统一执行；该待验证状态不阻断当前代码批次。
- MDC3/Trace 不得标记 `ARCH_ACCEPTED`、`ACCEPTED` 或 `CLOSED`，除非具备完整运行时链路证据（详见 `arch_evidence/MEAL-DATA-CONSOLIDATION-03/MDC3_CLOSE_PREPARATION.md`）。

- **项目地图同步**：全局关联任务先读 [00 导读与索引](00_导读与索引.md)，实现定位再读 `.ai-context/docs/功能路径索引.md`；实质变更架构、流程、页面/路由、算法真相源、数据/资料来源、AI/网络或公共复用能力时，同任务维护受影响分册、05 与路径索引。
- **AI 语义与日志**：AI 显式结构化结果优先，本地只归一、校验、查重和入库；缺失/不可信才规则补全并提示。禁止记录完整 prompt、原始饮食文本、完整响应和密钥；发现现存日志违规按安全缺陷处理（→[21](21_AI与网络请求策略（专属）.md)）。

- **AI 注释**：AI 生成/改的代码加详细注释 + `[AI生成]`/`[AI修改]` 标识；新文件用类注释模板。
- **Git**：每完成一可验证节点即 commit；只在用户要求时 push；无人值守 `[unattended]` 前缀。**commit 前 `git status --short` 核对全部改动都已 `git add`**（曾漏 add 两个 shared 文件致 push 的 master 编译不过·教训）。
- **构建**：统一 `scripts\build-cli.bat`（显式 JDK17）。
- **临时文件**：放 `temp/claude/`。

## 验证与质量基线（2026-08-17 新增）

- **单测位置与运行**：`shared/src/androidUnitTest/`（90+ `*Test.kt`，覆盖领域/算法/Repository）+ `androidApp/src/test/`（ViewModel）；命令 `scripts\build-cli.bat :shared:testDebugUnitTest` / `:androidApp:testDebugUnitTest`。**纯逻辑必带单测**（算法、评分器、解析器等不依赖 UI/DB 的函数）。
- **当前无 CI**：质量靠三门禁（见上）+ 本地构建/测试命令 + 真机验证清单，不依赖自动化流水线；改动后必须本地实跑验收命令，不能只凭 diff 判断。
- **真机验证唯一真相源**：`.ai-context/docs/真机验证/真机待验证清单_<yyyyMMddHHmm>.md` 中时间最新的一份；`07` 不重复摘抄具体项。
- **Verification 闭环**（2026-08-19 D-25 修订）：原基于 `project_graph/` Verification 实体的正式闭环契约随 Graph 一并归档退休，**未替换成同等强度的新正式契约**——验证状态改为轻量记录：真机验证项状态在 `真机验证/真机待验证清单_<最新>.md`（唯一真相源，用户填 `验证结果`/`原因`）；代码缺陷在对应 `features/<F-ID>/40_缺陷.md`。这是本次重构里"故意没做"的一项（避免用一个没人真正维护的正式契约替代另一个），不是遗漏。
- **机械核对工具**：`.ai-context/tools/blueprint_check.py`（allowlist 越界差集 / 台账证据真实性 grep），配套判据见 `experience/12_多模型协作与实施蓝图规范.md` §14.2。
- **全景图新鲜度自检**（2026-08-17 新增）：`python .ai-context/tools/review_freshness.py`（零依赖，比对 Tier B 六册`01/03/04/20/21/22`页脚「监视路径」之后的 git 提交 + 重算「事实锚」计数，只报"哪几册地基动过/哪个数字对不上"，不判断语义）。**脚本不存在或跑不动时的等价手工命令**：`git log --oneline <该册页脚sha>..HEAD -- <该册监视路径> | wc -l`（>0 需人工复核该册）；`grep -c "CREATE TABLE" shared/src/commonMain/sqldelight/com/sxdbsm/cookbook/db/Cookbook.sq`（核对 `04` 的 `tables` 锚，其余锚同理）。触发时机、结果落点与止损条件见 `projectReview/08` D-20。**页脚字段格式契约（独立复核 2026-08-17 发现并订正）**：字段间用 ` · ` 分隔，**字段内禁用 `·`**（脚本按 `·` 切分，字段内混入会被静默切错）；`监视路径`/`事实锚` 段内若需夹带说明性反引号文字（如举例、备注），脚本只识别形似路径（含 `/` 或 `.`）的反引号项与 `FACT_ANCHORS` 白名单 key，其余自动忽略、不触发误判。
- **交付回写门禁**：`BLUEPRINT_STATE.md` 批次状态转 `ACCEPTED` 时必填「全景图回写」字段（见该文件顶部说明区），详见 `projectReview/00` §落图与回写门禁。
- **全景图内容归属判断规则（2026-08-18 新增 D-23，2026-08-19 D-25 扩为三分类）**：
  1. **纵轴**：只影响**一个** Feature 的具体状态/进度/界面/待办/bug/验证 → 归 `projectReview/features/<F-ID>/`（`README.md`+按需的 `10_界面/20_实现/30_待办/40_缺陷/60_方案与决策`，非 D-23 时期的扁平单文件）。
  2. **横轴·本体**：影响**≥2 个** Feature 的机制/算法/架构/数据口径/约定 → 归对应横轴册（`01/02/04/06/20/21/22`）。
  3. **横轴·跨功能待办**（D-25 新增）：影响**≥2 个** Feature 或整个产品的待办/战略/风险，且不是既成机制 → 归 `09_跨功能待办与战略.md`（原 6 个 `feature/待办_*.md` 与 `feature/待办索引.md` 已迁移至此/各功能文件夹，仅留 tombstone）。
  两边都沾边时，窄的一边只放摘要+链接，宽的一边放权威内容，**不重复写**。判不清时按"这段内容删掉后，另一边是否仍完整可懂"判断——删了还完整，说明是可摘要的一边。**机械补充**：同一条目 ID 只能出现在一个位置，`feature_sync_check.py --struct`（C4）查重，命中即阻断。
- **全景图新鲜度机械门禁（2026-08-19 新增，D-25，纵轴专用）**：`python .ai-context/tools/feature_sync_check.py --range <基线sha>..<headsha>`，批次转 `ACCEPTED` 前必跑，硬阻断（C1 UNMAPPED/C2 BEHIND/C3 FAKE-BUMP/C4 STRUCT/C6 INDEX-STALE 任一命中即不得转 TURN）；`--backlog` 出历史欠账软信号（C5，进交接第六节）。与上面 `review_freshness.py`（横轴六册页脚 STALE/ANCHOR-MISMATCH）分工：一个管"册"，一个管"功能文件夹"，信号域不重叠，`feature_sync_check.py` 复用 `review_freshness.py` 的监视路径数据当覆盖图的一部分。设计全文见 `projectReview/08` D-25。
