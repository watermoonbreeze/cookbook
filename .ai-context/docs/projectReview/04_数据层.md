## 概览层：数据三层

| 层 | 是什么 | 代表 |
|---|---|---|
| **用户生成** | 用户建/记的内容 | `dish/ingredient/...(source='user')`、`meal_record`、`pantry`、`family_member`、`dish_favorite` |
| **预设基础** | seed 灌入的底料 | `ingredient/dish/food_category/...(source='preset')`、`meal_type`、`measurement_unit` |
| **外部参考** | 权威参考数据（AI 整理·标 ref/待核） | `ingredient_nutrition`、`ingredient_detail`、`ingredient_care_rule`、`crowd_ingredient` |

**心智** — UI/VM 只依赖 Repository（返回领域模型，不碰 SQLDelight 行）；查询支持 Flow 监听 + suspend 一次性读。

## 细节层：表清单（36 张，按域）

- **字典**：`cooking_method`(烹饪方式)、`measurement_unit`(单位, 含 `grams` 克当量)、`meal_type`(餐次)、`crowd_type`(人群·**旧体系，逐步被 food_category 调养病种替代**)、`dish_tag`(标签)。
- **食材体系**：`ingredient`(主表, `name` 全新库 UNIQUE/老库可能同名多 id)、`ingredient_nutrition`(每100g 营养·PK=ingredient_id)、`ingredient_detail`(做法/选购/储存/健康说明)、`food_category`(分类树, dimension=general/nutrition/season/crowd)、`ingredient_category`(食材↔分类 多对多)。
- **调养/健康**：`ingredient_care_rule`(新体系·食材+病种→avoid/limit/recommend)、`crowd_ingredient`(旧体系)、`user_health_profile`(启用病种)、`family_member`(成员+身体数据·`is_focus` 关注·**多人关注起可多个=1**)、`member_care`(成员↔病种)、`member_avoid_category`(**v29·成员↔忌口分类**·个人忌口按 food_category 分类·与 member_care 平行·推荐时全家并集展开为食材 id)、`day_absentee`(缺席按天)。
- **菜品体系**：`dish`(主表, `preference` 喜爱度/`cuisine` 菜系)、`dish_ingredient`(配料·quantity/unit_id/is_main·UNIQUE(dish_id,ingredient_id))、`dish_step`(步骤)、`dish_cooking_method_rel`/`dish_tag_rel`/`dish_crowd`/`dish_meal_slot`(**v28·菜↔餐次·多对多·仿 dish_cooking_method_rel·指向 meal_type**)、`dish_favorite`(收藏置顶)、`dish_dislike`(负反馈踩)。
- **餐食记录**：`meal_record`(每餐·date/meal_type_id/status 软删)、`meal_record_dish`(餐↔菜)。
- **收藏/模板**：`favorite_combo(_dish)`(收藏组合)、`step_template(_item)`(步骤模板)、`ingredient_group(_item)`(常用配料组)。
- **库存/工具**：`pantry`(库存·serving_count 份数/added_at 窗口/status)、`cooking_timer_template`(计时模板)、`user_preferences`(K-V 偏好)。

**关系要点** — 关联表多为 `ON DELETE CASCADE`；`dish_ingredient` 关联 `measurement_unit` 折算克数（营养估算）。

## 参考层：seed / 迁移 / 偏好 / Repository

### Seed 文件（`shared/src/commonMain/resources/seed/`，按名 upsert 幂等）
`ingredients.json`(食材主体, 不含营养) · `ingredient_nutrition.json`(营养 L2, 独立单表单文件) · `ingredient_details.json`(详情) · `food_categories.json`(分类树) · `dishes.json`(菜品+配料+步骤·**含 `mealSlots` 餐次 code·567 道·v28 起**) · `crowd_rules.json`(人群建议·旧) · `ingredient_care_rules.json`(调养·新)。
> 营养数据标 `ref`(来源)+`review`(待审)——**AI 整理、非权威核对，缺数据省略不编造**。预设菜餐次由 `seedDishMealSlots` 按 `MealSlotMatcher` 推断补齐(回填只补空)。
> **`SEED_LOGIC_VERSION`(当前 `seedlogic-v6`)**：seed **处理逻辑**变更(非 JSON 内容)时 +1 混入指纹，让老库跑一次(v6=餐次分类补齐)；否则指纹不变、老库跳过。

### 迁移机制（红线详见 [06](06_约定与红线.md)）
- `.sqm` 迁移在 `shared/.../db/`，**当前到 `29.sqm`**（28=dish_meal_slot 餐次分类·29=member_avoid_category 个人忌口·均纯新表零风险）；真实版本=`.sqm` 文件数（build.gradle version 无效）。
- 新迁移名=目录最大 N+1；加列要 CREATE TABLE 同步加 + 新 `N.sqm ALTER`（幂等）+ 所有构造/调用点同步。
- 单测走 `Schema.create` 不跑迁移链——改迁移须推演旧库升级。

### 偏好存储（`user_preferences` K-V + `PreferenceRepository`）
主题 `THEME_MODE`/`APP_PALETTE`、布尔开关(1=true)、身体数据 `BODY_METRICS`(JSON 序列化·`ignoreUnknownKeys`·**加字段零迁移**)、推荐风格 `RECOMMEND_STYLE`、AI Key/模型(**不备份同步**)、`HAS_SEEN_GUIDE`、`FOCUS_VIEWING_MEMBER_ID`(**多人关注·当前查看成员指针·今日卡+报告共用·零迁移·失效自愈**)。

### Repository 清单（`shared/.../data/repository/`）
`Ingredient`/`Dish`/`MealRecord`/`Nutrition`/`Pantry`/`Family`/`HealthProfile`/`Preference`/`CookingTimer`/`FavoriteCombo`/`StepTemplate`/`IngredientGroup`/`ShoppingList`Repository。
