# 22 · 预设与参考资料治理（本项目专属）

> 这册讲什么：预设食材/菜品、营养事实和外部参考资料如何生产、审核、入库和被应用复用。
> 服务用途：掌握全貌 ✅ ｜ 反查数据来源 ✅ ｜ 审核健康数据边界 ✅
> 装什么：数据分层、生产链、可信度、复用边界、扩展规则。
> 不装什么：具体表字段（→[04](04_数据层.md)）、健康算法消费细节（→[20](20_健康与算法逻辑（专属）.md)）。

## 概览层：内容是可追溯资产，不是散落常量

**内容治理链** — 外部权威资料和人工审核形成可追溯 seed；应用首次/升级初始化写入本地库；算法和界面只消费带来源与状态的数据。

```text
权威资料 / 人工审核
  → data-pipeline（整理、校验、保留来源）
  → resources/seed JSON
  → PresetDataSeeder / SeedUpdateCenter
  → SQLite 预设与参考事实
  → 食材、菜品、营养、健康规则、推荐与参考页
```

## 数据可信度与优先级

| 数据类型 | 来源与用途 | 是否可作为后续高可信匹配 |
|---|---|---|
| 预设/权威营养事实 | `ingredient_nutrition` 等带 `ref/review` 的资料 | 可以；要求可追溯、已审核 |
| 用户手工修改 | 家庭本地事实，优先级最高 | 可以，须标明用户来源 |
| AI 创建实体 | AI 建议，经用户确认后入库 | 可引用实体；营养事实仍需独立可信度 |
| 本地算法估算 | `NutritionGuesser` 等无法精确匹配时的建议 | 不可以；不得回流升级为权威或高置信候选 |

## 预设与资料的复用规则

- 预设食材、菜品、做法、餐次、分类等由 seed 统一管理；用户和 AI 创建的数据不得覆盖 `source=preset`。
- 参考页只解释已采用的口径，应能追到共享准则或数据记录；无法核验时标记待审核，不编造出处。
- 新增营养元素、食材属性或菜品扩展时，先定义数据来源、审核状态、单位和消费者，再扩 seed、schema 和 UI。
- 扩展工具（搜索、推荐、自由搭配、库存、报告）复用同一实体和营养事实，不各自维护副本。

## 参考层：生产与消费位置

| 责任 | 关键位置 |
|---|---|
| seed 资源 | `shared/src/commonMain/resources/seed/` |
| 初始化与版本控制 | `data/seed/PresetDataSeeder`、`SeedResourceLoader`、`SeedUpdateCenter` |
| 数据生产链 | `data-pipeline/`（离线整理与校验；产物必须回链来源） |
| 本地事实 | `Cookbook.sq`、`data/repository/NutritionRepository`、`IngredientRepository`、`DishRepository` |
| 对用户透明 | Android `ui/reference/` 各参考页面 |
