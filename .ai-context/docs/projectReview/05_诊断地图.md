# 05 · 诊断地图（反查入口）

> 这册讲什么：**遇到任何界面/行为现象时的第一入口**——现象 → 逻辑 → 代码 → 判 bug/需求。
> 服务用途：反查 ✅（solve 模式起点）｜ 审核 ✅
> **寻路承诺**：从任一现象出发 **≤2 跳**到代码位置或红线——第 1 跳进本册分诊台，第 2 跳落到目标行/册节。
> 用法：先在"层 A 分诊台"按现象类别找方向 → "层 B"查具体链路与判据 → 命中已知坑则看"层 C"。

---

## 层 A · 症状分诊台

| 现象类别 | 典型描述 | 首查 | 一句话诊断提示 |
|---|---|---|---|
| 某数据算错 | 热量显示 0、营养对不上 | 层 B「热量算0」 | 多为配料未关联或用量为 NULL |
| 某项没出现 | 该推的菜没推、库存菜看不到 | 层 B「推荐缺项」「库存缺项」 | 多为忌口过滤/同名多id/份数不足 |
| 某页空白/列表空 | 保存后看不到、分类下没东西 | 层 B「保存后不显」 | 多为查询依赖陈旧派生态 |
| 某操作没反应 | 加份数无变化、toggle 回不来 | 层 B「操作无效」 | 多为当天餐扣回/stateIn 冻结 |
| 某处样式不对 | 双边距、状态栏割裂、图偏转 | 层 C + [06](06_约定与红线.md) | 多为 insets/系统栏/EXIF 红线 |
| 真机初始化失败 | 装新版打不开/数据丢 | 层 C + [06](06_约定与红线.md) | 多为 SQLDelight 迁移链断 |
| 慢/卡顿 | 生成计划慢、列表卡 | 层 B「性能」 | 多为 N+1（部分已修） |
| AI/网络失败 | Key 无效、超时、解析无效、规则替代 | 层 B「AI 请求失败」 | 区分配置、HTTP、截断、schema 与用户确认降级 |
| 预设/来源异常 | seed 不更新、营养来源缺失 | 层 B「预设审校」 | 先分辨运行时 seed 与离线数据管线 |
