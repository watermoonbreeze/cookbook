# 21 · AI 与网络请求策略（本项目专属）

> 这册讲什么：AI 能力从本地准备、云端请求到结构化入库的边界与降级策略。
> 服务用途：掌握全貌 ✅ ｜ 反查 AI/网络问题 ✅ ｜ 审核 AI 安全与体验 ✅
> 装什么：Runtime、请求责任、结构化响应、失败降级、隐私、诊断入口。
> 不装什么：健康评分细节（→[20](20_健康与算法逻辑（专属）.md)）、数据库表定义（→[04](04_数据层.md)）。

## 概览层：本地可控，AI 负责生成

**AI 请求链** — 本地先准备约束和候选，AI 只生成或理解结构化语义；结果必须经过本地校验、预览和用户确认才能入库。

**AI 输出展示总规则** — 凡是 AI 生成界面或生成内容，默认按流式/渐进式显示设计：请求发出后立即进入生成态，UI 能承接部分结果、增量追加、最终重排、失败尾部和人工重试；不能把“等完整响应落地后再显示”作为唯一体验路径。

```text
UI 输入 / 推荐操作
  → ViewModel
  → 本地规则、健康约束、候选数据
  → AiRuntime（云端模型 / 规则降级 / 端侧预留）
  → 协议解析与 schema 校验
  → 规范化、预览、确认入库
```

| 场景 | AI 的职责 | 本地的不可让渡职责 |
|---|---|---|
| 推荐下一餐/周期计划 | 在安全候选内编排与解释 | 忌口、库存、份数、候选范围、排序与结果校验 |
| AI 记一餐 | 将自然语言转为日期、餐次、菜品、食材、调料、做法、份量 | 日期锚定、schema 校验、实体归一、查重、预览、写库 |
| AI 设置 | 验证配置、选择可用模型 | 密钥本地保存、脱敏、失败提示与禁用不安全请求 |

## 细节层：AI 记餐的语义与降级

### 显式结构化结果的入库边界

**预期行为** — AI 给出结构化食材、调料、做法时，本地不重新按菜名解析；只核验本地库是否已有同一规范实体，已有则引用、没有则以 `source=ai` 新建。菜名解析仅用于规则模式或 AI 结果缺失/不可信时的补全候选。

### 可见降级而非静默替换

**预期行为** — AI 请求失败、响应截断、JSON 无效或校验失败时，保留原始输入和失败原因，提示用户是否转规则模板；预览明确显示“AI 解析”或“规则匹配/规则补全”。规则不能伪装成 AI 成功结果。

### 长输入与结构化输出

- 输入按日期块、餐次块切分，保留原始文本与日期锚点；不可按字符随意截断。
- 请求只要求最小结构化字段；限制天数、餐次、菜品、食材和输出 token。
- `finish_reason != stop`、未闭合 JSON、字段越界均视为 AI 失败，不提交半成品。
- schema 校验、日期解析和多日聚合在写库前完成；任何丢弃/补全要进入预览警告。
- 当前 Flat 协议按“完整日期 → 餐次”聚合，但日期真相源先看用户原文：仅原文有绝对日期时才采纳 AI 的 `date`；无绝对日期时强制以添加页所选日期为锚点；周一至周日映射到该锚点所在周，且只显示一条锚定提示。`targetDate` 在重新输入、预览与确认间不可丢失或被 AI 首日反写。Schema 错误阻断预览，warning 必须可见；有既有餐食时，用户需明确确认 MERGE 后才会写库。

### 周期记 + NDJSON 流式解析（已定方案·待实现）

落地方案文档：`feature/AI记一餐_周期记_NDJSON流式改造落地方案.md`。下个干净 session 以该文档为实施入口。

- 输入分两档：快速记≤200字；周期记按周/日期分段，每段≤200字，发送时按日期块请求，确认页合并展示。
- Token 上限按场景配置，DeepSeek 与其他云端模型统一放大到可覆盖“一周餐食解析”；`finish_reason=length` 必须单独提示“模型输出被截断”，不可只报 schema 无效。
- 输出协议改为 NDJSON/JSONL 优先：每行是一条可独立校验的餐食/菜品/建议事件，必须携带稳定归属键：`segment_id` 标识输入分段，`meal_id={date}|{slot}` 标识餐次，`dish_id={meal_id}|d{index}` 标识菜品；本地以父子键聚合，不以行顺序作为唯一归属依据。
- UI 发送后立即进入生成确认页；中间餐食信息按已解析事件实时展开。当前已解析且合法的内容可查看、可确认记下；未闭合或失败的尾部只进诊断，不阻断已合法内容。
- 该流式体验是 AI 横向规则，不只限 AI 记餐；后续 AI 推荐、AI 生成菜品、AI 建议等输出显示都按同一兼容口径设计。
- 服务端若仍返回整体 JSON，本地保留兼容适配层：先尝试 NDJSON，失败后尝试对象/数组 JSON，再规范化为确认页同一扁平结构；不得因“不是扁平返回”直接拒绝，除非无法提取任何有效菜名。
- 健康建议仍只展示、不持久化；建议事件可流式显示，但保存餐食只写真实餐食、菜品、食材实体。

### 双阶段请求与健康档案最小化（已决方案）

1. **解析请求**：输入自然语言→`meal-log.v2` 宽松扁平结果。Prompt 要求尽量输出时间、餐次、菜名、食材/调料/做法、食材大类与营养元素；只有菜名为必需，`null`/缺失的可选字段不构成协议失败。
2. **本机事实层**：不联网即可依据档案和已核验数据生成 `HealthSafetyReport`，它是安全提示的唯一事实来源。
3. **建议请求（可选）**：仅在用户针对本次操作单独同意时发送；使用成员匿名标签、年龄段/生命阶段、关注项和忌口摘要及本餐摘要，禁止发送姓名、ID、原始输入、完整病史、生命体征、检查报告、用药和历史餐食。响应为非诊疗、展示用 `AiHealthReviewDraft`，失败不影响记餐。
4. **会话与诊断**：建议及原始响应只在内存会话保存，离开/重输即清除；解析失败可在确认页结果图标中查看阶段、HTTP/错误码、长度和脱敏摘要，原始返回须二次点击才临时展示。禁止复制/分享、持久化、埋点和全量日志。

## 网络、配置与隐私

| 项 | 规则 |
|---|---|
| Runtime | `AiRuntime` 抽象云端、规则降级与端侧预留；协议实现与 UI 解耦 |
| 配置 | API Key/模型配置通过偏好持久化；密钥不进入备份、同步、截图或日志 |
| 日志 | 禁止记录完整 prompt、原始饮食文本、完整模型响应或密钥；仅记录脱敏错误码、长度、模型、阶段和 requestId |
| 请求测试 | 设置页可发起显式测试；测试结果可见，模型列表仅在服务端实际返回时展示 |
| 离线/失败 | 推荐退规则候选；AI 记餐保留输入并请求用户选择规则匹配，不静默写库 |
