# 21 · AI 与网络请求策略（本项目专属）

> 这册讲什么：AI 能力从本地准备、云端请求到结构化入库的边界与降级策略。
> 服务用途：掌握全貌 ✅ ｜ 反查 AI/网络问题 ✅ ｜ 审核 AI 安全与体验 ✅
> 装什么：Runtime、请求责任、结构化响应、失败降级、隐私、诊断入口。
> 不装什么：健康评分细节（→[20](20_健康与算法逻辑（专属）.md)）、数据库表定义（→[04](04_数据层.md)）。

## 概览层：本地可控，AI 负责生成

**AI 请求链** — 本地先准备约束和候选，AI 只生成或理解结构化语义；结果必须经过本地校验、预览和用户确认才能入库。

```text
UI 输入 / 推荐操作
  → ViewModel
  → 本地规则、健康约束、候选数据
  → AiRuntime（云端模型 / 规则降级 / 端侧预留）
  → 协议解析与 schema 校验
  → 规范化、预览、确认入库
```

| 场景 | AI 的职责 | 本地的不可让渡职责 |
|---|---|---|
| 推荐下一餐/周期计划 | 在安全候选内编排与解释 | 忌口、库存、份数、候选范围、排序与结果校验 |
| AI 记一餐 | 将自然语言转为日期、餐次、菜品、食材、调料、做法、份量 | 日期锚定、schema 校验、实体归一、查重、预览、写库 |
| AI 设置 | 验证配置、选择可用模型 | 密钥本地保存、脱敏、失败提示与禁用不安全请求 |

## 细节层：AI 记餐的语义与降级

### 显式结构化结果的入库边界

**预期行为** — AI 给出结构化食材、调料、做法时，本地不重新按菜名解析；只核验本地库是否已有同一规范实体，已有则引用、没有则以 `source=ai` 新建。菜名解析仅用于规则模式或 AI 结果缺失/不可信时的补全候选。

### 可见降级而非静默替换

**预期行为** — AI 请求失败、响应截断、JSON 无效或校验失败时，保留原始输入和失败原因，提示用户是否转规则模板；预览明确显示“AI 解析”或“规则匹配/规则补全”。规则不能伪装成 AI 成功结果。

### 长输入与结构化输出

- 输入按日期块、餐次块切分，保留原始文本与日期锚点；不可按字符随意截断。
- 请求只要求最小结构化字段；限制天数、餐次、菜品、食材和输出 token。
- `finish_reason != stop`、未闭合 JSON、字段越界均视为 AI 失败，不提交半成品。
- schema 校验、日期解析和多日聚合在写库前完成；任何丢弃/补全要进入预览警告。

## 网络、配置与隐私

| 项 | 规则 |
|---|---|
| Runtime | `AiRuntime` 抽象云端、规则降级与端侧预留；协议实现与 UI 解耦 |
| 配置 | API Key/模型配置通过偏好持久化；密钥不进入备份、同步、截图或日志 |
| 日志 | 禁止记录完整 prompt、原始饮食文本、完整模型响应或密钥；仅记录脱敏错误码、长度、模型、阶段和 requestId |
| 请求测试 | 设置页可发起显式测试；测试结果可见，模型列表仅在服务端实际返回时展示 |
| 离线/失败 | 推荐退规则候选；AI 记餐保留输入并请求用户选择规则匹配，不静默写库 |
