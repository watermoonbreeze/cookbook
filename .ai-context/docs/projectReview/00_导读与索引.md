# 00 · 导读与索引

> 这册讲什么：整个说明书的**总入口与地图**——一句话认识项目、按意图选路、术语与状态图例。
> 服务用途：掌握全貌 ✅ ｜ 反查 ✅（去 [05 诊断地图](05_诊断地图.md)）｜ 审核 ✅
> 装什么：项目定位 / 模块全景 / 任务导向阅读路径 / 分册清单 / 术语表 / 状态图例。
> 不装什么：具体流程/界面/数据细节（各在其册）。

## 项目一句话

**Cookbook（家庭记菜）** — 一款面向慢性病（三高、痛风等）家庭的**饮食规划 App**，帮家庭解决"每天吃什么"的决策疲劳：记录每餐 → 看历史 → 复用/推荐 → 结合营养与慢病忌口给建议。KMP 跨平台架构，当前**只交付 Android**（Compose UI）。

## 项目地图系统（所有模型的首读入口）

**项目地图系统** — 用"全景说明书 + 代码级路径索引 + Project Graph"三层分别回答项目的方向、实现落点和当前状态；三者互补，各有权威范围，不是互相竞争的事实源（2026-08-17 起明确，此前长期只讲前两层，见下方「与 Project Graph 的边界」）。

| 层级 | 回答的问题 | 唯一入口 | 维护要求 |
|---|---|---|---|
| 全景说明书 | 项目有什么、为何如此、各层如何协作、应该先读哪里 | 本册及 01–08、20–22 | 影响架构/流程/UI/算法/数据/AI/资料来源时，同任务更新受影响分册与 [05](05_诊断地图.md) |
| 功能路径索引 | 某功能、真相源、Screen、VM、Repo 或 Engine 在哪里 | [功能路径索引](../功能路径索引.md) | 增删移动关键实现或真相源时，同任务更新 |
| Project Graph | 某 Feature/WorkItem **现在处于什么状态**（做没做完、验没验过、有哪些 Bug/Todo） | `.ai-context/project_graph/` | AI 维护，人工只读；Phase 3 生成视图激活前，`07` 是可能滞后的人工摘要 |

**使用顺序** — 全局关联任务先读本册，按阅读路径下钻；确认要改的功能后，再用功能路径索引精确定位；要知道某功能**当前状态**（而非"是什么"），去 Project Graph。不得只凭局部代码推断项目全局。

### 与 Project Graph 的边界（过渡期，2026-08-17 新增）

`projectReview/`（本说明书）与 `.ai-context/project_graph/` 现在并存，边界如下，防止未来变成两套互相矛盾的真相源：

1. **本说明书回答"是什么/为什么"**（架构、业务流程、界面、数据口径、算法、历史取舍）；**Project Graph 回答"现在处于什么状态"**（Feature 的 lifecycle/activity/health，WorkItem 的 status，Verification 的 pending/pass）。
2. **凡状态类字段（做没做完、验没验过、健康度）以 Project Graph 为准**；本说明书（尤其 `07`）只做摘要，且可能滞后于 Graph 与代码——`07` 顶部已加显式滞后声明。
3. **Phase 3（生成视图 + 激活）落地后，`07`/`功能路径索引`/待办索引转为从 Graph 自动生成的视图**，本节随之改写；Phase 3 现状见 `.ai-context/project_graph/README.md`，决策记录见 [08](08_决策记录.md) D-18。

### 落图与回写门禁（2026-08-17 补齐对称的另一半）

方案入图（下方§入）防不住"实现完成后没同步"这类漂移——`07` 曾停更 12 天、181 个提交里两个已落地功能（L1/K1i）一个字没提，根因正是只有入口没有出口。两条门禁对称、不重复：

**（入）方案型决策落图门禁** —— 凡形成或调整产品规则、业务流程、算法、AI 边界、数据口径、自动行为、权限/隐私或关键交互的**方案型决策**，方案文件不能成为孤岛：同一任务必须把方案文档挂到全景图对应功能分册，并在本册给出一句话决策与阅读路径；同步更新受影响分册、`05_诊断地图.md` 的反查条件、`08_决策记录.md`（长期取舍）和 `功能路径索引.md` 的代码真相源；完成前逐项核对。纯局部实现细节可不写 ADR，但仍要维护对应索引。

**（出）交付回写门禁** —— 方案入图之后，实现完成时必须有对称的一次回写，否则全景图会停留在"方案态"而与代码分叉：
1. **触发**：`BLUEPRINT_STATE.md` 任一批次状态写入 `ACCEPTED` 的那次编辑（不是"功能做完时"，不是"提交代码时"——那两个时点太模糊，无法判断"做没做"）。
2. **动作**：同批填写 `BLUEPRINT_STATE.md` 该批次表的「全景图回写」字段；有产品代码改动的批次，在 `07` §能力成熟度追加**一行**（限一行，禁止借机扩写）。
3. **禁止**：把回写事项记入任何"可选/并行/有空再做"的清单——2026-08-11 的 SESSION 已实证该做法等于不记（漂移被记录后仍躺了 6 天没处理）。
4. **`08` 不参与回写**：决策记录只记"决定了什么"，不带实现状态后缀（`｜已实现`/`｜待实现` 这类字段天生会漂，D-16 曾因此漂移）；实现状态一律以 Project Graph 为准。

当前落图示例：**AI 记一餐日期锚点 / 周期记 NDJSON 流式改造** — 日期锚点详见 [21 AI 与网络](21_AI与网络请求策略（专属）.md) 与 D-15；周期记+NDJSON流式大改详见 [21 AI 与网络](21_AI与网络请求策略（专属）.md)、`feature/AI记一餐_周期记_NDJSON流式改造落地方案.md` 与实施基线 `feature/AI记一餐_周期记_NDJSON流式开发规范.md`。反查走 [05 诊断地图](05_诊断地图.md)，取舍走 [08 决策记录](08_决策记录.md)，代码定位走功能路径索引。

## 应用全景链路

```text
页面与交互（Compose / 路由 / 共用组件）
  → ViewModel 编排与状态反馈
    → 领域能力层（食材、菜品、营养、健康、推荐、自动生成）
      → Repository / SQLDelight / 用户数据与预设数据
      → AI Runtime / 网络请求 / 结构化校验与规则降级
      → 参考资料 / 营养事实 / seed 数据生产与审核
  → 预览确认 → 入库 → 食历、库存、推荐、营养报告复用
```

## 术语表（一物一词）

| 词 | 指 |
|---|---|
| 菜品 | 一道菜（预设或自建），含配料/做法/步骤。不叫"菜谱/食谱" |
| 食材 | 原料（预设或自建）。"配料"仅指某菜用到的食材关系 |
| 餐次 | 早餐/午餐/晚餐/加餐 |
| 记一餐 | 记录某日某餐吃了哪些菜 |
| 库存 | 家里在手的食材（份数=可做几次） |
| 计划 vs 食历 | 计划=未来餐；食历=历史餐（同一时间线） |
| 忌口/限量/推荐 | 健康档案对食材的三档建议（avoid/limit/recommend） |
| 色系墙 | 首页按膳食结构多样性上色的日历墙（**不关联热量/慢病**） |
| 今日卡 | 首页当天营养卡（热量/宏量/慢病温和提示，个人视角） |
| care/病种 | 慢病类型（高血压/糖尿病/高血脂/痛风…），驱动忌口与提示 |
| 项目地图 | 本说明书 00–08、20–22 + 功能路径索引组成的**面向理解**的全局入口；**状态类事实的权威在 Project Graph**，见上方「与 Project Graph 的边界」 |
| 显式 AI 语义 | AI 已结构化给出的菜品、食材、调料、做法与份量；本地只规范化、校验与入库，不反向覆盖解析 |
