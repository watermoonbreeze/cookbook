## 项目一句话

**Cookbook（家庭记菜）** — 一款面向慢性病（三高、痛风等）家庭的**饮食规划 App**，帮家庭解决"每天吃什么"的决策疲劳：记录每餐 → 看历史 → 复用/推荐 → 结合营养与慢病忌口给建议。KMP 跨平台架构，当前**只交付 Android**（Compose UI）。

## 项目地图系统（所有模型的首读入口）

**项目地图系统** — 用"全景说明书（横轴+纵轴）+ 代码级路径索引"两层分别回答项目的方向/状态和实现落点（2026-08-19 D-25 修订：原三层里的 Project Graph 已整体归档退休，不再是独立的第三层，`projectReview/features/` 直接承担"某功能现在什么状态"这个问题，见 `08` D-25）。

| 层级 | 回答的问题 | 唯一入口 | 维护要求 |
|---|---|---|---|
| 全景说明书·横轴 | 项目整体架构/流程/数据/算法/AI/资料来源为何如此 | 本册及 01/02/04/06/08、20–22 | 影响跨 ≥2 功能的机制时，同任务更新受影响分册与 [05](05_诊断地图.md) |
| 全景说明书·纵轴 | 某功能现在是什么、什么状态、有什么待办/bug/验证项 | [`features/<F-ID>/`](features/)（README + 按需 10/20/30/40/60 子文件），全项目一览见生成视图 [07](07_项目现状.md) | `feature_sync_check.py` 机械阻断：改动命中某功能的代码路径时，该功能文件夹必须同批更新（见 `06`/`08` D-25），不是靠自觉 |
| 功能路径索引 | 某功能、真相源、Screen、VM、Repo 或 Engine 在哪里 | [功能路径索引](功能路径索引.md)（物理已迁入本目录） | "分功能落点"段脚本生成（`--emit-index`），"跨功能基础设施"段改动时手改，机械一致性由 C6 检查兜底 |

**使用顺序** — 全局关联任务先读本册，按阅读路径下钻；确认要改的功能后，先看该功能 `features/<F-ID>/README.md`，再用功能路径索引精确定位代码。不得只凭局部代码推断项目全局。

## 应用全景链路

```text
页面与交互（Compose / 路由 / 共用组件）
  → ViewModel 编排与状态反馈
    → 领域能力层（食材、菜品、营养、健康、推荐、自动生成）
      → Repository / SQLDelight / 用户数据与预设数据
      → AI Runtime / 网络请求 / 结构化校验与规则降级
      → 参考资料 / 营养事实 / seed 数据生产与审核
  → 预览确认 → 入库 → 食历、库存、推荐、营养报告复用
```

## 术语表（一物一词）

| 词 | 指 |
|---|---|
| 菜品 | 一道菜（预设或自建），含配料/做法/步骤。不叫"菜谱/食谱" |
| 食材 | 原料（预设或自建）。"配料"仅指某菜用到的食材关系 |
| 餐次 | 早餐/午餐/晚餐/加餐 |
| 记一餐 | 记录某日某餐吃了哪些菜 |
| 库存 | 家里在手的食材（份数=可做几次） |
| 计划 vs 食历 | 计划=未来餐；食历=历史餐（同一时间线） |
| 忌口/限量/推荐 | 健康档案对食材的三档建议（avoid/limit/recommend） |
| 色系墙 | 首页按膳食结构多样性上色的日历墙（**不关联热量/慢病**） |
| 今日卡 | 首页当天营养卡（热量/宏量/慢病温和提示，个人视角） |
| care/病种 | 慢病类型（高血压/糖尿病/高血脂/痛风…），驱动忌口与提示 |
| 项目地图 | 本说明书 00–09、20–22（横轴）+ `features/<F-ID>/`（纵轴）+ 功能路径索引组成的全局入口；**Project Truth（状态类事实的权威）即 `projectReview/features/`**，见 `08` D-25（原 Project Graph 已归档退休） |
| 显式 AI 语义 | AI 已结构化给出的菜品、食材、调料、做法与份量；本地只规范化、校验与入库，不反向覆盖解析 |
