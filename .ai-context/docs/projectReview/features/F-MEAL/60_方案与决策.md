# F-MEAL · 讨论中的方案与决策

## MEAL-DATA-CONSOLIDATION-02 · Projection Boundary

已执行（2026-08-21）。本批只收口读取边界，不改变用户行为、数据库 schema 或领域模型。

### 稳定契约

```text
Database Truth
  -> MealRecordRepository
  -> MealDayContent
  -> MealDayCardProjector
  -> DayMealCardData
  -> Home / Timeline / Search
```

- `MealDayContent` 是稳定的中性读取契约，不携带今天/未来、页面加载或编辑状态。
- `MealDayCardProjector` 是时间语义的唯一投影边界，调用方必须传入显式 `referenceDate`。
- `DayMealCardData` 是共享 Meal Read Projection，不是 Feature 状态容器；营养聚合只能消费其餐食内容，不能反向污染投影。
- 现有 Repository 直接返回 `DayMealCardData` 的便捷 API 保留为兼容面；后续新增读取 API 不得返回 Feature Card，优先返回 `MealDayContent`。

### 本批证据与限制

- 边界测试：`MealDayCardProjectorTest.projectionPreservesStableContentAndAddsOnlyTemporalRole`。
- 允许：契约文档、API 稳定性 KDoc 标记、Projection Boundary 测试、Feature 文档同步。
- 禁止：`MealPlan`、schema migration、新领域实体、Repository 拆分、Projection Service、用户行为变更。
