# F-AI-MEAL · 已知问题

- ⚠ **AI 日志隐私风险**：云端 Runtime 仍可能记录完整请求/响应，须脱敏后才能宣称符合隐私口径。
- 🔧 **E-B7F-03 周期记流式请求可无限期卡死（真机复现，2026-08-19；2026-08-20 已修复待真机确认）**：周期记"周一到周五"，周一段 200 成功返回后，周二段请求发出（22:37:34）后**日志此后 15 分钟无任何一行**——无 200 成功、无 `STREAM_IO_ERROR`、无任何异常，直到用户手动退出页面。根因：`StreamTransport.kt`（`HttpUrlStreamCall.execute`）只设置了 `readTimeout=60000`（单次 `read()` 空等上限），**没有整个请求的总时长上限**；`readSseStream()` 逐行读取时，任何非 `data:` 开头的行（SSE 协议常见的心跳/注释行，防中间代理判定连接空闲断开）会被 `continue` 静默丢弃且不产出任何 delta——但这次 `read()` 已经"读到"了东西，60 秒计时器随之清零。只要服务商这一段持续发送心跳但迟迟不出正文，客户端没有任何兜底，可无限期挂起，UI 表现为"一直卡在正在解析下一段"。复现：日志 `真机验证/日志/2026-08-19-ai.logt` 第 276-284 行。**修法方向**：给 `call.execute(...)` 整体包一层 `withTimeout(N秒)`（总时长上限，与已有的单次 read 超时正交），超时按已有的段级失败路径处理（`session.onFailed`+`attemptRuleFallback`，与 HTTP 错误一致），具体秒数与是否重试待设计决策，建议单开 Bug 修复 session 处理（非文档/判据问题）。
- 🔧 **E-L1-11 弹层互斥"关闭后重新弹出"未实现（代码走查发现，2026-08-19；2026-08-20 已修复待真机确认）**：`AiSettingsScreen.kt:71-77` 的 `LaunchedEffect(state.loaded)` 只在 `state.loaded` **首次**翻 true 那一刻检查一次三弹层互斥守卫（`!keyDialogOpen && !consentPanelOpen && !vendorConfirmOpen`），若那一刻 `keyDialogOpen=true`（用户手快，在冷启动 loaded 翻转前已打开设置密钥弹窗）——确实不会与 grandfather 面板同屏堆叠（这部分做对了），**但之后 `keyDialogOpen` 变回 false 时没有任何代码重新触发这个检查**，grandfather 面板会静默永久不出现（本次会话内）。真机待验证清单 E-L1-11 写的预期"关闭 KeyDialog 后 grandfather 面板正常弹出"在当前代码里未实现，不是用户操作太快导致的偶发，是确定性缺口；无现成单测覆盖（Compose 弹层时序场景，本项目此类场景一贯靠代码走查而非单测）。**修法方向**：改成同时 watch `keyDialogOpen`（比如把守卫条件放进单独的 `derivedStateOf`/额外 `LaunchedEffect(keyDialogOpen, consentPanelOpen, vendorConfirmOpen)`，在三者都变 false 且 `state.loaded` 且状态仍是 `GRANDFATHER_PENDING` 时再弹一次），建议与 E-B7F-03 并入同一个 Bug 修复 session。
