# 14. 模型执行力评估

> 用户 2026-08-07 提出：`BLUEPRINT_STATE.md` 的 `ARCH`/`CODE`/`TURN` 字段是**抽象角色位**（禁止出现具体模型名，见该文件头部命名规则），但用户计划后续用不同模型轮流担任 CODE，需要**单独一份文档**积累"哪个模型执行力如何、边界在哪、什么情况下该用什么模型"的实证依据。本文件是该记录的唯一真相源，`BLUEPRINT_STATE.md` 只留指针，不重复内容。

## 定位：与 `~/.ai-context/MODEL_ROUTING.md` 的关系

`MODEL_ROUTING.md` 定义的是**抽象能力层**（旗舰/主力/快速）和分发规则，跨项目通用、不绑定具体商业模型。本文件反过来，是**具体模型 → 抽象能力层实际表现如何**的项目内实证记录（哪个具体模型在 CODE 这个岗位上，遇到什么样的任务会掉到哪一档）。证据积累到足够置信度后，可复用的结论才反哺回 `MODEL_ROUTING.md` 或对应模型的路由建议；单次/单批次的观察不构成结论，只进本表。

## 使用方法

- **CODE 完成一批交付时**：在下方"评估台账"追加一行（只追加不覆盖，历史留痕，格式同 Q/AF 编号规则）；模型名据实填写，不确定就填"未知/未声明"。
- **ARCH 复核后**：补最后一列简评，客观描述这批任务的复杂度特征（长程/短平快、文件数、是否命中 GC 高风险类条款）与该模型的实际表现（哪些做对了、哪些没做到、是否需要额外复核轮次）。
- **不下过早结论**：少于 3 个批次的同一模型数据，不得写入"边界结论"章节；只能停留在台账里当原始记录。

## 模型能力画像（ARCH 起草蓝图前必读，2026-08-17 新增）

> 与下方"评估台账"分工：**台账**是逐批只追加的原始事实（发生了什么）；**本表**是按 `(模型 × 任务族)` 聚合的**当前生效处方**（据此怎么起草下一份蓝图），可被撤销和改写。归因方法见 `12_多模型协作与实施蓝图规范.md` §14.2 的 AT-01~AT-10。

**消费点（强制）**：ARCH 为某模型起草任何蓝图前，必须先查本表对应 `(模型, 任务族)` 行，按"最低要求 Level""强制附加项""执行模式"三列出蓝图；查无此行按项目基线。**本表若在某批未被读取，该批复核不得转 TURN。**

**写入规则**：只由 `EXEC` 类偏差（AT-02/03/04/06，即 `OMISSION`/`SCOPE`/`SURFACE`/`INTEGRITY`）驱动；`BP`（蓝图侧缺口）与 `NON-BP`（环境/需求/ARCH 自身缺陷）**不得**写入本表——那两类分别走 `blueprint_protocol.md` §4 三分支和 fast-follow 清单，跟模型能力无关。每格必须能指回"评估台账"的具体批次行，不允许凭印象填写。

**加严 vs 放宽的不对称门槛**（理由：加严是可逆的局部保险，放宽是不可逆的路由决策，成本不对称）：
- **加严**（提 Level / 加强制附加项 / 转 `ASSISTED`）：同一 `(模型, 任务族)` 上**同类偏差第 2 次**触发（`INTEGRITY` 类第 1 次即触发，因为它破坏的是复核体系赖以运作的前提）。**每条加严项必须同时写退出条件**：连续 2 批不复发 → 标"候选撤销"，下一批 ARCH 须显式裁决保留（写理由）或撤销。单个 `(模型, 任务族)` 同时生效的加严项 ≤3 条，超出须先撤销一条或直接判"不适配"。
- **提升最低 Level**：仅当同一任务族出现 **≥2 条 `SURFACE` 型**记录才允许（AT-07）——`OMISSION`（遗漏枚举项）与 `SCOPE`（越界改动）提 Level 无效，对症对策是外部核验/脚本机械核对，不是把蓝图写得更细。
- **止损**：某 `(模型, 任务族)` 已达 `最低Level=项目基线上限` 且 `执行模式=ASSISTED`，仍出现同类偏差第 3 次 → 停止继续加严，改判"不适配"（换模型或改由 ARCH 直接实现，登记为 `ARCH_REFERENCE`，不计入该模型能力样本）。
- **`ASSISTED` 的合法形态仅限于"只答 Q 单澄清蓝图缺口"，不得中途修改蓝图内容或范围**——否则与"CODE 执行期间不接受实时纠偏"这条方法论原则冲突，评估结果会失真。
- **任务族须在蓝图冻结时随批次声明**（写入 `BLUEPRINT_STATE.md` 该批次行），不得复核后回填，防止"看了结果再选分类"。

**任务族枚举**（封闭集合，从真实记录归纳，不发明未观测到的族；新增族须先有 ≥1 条真实批次）：`MECH-STEP`（冻结 STEP 机械转录）/ `LONG-FIX`（长程多阻断修复）/ `MICRO-FIX`（短小定向修复）/ `DOC-GOV`（纯文档/治理）。

**认识论边界（必须遵守的措辞纪律）**：本表是运营用的保险清单，不是模型能力的科学结论——单个项目、单一 ARCH、小样本的观察性数据无法排除"蓝图恰好写得好/差"这类混杂因素，禁止写成"某模型的能力边界是 X"这类因果断言。反哺 `MODEL_ROUTING.md` 时须标注样本批次数与混杂说明，且只作为候选信号提交人工裁决，不自动落地——这条红线直接对治 UBF 支线的失败模式（用不足的证据做因果推断）。
