# Blueprint 任务包标准（夜间批次固化版）

## 2026-08-26 · 代码先行与统一真机收口

- 代码批次的自动化门（编译、单测、静态质量）通过后，可以继续下一批功能；真机项必须立即追加到唯一真机清单，状态固定为 `PENDING_DEVICE_VERIFICATION`。
- 真机验证集中放在所有代码批次完成后执行；静态审查、构建和单测均不得把运行时项写成 `PASS`、`ACCEPTED` 或 `CLOSED`。
- 并发 trace 的验收使用受控 barrier/dispatcher 验证交错与 first-wins，禁止以 sleep 或全局 current trace 代替显式传播。

后续可执行任务包必须在同一目录包含以下六个文件：

| 文件 | 必填内容 | 作用 |
|---|---|---|
| `README_FIRST.md` | 目标、顺序、禁止项、入口阅读路径 | 首读和范围门禁 |
| `EXECUTION_CHECKLIST.md` | 按序勾选的实现、测试、状态、提交项 | 执行清单 |
| `ARCH_BLUEPRINT.md` | 范围、allowlist、forbidden、验收契约 | 架构约束 |
| `CODE_EXECUTION_PACKAGE.md` | 文件级动作、测试命令、交付格式 | 编码执行说明 |
| `EVIDENCE_CONTRACT.md` | 自动证据、真机证据、PASS/BLOCKED 判据 | 验收证据 |
| `BLUEPRINT_STATE_UPDATE.md` | 批次、状态、TURN、commit、下一步 | 状态回写草案 |

## 最小模板

```text
README_FIRST.md
  目标 / 执行顺序 / 禁止项 / 真机边界 / 交付文件
EXECUTION_CHECKLIST.md
  [ ] 读取蓝图  [ ] 修改 allowlist 内文件  [ ] 自动测试
  [ ] 更新经验  [ ] 更新 BLUEPRINT_STATE  [ ] 提交 commit
ARCH_BLUEPRINT.md
  Scope / allowlist / forbidden / INV / T / E / Q-AF / ARCH gate
CODE_EXECUTION_PACKAGE.md
  STEP-01...N：文件、动作、测试、不可改变项
EVIDENCE_CONTRACT.md
  每条 T/E 的输入、命令、预期、失败判据、证据位置
BLUEPRINT_STATE_UPDATE.md
  状态 / TURN / 基线 / 交付 commit / 真机清单 / 下一步
```

## 兼容规则

- 旧包若以 `00_EXECUTION_ORDER_CHECKLIST.md` 作为首读文件，可在迁移批次继续执行；新包必须使用 `README_FIRST.md`，并在其中引用顺序清单。
- 缺失任一必填文件只能进入 `DRAFT`/`BLOCKED`，不得进入 `BLUEPRINT_READY` 或 `IMPLEMENTING`。
- `BLUEPRINT_STATE.md` 是项目唯一状态真相源；包内 `BLUEPRINT_STATE_UPDATE.md` 只是待回写草案，完成后须将 commit 和证据回填项目状态。
- 真机步骤必须逐条进入唯一的最新真机待验证清单；没有设备时只登记 `PENDING_DEVICE_VERIFICATION`，不得用自动测试替代。
