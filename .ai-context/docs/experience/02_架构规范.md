# 架构规范

## 方法论沉淀（2026-07-21 超长无人值守 session）

### 表单越层修复:min-fix(只移 Repository 注入) vs 抽完整表单 VM——按准则 A 判
- 场景:`MemberEditorScreen`(成员编辑全屏表单)审计标"20+ remember 业务态+直注 IngredientRepository+手写 isDirty→抽 MemberEditViewModel"。
- 判断:三"症状"里**只有 `koinInject<IngredientRepository>` 查名是真越层**(违"Screen 不得注入 Repository");**20+ 本地态/isDirty 非违规**——准则 A 明确背书"以**本地 UI 态**为写回单一真相源+异步回灌 hydrated 守卫",表单本地态是**规定做法**,isDirty 是派生态(由 State 计算)。
- 正解=**min-fix**:只把查名收进 VM(`FamilyViewModel.ingredientNamesByIds`)+回调下传(`onResolveNames`·同 careOptions 下传范式),20+ 本地态/hydration 守卫**原样不动**。抽完整 VM 属**高危低收益**(要重引 `ingLoaded` 异步查名守卫+已修的"未查完保存清空既有忌口"数据丢失坑),违反过度设计红线。Google 架构审确认 min-fix 正确、F-Arch2 结案。**通则:审计条目要按项目准则复核实质违规,不照字面照搬"抽 VM";表单本地态该留 Composable。**

### 抽共享防调参漂移(单一真相源)——本轮两例
- `ChronicDiseasePenalty`:慢病 GI/嘌呤软降罚分公式,**单餐 `HealthRuleEngine` + 周计划 `PeriodPlanner` 共用**(同 `MealCompositionScorer` 思路)。防两处各改各的漂移。
- `DishNutritionLine`(Composable):AiRecommend `DishRow` + AiPlan `DayCard` 每菜营养行共用。
- **通则:凡"两处语义/常量相同的评分或呈现",抽成共享 object/Composable,别复制。判据:改一处会不会漏另一处。**

### "把已算的盛出来"优先于"造新算法"——营养线案例
- 用户要"周计划营养线(整体均衡)"。摸码发现 `PeriodPlanner.score()` **已在算** `usedNutrition`(跨餐跨天营养维度覆盖/去重),只是**从没呈现到 UI**(nutritionTags 在 Screen 层零引用)。
- 落地=先 domain 聚合器(`WeeklyNutritionLineAggregator` 结构层·复用 `FoodGroup`)把整周覆盖/缺口/均衡度算出来+AiPlan 概览卡呈现;算法只需一处"从防重复到填缺口"最小增强(未做·follow-up)。**通则:接新需求先摸"是不是已经算了、只是没显",呈现层补齐往往比新算法性价比高。**

### 多角色会商并行→主 agent 汇总收敛落方案文档
- 大设计/战略题(如"周计划营养线")spawn 产品(general-purpose)+营养师(algorithm_engineer)+运营(apple_operations_designer)+文案(copywriter)**并行**各出镜头分析→主 agent **汇总收敛**成单一方案文档(含共识/分歧/MVP/红线/分期)供用户拍板。UI 统一/界面改动同理先 `apple_ux_designer` 出规范再编码(崩溃敏感区必走)。**产出落 `feature/*方案.md`,不散在对话。**

## 整体架构

[2026-05-14] 采用 Clean Architecture 简化版（UI / Domain / Data 三层）：

- **shared/commonMain** 存放 Domain 层（Model、UseCase）和 Data 层（Repository、SQLDelight）
- **androidApp** 仅负责 UI 层（Compose 页面、ViewModel、Theme、Navigation）
- UI 与业务逻辑按模块分离，各平台 UI 独立

## 数据流

[2026-05-14]

```
UI (Compose) → ViewModel → UseCase → Repository → SQLDelight (DB)
```

- Repository 返回 `Flow<T>`，ViewModel 通过 `collectAsState` 绑定 UI
- UseCase 封装业务逻辑，供 ViewModel 调用

## KMP 工程边界

[2026-05-24]
- `shared` 保持 Domain/Data 跨平台能力，平台 API 必须通过 `expect/actual` 适配。
- Android UI 只放 Compose Screen、ViewModel、Navigation、Theme、Android DI。
- iOS UI 后续应使用 SwiftUI 和 iOS 原生交互风格，不照搬 Android Material 组件。
- 详细统一规范见 `.ai-context/docs/experience/09_工程统一规范.md`，开发前应按需读取。

## Codex 命令机制

[2026-05-24]
- `~/.codex/commands/*.md` 是兼容命令档案，不会自动等同于 Claude Code 的裸 slash command。
- 若用户输入普通文本“执行 zongjie / 总结经验”，Codex 可按 `~/.codex/commands/zongjie.md` 执行。
- 若要更接近 Claude 风格，需要用 Codex plugin 暴露 `commands/`。
- 已创建并安装本机个人插件 `personal-workflow@personal`，命令文件来自 `~/.codex/commands/`。
- 插件命令通常使用命名空间形式，例如 `/personal-workflow:zongjie`；裸 `/zongjie` 不保证可用。
