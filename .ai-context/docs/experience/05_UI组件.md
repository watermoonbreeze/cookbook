## Android 启动图标配置

[2026-06-12]
- Android App 图标放在 `androidApp/src/main/res/mipmap-*`，不要放到 shared 或普通业务图片目录。[AI生成]
- 源图如果是 1024x1024 PNG，可生成 `mdpi/hdpi/xhdpi/xxhdpi/xxxhdpi` 多密度 `ic_launcher.png`，并同步准备 `ic_launcher_round.png`。[AI生成]
- Android 8+ 需要在 `mipmap-anydpi-v26/` 增加 adaptive icon XML，通常包含 `background` color 和 `foreground` mipmap；背景色放到 `values/colors.xml` 统一管理。[AI生成]
- Manifest 的 `application` 必须同时配置 `android:icon="@mipmap/ic_launcher"` 和 `android:roundIcon="@mipmap/ic_launcher_round"`，否则安装器/桌面可能仍显示默认图标。[AI生成]
- 图标资源配置后至少运行 `./gradlew :androidApp:assembleDebug`，确认 AAPT、Manifest 合并和资源引用都通过；本经验只覆盖 Android，iOS 仍需单独维护 AppIcon。[AI生成]

## 图片展示组件

[2026-05-24]
- 使用 `StoredImage` 统一展示本地/系统 URI 图片。
- `StoredImage` 读取 `image_path` 中 `|` 分隔的第一张 URI，支持 `content://` 和文件路径，失败时回退到占位 UI。
- 菜品卡片、菜品列表行、菜品详情、食材选择项、图片选择区都应复用该组件，不要各自手写图片加载逻辑。
- [2026-05-25] `StoredImage` 列表缩略图需要走有容量上限的 LRU 缓存；点击预览时单独读取更清晰图片，不复用低清缩略图作为大图。
- 默认无图展示：
  - 菜品使用菜名/餐食 emoji 占位。
  - 食材使用蔬菜类 emoji 或食材首字占位。
- 图片选择统一用 `ImagePickerButton`，支持相册多选和系统相机拍照，最多 3 张。

## 烹饪计时交互

[2026-06-14]
- 多个倒计时同时运行时，不要把运行中/完成中的条目自动置顶；列表重排会导致用户正在看的计时项跳动，固定创建顺序更稳定。[AI生成]
- 倒计时模板和倒计时运行态要分开：模板可保存到数据库，运行/暂停/完成/剩余时间留在页面状态，避免重进页面恢复出不可信的运行状态。[AI生成]
- 计时结束的响铃必须可控：保存 `Ringtone` 实例，用户点击完成记录或停止按钮时主动 `stop()`，页面退出或实例替换时也要停止，不能只调用一次 `play()` 后失去控制。[AI生成]
- 完成态需要明显视觉反馈，例如使用 `errorContainer` 红色卡片状态；但确认后应回到普通显示态，避免用户误以为计时仍在进行。[AI生成]
- 时长输入用“分 / 秒”两个数值输入，比 `10:30` 文本格式更适合移动端键盘，也更容易做秒数 0-59 校验。[AI生成]

## 首页与食历性能

[2026-05-24]
- 首页内容变多后不要用 `Column + verticalScroll` 包整页，优先用 `LazyColumn` 分 item 组合，减少页面切换时一次性重组。
- 食历列表使用 `LazyColumn`，数据库组装放到 Repository 的后台线程 Flow 中，避免主线程卡顿。
- [2026-05-25] 列表搜索输入要做短延迟防抖并取消旧查询；但“添加菜品后返回菜品库”的 `refresh(force=true)` 必须保持立即刷新。
- [2026-05-25] 食历和首页计划的餐食卡片组装必须批量取餐食记录下的菜品、标签和烹饪方式，避免每条记录/每个菜品继续触发 N+1 查询。
- [2026-05-25] 食历列表只能展示 `meal_record` 中真实存在餐食的日期，不再用连续自然日窗口生成空日期 item。
- [2026-05-25] 食历顶部日期范围放在标题栏右侧，只显示全量餐食记录最早/最晚日期；点击后弹自定义月历，有餐食日期用小圆点标识。
- [2026-05-26] 首页搜索图标进入独立 `SearchScreen`；搜索页按菜品、食材、餐食三组展示，空关键词不做全量查询。
- [2026-05-26] 底部中间“添加餐食”按钮应作为 `NavigationBar` 正中 item 融入底栏，不再使用 Scaffold 的悬浮按钮槽。
- [2026-05-26] 物理返回键统一规则：非首页优先按路由返回；路由到底且不是首页则回首页；首页连续两次返回退出应用。

## 菜品模块打磨（2026-07-10，D1-D5）

- [2026-07-10] `combine` 最多 5 路带类型的重载；DishesViewModel 排序+烹饪方式+标签本是 3 路，与 popular/observed/搜索/关键词一起会超 5 路 → 把排序+两个筛选合并成 `viewOpts`(Triple) 一路，再 `combine(popular,observed,searched,kw,viewOpts)`。6+ 路只能用 vararg 版(丢类型)，故优先合并。
- [2026-07-10] 筛选下拉/Chip 的可选项要从**筛选前的 raw 列表**派生（distinct().sorted()），否则选中某项后其它项会消失、无法切换。再点同一项取消(toggle=当前值? null : 值)。
- [2026-07-10] 详情页"相关菜品"复用 `DishRepository.findDishesByIngredients(mainIds)`(含该食材即匹配)去掉自身取前 N；`DishMiniCard(onClick)` → 导航到同一 `Routes.dishDetail` 可继续下钻(堆栈递归 OK)。
- [2026-07-10] 步骤排序不引 DnD 库：每步"步骤N"标题 + 上移/下移 IconButton(`KeyboardArrowUp/Down`，首尾禁用)，VM `moveStep` 交换相邻再 `mapIndexed` 重排 sortOrder。轻量够用。
- [2026-07-10] 全屏烹饪保持亮屏：`DisposableEffect` 里 `context.findActivity()?.window?.addFlags(FLAG_KEEP_SCREEN_ON)`，onDispose 清除；`findActivity` 沿 `ContextWrapper.baseContext` 向上解包取 Activity。
- [2026-07-10] Cook Mode 每步内嵌计时是**自包含轻量版**(非接持久化 CookingTimerService)：`remember(resetKey=stepIndex)` 让翻步重置；`LaunchedEffect(endAt)` 循环按 `elapsedRealtime` 结束时刻算剩余(见踩坑红线倒计时条)，到点 `RingtoneManager` 响一次。适合"人盯着屏幕做菜"场景。
