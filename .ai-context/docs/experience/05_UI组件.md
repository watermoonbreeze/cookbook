## 拍照EXIF方向 / 系统栏色跟随（2026-07-16）

- [2026-07-16] **拍照结果旋转(小米/华为等)**：相机把方向写进 EXIF、像素不转，`BitmapFactory.decodeStream` 不应用 EXIF → 保存的图偏 90/180/270°。修：加 `androidx.exifinterface:exifinterface`(InputStream 构造全 API 可用，比 `android.media.ExifInterface` 的 InputStream 构造要 API24 稳，minSdk21 首选)，`ExifInterface(stream).getAttributeInt(TAG_ORIENTATION)` → `Matrix.postRotate/postScale` → `Bitmap.createBitmap(bmp,...,matrix,true)` 摆正后再存(存摆正像素，读取处零改动)。覆盖 ROTATE_90/180/270 + FLIP_H/V + TRANSPOSE/TRANSVERSE。
- [2026-07-16] **系统状态栏/导航栏色跟随界面**：仅设 `navigationBarColor=TRANSPARENT`+edge-to-edge **不等于**跟随界面色——`styles.xml` 的 AppTheme 未覆盖 `windowBackground` 时，透明系统栏区域(全屏页 `navigationBarsPadding` 下方)会露出 android 默认 windowBackground(浅色白)，在"app 深色但系统主题仍浅色"时与界面割裂。修：在 Compose 主题内 `SideEffect { window.statusBarColor = window.navigationBarColor = MaterialTheme.colorScheme.background.toArgb() }`，系统栏跟 Compose 主题背景明暗自适应、浑然一体。(scrim `isNavigationBarContrastEnforced=false` 是另一件事，早已关。)

## 烹饪计时交互

[2026-06-14]
- 多个倒计时同时运行时，不要把运行中/完成中的条目自动置顶；列表重排会导致用户正在看的计时项跳动，固定创建顺序更稳定。[AI生成]
- 倒计时模板和倒计时运行态要分开：模板可保存到数据库，运行/暂停/完成/剩余时间留在页面状态，避免重进页面恢复出不可信的运行状态。[AI生成]
- 计时结束的响铃必须可控：保存 `Ringtone` 实例，用户点击完成记录或停止按钮时主动 `stop()`，页面退出或实例替换时也要停止，不能只调用一次 `play()` 后失去控制。[AI生成]
- 完成态需要明显视觉反馈，例如使用 `errorContainer` 红色卡片状态；但确认后应回到普通显示态，避免用户误以为计时仍在进行。[AI生成]
- 时长输入用“分 / 秒”两个数值输入，比 `10:30` 文本格式更适合移动端键盘，也更容易做秒数 0-59 校验。[AI生成]
