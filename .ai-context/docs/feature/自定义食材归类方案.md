# 自定义食材如何归到「主食/鸡鱼肉蛋」等分类（方案建议）

> [AI生成] 2026-07-15。用户问：添加的食材如何归到主食或鸡鱼肉蛋这些分类中去。本文档给方案建议（先不动代码）。

## 一、现状与问题

现有两套"分类"，作用不同：

1. **营养大类**（`FoodGroup.Group`，10 类）：主食/蔬菜/菌菇/水产/红肉/禽肉/蛋/奶/豆坚果/水果。
   - 由 `FoodGroup.classify(name)` **按食材名关键词**判定（如名字含"鸡"→禽肉、含"鱼虾"→水产）。
   - **驱动**：营养色系等级、餐次头图标、营养均衡摘要、库存自由搭配的荤素判定。
2. **食材分类树**（`food_categories`，130 个 code）：日常分类(主食/蔬菜/水果/蛋奶…) + 营养维度(低GI/高嘌呤/高钾…)。
   - 食材通过 `ingredient.categories`(code 列表) 挂到这棵树，用于**分类浏览/筛选**。

**问题**：用户新建食材时——
- 若名字含已知关键词（如"鸡胸肉"含"鸡"），营养大类**已能自动识别**、色系/均衡已生效（这条现在就 work）。
- 但**名字无关键词**的（如"娃娃菜""藜麦""某地方菜名"）→ `classify` 返回 null → **不计入任何大类**，色系/均衡漏掉它。
- 且用户很少手动去 `categories` 里勾选分类树 → 食材**挂不到分类树**，分类浏览里找不到。

## 二、推荐方案（P1：小迁移 + 创建时一次单选）

### 2.1 给食材加显式「营养大类」——彻底解决归类
- **加一列**：`ingredient.food_group TEXT`（可空，存 `Group` 名，如 `WHITE_MEAT`）。按红线走加列全套（CREATE TABLE 加列 + N.sqm ALTER + insert/update 及所有调用点 + 显式列 SELECT + 领域模型加字段 + seed 幂等回填）。
- **`FoodGroup.classify` 改造**：优先用食材显式 `food_group`，无则回退现有关键词猜测。这样**名字无关键词的用户食材也能 100% 归类**，色系/均衡不再漏。
- 预设食材：seed 时按现有关键词回填 food_group（一次性），保证预设也有显式大类。

### 2.2 创建/编辑食材时「营养大类」单选（关键词预选）
- 编辑器加一个**营养大类单选**（10 个 Group + "其他/暂不归类"），紧凑胶囊或下拉。
- 打开时用 `FoodGroup.classify(name)` **猜测并预选**（名字含"鸡"→预选"禽肉"）——猜对占多数、零操作；猜错一键改。
- 名字变化时可**实时更新猜测**（未手动改过则跟随）。

### 2.3 营养大类 → 分类树 code 自动映射
- 建一张 `Group → 顶层分类 code` 映射表（如 WHITE_MEAT→"禽肉"分类、STAPLE→"主食"分类、FISH→"水产"分类…；映射到 `food_categories.json` 的对应日常分类 code）。
- 保存食材时，把选中大类映射的分类 code **自动并入 `ingredient.categories`**（用户仍可再加低GI/高嘌呤等营养维度 code）。
- 效果：用户食材**既进营养大类(色系/均衡准)、又挂上分类树(浏览能找到)**，且只需确认一次单选。

## 三、分期
- **P1**：`ingredient.food_group` 列 + 迁移 + 预设回填；`classify` 优先显式列；编辑器营养大类单选(关键词预选)；Group→分类code 映射并入 categories。
- **P2**：输入名字**实时提示**"识别为：禽肉 ✓"，一键接受；持续扩充 `FoodGroup` 关键词库(减少猜不中的情况)。
- **P3**（可选）：结合④拍照识别/关键词，识别结果直接带出营养大类与分类。

## 四、更轻的替代（若不想动迁移）
- 只做 **2.2 单选 + 2.3 映射**（不加 food_group 列）：用户食材靠"选中大类映射的分类 code + 名字关键词"归类。
- 局限：色系/均衡的 `classify` 仍纯按名字——名字无关键词的用户食材，色系/均衡**仍漏**（因为没有显式大类可读）。
- 结论：要让色系/均衡对用户食材也准，**2.1 的显式列不可省**；只做轻量版则色系准度打折。**推荐还是走 P1 完整版**。
