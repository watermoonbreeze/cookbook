# AI记一餐：分段解析与可控降级

## 已定行为

1. AI 开启时开放语音；语音仅转文字，随后与手输走同一 AI 解析链。
2. AI 成功：进入 AI 结构化预览，标“AI解析”。
3. AI 失败/超时/非JSON/校验失败：原文不丢；提示是否切规则模板；用户确认后将可确定的日期/餐次/菜名预填模板，不确定原文保留并标注；确认模板后才规则预览。
4. 不再静默 fallback；预览标“规则解析（AI失败后确认切换）”。

## 截断治理

日志已证实：DeepSeek HTTP 200 但 `finish_reason=length`，4096 completion token 截断 JSON，解析必失败。

管道：

`原文 → 本地按日期/周标题切 DayBlock → 每 DayBlock 独立 AI → 单段校验 → 合并 → DateAnchor/Schema 校验 → 预览`

- 单日仍过长：按餐次拆分。
- 每段 token 预算 800~1200；失败只重试该段。
- `finish_reason != stop` 视为失败，禁止解析半截 JSON；续写仅兜底，不是主路径。
- 合并键：完整日期标识 + 餐次 + segmentId，禁止只用 offset+mealType。
- AI 输出收缩为日期/餐次/菜名/食材名/做法；菜系、标签、描述、营养克数不作为本阶段 AI 必填输出。
- 份数/克数由本地规则、已有菜谱或用户确认处理；在份数数据模型完成前，不显示伪精确摄入量。

## 验收

- 7 天菜单不因 token 截断整体失败；单段失败可定位、其余天保留。
- 用户能保留原文并自主确认是否转规则模板。
- AI、规则、AI失败后规则三类来源在预览和日志摘要可区分。
- 任何非法/截断输出零写库。
