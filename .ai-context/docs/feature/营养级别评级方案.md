# 营养级别评级逻辑设计方案（待审 · 只出方案不实装）

> 2026-07-16。基于已联网核准的权威阈值（见「膳食参考依据」页 / `DietaryReference.kt` / `temp/claude/ref_*.json`）规划。
> **本文档仅供拍板，未改任何评级代码**。所有措辞/阈值最终以你确认为准；缺数据一律向后兼容退回现状。

## 一、现状与问题
- 现「营养色系墙 / 营养级别」的绿/黄判定偏向**多样性/覆盖度**，容易给出**误导性的绿色**（吃得单调或偏咸也可能显绿）。
- 慢病数值（钠/GI/嘌呤）虽已入库，却**没进评级**——"数据已有但没用起来"。

## 二、目标
把「级别」从"多样性"升级为**「热量达标 + 关键慢病指标」**双维度，且：
1. **只对家庭已登记的病种**触发对应指标（无高血压不判钠、无糖尿病不判 GI…），避免对普通家庭过度告警。
2. **缺营养数据 → 退回现有多样性评级**（向后兼容，不硬判、不留空）。
3. 全程「仅供参考 · 非医嘱」，守免责红线。

## 三、口径决策（建议，请拍板）
| 指标 | 建议口径 | 依据 |
|---|---|---|
| **GI** | 食物**固有分级**，低≤55/中56-69/高≥70，与份量无关 | FAO/WHO，糖尿病指南采纳 |
| **钠** | **单日累计**对比每日限量：一般 2000mg、高血压 2400mg | 膳食指南2022 / 高血压指南2018 |
| **添加糖** | 单日累计对比 25g(理想)/50g(上限) | 膳食指南2022 |
| **饱和脂肪/胆固醇** | 单日累计对比 供能比<10%(高血脂<7%) / 胆固醇<300mg(高胆固醇<200mg) | 血脂指南/食养指南2023 |
| **嘌呤** | ⚠**无国标数值阈值**：建议**不做数值分级**，改用 WS/T 560-2017 的"应避免/限制食物"清单做**定性提示**（如"含动物内脏/浓肉汤，痛风留意"）；惯例三级(25/150)仅作可选参考并标"非国标" | WS/T 560-2017 只给定性食物类别 |
| **钾 / 钠钾比**（高血压·DASH 增钾） | ✅**只做正向提示、不改级别**：单日累计钾对比 **PI-NCD 3600mg/日**，≥**80%**（惯例"较充足"提示线·非国标临界·纯信息故低风险可调）→加正向"钾摄入较充足·利于钠钾平衡"。**钠钾比无国标阈值**（"理想≈摩尔比1"仅 WHO 定性方向）→**不做硬评级、不抵消钠罚分、不因低钾下调**（低钾扣分越免责红线、肾病者反需限钾） | 钾 PI-NCD：WS/T 578.2-2018；DASH：膳食指南2022 / WHO 2013 钠钾指南 |

> 核心口径：**GI 用固有分级；钠/糖/脂肪/胆固醇按"单日累计 vs 每日限量占比"；嘌呤走定性食物清单**（因无权威数值阈值）；**钾只做正向提示不改级别**（钠钾比无国标阈值，见治理方案 §八 与 `高血压钾维度深挖.md`）。

## 四、分级映射（建议三级，请拍板阈值）
以"单日累计占每日限量的比例"为例（占比阈值可调）：
- **好（绿）**：各触发指标均 < 70% 每日限量，且热量在个人目标 ±15%。
- **中（黄）**：任一指标 70%~100%，或热量偏离 15%~30%。
- **注意（橙/红）**：任一指标 > 100% 每日限量（如钠 > 2000mg），或高 GI 菜占比偏高（糖尿病），或命中嘌呤"应避免"清单（痛风）。

措辞示例（挂"仅供参考·非医嘱"）：
- "偏咸（今日钠已达 110%）· 高血压成员留意"
- "含高 GI 主食 · 糖尿病成员可换低 GI"
- "含浓肉汤/内脏 · 痛风成员建议避免"

## 五、数据依赖与分阶段（建议）
评级质量取决于食材营养数据完整度。现状：钠/GI/嘌呤等**部分食材仍缺值/pending**。
- **P1（数据最全先做）**：热量达标 + 钠（高血压）。
- **P2**：GI/添加糖（糖尿病）。
- **P3**：脂肪/胆固醇（高血脂）。
- **P4**：嘌呤定性清单（痛风）——纯定性、不依赖数值。
- 每阶段：缺数据的食材/菜 → 该指标不判、退回多样性，UI 标"数据不全暂不评级"。

## 六、需你拍板的点
1. 口径是否按第三节（GI固有 + 钠/糖/脂按每日占比 + 嘌呤定性）？
2. 三级的**占比阈值**（建议 70% / 100%）与**热量偏离带**（±15% / ±30%）？
3. 嘌呤是否**只做定性清单**（我倾向是，因无国标数值）？惯例三级(25/150)要不要作为可选参考展示？
4. 级别**措辞**（上面示例可改）。
5. 是否先只上 **P1（热量+钠）**、真机看观感再逐步加？

## ★ 决策（2026-07-16，用户拍板）
- **色系墙保持"纯结构"，不关联热量**（延续既有决定：色系墙=全家膳食结构均衡度、与成员/热量无关）。
- **热量达标**是**个人**概念 → 只放**今日营养卡/个人视角**，永不进色系墙（墙上 `calorieStatus` 恒传 null）。
- **慢病提示（钠/嘌呤/GI 等食物属性）** → 放**餐食卡/今日卡的个人视角**，也不改色系墙语义。
- 故 `NutritionLevelEvaluator` 的热量+钠只服务个人/餐食卡；色系墙 `FoodGroup.nutritionLevel` 维持不变。

## ★ 落地进度（2026-07-16）
- ✅ **评估核心已实装 + 单测**：`shared/domain/NutritionLevel.kt` `NutritionLevelEvaluator.evaluate(baseLevel, totals, calorieStatus, conditions, dayCount)`——以多样性 baseLevel 为底，**钠(高血压,≥2400mg上限→注意封2/≥70%→中封3)** + **热量(ABOVE→封2)** 下调并给提示；**缺营养数据(totals null/热量≤0)→原样返回 baseLevel 不下调**；`HealthCondition.fromCareName` 病种名→类型映射。7 个单测过。**只上 P1 热量+钠(数据齐)**；GI/嘌呤/脂肪待逐项数据齐扩展。
