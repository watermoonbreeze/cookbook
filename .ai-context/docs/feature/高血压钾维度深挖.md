# 高血压钾维度深挖（DASH 限钠增钾）

> 2026-07-17 无人值守。治理方案 §八.4/§八.5「逐病种深挖·先高血压端到端」的第一版落地。
> 多角色验证收敛（现状映射 Explore + 权威指南研究员联网 + 产品经理 scope + Google 代码审查）。

## 一句话
高血压评级此前**只罚高钠、完全不看钾**——与 app 膳食参考页早已写明的"限钠增钾、改善钠钾比是高血压膳食核心"（DASH）自相矛盾。本版补上**钾的正向提示**，把承诺兑现，让高血压家庭从"只会被骂咸"升级到"钾吃够也被认可"。

## 操作逻辑（公式/阈值/数据来源/何时生效）

- **数据来源与阈值（权威可回溯）**：
  - 钾每日建议量锚 **钾 PI-NCD（预防慢病建议摄入量）= 3600 mg/日**，出处 **WS/T 578.2-2018《中国居民膳食营养素参考摄入量·常量元素》**（app 膳食参考页已引用同一数字）。
  - 依据 **膳食指南2022** 背书 DASH「高钾低钠」、**WHO 2013 钠钾指南**（增钾≥3510mg/日、条件性推荐）。
  - `POTASSIUM_PI_NCD_MG = 3600.0`、`K_ADEQUATE_RATIO = 0.8`（`NutritionLevel.kt`）。
- **判定（`NutritionLevelEvaluator.evaluate` 末尾分支，纯函数可单测）**：
  - 仅当**已登记高血压** 且 `totals.potassiumMg > 0` 时：`kRatio = potassiumMg / (3600 × dayCount)`；`kRatio ≥ 0.8` → 追加一条正向 concern：
    「钾摄入较充足（约X%建议量）· 利于钠钾平衡 · 仅供参考」。
  - 放在 evaluate 最末（钠/GI/嘌呤/热量之后）→ **正向 concern 永远排在负向之后**；高钠高钾时"偏咸留意"与"钾较充足"两条**诚实并存**（即 DASH「增钾改善钠钾平衡」）。
- **红线（本版最关键的保守取舍，采纳权威研究员口径否决 PM 的"抵消式微调"）**：
  - 钾**不改健康级别**（只 `concerns +=`，无 `minOf(level,…)`）。
  - 钾**不抵消/不扣回钠罚分**——"理想钠钾比≈摩尔比1"仅 WHO **定性方向、无国标数值阈值**，把无阈值量做成改级别的硬评级=**自造标准=误导**（违反"营养阈值用国标口径、无国标必标注惯例"红线）；数值扣回还会**稀释"这道偏咸"的真实警示**、无权威换算依据。
  - **低钾绝不下调**——低钾扣分=隐含病理判断，且**肾功能不全/服保钾药者反需限钾**，消费级 app 无从判断个体肾功能，不能用等级暗示"应多补钾"。故钾**只锦上添花、不雪上加霜**。
  - 措辞守免责：用"较充足/利于"，**禁"降压/治疗/达标"**；非处方语气（观察"摄入较充足"而非命令"应增钾"），规避肾病人群误导。
- **接线**：`HomeViewModel.personalTotals` 原**只传 sodiumMg、漏了 potassiumMg**（钾拿不到数据）→ 补 `potassiumMg = totals.potassiumMg * share`（按关注成员份额，与钠一致）。
- **零迁移/零联网**：`NutritionTotals.potassiumMg` 全链路早已通、potassium 数据覆盖 436/440（99%），`evaluate` 无需改签名（直接读 `totals.potassiumMg`）。

## 用户验证方法（真机/数据怎么判断对不对）
前置：家庭档案给关注成员勾选"高血压"；确保当天记的菜含高钾食材（菠菜/毛豆/土豆/香蕉等，钾数据已在库）。
1. **钾充足日**：记满高钾且不太咸的一天 → 今日营养卡出现「钾摄入较充足（约X%建议量）· 利于钠钾平衡 · 仅供参考」，**级别不因钾变化**。
2. **高钠高钾**：记又咸又高钾的一天 → 同时出现「偏咸（钠约X%上限）· 高血压留意」**和**「钾摄入较充足…」两条，**偏咸在前**、级别仍被钠封（钾不抵消）。
3. **低钾**：钾不足的一天 → **无**钾提示，级别与改动前完全一致。
4. **向后兼容**：无钾数据的菜 / 未登记高血压的家庭 → 全程**看不到**任何钾提示。
5. **自动化**：`:shared:testDebugUnitTest` 的 `NutritionLevelEvaluatorTest` 新增 4 用例（钾充足正向且不改级别 / 高钠高钾并存且不抵消 / 低钾不提示不下调 / 无钾数据·未登记 gate）全绿即锁。
