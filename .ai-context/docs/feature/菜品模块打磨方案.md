# 菜品模块打磨方案

> [AI生成] 2026-07-10。之前一直优化食材层，现打磨菜品(dish)模块。用户要全方向 + 菜品扩充。

## 现状
- 菜品库 `DishesScreen`(列表/热门/最近/拼音搜索)；创建编辑 `NewDishScreen`(名称/烹饪方式多选/食材分主料辅料调料/步骤含图/标签/图片/备注/描述)；详情 `DishDetailScreen`(菜名/喜爱度/标签/图/食材含用量/步骤/做法/备注)；喜爱度自动累加；预设 vs 自建(预设复制后可编辑)。
- **详情页缺**：库存可做/缺料、健康适宜性、做过次数、营养概要、计时联动、相关菜品。

## 复用的已有能力
- **库存/份数/采购**：`PantryAllocation`/`PantryPlanAnnotator`/pantry 查询 → 菜品"可做/缺料/采购"。
- **健康规则**：`HealthRuleEngine` + crowd_ingredient(avoid/limit/recommend) + 启用健康档案 → 菜品"适宜性"。
- **营养维度标签**：`selectNutritionSeasonTags`(优质蛋白/高纤维等**标签**，非数值卡路里) → 营养概要(标签版)。数值卡路里/蛋白克数需另补数据(见 待办 营养素)。
- **烹饪计时**：现有计时器 → 菜品/步骤一键开计时。

## 分阶段(逐个做, 每阶段 build+单测校验)
- **D1 详情页信息增强**(最高价值, 复用库存/健康)：
  - 库存可做/缺料/采购徽标(用当前库存快照, 主料不在库→采购、在库份数不够→缺, 复用派生逻辑)。
  - 健康适宜性：按启用档案标食材 忌口(红)/限量(橙)/推荐(绿) + 整体徽标(含忌口→不适合、含推荐→有益)。
  - 做过次数 + 最近做过(查 meal_record_dish)。
  - 营养概要(聚合食材营养**标签**去重)。
- **D2 列表/搜索/筛选/发现**：DishesScreen 加 筛选(烹饪方式/标签/主料/库存可做/健康适宜)+排序(喜爱度/最近/字母)；详情页"相关菜品"(同主料·同做法)。
- **D3 烹饪体验**：菜品/步骤一键开计时(接现有计时器)；分步烹饪全屏模式(大图+每步计时)。
- **D4 创建/编辑体验**：步骤拖拽排序、食材用量/单位录入优化、从菜品派生(复制)。
- **D5 菜品扩充**(纯数据)：dishes.json 补更多预设菜(遵健康数据免责红线, 引用完整性校验 + :shared:testDebugUnitTest)。

## 注意/红线
- 健康数据免责：营养/健康适宜性为 AI 参考整理、非权威；文案标注免责。
- 库存/健康标注只影响展示，不改数据；无库存/无档案时不标(避免打扰)。
- 数值营养(卡路里/克数)依赖营养素数据补全，D1 先做标签版。
- seed 改动走脚本 + 引用完整性 + 单测。
