# 参考内容数据驱动 + 未来接口下发 架构方案

> [AI生成] 2026-07-20 用户提+会商定案(google_architecture_engineer × apple_architect 会诊·主 agent 取中)。
> 目标：把写死在 Kotlin 里的参考页内容改为数据驱动(加减不改代码)，形态天然=未来后台接口下发契约。**用户已认可·时机=F批真机项之后紧随**。

## 背景
参考页(`androidApp/.../ui/reference/`)现状：`DietaryReference.kt`/`DataSourceReference.kt`=已结构化 Kotlin object(共用 `DietaryRefCategory/Item/Level/Source`)；`HealthConditionReferenceScreen`/`TcmReferenceScreen`=纯 Composable 硬编码散文。痛点：加减一条来源/阈值要改代码重新出包。用户明确"后期肯定走后台接口下发"。

## 会商共识
- **纯展示内容用 JSON、不进 SQLite**(不查询/不产生用户态数据→DB无收益，只增迁移负担)。复用现成 `SeedResourceLoader`(expect/actual·`MedicinalFoods.kt` 是"JSON→domain"现成范例)。
- **bundled 优先·离线兜底**(健康 App 红线·断网不白屏)。
- 🔴**最重要红线：展示阈值 JSON ≠ 判定引擎阈值常量(两份)**。JSON 化后**禁止**让展示 JSON 成为 `HealthRuleEngine`/`NutritionInterpreter` 判定数据源——否则 server 下发错阈值直接影响忌口/评级。**判定常量留 shared 代码(可审计·随版本发布)，展示 JSON 只讲解。** schema 注释显式声明"仅展示"。

## 定案(主 agent 取中)
| 决策 | 取舍 |
|---|---|
| schema | 用现有 data class + `@Serializable`，**加 `version`+`schemaVersion` 字段**(便宜·防未来炸旧包·老客户端遇未知 schemaVersion 降级 bundled)；**不建** Repository interface，只留**一个加载函数**接缝 |
| 落位 | 放 **`:shared`**(未来 server 走 KMP·复用 SeedResourceLoader·shared 单测校验引用完整性) |
| 散文页 | 一期只搬**已结构化两页**(数据来源/膳食依据)→JSON；病种/中医散文页编辑频率低**先不动**(不硬塞 schema) |
| server 下发/缓存/版本比对 | **留接缝·不实现**(YAGNI·后端未定不提前造抽象) |

## 一期落地步骤(纯内部重构·低风险·无行为变化)
1. `:shared` 建 `ReferenceDocument`(@Serializable·带 version/schemaVersion/disclaimer/sections/sources)+ 一个 `loadReferenceDoc(key)` 函数(读 `commonMain/resources/reference/<key>.json`·bundled)。
2. 数据来源/膳食依据两 object → `datasource.json`/`dietary.json`；`sourceRef` 引用 key 去重(替代 source 整串重复)。
3. androidApp 复用现有 `ReferenceScaffold` 渲染(读 doc)；删两 object。
4. **引用完整性单测**(sourceRef 都能在 sources 找到·disclaimer/sources 非空·JSON 可反序列化)入 `:shared:testDebugUnitTest`。
5. 守红线：disclaimer/sources 非空校验；展示 JSON 不碰判定逻辑。

## 二期(后端就绪·增量·现在不做)
`CachedReferenceRepository`(server+缓存+三级降级 server缓存→上次缓存→bundled)·Koin 换绑定(UI/schema 零改)·内容更新走**非阻断 changelog 提示条**(参考资料更新≠App版本升级·别弹打断式弹框·符合透明准则"静默应用+可查看变更")·server 下发准入校验(免责/来源非空·schemaVersion 可识别·不过则弃用留 bundled)。

## 不做/边界(YAGNI)
两套数据通道(seed→DB vs reference→UI)**明确不合并**(语义不同·只复用 loader 与引用校验方法论)；effectiveFrom 灰度/locale 多语言/changelog diff 引擎=字段留·逻辑不写。
