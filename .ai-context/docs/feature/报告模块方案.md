# 报告模块方案（周/月/年 · 家庭+个人）· 待确认

> [AI生成] 2026-07-18 执行队列第6项。用户提"生成每周/月/年的家庭报告与个人报告"，先出**方案文档待你确认**，不实现。
> 定位：家庭记菜的"回顾"价值——把一段时间的饮食如实汇总成**一眼看懂的回顾页**（图表+要点+温和建议），
> 让家庭看到"这段时间吃得怎么样"，顺带发现结构缺口。**守健康免责红线**（仅供参考·非医嘱）。

## 一、定位与原则

- **回顾而非考核**：报告是"记录的镜子"，如实呈现 + 鼓励，不打分羞辱、不制造焦虑（文案准则：鼓励非责备）。
- **两个视角**：
  - **家庭视角**：全家整体（吃了多少道菜、结构多样性、采买/库存），不折算份额。
  - **个人视角**：按关注成员的**饭量系数(share)**折算摄入（热量/营养/慢病关注），同今日营养卡口径。
- **三种周期**：周 / 月 / 年，同一页切换（周期 chip）。
- **免责红线**：营养/慢病维度守"仅供参考·非医嘱"，禁"降压/达标/治疗"断言；阈值口径标来源（膳食指南/DRIs/GB 28050，嘌呤"非国标·惯例"）。
- **简洁**：默认露高频要点，细节折叠；一屏能扫读到"这段时间的3个关键点"。

## 二、报告维度（分组）与数据来源

> 数据基础**多已具备**，无需新表；报告=对现有数据的**聚合查询 + 展示**。

| 分组 | 维度（示例指标） | 视角 | 数据来源（已存在） |
|---|---|---|---|
| **记录概况** | 记餐天数、覆盖率(记了/周期天数)、总餐次数、平均每天菜数 | 家庭 | `meal_record`/`meal_record_dish`（按日期区间聚合） |
| **菜品** | 不同菜品数(多样性)、TOP 常吃菜、本期新尝试菜、复用率 | 家庭 | `meal_record_dish`+`dish`；喜爱度 `dish.preference` |
| **食材** | 用到的食材种数、TOP 食材、五大类食材覆盖 | 家庭 | `dish_ingredient`+`ingredient`+`food_category` |
| **膳食结构** | 色系墙均级(本期平均多样性)、五大类均衡度、结构缺口(缺蛋白/蔬菜…) | 家庭 | `FoodGroup.nutritionLevel`/`nutritionGaps`（本会话已用） |
| **营养摄入** | 日均热量、达标天数占比、三大宏量供能比、钠/钾/纤维/饱脂/胆固醇日均 | 个人(share) | `NutritionRepository.totalOf`/`dishNutrition` + `CalorieTarget` |
| **慢病关注** | 登记病种的 concern 出现频次(偏咸/高GI/高嘌呤/高饱脂 天数)、忌口命中次数、正向(钾/纤维充足)天数 | 个人 | `NutritionLevelEvaluator.evaluate` 逐日跑 + `HealthRuleEngine` 忌口 |
| **库存/采购**(可选) | 入库/出库次数、常买食材、可估"用了多少" | 家庭 | `pantry` + `PantryUsage`（占用记录） |

**慢病维度守免责**：只列"这段时间有 N 天出现偏咸/含高GI主食"等**客观频次**，配"仅供参考·非医嘱"，给"注意少盐/换低GI"的温和建议，**不下结论、不诊断、不承诺**。缺数据的成员/天不计入（同评级器缺数据不触发）。

## 三、页面与交互

- **入口**：首页或"我的"加"饮食报告"入口（低频→不占主区，放"我的"或首页底部/更多）。
- **顶部**：`SegmentedControl`(周/月/年) + 视角切换(家庭/个人，个人时选关注成员) + 期次选择(本周/上周… 用日期区间或左右翻页)。
- **主体（自上而下，克制）**：
  1. **本期概览卡**：一句话总结 + 3 个关键数（记餐天数/菜品数/日均热量或多样性均级）。
  2. **要点卡**：2~4 条"本期发现"（如"蔬菜略少，可多加绿叶菜"/"结构较均衡，继续保持"），鼓励语气、温和建议。
  3. **分组明细**（折叠/分区）：按上表分组，每组一张卡；图表用**简洁可视**（趋势用折线/柱、占比用分段条，复用色系墙已有 `Brush` 平滑渐变思路）。
  4. **慢病关注区**（仅登记病种显示）：客观频次 + 免责行。
- **M3 1.1.2 约束**：无 `SegmentedButton`(用自绘 `SegmentedControl`)、无三方图表库倾向→**优先自绘轻量图**（柱/折线/分段条，Canvas 或 Row+权重），避免引重依赖；分隔用 `Divider`。
- **空态**（§9.6 给下一步）：本期没记 → "这段时间还没记餐，去记一餐就能生成报告" + 动作。
- **性能**：报告为**区间聚合**，逐日跑评级器可能上百次→用**批量查询**（本会话 gatherForPlan/dishNutrition 已批量化经验），后台 `combine+mapLatest` 计算，避免主线程。

## 四、导出与分享

- **导出**：SAF `CreateDocument` 存**图片(长图)或文本摘要**到用户选的位置（存储合规红线：走 SAF 不写公共目录）。
- **分享**：可选系统分享 sheet 发图片。
- **隐私**：报告含饮食/健康信息，导出/分享**用户主动触发**，不自动上传；文案提示"含健康信息，注意分享对象"。
