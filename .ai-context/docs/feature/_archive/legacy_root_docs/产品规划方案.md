# 慢性病饮食规划 APP 产品规划方案

> 历史规划资料（2026-08-05 迁入）；不作为当前实施或项目状态依据。

## 一、产品定位

**一句话描述**：帮助慢性病（三高、痛风等）患者轻松规划每日饮食的工具。

**核心价值**：不是教你做菜，而是告诉你今天该吃什么、怎么搭配。

**目标用户**：
- 有三高、痛风等慢性病的患者及其家属（负责做饭的人）
- 有营养师指导但不知道如何落地执行的人群
- 注重健康饮食但每天纠结吃什么的人

## 二、核心痛点

| 痛点 | 描述 | 当前解决方式 |
|------|------|-------------|
| 决策疲劳 | 每天不知道吃什么，反复纠结 | 凭记忆、随意决定 |
| 搭配困难 | 多种慢性病共存，食材禁忌复杂 | 咨询营养师，但难以持续执行 |
| 方案落地难 | 营养师给了方案，不知道怎么拆分到每餐 | 靠自己理解，容易偏差 |

## 三、功能规划

### MVP 阶段 — 记录与复用

> 目标：自己先用起来，验证核心流程

**1. 每日菜单记录**
- 日历视图，点击日期查看/编辑当天菜单
- 按早/中/晚三餐分区记录
- 添加菜品：搜索 + 最近使用 + 收藏，3 秒内完成添加

**2. 历史菜单复用**
- 浏览历史菜单记录
- 一键复用某天/某餐的菜单到今天
- 支持"菜单组合"收藏（如：常吃的早餐组合）

**3. 基础食材库**
- 预置常见家常菜品名称
- 支持自定义添加菜品

### 一期 — 健康约束与营养方案

> 目标：加入疾病维度，让推荐更科学

**4. 个人健康档案**
- 设置个人慢性病标签（糖尿病、高血压、高血脂、痛风等）
- 支持多标签组合（如：糖尿病 + 高血压）

**5. 食材风险提示**
- 基于健康档案，选择菜品时给出风险提示
  - 痛风患者选了海鲜 → 提示高嘌呤警告
  - 糖尿病患者选了白粥 → 提示升糖快
- 提示方式：标签颜色区分（绿色安全、黄色注意、红色避免）

**6. 营养餐方案管理**
- 手动输入营养师开具的方案（每日总热量、碳水/蛋白质/脂肪比例等）
- 系统按三餐比例（如 3:4:3）自动拆解到每餐
- 对照方案查看当日菜单的大致匹配情况

### 二期 — 智能推荐

> 目标：从"自己选"到"系统推荐"

**7. AI 智能菜单生成**
- 基于历史饮食偏好 + 健康约束，自动生成每日/每周菜单建议
- 支持"换一换"，不满意可刷新推荐
- 考虑食材多样性，避免连续几天重复

**8. 营养方案智能识别**
- 拍照识别营养师处方/报告
- 自动提取关键营养指标并录入系统

**9. 季节与时令推荐**
- 根据当前季节推荐时令食材和菜品
- 结合健康约束给出季节性建议

## 四、产品设计原则

1. **极简操作** — 核心流程（记录一餐）不超过 3 步
2. **一目了然** — 日历视图为主界面，打开即看到本周饮食全貌
3. **渐进增强** — 基础功能零门槛，健康功能按需开启
4. **不做菜谱** — 只管"吃什么"，不管"怎么做"，与下厨房等互补而非竞争

## 五、核心页面设计

```
首页（日历视图）
├── 周视图：一眼看到本周每天三餐安排
├── 点击某天 → 当日菜单详情
│   ├── 早餐：[菜品列表] [+添加]
│   ├── 午餐：[菜品列表] [+添加]
│   └── 晚餐：[菜品列表] [+添加]
├── 添加菜品弹窗
│   ├── 搜索框
│   ├── 最近使用
│   └── 收藏组合
│
我的
├── 健康档案（一期）
├── 营养方案（一期）
├── 菜单收藏
└── 食材库管理
```

## 六、技术选型

| 维度 | 方案 | 理由 |
|------|------|------|
| 跨平台框架 | Kotlin Multiplatform (KMP) | `shared` 模块共享业务逻辑，各平台 UI 独立 |
| Android UI | Jetpack Compose + Material3 | 现代声明式 UI，`androidApp` 模块 |
| iOS UI | SwiftUI | `iosApp` 工程，调用 shared framework |
| 数据库 | SQLDelight | KMP 原生支持，跨平台 SQLite |
| 依赖注入 | Koin | 轻量级，KMP 友好 |
| 后端 | MVP 阶段纯本地 | 无需自建服务器，后续按需接入云服务 |
| AI 能力（二期） | 大模型 API（如 Claude / GPT） | 菜单生成与营养分析 |

详见 [技术栈与主题风格.md](技术栈与主题风格.md)

## 七、推进计划

| 阶段 | 周期 | 交付物 |
|------|------|--------|
| 需求细化 | 1 周 | 详细需求文档 + 原型图 |
| MVP 开发 | 3-4 周 | 可用的菜单记录与复用功能 |
| 自用验证 | 2-4 周 | 收集使用反馈，优化体验 |
| 一期开发 | 3-4 周 | 健康档案 + 风险提示 + 营养方案 |
| 二期开发 | 4-6 周 | AI 推荐 + 智能识别 |

## 八、市场验证思路

1. **先做自己的用户** — MVP 自己用 2-4 周，验证是否真的解决了每天纠结吃什么的问题
2. **小范围扩展** — 找身边有类似需求的亲友试用，收集反馈
3. **社区验证** — 在慢性病患者社群（如糖友圈）发布体验版，观察留存率
4. **差异化定位** — 如果验证可行，以"慢性病饮食规划"为核心卖点，与现有菜谱/健康 APP 区分
