# 周计划「营养线」方案（四角色会商收敛）

> [AI生成] 2026-07-21。用户洞察发起，产品/营养师/运营/文案四角色并行会商后收敛。**属方案阶段·待用户拍板范围与信息架构分歧后再编码。**
> 来源洞察（用户 2026-07-21）：周计划的价值不是"7 天×N 餐各自独立的菜单"，而是**餐与餐、天与天有营养关联的一条"营养线"**——顺着吃下来整体能补齐哪些营养、达到均衡。与单餐推荐（这一餐好不好）是**两个价值维度**，直接对齐一期北极星「健康推荐餐食」。

---

## 一、核心共识（四角色一致·最重要结论）

**"营养线"不是从零造功能，而是"把引擎里已经在跑的那条线，盛出来给用户看" + 一处最小算法增强。**

- `PeriodPlanner.score()` 已有 `usedNutrition`（营养维度→整周已覆盖次数），并对**少覆盖维度加分**（`NUTRITION_BONUS/(1+已用)`）——这正是"跨餐跨天补齐营养维度"的算法内核，**已在跑**。还有健康占比目标 `HEALTHY_TARGET=0.8`、重油跨天去重。
- **但产出到 UI 只有逐日卡**：`nutritionTags` 在 Screen 层零引用（grep 确认）。营养线在算法里、不在眼里。
- 故最高性价比动作 = **呈现优先于算法、加法优先于重构**：先让营养线被看见，再谈定量。

---

## 二、价值主张（一句话）

> **"这一周照着吃，营养是配齐的。"** 周计划不是 7 天各自"这餐还行"的拼盘，而是一条餐餐相扣的营养线：顺着吃下来，蛋白/主食/蔬果/膳食纤维等关键维度**整体补齐**，让慢病家庭不必每餐都算、也不担心"这周是不是偏了"。

单餐推荐回答"这一餐好不好"（已有）；**周营养线回答"这一整周均衡不均衡、还差点啥"**——后者才是"每天吃什么"决策疲劳的真正解药。

## 三、⚠️ 待用户拍板：信息架构分歧（会商暴露的关键分歧）

项目里有**两个"周计划"**，营养线放哪需你定夺：

| | AI 周期规划（PM 认定的载体） | 一周计划视图（运营提到的页） |
|---|---|---|
| 代码 | `AiPlanScreen`/`AiPlanViewModel` + `PeriodPlanner` | `WeekPlanScreen`/`WeekPlanViewModel` |
| 本质 | 从整库贪心排 N 天菜单**建议**（PlanDish·带 nutritionTags）| 已排餐食的**记账网格**（MealRecord·纯浏览编辑）|
| 数据源 | `PlanDish`（有营养标签，能直接算营养线）| `MealRecord`（需走 DietReport 式周聚合）|

**推荐（我的判断）**：**营养线概览优先放在「AI 周期规划结果页 AiPlanScreen」**——那里的数据（PlanDish/nutritionTags）天然支撑营养线，且用户刚生成完整周、正好在看整体。`WeekPlanScreen`（已排记账）可二期用 DietReport 周聚合补一个"已排这周的营养线"，但数据源不同、不混做。
→ **请拍板**：营养线先做在 ①AiPlanScreen（生成建议·推荐） ②WeekPlanScreen（已排记账） ③两者都做。

## 四、MVP 范围（守反过度设计·先做一版看效果）

### ✅ 第一版做
1. **顶部"一周营养搭配"概览条**（呈现层·主战场·复用 `usedNutrition`，零新算法）：
   - **已覆盖 X 维度**：整周 `nutritionTags`/`usedNutrition` 去重 → 小色点/胶囊列出（蛋白·蔬菜膳食纤维·主食碳水·深色蔬菜…），已覆盖点亮、偏少灰着（**不红字、不报警**）。
   - **还缺 Y**：从收敛的"关键维度清单"减去已覆盖。
   - **建议再加 Z**：一句连贯人话（"整周蔬菜偏少，某天加一道深色蔬菜就更全"）。第一版可先只到"还缺 Y"，精确到"哪天加 Z 道"放二期。
2. **逐日/整周切换（轻量）**：概览默认整周，逐日卡保留。不做复杂图表。
3. **算法一处最小增强：从"去重"到"缺口保底"**：某关键维度整周 `used==0` 时给含该 tag 候选**明显加分**（强于普通新颖度、**弱于应季/健康/忌口次序**），保证生成结束关键维度尽量都被点亮。守住"不反超忌口硬过滤（`hasAvoid` 剔除在先）"。

### 关键维度清单（务实两级）
- **三大结构支柱**（100% 可算·复用 `FoodGroup.nutritionLevel` 口径·免责友好）：**优质蛋白 / 主食·碳水 / 蔬菜·膳食纤维**。
- **少数高价值加分维度**（覆盖率够才纳入）：深色蔬菜 / 全谷物 / 高钙。覆盖太低的（血红素铁细分等）先不进 MVP。

### ❌ 第一版不做（守边界）
周级卡路里/宏量定量达标热力图·DRI 百分比进度条（涉个人数据×多成员×焦虑，二期）；精确到"替换某道菜"的自动改写；把 B3 记账网格也塞营养线；全量 tag 铺陈/雷达图。

### 用现有数据能算到什么程度（诚实）
- **能算准**：整周三支柱覆盖、维度去重分布、每天大类点亮数（`FoodGroup`+`nutritionTags`+`usedNutrition` 全现成）。
- **半准**：`nutritionTags` 依赖食材标签覆盖率，自建/新菜可能缺 → **如实"已覆盖"、缺数据不显不脑补**。
- **暂不算**：周级"蛋白共 X 克/达 DRI%"（涉个人身体数据+口径，二期）。MVP 只做结构维度覆盖（定性·免责友好·不制造精确焦虑）。

## 五、营养算法方案（营养师·domain 层·一期只交付算法）

新建 **纯函数聚合器**（commonMain·可单测·风格对齐 `DietReportAggregator`/`NutritionLevelEvaluator`），**不改** DietReportAggregator（那面向"回顾已吃"，营养线面向"前瞻计划+连贯建议"）：

- `NutritionLine`（数据结构）：`perDayLevel`(每天0~4结构级)、`weekGroupFrequency`(每大类整周**出现天数**·天维度去重防"一天三道猪肉虚高")、`coveredTags`、`pillarGapDays`(三支柱各缺失天数)、`proteinSourceKinds`(蛋白源多样性)、`macroPct?`(缺数据→null不臆造)、`sodiumHighDays/highGiDays/purineHeavyDays`(**一周分布非总分**)、`balanceScore`(0~100)。
- `balanceScore` **只用结构维度**（数据最全·合"色系墙不关联热量/慢病"红线）：0.35 结构 + 0.25 广度 + 0.20 蛋白多样 + 0.20 连贯（惩罚"某支柱长期缺"）。慢病/宏量走独立提示不进分。
- `NutritionLineAdvisor`（4 类建议·都强调**关联性**·鼓励口吻）：支柱缺口（用天数说话）/维度欠缺/单调堆积（蛋白源单一）/慢病分散（"分散>禁止"·守免责）。
- **可复用积木**：`NutritionLevelEvaluator.evaluate(dayCount=N)` 已内建多日窗口（钠/GI/嘌呤×days）；`NutritionRepository.dishNutrition(dishIds)` 批量出每菜营养**零 N+1**。
- **单测**：空计划/单类计划(7天清汤面)/均衡计划/缺数据→macroPct=null/天维度去重/慢病分布/dayCount 边界(1~30)。Advisor：缺口出建议且含天数、全覆盖不硬凑、单调正向口吻（断言不含"缺乏/不足"责备词）。
- **二期增强**：微量元素 mg 级达标（补 DRIs）、添加糖、补充建议**回灌 PeriodPlanner** 形成"分析→建议→重排"闭环、饱脂/胆固醇覆盖率补齐后进慢病分布。

## 六、文案套件（文案师·可直接用·守免责红线）

**对外命名**：统一叫 **「一周营养搭配」**（不用黑话"营养线"；"营养线"仅内部设计语，防外露让用户愣一下）。建议补进术语表。

- 概览标题：**这一周的营养搭配** ；说明：**不是七天各点各的，是顺着一整周帮你把常缺的营养补齐。**
- 进度：**这一周已吃到 蔬菜·谷物·豆制品，均衡得不错** ；待补：**再加点 鱼虾 和 奶类，这一周会更全**（用"再加点/会更全"，**禁**"缺/不足/未达标"）。
- 空态：**还没安排这一周** / **排上几天，就能看到这一周搭得均不均衡。** → 按钮 **安排这一周**。
- 回顾（分档正向·不打卡绑架）：搭得全"这一周搭得挺全，五大类都吃到了，继续保持"；偏单一"这一周菜色有点集中，下周换换花样会更均衡"。**禁** "完成计划🎉/连续打卡/达标"。
- 按钮：**看一周搭配 / 补一道 / 复用这天 / 帮我配一周**（动词开头·短标签不加句号）。
- 免责微文案：**均衡情况按食材参考数据估算，仅供了解，不作医嘱。** + **"五大类是否吃到"按日常膳食惯例判断，非国家标准，供你参考。**
- 现 `WeekPlanScreen` 文字审校：**无🔴必改**；🟡 最关键缺口=页面没体现营养线价值（需加概览卡）；"已删除{周几}的餐食"→"已删除 周三 的安排"（计划域用"安排"）。

## 七、运营与透明（运营师·守诚实不操纵）

- **触点**：①周计划顶部营养线概览带（复用 usedNutrition·零新算法·主战场） ②首页营养墙**接未来计划**（空心描边区分"计划中/已吃"·**去红**·把"记录墙"变"营养线全景"） ③记完一餐后**一次**克制正向反馈（"补上了本周偏少的绿叶菜"·每天至多一次·只在真有进展时） ④每周一次诚实回顾（周小结·默认可关）。
- **发现引导**：**不首启弹窗**；新用户"零录入示例线"（标"示例·记录后更懂你"）；老用户排完那刻一次性说明（用一次性守卫·看过不再出）。
- **留存**：周回顾（每周≤1·陈述非打分）+下一周连续性（建议非任务·**无 streak/无连续计数**）。
- **红线自检（功能【不能做】）**：禁 打卡/streak/连胜、假紧迫/倒计时、愧疚绑架、焦虑恐吓（偏少维度**不用红、不报警、不"不达标"**）、健康攀比排行、打分羞辱。默认对用户有利、摘要通知默认可关。
- **透明分级**：整周覆盖度（纯读聚合）=**T0 可查**；AI/规则生成计划（改"待排"建议·需确认落库）=**T1 事后留痕**（"已按整周营养错开帮你排好"）；周小结通知（触达）=**T2 事前告知+可选·默认可关**；偏少维度带进下周建议=**T1**。**无需 T2/T3 弹窗轰炸**（本地聚合无联网/上传·若未来上传则升 T3）。

## 八、贯穿红线（所有角色一致）

1. 健康免责：措辞"已覆盖/还缺/可以再加"，**禁** "达标/满足需求/降压/降糖/治疗"医疗断言；挂"仅供参考·非医嘱"。
2. 无国标口径标"惯例·非国标"（"五大类均衡"是惯例判断；嘌呤三级/GI 沿用已确立口径纪律）。
3. 不制造焦虑（Apple 诚实不操纵）：缺口用鼓励口吻、不吓唬、不假紧迫、不默认勾选。
4. 不误表健康数据：`nutritionTags` 缺失**如实不显、不推测**（不脑补"含 Omega-3"），自建菜标签不全优雅降级"营养信息待完善"。
5. 忌口红线不被"均衡"覆盖：营养线"补齐"永远在忌口硬过滤（`hasAvoid` 剔除）之后，**绝不为配齐某维度把忌口菜拉进来**。
6. `balanceScore` 只用结构维度，与"色系墙只看结构不关联热量/慢病"红线一致。
