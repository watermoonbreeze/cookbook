> 版本：v1.0 · 2026-08-01
> 会商团队：Apple-UX 设计师 × Apple 架构师 × 算法工程师 × 软件行为师 × 产品/运营 × 文案策划师
> 真实样本：下厨房 `m.xiachufang.com/recipe/106889995/`（冬瓜丸子汤·已验证可解析）

---

## 一、产品定位

**一句话**：把别人家的菜谱，变成你自己的健康菜单。

用户在"下厨房"等 App 看到菜谱 → 分享链接到本 App → 后台 WebView 加载 + 解析引擎提取结构化信息（菜名/食材/剂量/步骤/图片）→ BottomSheet 展示结果 → 用户确认 → 跳转编辑页预填 → 保存入库。**导入后立刻给出慢性病评估（忌口/宜口/营养）**——这是本功能的差异化价值。

MVP 范围：仅下厨房一个来源 + 预设正则解析 + 基础链接列表 + 存为菜品。AI 解析、多来源、批量操作放 Phase 2。

### 3.2 解析方法：纯正则对 innerText 提取

**决策**：不对原始 HTML 做 CSS 选择器解析。WebView `evaluateJavascript("document.body.innerText")` 获取的纯文本已经具备清晰的行结构（真实样本验证如下），正则完全够用。

#### 真实样本 innerText 结构

```
巨鲜美的冬瓜丸子汤

用料：冬瓜 500克、猪肉馅（前腿肉或者后腿肉，带点儿肥的更好吃）300g、姜末 4片、鸡蛋 1个、生抽 1勺、蚝油 半勺、盐 适量

步骤 1 猪肉馅➕4片姜末…➕1勺生抽…顺着一个方向搅拌上劲
步骤 2 冬瓜去皮切块…水开以后倒入冬瓜大火煮10分钟
步骤 3 转最小火，虎口挤出肉丸，再大火煮5分钟左右
步骤 4 撇去浮末，加适量盐，撒上葱花即可
步骤 5 成品展示…
```

#### 解析配置 JSON Schema

```jsonc
{
  "version": 1,
  "source": "xiachufang",
  "title": {
    // 从innerText中提取菜名：第一行或"用料"之前的大标题
    "pattern": "^(.+?)(?:\n|=)",
    "cleanPattern": "^(.+?)(?:的做法|$)$$"
  },
  "ingredients": {
    // 从"用料："行提取食材列表
    // 真实格式: "用料：冬瓜 500克、猪肉馅（...）300g、姜末 4片、..."
    "sectionStart": "用料[：:]",
    "separator": "[、，,]",
    "itemPattern": "([\\u4e00-\\u9fff()（）a-zA-Z·]+?)\\s*(\\d+(?:\\.\\d+)?)?\\s*(克|g|斤|两|个|只|根|勺|汤匙|茶匙|毫升|ml|升|L|片|半勺|适量)?"
  },
  "steps": {
    "sectionStart": "步骤\\s*\\d+",
    "itemPattern": "步骤\\s*\\d+[.、\\s]*(.+?)(?=步骤\\s*\\d+|$)"
  },
  "image": {
    "cssSelector": "meta[property=\"og:image\"]",
    "attr": "content"
  },
  "meta": {
    "author": "作者[：:]\\s*(.+?)(?:\\n|$)",
    "cookTime": "(\\d+)\\s*分钟"
  }
}
```

#### 解析流程伪代码

```kotlin
// RecipeParser.kt (shared)
fun parse(innerText: String, config: ParseConfig): ParsedRecipe {
    // 1. 提取菜名（第一行或\n前的标题）
    val title = Regex(config.title.pattern, RegexOption.MULTILINE)
        .find(innerText)?.groupValues?.get(1)?.trim() ?: ""
    
    // 2. 提取食材清单
    val ingredients = mutableListOf<ParsedIngredient>()
    val ingredientSection = innerText
        .substringAfter(Regex(config.ingredients.sectionStart).find(innerText)?.value ?: "")
        .substringBefore("\n步骤")
    val items = ingredientSection.split(Regex(config.ingredients.separator))
    for (item in items) {
        val match = Regex(config.ingredients.itemPattern).find(item.trim())
        if (match != null) {
            ingredients.add(ParsedIngredient(
                name = match.groupValues[1].trim(),
                quantity = match.groupValues[2].toDoubleOrNull() ?: 0.0,
                unit = match.groupValues[3].ifEmpty { "适量" }
            ))
        }
    }
    // 食材名清洗：去括号内的说明文字（保留括号外的名）
    // "猪肉馅（前腿肉或者后腿肉，带点儿肥的更好吃）" → "猪肉馅"
    
    // 3. 提取步骤
    val steps = Regex(config.steps.itemPattern, RegexOption.DOT_MATCHES_ALL)
        .findAll(innerText).map { it.groupValues[1].trim() }.toList()
    
    // 4. 图片URL（从HTML meta标签获取，WebView层提取）
    // imageUrl 由 WebView 层的 CSS selector 提取后传入
    
    return ParsedRecipe(title, ingredients, steps, imageUrl)
}
```

### 3.3 clear_text 获取

WebView 加载完成后通过 JS 提取：
```kotlin
webView.evaluateJavascript("document.body.innerText") { text ->
    // text 是 JSON string，需要去除首尾引号和转义
    val clearText = text.removeSurrounding("\"").replace("\\n", "\n")
    repo.updateClearText(linkId, clearText)
    // 触发解析
    parseRecipe(clearText, config)
}
```

图片 URL 通过 CSS selector 从 HTML 中提取（`meta[property="og:image"]`），不走 innerText。

### 4.2 链接列表页

- **入口**：菜品页右上角·搜索图标和+号之间·🔗链接图标（有未解析链接时显示红点）
- **排序**：未解析(0) → 解析失败(2) → 已存为菜品(3)，同状态按 created_at 倒序
- **每行展示**：来源胶囊标签 + 标题 + 链接URL（小号截断）+ 解析状态标签
- **交互**：点击 → 进入解析 Sheet · 左滑 → 删除 · 长按 → 多选模式(勾选圈+bottomBar批量删除)
- **空态**：`EmptyState` "还没有导入的菜谱" + 引导文字

### 4.3 未解析提醒

- **方式**：首页顶部横幅（复用 §9.31 `OutlinedCard` 范式，非弹框打断）
- **文案**："你有 N 条分享链接还未解析" → [去看看] [不再提醒]
- **频次**：每次冷启动有未解析链接时显示（当天不重复）·"不再提醒"后永久关闭
- **红点**：横幅关闭后链接图标保留红点（持久非侵入提醒）

### 4.4 菜品编辑页预填

| 解析结果 | 预填字段 | 方式 |
|---------|---------|------|
| title | 菜名 | 直接填入 |
| imageUrl→本地路径 | 封面图 | 保存时下载→本地路径 |
| ingredients | 食材清单 | 按名匹配现有食材库→自动关联 ingredientId；未匹配标"待匹配" |
| steps | 操作步骤 | 逐条填入 |
| source | 来源标注 | "来自 下厨房"·浅灰标签 |

## 附一：关键踩坑红线

1. **SQLDelight 迁移文件名 = 目录最大号+1**：现有最大 32.sqm → 新建 33.sqm
2. **sqlite_3_18 无 UPSERT**：INSERT OR IGNORE + UPDATE 两步放 transaction
3. **图片路径存相对路径**：不存绝对 URL/本地绝对路径
4. **软删走 status=0**：parse_state 只管解析状态
5. **食物 source 标 "link"**：区别于 preset/user/ai
6. **WebView 必须在后台运行、不可见**：用户界面只看到 BottomSheet
7. **表 `.sq` 不加列无需 .sqm**：加图是纯新查询不改表结构
8. **CRLF 文件正则注意**：`perl` 用 `$` 锚行尾在 CRLF 匹配不到
