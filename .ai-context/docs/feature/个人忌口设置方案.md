# 家庭成员通用忌口设置 · 设计方案

> [AI生成] 2026-07-19 apple_ux_designer 会商产出。用户诉求：普通人(无慢病)也有个人忌口(不吃香菜/葱姜蒜/羊肉/奶)，需专门忌口设置给家庭成员配置，与健康档案忌口组合生效。用户补充(2026-07-19)：**个人忌口对所有食材(主料+配料)生效，配料含忌口也要排后+标明"忌口:X"**。

## 一、产品定位
- **两类忌口正交、取并集**：`最终 avoidIds = 健康调养忌口(care派生) ∪ 个人忌口(用户直选)`。
- 健康忌口=慢病/生命阶段推断出的调养建议(可解释·带健康语境·剂量语义)；个人忌口=用户直接声明的口味偏好(与健康无关·无需解释·就是不吃)。
- 家庭多成员各自忌口 → 全家取并集(与现 care 忌口一致)。
- 覆盖空白：现忌口只有登记慢病/生命阶段的成员才有；健康家庭"孩子不吃香菜/老公不吃羊肉"是高频真实诉求。

## 二、信息架构(放哪)
**放进「家庭档案→成员编辑弹层」内作独立分区，不做独立入口**(忌口天然属于某个人·与已有"健康状态多选"同类并排·不增顶层入口)。
分区顺序：昵称/性别身高体重年龄/活动/饭量 → 健康状态(已有) → **不吃的食材(新增·chip列表+＋添加)**。

## 三、交互
- 复用 `IngredientPicker`(selectionMode 多选)，不自造。已选忌口渲染删除型 chip(`香菜 ×` 点×就地删)，末尾`＋添加`唤起全屏 Picker。
- **Picker 唯一扩展点**：加可选 `preselectedIds` 入参(回带成员现有忌口·在已选上增减)，不传=行为不变(参数驱动·不硬编码 mode)。
- 按分类快选("不吃奶制品")=P2待办(先"选具体食材"覆盖90%·整类忌口涉新数据语义复杂度陡增)。
- 推荐/记菜表现：个人忌口进 avoidIds 后**完全走现有忌口通道**(排末+标红+不隐藏+详情红字)，**无需新增任何推荐/展示逻辑**(最大省力点)。

## 四、数据模型
- 新表 `member_avoid_ingredient(member_id→family_member ON DELETE CASCADE, ingredient_id→ingredient, PK(member_id,ingredient_id))`，与 `member_care` 平行。纯新表无 ALTER·老库升级安全·新 sqm=目录最大序号+1·CREATE 同步进 .sq。
- `FamilyRepository` 加 `allPersonalAvoidIds()`(全家并集去重·对称 allEnabledCareIds)；`toModel` 读忌口进 `FamilyMember.avoidIngredientIds`(加字段→全仓位置构造改命名·红线)；create/updateMember 事务同步写(仿 member_care)。
- gather/gatherForPlan 并入：`avoidIds = care的AVOID ∪ personalAvoidIds`。

## 五、⚠️ 关键差异(用户已定·2026-07-19)
- **个人忌口对调料也真避开**(不套用健康忌口"调料只提示少放")：健康忌口是剂量问题(少盐)、个人忌口是存在问题(不吃葱=一点不要)。个人忌口那批 id **绕过 `!in seasoningIds` 过滤**直接进 avoid。
- **命中放宽到"含即命中"**(不限主料·辅料/调料含该食材即命中排后标明)：口味排斥不看剂量，与健康忌口"只判主料"故意不同。个人忌口需单独的命中判定(遍历全部食材角色)。
