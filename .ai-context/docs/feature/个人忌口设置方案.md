# 家庭成员通用忌口设置 · 设计方案

> [AI生成] 2026-07-19 apple_ux_designer 会商产出。用户诉求：普通人(无慢病)也有个人忌口(不吃香菜/葱姜蒜/羊肉/奶)，需专门忌口设置给家庭成员配置，与健康档案忌口组合生效。用户补充(2026-07-19)：**个人忌口对所有食材(主料+配料)生效，配料含忌口也要排后+标明"忌口:X"**。

> **【2026-07-19 用户修订·重要】改为「按分类选」不选具体食材**：只从**大类/子类**选即可——如 肉类/蔬菜类/菌菇类/豆类/奶类/口味调味类(酸甜苦辣)，或 鸡肉/羊肉/牛肉 这种子类；**不需要具体到每个食材**。存"忌口分类"，推荐时该分类下所有食材都算忌口。下文 §三交互/§四数据模型据此已更新(原"选具体食材"作废)。

## 一、产品定位
- **两类忌口正交、取并集**：`最终 avoidIds = 健康调养忌口(care派生) ∪ 个人忌口(用户直选)`。
- 健康忌口=慢病/生命阶段推断出的调养建议(可解释·带健康语境·剂量语义)；个人忌口=用户直接声明的口味偏好(与健康无关·无需解释·就是不吃)。
- 家庭多成员各自忌口 → 全家取并集(与现 care 忌口一致)。
- 覆盖空白：现忌口只有登记慢病/生命阶段的成员才有；健康家庭"孩子不吃香菜/老公不吃羊肉"是高频真实诉求。

## 二、信息架构(放哪)
**放进「家庭档案→成员编辑弹层」内作独立分区，不做独立入口**(忌口天然属于某个人·与已有"健康状态多选"同类并排·不增顶层入口)。
分区顺序：昵称/性别身高体重年龄/活动/饭量 → 健康状态(已有) → **不吃的食材(新增·chip列表+＋添加)**。

## 三、交互（2026-07-19 修订·按分类选）
- **按分类多选**，不选具体食材：成员编辑弹层"不吃的食材"区展示一组**分类 chip 多选**——大类(肉类/蔬菜类/菌菇类/豆类/奶类/口味调味类) + 常用子类(鸡肉/羊肉/牛肉/海鲜/内脏…)。点亮=忌该类。已选高亮，再点取消。
- 分类来源：复用现有**食材分类维度**(`food_category`/general 大类树 + 子类)；"口味调味类"对应调味/口味相关分类(酸/辣→对应调味食材分类)。分类项从分类表读、按 general 维度筛常用的展示(避免列太多)。
- 空态：`选择不吃的分类`一句引导。无需唤起全屏食材 Picker(比选具体食材少好几步·符合"少操作")。
- 推荐/记菜表现：个人忌口分类 → 展开为该分类下食材 id 集 → 进 avoidIds 后**完全走现有忌口通道**(排末+标红+不隐藏+详情红字)，标明"忌口:羊肉"(用命中的具体食材名或分类名)。**无需新增推荐/展示逻辑**。

## 四、数据模型（2026-07-19 修订·存分类）
- 新表 `member_avoid_category(member_id→family_member ON DELETE CASCADE, category_id→food_category, PK(member_id,category_id))`，与 `member_care` 平行。纯新表无 ALTER·老库升级安全·新 sqm=目录最大序号+1·CREATE 同步进 .sq。
- `FamilyRepository` 加 `allPersonalAvoidCategoryIds()`(全家并集)；gather/gatherForPlan 里 **分类 id → 该分类下食材 id**(复用 `ingredient_category` join / `listByCategories`) → 并入 `avoidIds = care的AVOID ∪ 个人忌口分类展开的食材ids`。
- `toModel` 读进 `FamilyMember.avoidCategoryIds`(加字段→全仓位置构造改命名·红线)；create/updateMember 事务同步写(仿 member_care)。
- **优势**：存分类比存食材更稳(食材同名多 id 问题天然规避·新增食材自动纳入该忌口类)、UI 更省(选几个分类 vs 逐个选食材)。

## 五、⚠️ 关键差异(用户已定·2026-07-19)
- **个人忌口对调料也真避开**(不套用健康忌口"调料只提示少放")：健康忌口是剂量问题(少盐)、个人忌口是存在问题(不吃葱=一点不要)。个人忌口那批 id **绕过 `!in seasoningIds` 过滤**直接进 avoid。
- **命中放宽到"含即命中"**(不限主料·辅料/调料含该食材即命中排后标明)：口味排斥不看剂量，与健康忌口"只判主料"故意不同。个人忌口需单独的命中判定(遍历全部食材角色)。

## 六、待用户拍板(其余按推荐落地)
1. 个人忌口只做"不吃"单档(不提供"少放")？—**推荐:单档**。
2. ✅按分类选(2026-07-19用户定)：分类 chip 多选直接放弹层内(无需全屏 Picker·省步)。
3. 分区标题「不吃的食材」vs「忌口」？—**推荐:「不吃的食材」**(口语·与健康忌口区分)。
4. ✅个人忌口对调料真避开？—**用户已定:真避开**("口味调味类"分类正是为此·不吃酸辣真避开)。
5. ✅命中放宽到含即命中(辅料/调料也算)？—**用户已定:含即命中·排后+标明**。
6. 分类粒度：展示哪些大类/子类 chip(肉/蔬/菌/豆/奶/口味 + 鸡/羊/牛/海鲜/内脏…)——实现时按 food_category 现有分类树选常用项，太细的不列。
