# Cookbook 一期目标与阶段规划（北极星）

> [用户 2026-07-16 定调] 本文件是**一期总目标与执行框架**，所有一期工作以此为纲、**按三部分顺序推进**，每部分绑定其负责角色与门禁。新任务先对照本文件归位。

## 最终目标（北极星）
用户通过本 APP 的**推荐**，解决**"吃什么、怎么吃"**——**根据自身健康情况，推荐出合理的餐食**，让用户**健康饮食**。

## 一期 = 三部分，按顺序处理

### 第一部分 · 基础（食材 / 菜品 / 餐食）
- **目标**：最基础层，让用户**更方便地记录每天的餐食**。
- **硬要求**：操作流程与体验**严格按 UX 设计师的规则**（少操作、简洁高效、苹果理念）。
- **负责角色 × 门禁**：Apple-UX 体验设计师（**UI/交互设计门禁**，编码前先出规范）+ Google 资深工程师（**代码质量门禁**，阻断项必修）。复用 §九交互模式库与 22 复用组件。
- **现状**：MVP 三大核心 + 食材体系/库存/详情/预设菜/全局搜索/应季 + 近期 UX 批次（B-1~B-8、菜品/食材大标题统一、食材"保存并继续"、AppTopBar 收敛等）**已落地**。剩余=打磨项（见待办总览 A/D/E 节：餐次内联常吃 chips、引导浮层、自由搭配存菜等）。

### 第二部分 · 营养膳食（搭配 + 指标准确）
- **目标**：营养搭配合理，**各项指标准确**。
- **硬要求**：需**权威数据支持**；此部分需**产品经理全权处理**（数据来源/口径/阈值/准确性/免责统筹）。
- **负责角色 × 门禁**：产品经理(PM) 主导（定口径/数据源/优先级）+ 权威数据核准（联网分片 agent，一手权威成分表/国标才 `verified`，查不到省略不编造、口径不定标 `pending`）+ Google 代码门禁。**健康免责红线**：均标"仅供参考·非医嘱"，禁编造权威出处。
- **现状**：营养体系框架（`ingredient_nutrition` 表 / `NutritionCalculator` 折算 / `NutritionRepository` 汇总）、今日卡（热量+宏量+慢病提示）、**营养级别评级 P1(热量+钠)已实装**、膳食参考依据页、健康口径（**忌口/调养只按主料判定**、**今日缺口**互补基线）**已落地**。剩余（PM 主导）：**食材营养数据补全**（GI/嘌呤/脂肪值 → 解锁营养级别 P2-P4 与糖尿病/痛风/血脂指标）、独立"膳食统计"页、数据可信度 verified/pending 在消费点分级、今日卡宏量目标参照线。

### 第三部分 · AI 推荐（合理理解）
- **目标**：**合理理解**用户，推出贴合其健康与偏好的餐食。
- **硬要求**：需**算法工程师 + AI 产品工程师协同**。
- **负责角色 × 门禁**：算法工程师（规则引擎/打分因子/画像/去重/多样性）+ AI 产品工程师（意图理解/prompt/端云路由/推荐理由表达）协同 + Google 代码门禁。守忌口/份数/免责红线。
- **现状**：规则引擎（可做性+忌口过滤+打分）、增长型打分（偏好画像/营养互补/主料去重/推荐风格）、云端 GLM + 云端切换框架、三入口 UI、MMR 批内多样性、**今日缺口即时因子**已落地。剩余：AI 结合真实历史学习偏好、画像/今日缺口写进 prompt 对齐云端/端侧、端侧本地模型 S4(LiteRT-LM)、自由搭配引入 AI、逐菜"推荐理由"细化。

## 执行策略 v2（薄闭环先通 + 依赖 DAG 加厚，2026-07-16 复盘优化）
三部分**不是串行三步，而是能力分层 + 依赖有向图**：
- **薄闭环已通**：记录(part1 MVP) → 营养 P1(part2 今日卡) → 规则推荐(part3 已上线)三层都有薄版本在跑。故策略=**薄闭环先通(已通)→ 按依赖逐层加厚**，非"做完一层再下一层"。
- **主线**：北极星"健康推荐"= part3 由 part2 喂养的结果。真正主线是 **part2 数据准确 → 喂 part3 健康推荐**，part1 是承载体验的底座。
- **关键路径 = part2 权威营养数据补全**(GI/嘌呤/脂肪)：同时卡着**营养级别 P2-P4** 与**健康感知 AI 推荐**两条线，杠杆最高、免责风险最大→ PM 全权、优先推进，不是"part1 之后再说"。

### 推进节奏（推荐）
1. **part1 打磨**：低风险、增量，随手推进（各过 UX+代码门禁），不阻塞他人——并行做。
2. **part2 数据(关键路径)**：PM 主导先出**数据治理方案**(数据源/优先级/口径/verified·pending 分级/免责)，再分片权威核准补全 → 边补边解锁营养级别 P2-P4 与慢病维度。
3. **part3 加厚**：随营养数据到位，把"忌口/今日缺口/画像"更深地喂进规则与 prompt；再上端侧模型/历史学习。

### 三条横切主题（贯穿三部分，别漏）
- **数据可信度 + 免责**(贯穿 2/3)：verified/pending 在消费点分级展示；所有健康提示"仅供参考·非医嘱"，禁编造权威出处。
- **反馈闭环 / 学习**(贯穿 1→3)：从用户真实记录(记了什么/评分/收藏)反哺推荐(增长型算法已起步)——记录得越多，推荐越准，是"健康饮食"能落地的引擎。
- **体验一致性**(贯穿全部)：四大页统一(大标题已统一)、§九交互模式库复用、少操作。

### 每部分"一期完成"判据（Definition of Done，让"完成"可衡量）
- **part1 基础**：记一餐 ≤ 3 步可达；四大页体验/顶栏一致；关键流程(记录/复用/搜索/编辑)无卡点、过 UX 门禁。
- **part2 营养**：预设食材营养覆盖率达标(先定目标%)；营养级别覆盖 热量+钠+GI/糖(P2)；慢病维度(钠/GI/嘌呤)可评且数据来源透明+免责；PM 数据治理方案落地。
- **part3 AI**：推荐能结合 健康(忌口/今日缺口)+偏好画像+库存；推荐理由可解释；(可观测)采纳率/命中口径确立。

## 执行原则（按依赖 + 角色门禁）
1. **不强制串行**：part1 打磨并行推进；part2 数据为关键路径优先；part3 随数据加厚。三者按依赖 DAG 而非直线。
2. **每部分绑定角色 + 双门禁**：part1 UX 设计门禁必过；part2 **PM 全权 + 权威数据不编造**；part3 算法+AI 协同。所有部分过 Google 代码门禁。
3. **待办总览按此三部分归类**：`待办总览.md` 的项映射三部分（A 功能≈基础/AI、D/E UX≈基础、健康膳食≈营养）。
4. 相关规划前身：`_archive/legacy_root_docs/产品规划方案.md`（MVP→一期→二期）、`_archive/legacy_root_docs/MVP开发规划.md`；本文件为一期**执行锚点**。
