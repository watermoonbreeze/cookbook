# Cookbook 一期目标与阶段规划（北极星）

> [用户 2026-07-16 定调] 本文件是**一期总目标与执行框架**，所有一期工作以此为纲、**按三部分顺序推进**，每部分绑定其负责角色与门禁。新任务先对照本文件归位。

## 最终目标（北极星）
用户通过本 APP 的**推荐**，解决**"吃什么、怎么吃"**——**根据自身健康情况，推荐出合理的餐食**，让用户**健康饮食**。

## 一期 = 三部分，按顺序处理

### 第一部分 · 基础（食材 / 菜品 / 餐食）
- **目标**：最基础层，让用户**更方便地记录每天的餐食**。
- **硬要求**：操作流程与体验**严格按 UX 设计师的规则**（少操作、简洁高效、苹果理念）。
- **负责角色 × 门禁**：Apple-UX 体验设计师（**UI/交互设计门禁**，编码前先出规范）+ Google 资深工程师（**代码质量门禁**，阻断项必修）。复用 §九交互模式库与 22 复用组件。
- **现状**：MVP 三大核心 + 食材体系/库存/详情/预设菜/全局搜索/应季 + 近期 UX 批次（B-1~B-8、菜品/食材大标题统一、食材"保存并继续"、AppTopBar 收敛等）**已落地**。剩余=打磨项（见待办总览 A/D/E 节：餐次内联常吃 chips、引导浮层、自由搭配存菜等）。

### 第二部分 · 营养膳食（搭配 + 指标准确）
- **目标**：营养搭配合理，**各项指标准确**。
- **硬要求**：需**权威数据支持**；此部分需**产品经理全权处理**（数据来源/口径/阈值/准确性/免责统筹）。
- **负责角色 × 门禁**：产品经理(PM) 主导（定口径/数据源/优先级）+ 权威数据核准（联网分片 agent，一手权威成分表/国标才 `verified`，查不到省略不编造、口径不定标 `pending`）+ Google 代码门禁。**健康免责红线**：均标"仅供参考·非医嘱"，禁编造权威出处。
- **现状**：营养体系框架（`ingredient_nutrition` 表 / `NutritionCalculator` 折算 / `NutritionRepository` 汇总）、今日卡（热量+宏量+慢病提示）、**营养级别评级 P1(热量+钠)已实装**、膳食参考依据页、健康口径（**忌口/调养只按主料判定**、**今日缺口**互补基线）**已落地**。剩余（PM 主导）：**食材营养数据补全**（GI/嘌呤/脂肪值 → 解锁营养级别 P2-P4 与糖尿病/痛风/血脂指标）、独立"膳食统计"页、数据可信度 verified/pending 在消费点分级、今日卡宏量目标参照线。

### 第三部分 · AI 推荐（合理理解）
- **目标**：**合理理解**用户，推出贴合其健康与偏好的餐食。
- **硬要求**：需**算法工程师 + AI 产品工程师协同**。
- **负责角色 × 门禁**：算法工程师（规则引擎/打分因子/画像/去重/多样性）+ AI 产品工程师（意图理解/prompt/端云路由/推荐理由表达）协同 + Google 代码门禁。守忌口/份数/免责红线。
- **现状**：规则引擎（可做性+忌口过滤+打分）、增长型打分（偏好画像/营养互补/主料去重/推荐风格）、云端 GLM + 云端切换框架、三入口 UI、MMR 批内多样性、**今日缺口即时因子**已落地。剩余：AI 结合真实历史学习偏好、画像/今日缺口写进 prompt 对齐云端/端侧、端侧本地模型 S4(LiteRT-LM)、自由搭配引入 AI、逐菜"推荐理由"细化。

## 执行原则（按顺序 + 依赖）
1. **顺序**：先夯实**基础(体验)**→再**营养(准确+权威)**→再**AI(理解)**。三者层层支撑：AI 推荐的"健康合理"依赖营养指标准确；营养级别 P2-P4 与慢病维度依赖营养数据补全。
2. **每部分绑定角色 + 双门禁**：第一部分 UX 设计门禁必过；第二部分 **PM 全权 + 权威数据不编造**；第三部分 算法+AI 协同。所有部分过 Google 代码门禁。
3. **待办总览按此三部分归类**：`待办总览.md` 的项映射到三部分（A 功能≈基础/AI、D/E UX≈基础、健康膳食≈营养）。推进时优先补齐当前阶段。
4. 相关规划前身：`docs/产品规划方案.md`（MVP→一期→二期）、`docs/MVP开发规划.md`；本文件为一期**执行锚点**。
