# 菜品「餐次分类」维度 · 设计方案

> [AI生成] 2026-07-19 apple_ux_designer 会商。用户诉求：给菜品加餐次分类，按餐次筛出可作对应餐次的菜(纯牛奶=早餐·小点心=加餐/上午/下午)。仅设计不改代码。

## 定位(D1)
把 `MealSlotMatcher`(现按菜名关键词临时猜)升级为**可存储、可编辑、多对多**的菜品属性；启发式**不删·降级为"生成默认值的推断器"**(新建/回填时推断初始餐次·之后以存储值为准)。一道菜可属多餐次(鸡蛋羹=早餐+加餐)。与菜系差异:菜系单值默认家常菜、餐次多值默认按 Matcher 推断，都守"少必填+合理默认"。价值=菜品页按餐次筛/搜索"早餐"出菜/AI推荐/记一餐精准预筛。

## 数据模型(D2·方向)
**新建关联表 `dish_meal_slot`**(仿 dish_cooking_method_rel·**不复用 dish_tag**[枚举维度别混自由标签]·**不加 dish 列**[多值存不下+牵连 SELECT * 红线])：
```
dish_meal_slot(dish_id→dish CASCADE, meal_type_id→meal_type CASCADE, status DEFAULT 1, PK(dish_id,meal_type_id)) + idx(meal_type_id)
```
指向 `meal_type` 表(餐次主数据·含加餐)保 FK。纯新表老库零风险(新 N.sqm 建表·Cookbook.sq 同步 CREATE·查询全纯新)。**预设菜 seed**:用 Matcher 批量推断516菜生成初始餐次+人工粗校明显错的(整理值·常识判断非健康数据·可不标来源);seeder 幂等只补空+`SEED_LOGIC_VERSION`+1;自建菜保存时按 Matcher 推断默认写入。

## 设置交互(D3)
`NewDishScreen` 折叠区**上方**加"适合餐次"行(**可见非必填**·别藏折叠·让用户一眼确认默认对不对)：多选 chip 横向流式(早/上午/中/下午/晚/宵夜·选中实心)。新建按 Matcher 预选(菜名 blur/保存时推断·避免每输入抖动)、编辑回显存储值、手动碰过则锁定不再自动改(`mealSlotTouched` 守卫)。空则保存时 Matcher 兜底(永不出现无餐次菜)。文案"已按菜名智能预选,可增减"(仅新建显)。

## 筛选/搜索(D4)
- **菜品页按餐次筛=横切维度**(不做第5个一级Tab)。**推荐方案A**:一级Tab下方加**二级餐次胶囊栏**(复用§9.18 `PrimaryTabRow(scrollable=true)`·作用所有档·全部时隐栏省竖向空间)。
- **搜索"早餐"**(整合"搜索按餐次"待办):搜索框识别餐次关键词(早餐/午餐/晚餐/加餐/宵夜…)→切"按餐次筛"模式查 dish_meal_slot·头部提示"适合早餐的菜品"·老库无关联用 Matcher 兜底·走§9.2/§9.19。
- **食材餐次=一期不做**(食材餐次归属模糊·鸡蛋样样餐次都行·反过度设计);搜食材"早餐"用轻量启发式临时归类不建表。

## 与 AI 推荐/记一餐整合(D5·最大价值)
- AI 推荐 `RecommendationDataSource` 的 mealSlot 过滤**改优先查 dish_meal_slot 关联**(缺才回退 Matcher)→推"早餐"出真标早餐的菜(不再把番茄炒蛋当早餐)。
- 记一餐选菜按当前餐次**预筛+可切全部**(不硬隐藏·告知不替决定)。
- 三处(推荐/记一餐/搜索)统一走 dish_meal_slot=餐次单一真相源。

## 边界/红线
多餐次常态·默认不强制(空则兜底)·餐次是常识分类非健康数据(seed 可不标来源·不做"早餐必吃X"断言)·SQLDelight 纯新表一条 sqm+纯新查询·SEED_LOGIC_VERSION+1·回填只补空·meal_type code 按名解析加引用完整性单测·多入口独立守卫·§9.18复用。

## 拍板清单(建议全采纳)
D1 餐次=可存储多值属性/Matcher降默认 · D2 预设菜Matcher推断+粗校·整理值不标源 · D3 编辑页可见非必填+预选+手动锁定 · D4 筛入口方案A(二级横滚栏·全部时隐)+食材餐次一期不做 · D5 记一餐按餐次预筛可切全部。
**进实现前门禁**：Apple-UX 细化布局(chip尺寸/二级栏显隐动效/预选提示)+编码后 Google 审查(迁移安全/SEED_LOGIC_VERSION/引用完整性单测)。
