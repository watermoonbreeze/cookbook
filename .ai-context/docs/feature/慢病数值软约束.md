# 慢病数值软约束（推荐软降）

> 2026-07-16 无人值守。经**多角色验证**（临床营养/算法 + 产品/免责 双组）+ Google 审查门禁。守健康免责红线。
> 本文档按规则含【操作逻辑】+【用户验证方法】（算法类功能须让用户能自行判断对不对）。

## 一、目标
登记糖尿病/痛风的家庭，本地推荐时把**高GI(糖尿病)/高嘌呤(痛风)主料**的菜在正常层内**梯度软降**（排名靠后但**不剔除**，区别于忌口硬标排末层）。温和引导，不越免责。

## 二、多角色验证收敛（4 角色）
- **钠不做菜级软降**（关键裁决）：菜级 `sodiumMg` 含盐/酱油等调料无法拆，几乎每道热菜都放盐→按菜级钠软降会**惩罚每道菜**=失效（CLAUDE.md 红线"盐对高血压忌口让每道菜都忌口"的数值翻版）。钠继续靠 care limit + `cookingCautions`(少盐/少酱油) + 今日卡钠占比提示（均已上线）。GI/嘌呤是"绑定特定主料"的食材属性，适合软降；钠是"无处不在"的调料属性，不适合。
- **默认权重 0、仅"营养优先"风格生效**（默认 vs opt-in 分歧裁决）：软降是弱可感知的排序微调，"默认静默重排"在慢病语境有操纵感/信任风险；**用户主动选营养风格=知情同意**，语义自洽、零新增开关、无需现场提示。算法角色的"默认对病种生效"记为可选后续（日后若加透明现场提示可提权重）。
- **复用去重**：高GI/高嘌呤主料若已在 care avoid/limit→已被罚，软降跳过（防双重罚），复用详情页 `dishQualitativeHits` 的 `filterNot{in avoid∪limit}`。
- **缺数据/无病种=0 向后兼容**（同评级器全局口径）。

## 三、【操作逻辑】（算法细节，可回溯）
**落点**：`HealthRuleEngine.evaluate()` 打分累加段（`mainRepeat` 罚之后、`avoid` 罚之前），加因子 `chronicDiseaseNutrition`。**不改 `sortedWith` 分层**（忌口菜仍靠 avoidNames 绝对排末层，软降只在正常层内微调 score）。

**因子公式**（仅当 `weights.chronicDiseaseNutrition>0 && conditions.isNotEmpty()`）：
```
flagged = 本菜主料中已在 care avoid ∪ limit 的名字集
(highGi, highPurine) = dishQualitativeHits(主料名, conditions, giByName, flagged)
   ├ highGi   = 主料中 GI≥70(FAO/WHO,查 giByName) 且不在 flagged 的名字   (仅 DIABETES 触发)
   └ highPurine = 主料中命中高嘌呤关键词(WS/T560定性,内脏/浓汤/部分海鲜) 且不在 flagged (仅 GOUT 触发)
penalty = ( min(highGi数,2) + min(highPurine数,2) ) × 0.25 ，再 coerceAtMost(0.7)   // 每类最多计2味、整因子封顶0.7
score  -= weights.chronicDiseaseNutrition × penalty
```
**权重取值**：`chronicDiseaseNutrition` 默认 **0.0**（综合/偏熟悉/偏新鲜风格=不生效）；**NUTRITION(偏营养)风格 = 0.6**。故单菜最大软降 = 0.6×0.7 ≈ **0.42**，显著小于 `avoid=5.0`、也小于 `base=1.0`（不反超"物尽其用"核心信号、不把菜压进忌口层）。

**数据来源**：
- GI 值：`ingredient_nutrition.gi`（中国食物血糖指数表/悉尼GI库交叉，`NutritionRepository.giByName()` 名→GI；仅登记糖尿病才查表）。分级 GI≥70=高（**FAO/WHO 口径，非 WS/T652**）。
- 嘌呤：`NutritionLevelEvaluator.HIGH_PURINE_KEYWORDS`（WS/T560-2017 定性食物类别，**无国标数值分级**故用关键词，非编造阈值）。
- 病种：家庭 enabled 健康档案 care 分类名 → `HealthCondition.fromCareName`（与今日卡/详情页同口径）。

**透传链**：`RecommendationDataSource.gather()` 派生 conditions+giByName → 装入 `RecommendationInput` → `RecommendationOrchestrator.recommend()`/`ruleCandidates` 的 `engine.evaluate()`。周期计划(`gatherForPlan`→PlanContext)是独立路径，本期不含软降。

## 四、【用户验证方法】（真机/数据怎么判断对不对）
1. **默认不生效（向后兼容）**：推荐风格保持"综合/偏熟悉/偏新鲜"时，推荐顺序**与本次改动前完全一致**（软降权重0）。→ 判断：切这三种风格，高GI菜(如白米饭套餐)不应因慢病被额外排后。
2. **营养风格 + 登记病种才生效**：我的→功能设置登记糖尿病(或痛风)档案；AI推荐页选**"偏营养"**风格 → 含高GI主料(米饭/馒头/白粥等)的菜、或含高嘌呤主料(猪肝/内脏/浓肉汤/沙丁鱼等)的菜，**在同批正常菜里排得比同类普通菜靠后**（但仍在列表里、可滚动找到、不标红、不剔除）。→ 判断：对比"偏营养"vs"综合"两风格下同一批候选，高GI/嘌呤菜在偏营养下相对靠后。
3. **不越忌口分层**：忌口菜(如高血脂忌五花肉、已在 care avoid)**永远排在所有软降菜之后**(末层标红)。→ 判断：忌口菜始终在最后，软降只影响忌口之前的正常菜相对顺序。
4. **不双重罚(去重)**：若某高GI/嘌呤主料同时被你在健康档案设为"限量"，它只按限量罚一次、软降不再叠加。
5. **无病种/无数据零影响**：没登记任何慢病 → 软降永不触发；菜的主料无 GI 数据 → 该菜不被 GI 软降（数据越全越准，会随营养库成长）。
6. **代码级验证**：`:shared:testDebugUnitTest` 的 `慢病软降_*` 两个测试断言了上述①②④（营养风格软降、默认风格0、无病种0、limit去重不双重）。
7. **免责**：软降只调**排序**、不隐藏任何菜、不构成医嘱；GI 用 FAO/WHO、嘌呤定性非国标数值。
