# 菜品页「餐次升为主分类」交互重设计方案

> [AI生成] 2026-07-19 apple_ux_designer。用户诉求：菜品的餐次要和菜系**并列作主分类**，现状让餐次像菜系子分类不合理。
> **状态：设计完成·方案A推荐·待用户过目方向后实现**（方案A 会把"最近/喜爱/家庭"一级Tab降为排序器，超出"餐次并列"窄诉求、改动主导航，建议用户确认方向/D1-D8 后再编码）。

## 一、诊断：为什么餐次显得从属
现状把 4 类层级各异的东西混在两排：
- 一级 Tab：**最近/喜爱/家庭**(排序/来源视图) + **菜系**(分类维度·占1席) — 混排。
- 菜系 Tab 选中：左侧竖排 `CuisineRail` + 右列表（重形态）。
- 二级餐次横条：全部/早/中/加/晚/宵（常驻全局·§9.18 横滚·轻形态）。
- 烹饪方式/标签：列表头 FilterChips。

**三根因**：①形态不对等（菜系=Tab+Rail重、餐次=横条轻）②语义层级错配（菜系与"最近/喜爱/家庭"不同层却同排）③餐次横条只在菜系Tab下伴左Rail出现、空间上被"包"进菜系视图。

## 二、信息架构分层（三方案共用地基）
```
L0 页面身份   「菜品」大标题 + 🔍 ＋
L1 分类维度   菜系 ⟺ 餐次      ← 两者对等(本次核心)
L2 维度内分堆  菜系:家常/川/粤…  餐次:早/中/加/晚/宵
L3 排序/视图   最近·喜爱·全部·家庭  ← 从一级Tab降为排序器(对两维度都生效)
L3 次级筛选    烹饪方式/标签/清除   ← FilterChips 不变
```
关键：**"最近/喜爱/家庭"是排序/视图、不是分类维度**，不该与"菜系/餐次"抢一级席位。

## 三、方案对比

| 维度 | A 维度切换+共用Rail ★推荐 | B 双横条对等 | C 单维度切换(A去叠加) |
|---|---|---|---|
| 菜系/餐次对等 | ★★★同一切换器两选项 | ★★★同款横条 | ★★★ |
| 保留菜系竖排浏览 | ✅Rail | ❌变横条 | ✅Rail |
| 顶部空间 | 低(1行切换器) | 高(2行横条) | 低 |
| 维度正交叠加(川菜∩加餐) | ✅ | ✅ | ❌简化 |
| 复用现有代码 | 中(Rail泛化) | 高(照抄横条) | 中 |
| 认知负担 | 低 | 中 | 最低 |

### 方案A（推荐）：维度切换器 + 共用 Rail
一级放"按菜系 / 按餐次"分段切换器(SegmentedControl 均分2项)；切到哪个维度左侧 Rail 就列哪个维度的分堆(菜系→川菜/粤菜…；餐次→早/中/加/晚/宵)。两维度共用同一"左Rail+右列表"骨架、形态完全对等。"最近/喜爱/全部/家庭"降为右侧列表头排序器(⇅ 弹 ActionSheet)、对两维度都正交生效(现状做不到"看川菜里我最爱的")。
```
菜品                     🔍 ＋
[ 按菜系 ● │  按餐次 ]          ← L1维度切换
全部│ 共128道      ⇅最近▾       ← L3排序器(右上)
家常│ #川 #清蒸 清除            ← L3次级筛选
川菜●│ 宫保鸡丁  ★🔥
粤菜│ 回锅肉
… │ …
```
切"按餐次"：同骨架、左Rail换成 全部/早餐/中餐/加餐/晚餐/宵夜。

### 方案B（最小改）：菜系也降成横条、与餐次两条并列(丢左Rail竖排浏览、顶部占用高)。
### 方案C（极简）：同A的切换器但不保留另一维度叠加(切维度即清另一维度)。

## 四、推荐 A 的落地边界（高度复用·不推翻页面）
- L1 维度切换=复用 `SegmentedControl`(2项均分)、新增"维度"枚举。
- `CuisineRail`→泛化 `CategoryRail(items,selected,onSelect)`，菜系/餐次共用。
- 右侧列表/`DishRow`/`DishFilterChips`/`LetterIndexBar`/`ActionSheet`/`DishSearchOverlay`/删除流 **原样复用**。
- VM：新增 `_dimension`(CUISINE/SLOT)并入 ViewOpts(已是合并载体·不新增combine路)；`_mealSlotFilter` 保留(选择入口从横条改Rail)；`_sortTab` 语义调为排序器。
- **红线**：字母索引 `letterHeaderCount`/`letterIndexMap` 偏移随列表头item增减同步+纳入remember key；重建UiState用`.copy`保留维度/餐次/排序粘性字段；`stateIn.value`不做toggle判定。

## 五、需用户拍板（每点给推荐）
- **D1 选方案**：**A**(维度切换+共用Rail·推荐)/C(极简去叠加)/B(最小改双横条)。
- **D2 "最近/喜爱/全部/家庭"降层放哪**：收进右侧列表头"排序/视图"入口(⇅ ActionSheet)·分"排序:最近/喜爱"+"范围:全部/我家自建"·对两维度正交生效。**推荐**。
- **D3 排序入口形态**：计数行右侧文字按钮「⇅最近▾」弹ActionSheet(省空间·推荐) / 另起一条胶囊。
- **D4 是否保留 菜系∩餐次 正交叠加**：保留(A·推荐) / 不保留(C·切维度即清另一维度)。
- **D5 餐次维度下右列表排序/字母索引**：餐次维度按最近/喜爱排、隐 LetterIndexBar(字母索引对餐次意义不大)。
- **D6 "全部"Rail项两维度都留**：留(心智连续)。
- **D7 搜索联动**：搜"川菜/早餐"命中→跳对应维度+选中该分堆(openFromSearch 同步设 _dimension)。
- **D8 持久化**：新增 savedDimension/savedSlot·rememberSaveable(沿用现 savedSortTab/savedCuisine)。

> 沉淀目标：确认后进 Apple-UX 门禁细化→编码，结论入 `苹果风格UI设计方案.md §9.24`「菜品页维度切换：菜系/餐次对等 Rail」。
> **一句话**：病根=分类维度(菜系/餐次)与排序视图(最近/喜爱/家庭)混排、且菜系独占Tab+Rail重形态而餐次仅横条；方案A 用"按菜系/按餐次"切换器把两者做平权选项、共用左Rail骨架，并把排序视图降为对两维度都生效的排序器。**改动主导航·超出窄诉求·建议用户确认方向再实现。**
