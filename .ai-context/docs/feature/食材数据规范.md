# 食材数据规范（数据层框架契约）

> [AI生成] 2026-07-03 制定。后续所有食材基础数据的补充（人工整理 / 爬虫抓取 / AI 生成）都必须遵守本规范；
> 只填内容、不动架构。架构分层背景见文末"三层架构定位"。

## 一、数据文件清单（`shared/src/commonMain/resources/seed/`）

| 文件 | 表 | 唯一键 | 说明 |
|---|---|---|---|
| `food_categories.json` | food_category | `code`（JSON 内）；库内按 名称+维度+父级 匹配 | 分类树，支持任意层级 |
| `ingredients.json` | ingredient | `name`（食材名，全局唯一） | 基础食材 + 多分类归属 |
| `ingredient_details.json` | ingredient_detail | `ingredient`（食材名） | 做法/处理/注意/保存/健康说明文本 |
| `ingredient_care_rules.json` | ingredient_care_rule | `ingredient + category` | 调养建议（病种 × 剂量 × 原因） |
| `crowd_rules.json` | crowd_ingredient | `crowd + ingredient` | 旧版人群规则（保留兼容，新数据一律写 care_rules） |

## 二、字段规范

### food_categories.json
```json
{"code":"veg_leaf","name":"叶菜类","dimension":"general","parent":"vegetable","sort":10,"icon":""}
```
- `code`：小写下划线，前缀表意（`care_`=调养病种、`gi_`/`purine_`/`sodium_`/`fat_`=营养档位）。**一经发布不得改名/复用**。
- `dimension` 枚举：`general`（常规）/ `nutrition` / `gi` / `purine` / `sodium` / `fat` / `sugar` / `season`（营养/应季，均并入营养 Tab）/ `crowd`（调养）。应季前缀 `season_`（春/夏/秋/冬）。
- **调养维度只允许病种/人群层**（如 `care_gout`），禁止再建"绿灯/黄灯/红灯"剂量节点——剂量由 care rule 的 `level` 表达（2026-07-03 v10 模型统一）。

### ingredients.json
```json
{"code":"spinach","name":"菠菜","alias":"赤根菜","unit":"克","emoji":"🥬","categories":["veg_leaf","iron_rich","purine_mid"]}
```
- `name` 是运行时匹配键：**已发布食材不得改名**（改名=新增一个食材）；别名/纠错走 `alias`。
- `categories` 引用分类 `code`，跨维度多选；**不要引用 `care_*`**（调养走 care_rules 文件）。

### ingredient_care_rules.json
```json
{"ingredient":"猪肝","category":"care_gout","level":"avoid","reason":"动物内脏嘌呤高，痛风和高尿酸人群应尽量避免。"}
```
- `category` 只允许病种/人群层 code；`level` 枚举：`recommend` / `limit` / `avoid`。
- `reason` **必填**（健康建议必须带原因，禁止无依据判定）。
- 同一 `ingredient + category` 只允许一条（重复时导入层 upsert 覆盖）。

### 可选元数据字段（所有文件通用，解析器已容忍未知字段）
- `ref`：数据来源标注，如 `"ref":"中国食物成分表第6版"` 或 URL。爬虫/AI 产出**必须**带 `ref`。
- `review`：`"pending"`=待人工审核。审核通过后删除该字段。

## 三、数据来源注册表（权威优先级）

| 数据类型 | 首选来源 | 备选 |
|---|---|---|
| 营养素含量/档位 | 中国食物成分表（第6版） | USDA FoodData Central、FAO/INFOODS |
| 膳食搭配/推荐量 | 中国居民膳食指南（2022）+ DRIs（2023） | WHO 健康饮食指南（2024） |
| 慢病红绿灯 | 各病种临床营养指南、`temp/claude/日常食材维度.md`（已按指南整理） | DASH、地中海膳食 |
| 标签定义口径 | GB 28050-2025 营养标签通则 | Codex Alimentarius |

## 四、导入语义（补齐式，PresetDataSeeder）

- 启动时按唯一键**只补不删**：JSON 新增 → 入库；JSON 修改 detail/care rule → upsert 覆盖预设值；JSON 删除分类节点 → 库内不会自动删（需要 `.sqm` 迁移处理，参照 `9.sqm`）。
- **用户数据永远优先**：`source='user'` 的行、用户对预设食材的修改（alias/图片）不会被 seed 覆盖。
- 软删除的预设食材会在下次导入时恢复并刷新基础字段。

## 五、扩展路线（框架已预留，按需启用）

1. **L2 数值层**（未启用）：每 100g 嘌呤 mg、GI 值、钠/钾/钙 mg、蛋白/脂肪/碳水 g。启用时：ingredient_detail 加数值列（`.sqm` 迁移）+ JSON 加对应字段即可，浏览/筛选架构不变。
2. **爬虫/批量导入管线**：爬虫产出 → 校验脚本（唯一键冲突、枚举合法性、reason 非空、ref 必填）→ 合入 seed JSON → `PresetDataSeederTest` 回归 → 发版。校验规则以本规范为准。
3. **远程数据包**：JSON 结构即数据包格式，后续可加 `dataVersion` 做远程下发，导入器无需重写。

## 六、三层架构定位（用户设想的落地映射）

| 层 | 位置 | 职责 |
|---|---|---|
| 界面层 | androidApp / iosApp | 易用性；只消费 shared 暴露的业务能力 |
| 数据层-基础数据 | seed JSON + SQLDelight 预设表（source='preset'） | 本规范管辖：可维护、可扩展、来源可溯 |
| 数据层-用户数据 | SQLDelight 用户表/字段（source='user'、餐食/菜品/偏好） | 同步友好：全表带 status 软删 + 时间戳，导出走 BackupManager；后续多设备同步在此基础上做 |
| AI 层 | 端侧 AI（方案见 `端侧AI能力接入方案.md`） | 结合基础数据+用户数据给膳食指导；AI 产出回写基础数据须带 `ref`+`review:pending` |
