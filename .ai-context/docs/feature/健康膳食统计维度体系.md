# 健康膳食统计维度体系（预设 + 自定义 通用）

> [AI生成] 2026-07-14。统一定义 app 的健康膳食统计**维度**、每个指标**关联哪些食材数据**，
> 使**预设与用户自定义**的食材/菜品都能用同一套指标计算。解决"统计不准确"（现仅靠食物组多样性）。
> 健康数据为参考整理、非医嘱。

## 一、两层维度

### A. 量化营养维度（数值层 = `ingredient_nutrition` 每100g × 折算克数 求和）
| 维度 | 字段 | 聚合 |
|---|---|---|
| 热量 | energy_kcal | 加和 |
| 蛋白质/脂肪/碳水 | protein_g/fat_g/carb_g | 加和 + 供能占比(P×4/F×9/C×4) |
| 膳食纤维 | fiber_g | 加和 |
| 钠/钾/钙 | sodium_mg/potassium_mg/calcium_mg | 加和 |
| 嘌呤 | purine_mg | 加和(总负荷) |
| GI | gi | **碳水加权平均**(非简单和)：Σ(gi×carb)/Σcarb |

折算克数：`quantity × (measurement_unit.grams ?? ingredient.piece_gram ?? 兜底)`（见 NutritionCalculator）。

### B. 定性分类维度（标签层 = `food_category` 各 dimension）
| 维度 | 来源 dimension | 用途 |
|---|---|---|
| 食物组覆盖 | general(主食/蔬菜/水果/肉/蛋/奶/豆/菌藻/坚果) | 食物多样性 |
| 慢病档位 | gi/purine/sodium/fat/sugar/nutrition | 高钠/低GI/高嘌呤等标签 |
| 应季 | season | 应季优先 |
| 调养 | care_*(病种) | 忌口/限量/推荐(HealthRuleEngine) |

## 二、统计指标 ← 数据关联（核心表）
| 统计指标 | 关联数据 | 参照 |
|---|---|---|
| 每日热量/达标 | Σ热量 | BMR×活动系数(CalorieTarget)，±15%达标 |
| 宏量均衡 | 蛋白/脂肪/碳水供能占比 | 膳食指南 ~20/28/52% |
| 膳食纤维充足 | Σ纤维 | 成人 ~25–30g/日 |
| 钠控制(高血压) | Σ钠 | <2000mg/日(约5g盐) |
| 嘌呤控制(痛风) | Σ嘌呤 + purine 档位标签 | 急性期<150mg/餐 |
| 血糖友好(糖尿病) | 碳水加权GI + gi 档位 | 低GI<55 |
| 食物多样性 | 食物组覆盖数 | 每日≥5类、每周更广 |
| 慢病适宜 | care rule(忌口/限量/推荐) + 关键指标超标 | 健康档案病种 |

## 三、营养级别评定（修"不准确"）
**现状**：`FoodGroup.nutritionLevel(groups)` 仅按食物组多样性 0–4 → 色系墙/卡片配色。粗糙。

**新口径**（综合评分 → 0–4）：
```
score = w_div·多样性(食物组覆盖) + w_cal·热量达标 + w_macro·宏量均衡 + w_chr·关键慢病指标未超标
```
- 已在 2c 落地一部分：填了身体数据时"热量偏离目标降一档"。
- 进一步：宏量严重失衡(如碳水占比>70%)、关键指标超标(高血压者钠超标/痛风者嘌呤超标)也降档。
- **向后兼容**：无身体数据/无营养数据 → 退回纯多样性(现行为)。数据越全越准。

## 四、预设 vs 自定义 统一计算
- 一切统计基于两组数据：**ingredient_nutrition(数值)** + **ingredient_category(分类标签)**。
- **预设食材**：seed 已填数值(ingredient_nutrition.json 100个) + 分类。
- **自定义食材**：用户创建时可填「每100g营养(数值)」+ 选「分类(食物组/慢病标签)」。
  - 填了 → 完全进统计(和预设一样)。
  - 没填数值 → 只按分类进"多样性/慢病标签"，不进"热量/宏量"，其所在菜标"估算不全"，可后补。
- **自定义菜品**：由其配料(食材)经同一 `NutritionCalculator` 聚合，与预设菜同口径。

## 五、自定义食材接入（Item 4 落地）
1. **新建食材页加「营养素(每100g)」可选输入区**：热量/蛋白/脂肪/碳水/纤维/钠/钾/钙/GI/嘌呤/单件克重；存 `ingredient_nutrition`(user 来源)。
2. **创建时提示(营养色系开关开时显示)**：说明填哪些值影响哪些统计——
   - 热量 → 每日千卡/达标；蛋白/脂肪/碳水 → 宏量均衡；食物组分类 → 搭配多样性；钠/嘌呤/GI → 慢病指标(高血压/痛风/糖尿病)。
   - 让用户填时知道"为什么填、影响什么"。
3. **缺失兜底**：不填也能用(只少量化统计)，随时可补。

## 六、落地分期
- **P1(本轮)**：本文档(维度+指标关联)；自定义食材创建页营养输入 + 分类 + 营养色系开时提示(Item4)；nutritionLevel 评定纳入热量/关键指标(部分已做)。
- **P2**：每日/每周「膳食统计」页(各维度达标概览 + 趋势)；慢病专项(钠/嘌呤/GI)。
- **P3**：营养素数据持续补全(预设 + 引导用户补自定义)。
