# DATE-CALENDAR-01 — 单天手动复用食历月历实施蓝图

## 0. User requirement

目标页面：
`记录饮食 → 单天 → 手动选择`

要求：
1. 日期区域不要再有“昨天 / 今天 / 明天”快捷项；
2. 日期选择控件改成与“食历”一致；
3. 有餐食的日期必须在**选择前**明显可见；
4. 复用食历现有日期选择控件，而不是另造一份。

## 1. Verified current facts

### AddDayFoodScreen
当前：
- `FilterChip("昨天" / "今天" / "明天")`
- 下方 `OutlinedButton` 打开 Material3 `DatePickerDialogContent`
- 用户选中日期后才通过 `vm.setDate(date)` 查询 occupied 并提示

### FoodTimelineScreen
当前已有自绘轻量月历：
- 月份前后切换；
- 星期一~日表头；
- 6×7 月格；
- `hasMeal` 日期用 primary 文本 + 5dp primary 小圆点；
- Material3 DatePicker 因不能自定义 day dot，所以项目已经自行实现。

### Timeline data truth
`TimelineViewModel` 通过：
`MealRecordRepository.observeTimelineDates()`
拿到所有有 `meal_record` 的日期，写为 `mealDates: Set<LocalDate>`。

### AddMealViewModel
已经持有同一个 `MealRecordRepository`。
当前 `setDate()` 业务规则必须保留：
- occupied → 不切换，warning “已有餐食，请到食历编辑/另选空日期”
- empty → 切日期，保留当前正在编辑的餐次内容
- existing edit → 日期锁定
- copy `minSelectableDate` 规则保留

## 2. Architecture decision

不是“把 TimelineCalendarDialog 复制到 AddDayFoodScreen”。

应当：

```text
FoodTimelineScreen private calendar
              |
              v extract
ui/component/MealDateCalendarDialog.kt
              ^
        +-----+-----+
        |           |
FoodTimeline     AddDayFood
mealDates only   all in-month dates selectable
clickable        (VM still rejects occupied)
```

数据：

```text
MealRecordRepository.observeTimelineDates()
        +-- TimelineViewModel -> Timeline calendar
        +-- AddMealViewModel  -> AddDayFood calendar
```

不新增 SQL，不逐日查询 42 个格子。

## 3. Shared component contract

新建：
`androidApp/src/main/java/com/sxdbsm/cookbook/android/ui/component/MealDateCalendarDialog.kt`

建议 API（等价命名允许，语义不得变）：

```kotlin
enum class MealDateCalendarSelectionMode {
    MEAL_DATES_ONLY,   // 食历：只有已有餐食日期可点
    ANY_VISIBLE_DATE,  // 添加餐食：本月任意日期可点；occupied 仍由 VM 决定是否接受
}

@Composable
fun MealDateCalendarDialog(
    mealDates: Set<LocalDate>,
    initialDate: LocalDate,
    selectedDate: LocalDate? = null,
    selectionMode: MealDateCalendarSelectionMode,
    onDismiss: () -> Unit,
    onDateClick: (LocalDate) -> Unit,
)
```

组件内部复用/搬迁现有：
- `firstDayOfMonth`
- `addMonths`
- `monthRows`
- `CalendarDayCell`

### 视觉状态必须正交

每个日期格至少区分：

1. `inVisibleMonth`
2. `hasMeal`
3. `selected`
4. `enabled`（由 consumer policy 决定）

**hasMeal marker 不能因为 selected 消失。**

推荐：
- hasMeal：保留食历现有 5dp primary dot；
- selected：使用独立 container/outline/shape 表达；
- selected + hasMeal：两者同时可见；
- out-of-month：弱化且不可点。

不要求新设计另一套颜色体系；优先保持食历原视觉。

## 4. STEP

### STEP-DC-1 — 抽共享 Calendar
从 `FoodTimelineScreen.kt` 移出私有 Calendar 实现到共享 component。
Timeline 调用：
- `mealDates = state.mealDates`
- `initialDate = DateTime.today()`
- `selectedDate = null`
- `selectionMode = MEAL_DATES_ONLY`

**Timeline 原行为不得变化：只有有餐食的日期可点击跳转。**

### STEP-DC-2 — AddMealViewModel 订阅同一 mealDates truth

`AddMealUiState` 增加：

```kotlin
val mealDates: Set<LocalDate> = emptySet()
```

`AddMealViewModel` 在生命周期内收集：

```kotlin
mealRepo.observeTimelineDates()
```

并更新 `state.mealDates`。

要求：
- 不建立逐日 `loadDayMealsForEdit` 扫描；
- 不新增 repository API；
- 不影响 `sigNow()/isDirty()`：mealDates 是只读环境数据，不计入表单 dirty signature；
- repo flow 更新时 UI 自动刷新 marker。

已有 `datesWithMealsInWeek()` 暂不因本任务重构；它属于 AI 周期上下文，避免扩大范围。

### STEP-DC-3 — 删除 quick chips
`AddDayFoodScreen.kt`：
- 删除 `quickDates`
- 删除 “昨天/今天/明天” FilterChip Row
- 清理仅因此不再使用的 imports
- 不在日期文本上追加“今天/昨天/明天”相对词

编辑既有日期 (`isEditingExisting`) 的纯文本锁定行保留。

### STEP-DC-4 — Replace DatePicker
新增/复制场景的日期按钮点击仍打开 dialog，但 dialog 改为共享：

```text
MealDateCalendarDialog
  mealDates = state.mealDates
  initialDate = state.date
  selectedDate = state.date
  selectionMode = ANY_VISIBLE_DATE
```

onDateClick：
- 仍只调用 `vm.setDate(date)`
- 关闭 dialog 的时机可沿用当前“一次点击后关闭”
- occupied 被 VM 拒绝时当前 date 不变，原 warning 保留

不要在 UI 再实现第二套 occupied 业务判定来替代 VM。

### STEP-DC-5 — Preserve e927 AF01
修改 `AddDayFoodScreen.kt` 时必须确认：
- `bottomBar = FormBottomBar(...)` 仍不受 `embedded` 条件限制；
- Single+Manual 保存 CTA 在 Unified 中仍可见。

## 6. Tests / evidence

### Unit / pure
优先把月历网格/selection policy 中可纯函数化的逻辑做 internal 单测：
- month grid 42 cells / Monday-first
- `MEAL_DATES_ONLY`：无 meal 不 enabled
- `ANY_VISIBLE_DATE`：in-month date enabled，不因 hasMeal 改 UI selection policy
- out-of-month disabled

若项目当前没有 Compose test 基建，不为了本功能引入新依赖；UI 视觉走真机 evidence。

### ViewModel
若现有 repository test/VM test 基建可直接覆盖：
- `observeTimelineDates()` emission → `state.mealDates`
- mealDates emission 不影响 dirty signature

禁止为此新增 global replace/fake 后门。

### Device evidence
- **E-DC-01**：Single+Manual 日期区无昨天/今天/明天。
- **E-DC-02**：月历视觉与食历一致；打开当前月份能看到已有餐食日期 marker。
- **E-DC-03**：未点击 marker 日期前就能分辨哪些天已有餐食。
- **E-DC-04**：空日期可选择；当前日期 selected 明显。
- **E-DC-05**：点已有餐食日期，日期不切换，原“去食历编辑”提示仍有效。
- **E-DC-06**：返回食历打开月历，原 meal-only navigation 行为无回归。
- **E-DC-07**：Single+Manual 选菜后保存 CTA 可用并能完整保存（AF01 交叉回归）。
- **E-DC-08**：深色/浅色下 dot 与 selected 都可辨识。

## 7. Scope guard

明确不做：
- 点击已有餐食日期直接进入编辑；
- 改成“追加到已有日期”；
- 改动 save/move semantics；
- 删除 dateWarning；
- 改默认新建日期算法；
- 重写 FoodTimeline 分页；
- 新增 Material3 DatePicker 依赖/升级。
