# 换一换/切风格/切餐次/切窗口/药膳 · 缓存与成本策略方案

> [AI生成] 2026-07-19 ai_engineer 会商。现状:每个操作都全量 gather(18-22 SQL)+调云端。会诊定位每类操作真正改了什么→分层缓存。

## 归因(每类操作真正改变什么)
| 操作 | 真改了什么 | 现状 | 应该 |
|---|---|---|---|
| 药膳过滤 | **啥都没改**(纯VM本地重排 mapResult) | 全量gather+云端 | 🔴纯本地重排·一次SQL/云端都不该有 |
| 换一换 | 仅 rotation(gather输入不变) | 全量gather+云端 | 复用gather·只重orchestrate(云端可选) |
| 切风格 | style(打分权重+画像取数分支) | 全量gather+云端 | 多数只需重评分·个别补2-3查 |
| 切餐次 | mealSlot(改候选集本身) | 全量gather+云端 | **必须重gather** |
| 切窗口 | recentWindowDays(改基线) | 全量gather+云端 | **必须重gather** |

**核心：只有切餐次/切窗口真改候选集必须重 gather。药膳/换一换/多数切风格都不必。**

## 落地分批
### 🔴第一批(零风险纯赚·先做)
**药膳本地重排**：VM 缓存上次 `RecommendationResult`，`setMedicinalFilter` 只重跑 `mapResult` 排序，不 gather 不云端。省 18-22 SQL+1云端往返+瞬时响应。

### 🟡第二批(主体收益)
- **gather 结果缓存 + 失效键** `InputKey(mode,slot,window,风格取数形状,dataVersion)`：换一换/同形状切风格复用 gather。**失效**：切餐次/切窗口/切mode/踩菜。
- **换一换均衡档**(见拍板C)：首次云端预取多批(让模型基于前20-30候选给3-4组)→前几次换一换本地轮播+规则rotate兜底(永远换得动)→用尽才再调云端。
- **画像/GI/调料缓存**(性能地图痛点#1/#2/#5)：让"必须重gather"也便宜。

### ⚪第三批(可选彻底解耦)
- style 移出 gather 到 orchestrate 入参 + gather 去 style gate → 切风格永不 gather(纯搬移·风险低)。
- JSON模式+glm-4.5-flash(前置增强·让预取多批更可靠)。

## 失效脏读守卫
- 主风险=缓存脏读。守卫：`setDisliked` 立即失效(踩菜是唯一本页强预期即时反映)；记一餐/改库存在别页发生·遵循已定"仅手动刷新"不自动反映(可接受)。
- 忌口正确性不受影响(过滤在 evaluate/selectable 代码层每次重跑·缓存只是 gather 原始输入)。
