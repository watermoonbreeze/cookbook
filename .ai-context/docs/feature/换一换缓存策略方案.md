# 换一换/切风格/切餐次/切窗口/药膳 · 缓存与成本策略方案

> [AI生成] 2026-07-19 ai_engineer 会商。现状:每个操作都全量 gather(18-22 SQL)+调云端。会诊定位每类操作真正改了什么→分层缓存。

## 归因(每类操作真正改变什么)
| 操作 | 真改了什么 | 现状 | 应该 |
|---|---|---|---|
| 药膳过滤 | **啥都没改**(纯VM本地重排 mapResult) | 全量gather+云端 | 🔴纯本地重排·一次SQL/云端都不该有 |
| 换一换 | 仅 rotation(gather输入不变) | 全量gather+云端 | 复用gather·只重orchestrate(云端可选) |
| 切风格 | style(打分权重+画像取数分支) | 全量gather+云端 | 多数只需重评分·个别补2-3查 |
| 切餐次 | mealSlot(改候选集本身) | 全量gather+云端 | **必须重gather** |
| 切窗口 | recentWindowDays(改基线) | 全量gather+云端 | **必须重gather** |

**核心：只有切餐次/切窗口真改候选集必须重 gather。药膳/换一换/多数切风格都不必。**

## 落地分批
### 🔴第一批(零风险纯赚·先做)
**药膳本地重排**：VM 缓存上次 `RecommendationResult`，`setMedicinalFilter` 只重跑 `mapResult` 排序，不 gather 不云端。省 18-22 SQL+1云端往返+瞬时响应。

### 🟡第二批(主体收益)
- **gather 结果缓存 + 失效键** `InputKey(mode,slot,window,风格取数形状,dataVersion)`：换一换/同形状切风格复用 gather。**失效**：切餐次/切窗口/切mode/踩菜。
- **换一换均衡档**(见拍板C)：首次云端预取多批(让模型基于前20-30候选给3-4组)→前几次换一换本地轮播+规则rotate兜底(永远换得动)→用尽才再调云端。
- **画像/GI/调料缓存**(性能地图痛点#1/#2/#5)：让"必须重gather"也便宜。

### ⚪第三批(可选彻底解耦)
- style 移出 gather 到 orchestrate 入参 + gather 去 style gate → 切风格永不 gather(纯搬移·风险低)。
- JSON模式+glm-4.5-flash(前置增强·让预取多批更可靠)。

## 失效脏读守卫
- 主风险=缓存脏读。守卫：`setDisliked` 立即失效(踩菜是唯一本页强预期即时反映)；记一餐/改库存在别页发生·遵循已定"仅手动刷新"不自动反映(可接受)。
- 忌口正确性不受影响(过滤在 evaluate/selectable 代码层每次重跑·缓存只是 gather 原始输入)。

## 待用户拍板
- **拍板C(最关键·用户口味)**：换一换新鲜感档位——**省钱档**(纯本地轮播·完全不再联网·最省但组合有限) / **均衡档(推荐)**(首次预取多批+本地轮播+用尽再联网·省大部分调用·新鲜够用) / **新鲜档**(每次联网·最贵·且需调高temperature=0.7~0.9否则同prompt返相近组合花钱换不出花样)。
- 拍板A：换一换失效范围——①仅踩菜失效(推荐·合"仅手动刷新") / ②全写路径(需dataVersion)。

## 第二批会诊修正（2026-07-19 · algorithm_engineer + ai_engineer 双镜头·实现前必读）

> 第二批(gather缓存+均衡档预取)动核心编排，两方会诊揪出**1条红线级错误假设 + 若干设计缺口/代码前置**。原文上方 §落地分批 第二批的乐观描述需按此修正。

### 🔴 红线级（必先解决，否则忌口可能被推进这一餐）
1. **忌口输入绝不能随 gather 缓存复用**（推翻原文"忌口正确性不受影响"的结论·该结论错）：`gather` 里 `constraints`(avoid/limit/recommend/personalAvoid) 由 `familyRepo.allEnabledCareIds()`/`allPersonalAvoidCategoryIds()` 算，来自**健康档案页/成员页**(别页)。若那里新增忌口后回推荐页点换一换、命中旧 `cachedInput`，则 `input.constraints` 是旧的 → evaluate 算出的 `avoidNames` 是旧的 → orchestrator 第57行 `selectable` 过滤/fallback 用的是旧 avoidNames → **一道该忌口的菜被推进这一餐**。「过滤每次重跑」≠「过滤用最新忌口」。
   **改法(推荐)**：忌口/limit/recommend 相关取数**不进缓存**，每次 recommend **轻量重取**(`allEnabledCareIds`+`listByCare/Categories`，仅3-4条 SQL·远小于全量22条)覆盖进 input 再 evaluate。候选集仍复用、忌口永远最新。或给 care/family 维 `careVersion`(写时 bump)进 InputKey。
2. **style 与 gather 取数同源**：`gather` 内部第169-171行**自读 DB 的 RECOMMEND_STYLE**(签名无 style 参数)，而缓存 Key 用 VM 侧 styleName。二者须强绑定，否则误判命中复用"按旧 style 取数"的 gather。**建议把"style 移出 gather、作显式参数传入"从第三批提前到第二批**(纯搬移·顺带消除该结构性隐患)。

### 🔴 代码前置（均衡档"稳定一次返多组"的前提·优先级高于 prompt 措辞）
3. **关闭 GLM-4.5-Flash 默认思考**：该模型默认开动态思考，思考链吃输出 token 预算 → 要它一次返 9 组 JSON 极易在数组没闭合处被截断(正是"少返/坏格式"根因)。`GlmProtocol.buildRequestBody` 加 `thinking:{"type":"disabled"}`(可选参数·null 不序列化兼容他厂)，并**显式设 `max_tokens`≈1500**(须在关思考之后设)。
4. **预取走独立校验路径·别复用 validate**：`RecommendationOrchestrator.validate` 第89行 `.take(mealCount=3)` 会把预取的 9-12 组**当场砍到3组**→预取进不了缓存；且只去组内重复(distinct)、不去组间重复。预取需：`take(prefetchGroups)` + **组间去重**(dishIds.sorted() 为 key 完全去重 + Jaccard≥0.8 近似去重·复用已有 jaccard) + **不足目标组数用本地 rotate/fallback 补足**。

### 🟡 设计缺口（原文未覆盖·实现前补清）
5. **两视图换一换如何联动**：flat 候选列表(dishItems·按 rotate 分批10个) 与 云端组合(suggestionGroups·模型基于20-30池跨批生成) **分页语义不同**、无法用同一指针对齐。建议**以"组合段"为换一换主轴**(均衡档核心价值=云端组合多样性)，flat 跟随当前段所涉候选补齐到10展示。
6. **RANDOM 分叉**：RANDOM 模式 rot 是随机数(rotation 不自增)，与"顺序推进预取指针"冲突，且顺序轮播削弱"随机=每次不同"心智。**均衡档预取只对 PANTRY，RANDOM 保持每次随机 rot**(是否联网看档位)。
7. **降级链(永远换得动)**：云端返 0 组/纯 fallback → 均衡档自动降级为本地 rotate 轮播(等同省钱档·不报错)；`selectable` 空(全忌口)或候选空 → **跳过预取**、退化为标红全列表、换一换禁用；候选不足一批(≤10) → 换一换按钮禁用+提示"已无更多·去添加菜品/放宽去重周期"。`fallback` 的 `repeat(mealCount)` 改 `repeat(prefetchGroups)` 让本地兜底也够轮播。
8. **失效点清单要列全**：切餐次/窗口/风格/mode/踩菜/健康档案变更/**手动刷新丢弃预取重取**/seed 更新(dataVersion)/**跨自然日**(近吃标签陈旧·缓存带日期戳跨日失效)——每个失效点须**同时**清 cachedInput+cachedResult+预取指针+预取组(别只清一个)。

### 参数取值（会诊建议·pending 待埋点校准）
- 预取甜点区 **9 组**(=3屏×3组·覆盖3次换一换·输出安全区)，"最低可用"3组即先展示；候选池 **20** 道(非30·token 性价比拐点)；temperature **0.6**(JSON mode 高温易坏格式·多样性下限靠代码去重+补足保证不押注温度)。
- prompt 组间差异给**量化约束**(同主料最多现2-3组·荤素/菜系/做法交替·越靠后越换口味)，**不预分组候选**(留模型组合自由度·MMR 已兜底)。

> 一句话：性能思路成立，但**忌口 constraints 随缓存复用是唯一红线错误**必先解决；其次两视图联动、RANDOM 分叉两处设计缺口，以及关思考、预取独立校验两处代码前置。实现顺序：先做子步骤1(gather候选缓存·忌口重取)→再做子步骤2(关思考+独立预取校验+均衡档)。
