# MEAL-SEMANTICS-01：餐食事实、计划、摄入与库存语义

> 状态：**DECIDE**；不授权 schema 改动、库存自动扣减或日期驱动的状态迁移。  
> 覆盖：J2、J7、K13、战略会商-6729、P5-B 与 R5 的已吃/未吃前置。

## 1. 当前事实

| 维度 | 当前实现证据 | 缺口 |
|---|---|---|
| 摄入比例 | `meal_record_dish.eaten_ratio` 可按菜或整餐更新，并被今日卡观察令牌读取。 | 不能表达“计划未吃”“外食”“给他人做/成员份额”。 |
| 计划/历史 | 同一 `meal_record`/日期读模型承载未来计划与历史；存在“日期到达即成为事实”的语义风险。 | 无显式事实状态和状态变迁审计。 |
| 库存 | `selectPantryUsageChrono` 将餐食/计划按时间计算派生占用。 | 计划占用、实际消耗、撤销、外食和补录的幂等关系未冻结。 |
| 成员 | 健康/统计已有成员视角，但摄入比例不是 per-member-per-dish。 | J2 需要更细粒度数据模型，不能靠 UI 局部 state 伪造。 |
| Repository | P5-A 仅收敛 mutation；P5-B 尚未 reality review。 | 不得借语义改造删除兼容读 API 或提前进入 Phase 6。 |

## 2. 必须先决策的状态机

最小候选状态：`PLANNED`（意图）、`CONSUMED`（事实）、`SKIPPED`（明确未吃）、`OUTSIDE_MEAL`（不挂家庭库存的事实）、`CANCELLED`（撤销计划）。是否需要这些字段、迁移旧记录与用户默认值，均需 ADR；当前不得从日期自动推断 `CONSUMED`。

| ADR | 冻结问题 | 不变量 |
|---|---|---|
| ADR-MS-01 旧记录迁移 | 既有无状态记录如何解释：历史日期、未来日期、已调 eaten ratio、同步/备份记录。 | 不默默把用户历史改为“吃完”；迁移可回滚、可审计。 |
| ADR-MS-02 库存结算 | 计划是否只占用提示、何时实际扣减、外食/跳过/撤销如何返还。 | 日期推进不产生写入；任一实际结算幂等且用户可见。 |
| ADR-MS-03 成员摄入 | 是否引入 per-member-per-dish，未分配时怎样展示个人/全家营养。 | 不把总餐量重复计入每个成员；分配可编辑且和总量一致。 |
| ADR-MS-04 非家庭用餐 | 属性属于菜品、餐次菜实例还是成员事件。 | 不用菜品全局 flag 覆盖同一菜在不同餐的真实情境。 |

## 3. 后续批次顺序

1. `MEAL-STATE-ADR-01`：全读写路径、备份/同步、报告、推荐、库存依赖图与迁移方案；无代码。
2. `MEAL-STATE-SCHEMA-01`：在 ADR 接受后只建字段、迁移、Repository 原子 API 与固定迁移 fixture。
3. `PANTRY-SETTLEMENT-01`：从显式 `CONSUMED` 事件派生库存结算；计划仅作可见占用，不写库存。
4. `MEMBER-INTAKE-01`：如 ADR 通过，单独引入成员摄入份额、总量校验、报告与历史兼容。
5. `OUTSIDE-MEAL-UX-01`：经 UX 定义后呈现“非家庭用餐/不扣库存”，不得改变健康/营养事实。
6. P5-B 必须在上述语义完成或明确排除后另行 reality review；Phase 6 始终受禁令约束。

## 4. 验证合同

- 迁移：空库、旧历史、旧未来、已调 `eaten_ratio`、软删、备份恢复和双端同步样本。
- 状态：每一合法/非法转换；重复点击、进程重启、撤销、补录过去日期均幂等。
- 库存：计划、吃完、部分吃、未吃、外食、取消、补录按日序混合；断言不重复扣/返。
- 成员：未分配、单成员、多人比例和为 1、成员删除/新增、个人与家庭汇总。
- 回归：今日卡、食历、周计划、推荐、报告与库存钩子在状态缺失时诚实降级。

## 5. 禁止事项

- 禁止 `date <= today` 自动写“已吃”或自动消耗库存。
- 禁止把 `eaten_ratio=0` 当作未吃状态或以 null/0 混淆计划与事实。
- 禁止将非家庭用餐做成菜品永久属性。
- 禁止在 P5-B reality 前重构 Repository 内部兼容行为。
