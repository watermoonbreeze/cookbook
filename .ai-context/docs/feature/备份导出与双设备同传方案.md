# 备份导出与双设备同传方案

> [AI生成] 2026-07-09。承接 P0 存储合规（数据已入 app 专属目录，用户不可直接访问）。
> 现状：备份仅本地——`BackupManager` 在 app 专属 `backups/` 建/列/恢复/删，**只备 DB、不含图片**，用户在文件管理器看不到。
> 目标：完整可携带备份 + 导出/导入 + 局域网双设备同传。

## 关键前提：图片改相对路径（第一期先做）
- 现状：`image_path`/`thumbnail_path` 存**绝对路径**（`ImagePickerButton` 存 `imageFile.absolutePath`，`StoredImage` 用 `BitmapFactory.decodeFile`）。
- 问题：① 只备 DB 丢照片；② 绝对路径跨设备/跨安装失效。
- 改法：写入只存**文件名**（如 `20260709xxx.jpg`）；`StoredImage` 读取时 `CookbookStorage.requireSubDir(IMG)/文件名` 解析；`content://`/`android.resource://` 等非文件 URI 原样透传（兼容 seed 资源图）。
- 开发阶段无历史数据，无需 DB 数据迁移（新写即相对）。**注意**：这是双设备同传能用的基础。

## 第一期：完整备份 + SAF 导出/导入
1. **完整备份包（zip）**：`backup_yyyyMMdd_HHmmss.ckbk`（zip），含
   - `cookbook.db`（+ wal/shm checkpoint 后）
   - `img/` 全部图片与缩略图
   - `manifest.json`：`{app, schemaVersion, createdAt, dbName}` 供导入校验/版本兼容判断
   - 用 `java.util.zip`，无三方依赖。
2. **本地备份仍在** app 专属 `backups/`（快照/回滚），但升级为 zip（含图片）。
3. **SAF 导出**：`ActivityResultContracts.CreateDocument("application/octet-stream")` → 把选中 zip 写到用户位置（下载/网盘/U盘）。
4. **SAF 导入**：`ActivityResultContracts.OpenDocument` 选 `.ckbk` → 校验 manifest（schemaVersion 不高于当前）→ 关库 → 覆盖 db + 释放 img → 提示重启。
5. UI：`我的-本地备份与恢复` 弹框加「导出」（每条备份右侧）与「从文件导入」按钮。

## 第二期：局域网同传（同 WiFi 直传）
- **形态**：发送端起临时 HTTP 服务（`ServerSocket`，端口如 8969），生成 zip 到内存/临时文件；接收端输入 `IP:端口 + 4位校验码`（或扫二维码）拉取并导入。
- **实现**：优先**纯 `ServerSocket`/`Socket` + 极简 HTTP**（零依赖，只传一个 zip 流）；如需健壮再评估 NanoHTTPD/Ktor。
- **权限**：`INTERNET`/`ACCESS_NETWORK_STATE` 已有；读本机 IP 用 `WifiManager`/`NetworkInterface`。二维码可选（发送端出码=`ip:port:code`，接收端扫）。
- **流程**：发送端点「发送到另一台设备」→ 打完整 zip → 起服务显示 IP+码/二维码 → 接收端「从另一台设备接收」→ 连接拉流 → 校验 → 导入 → 双方结束关服务。
- **约束**：仅同一局域网；超时/断连要能取消并清理临时文件与服务端口。
- **安全**：临时随机端口 + 一次性校验码防误连；传输内容是本地数据、局域网内，风险可接受。

## 落地顺序
1. 图片相对路径重构（+ 单测/构建）。
2. 完整 zip 备份（BackupManager 升级）+ 本地备份 UI 适配。
3. SAF 导出/导入 + UI。
4. 局域网同传（发送/接收 + IP/码/二维码 + 清理）。
5. 真机验证：导出→导入同机、A→B 跨机、局域网直传。
