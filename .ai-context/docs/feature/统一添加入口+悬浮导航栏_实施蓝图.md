## 3. 审核结论摘要（先看这个）

对两份外部产出做了代码级审核（实读 `AiMealInputSheet.kt`/`AiMealInputViewModel.kt`/`AddDayFoodScreen.kt`/`WeekPlanScreen.kt`/`UnsavedGuard.kt`/`MainScaffold.kt`/`Destinations.kt`），结论：**产品模型（2×2矩阵）、悬浮栏dp规格、"只统一新建入口"范围判断，全部准确，直接采纳**。但**外部产出 B 的状态管理部分建立在一个不成立的假设上**——"四个 Body 各自独立、需要各建一份 Draft 状态"，实际代码里 AI 相关的两个 Body（单天AI/周期AI）**本来就是同一个 ViewModel、同一份 State**，不需要（也不应该）拆成两份。下面 §4-6 详细说明，**实现时以本节为准，不要机械套用"singleAiState/periodAiState 两份独立状态"的说法**。

另发现一个外部产出没考虑到的真实约束：AI 解析有"生成中"这个异步阶段，"Mode 切换任何时候都不弹确认、不影响后台任务"的假设在生成中切换 Range 时不成立，见 §6。

## 4. 已验证的现有代码事实

### 4.1 AI Body（单天AI + 周期AI）本来就是一个 ViewModel

`AiMealInputViewModel`（`androidApp/.../ui/ai/AiMealInputViewModel.kt`）的 `AiMealInputUiState`（约102-159行）已把"快速记草稿"和"周期记草稿"存成**两个独立字段**，同属一个 State：

```kotlin
data class AiMealInputUiState(
    val inputMode: InputMode = InputMode.QUICK,   // 只是"当前显示哪个"的选择器
    val phase: AiMealPhase = AiMealPhase.INPUT,    // 全局阶段机，不分 quick/period
    val quickDraftText: String = "",               // 单天AI草稿，切 inputMode 不清空
    val periodInputs: Map<Int, String> = emptyMap(), // 周期AI草稿(0..6=周一..周日)，切 inputMode 不清空
    ...
)
```

`setInputMode(mode)` 只切换 `inputMode` 显示哪块 UI，两个草稿字段互不影响（代码注释原文："B4: 快速记草稿（切换模式保留）"）。

**结论**：统一入口的 `SINGLE_DAY+AI` 和 `PERIOD+AI` 两格，**必须复用同一个 `AiMealInputViewModel` 实例**，Range 在 AI 方式下的切换 = 调用 `vm.setInputMode(InputMode.QUICK / InputMode.PERIOD)`。

### 4.2 AI Body 的 `phase` 是全局的，不区分 quick/period

`AiMealInputSheet` 顶层按 `state.phase` 分发（`AiMealInputSheet.kt:174-192`）：`INPUT → GENERATING/PARTIAL_READY → PREVIEW_READY → SAVING → DONE`，`ERROR` 单独分支。**Range/Method 切换控件只在 `InputPhase` 里渲染**（`AiMealInputSheet.kt:198` 起）——一旦进入 `GENERATING`，没有回到"选择模式"的 UI 路径。

现有代码已处理"生成中/预览中想关闭 Sheet"的场景：`AiMealInputSheet.kt:141-161`，`showDismissConfirm` 弹窗 + `vm.cancelGeneration()`，触发条件是 `state.phase in [PARTIAL_READY, PREVIEW_READY]`（`SAVING` 时忽略关闭）。

**结论**：见 §6，统一页面的 Range/Method 切换器需要复用这套"生成中/预览中切换=需要确认放弃"的既有逻辑。

### 4.3 单天手动（`AddMealViewModel`）已有现成的 Dirty 概念

`AddDayFoodScreen.kt:157` 用 `koinViewModel()` 拿 `AddMealViewModel`；`AddDayFoodScreen.kt:191-192`：

```kotlin
val requestBack = com.sxdbsm.cookbook.android.ui.component.rememberUnsavedGuard(
    isDirty = { vm.isDirty() },
    ...
)
```

**结论**：`SINGLE_DAY+MANUAL` 格的 Dirty 判断直接复用 `vm.isDirty()`。

### 4.4 `rememberUnsavedGuard` 内部自带 `BackHandler`，只能在页面里调用一次

`UnsavedGuard.kt:27-34`：

```kotlin
fun rememberUnsavedGuard(
    isDirty: () -> Boolean,
    onConfirmLeave: () -> Unit,
    dialogText: String = "你的改动还没保存，返回将丢失。",
): () -> Unit {
    ...
    BackHandler(enabled = true) { requestBack() }
    ...
}
```

**结论**：抽取出的 Body Content 组件（`SingleManualContent` 等）必须去掉这个调用，改由 `UnifiedAddMealScreen` 顶层统一调用一次。原 `AddDayFoodScreen`（保留给"编辑某天"等直达入口用）继续保留自己的调用不受影响。

### 4.5 `PERIOD+MANUAL`（`WeekPlanScreen`）没有"草稿"概念

`WeekPlanScreen.kt` 全文159行：删除走软删+撤销 Snackbar，复制/编辑都是跳转到别的页面，本页自身**不持有任何未保存的表单状态**。

**结论**：Unified 页面的总 Dirty 判断实际上是三路，不是外部产出说的四路：

```kotlin
val hasUnsavedChanges =
    (aiVm.state.value.let { it.phase != AiMealPhase.INPUT || it.quickDraftText.isNotBlank() || it.periodInputs.values.any(String::isNotBlank) }) ||
    singleManualVm.isDirty()
    // periodManual（WeekPlanScreen）无 Dirty 概念，不参与判断
```

```text
    val range: MealRange = MealRange.SINGLE_DAY,
    val method: MealInputMethod = MealInputMethod.AI,

enum class MealRange { SINGLE_DAY, PERIOD }
enum class MealInputMethod { AI, MANUAL }
```

Range/Method 切换事件的真实映射：

| 事件 | 目标格 | 真实动作 |
|---|---|---|
| `range=SINGLE_DAY, method=AI` | 单天AI | `aiVm.setInputMode(InputMode.QUICK)` |
| `range=PERIOD, method=AI` | 周期AI | `aiVm.setInputMode(InputMode.PERIOD)` |
| `range=SINGLE_DAY, method=MANUAL` | 单天手动 | 渲染 `SingleManualContent(singleManualVm)`，不动 `aiVm` |
| `range=PERIOD, method=MANUAL` | 周期手动 | 渲染 `PeriodManualContent`，不动 `aiVm`/`singleManualVm` |

`method=MANUAL` 时 `aiVm` 只是"不显示"，不销毁不暂停，`state` 天然保留——**靠"不销毁 VM 实例"天然做到，不需要额外的 Draft 快照/恢复机制**。

## 6. Range/Method 切换的真实约束（外部产出未考虑，本节新增）

外部产出假设"任何时候切换 Range/Method 都无条件保留状态、不弹确认"。这对 `MANUAL` 方向成立，但对 `AI` 方向不完全成立：

- **`aiVm.state.phase == INPUT` 时**：自由切换 Range/Method，无需确认，草稿保留。
- **`aiVm.state.phase != INPUT`**（`GENERATING`/`PARTIAL_READY`/`PREVIEW_READY`/`SAVING`）**时**：
  - `SAVING`：禁止切换（选择器置灰不可点，复用现有"SAVING 中忽略关闭"逻辑）。
  - `GENERATING`/`PARTIAL_READY`/`PREVIEW_READY`：允许切换，但弹与现有 `showDismissConfirm` 语义一致的确认框（"AI 已解析的餐食预览将不会被保存"），确认后调用 `vm.cancelGeneration()` 再切换；取消则停留原状态。这是复用既有对话框逻辑（原挂在"关闭 Sheet"），扩展触发条件到"切走 Range/Method"，不是新增一套确认语义。

`method=MANUAL` 方向和 `range` 在 `MANUAL` 下的切换，维持"无条件不确认"结论不变。
