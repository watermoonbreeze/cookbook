# R10：统一真机回归与旗舰验收蓝图

> 状态：**READY（末期执行）**。R10 不是编码批，也不替代各批自动化验收；它在所有已实施批次通过旗舰代码复核后，统一闭合设备证据。

## 1. 唯一真相源与启动条件

- 唯一清单：`.ai-context/docs/真机验证/` 下时间戳最新的 `真机待验证清单_*.md`。当前基线为 `真机待验证清单_202608272229.md`；新增条目只能更新该文件并改名为新时间戳，禁止创建并行清单。
- 启动前，每个相关批次必须具备：L7 实现蓝图、`TURN=REVIEW` 或 `ACCEPTED`、对应自动化证据、旗舰 REVIEW 结论、明确的 `DEV-` 编号。
- 纯文档、研究、ADR 和 PARKED 项不创建真机条目。

## 2. 设备回归顺序

1. R1 已交付餐食入口：UEN、日期、首页合并等遗留 `PENDING_DEVICE_VERIFICATION` 项。
2. R2 AI 记餐：同意、取消、流式、超时、规则回退/诊断（仅实施且 ARCH 接受的子批）。
3. R3–R6 数据、健康、推荐、餐食语义：迁移/恢复、核心路径、无网降级和历史兼容。
4. R7 UI：大字体、TalkBack、横竖屏、手势导航、深浅色及入口回退。
5. R8 AI 扩展：本地映射、确认预览、离线/隐私与设备性能；只覆盖实际落地的子批。

失败必须回流到来源批次的 Q/AF 台账，不得临场扩展需求或将未实施事项标为通过。

## 3. 每个 DEV 条目的可复核记录

| 必填字段 | 内容 |
|---|---|
| 环境 | 设备型号、Android/iOS 版本、安装包 SHA、网络/权限状态 |
| 操作 | 可由另一位测试者复现的前置、步骤与输入 |
| 预期 | 用户可见现象或可搜索日志文本；不得使用未暴露的内部计数 |
| 证据 | 截图/录屏/日志路径及时间；敏感信息必须脱敏 |
| 结论 | PASS、FAIL 或 BLOCKED；FAIL 必须关联来源批次和 AF/Q |

## 4. 旗舰最终验收顺序

1. 从每个批次蓝图的“ID → 文件/符号 → 测试 → commit”映射反查真实 diff 与 allowlist。
2. 复跑该批 L0/L1 命令和 feature sync；不接受历史口述或旧 CI 结果代替当前证据。
3. 核对所有 `INV`、挑战台账、Q/AF、同意/取消/迁移/回滚边界；阻断项必须回 CODE 后重新验收。
4. 汇总已通过的 DEV 证据；最后一个相关 DEV 关闭后才能把批次标为运行时通过。
5. 更新全景图、功能纵轴、会话交接与经验册；再由用户决定是否推送或切换模型。

## 5. 不变量

- 自动化通过不等于设备通过；设备通过也不能覆盖未通过的自动化或旗舰审查。
- 一个批次只关闭自己产生的 DEV 条目；不得用相似页面或旧包截图替代。
- 任何健康、隐私或数据迁移问题优先保证不错误写入与可恢复，再讨论体验优化。
