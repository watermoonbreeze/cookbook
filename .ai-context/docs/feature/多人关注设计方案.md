# 家庭档案·同时关注多人 — 产品 + 交互方案

> [AI生成] 2026-07-18 Apple-UX（UX 产品经理身份）产出。当前单关注，本方案设计"多关注"。
> **定位**：跨切面大重构（>15 文件·高风险），**零 schema 迁移**、下游靠 `resolveViewing` 收口降险。
> **状态**：⏸ **方案待用户确认 5 个拍板项后**再进入实现门禁（Apple-UX 布局细则 → 编码 → Google 审查）。

## 现状架构（单关注真相源）
- 数据：`family_member.is_focus` **单选**（`clearAllFocus`+`setFocusMember` 保唯一）；`pickFocus()` 兜底 `isFocus→isSelf→first`。
- 消费点全围绕"这一个人"：`observeFocusBody`(今日卡/报告目标)、`observeFocusShare`/`observeFocusShareForDate`(份额)、`observeFocusName`(昵称)、`focusConditions`(HomeVM 今日卡慢病提示)、报告 personal 视角(share/body-target/name)。
- **不受影响**：忌口/病种 `allEnabledCareIds()` 已是**全家并集**，本方案不动。色系墙纯膳食结构，不动。

## 一、产品结论
**做"多选关注 + 一个'当前查看'指针"，不做"全合并聚合"。**
- 家庭真实场景 = "夫妻俩都三高，想**分别**盯各自达标/慢病"→诉求是看清每个人，非把热量加总。
- 聚合无意义且危险：热量/钠/份额是"个人身体×个人饭量系数"概念，A+B 合计不对应任何人达标、易误读（碰健康免责红线）。
- 家庭 app 少操作：关注多人只是"看时切个人"的低频动作，别做成多选管理后台。

**一句话**：把"设为唯一关注"升级为"加入我关注的人"，看数据时在关注的几人间**一键切换**（非聚合）。

## 二、关注模型（数据语义）
| 项 | 现状 | 新 |
|---|---|---|
| 关注标记 | `is_focus` 唯一 | `is_focus` **可多个=1**（关注集合，约束**至少 1 人**，软上限 6） |
| 当前查看 | 无（关注即查看） | **新增 `focusViewingMemberId` 指针**，存**偏好 JSON（零迁移）** |

- `resolveViewing(members)`：`viewingId∈关注集合→用它`；否则回退关注集合首位(按 sort)；集合空→`isSelf/first`。指针失效自愈。
- **今日卡与报告共用同一指针**，一处切两处同步。
- `pickFocus()` 语义 → "当前查看人"：`observeFocus*` 内部把 `pickFocus` 换 `resolveViewing`，**签名不变、下游几乎不动**（最小改动关键）。
- **⚠️ 零 schema 迁移**：`is_focus` 唯一→可多**不改表**(列已存在，只是不再 `clearAllFocus`)；指针走偏好 JSON。本 MVP **无 `.sqm`**——刻意压低跨切面重构风险。

## 三、各消费点展示（复用 §九）
- **今日卡**：1 人=**维持现状零变化**；≥2 人=顶部**可滚成员切换 chip 行**（§9.18 可滚不均分胶囊，选中实心/未选描边），点即切指针、整卡换该人视角（热量/宏量/达标/concerns）。**不轮播不聚合**（chip 显性看全"有几人+当前谁"）。
- **报告个人视角**：保留现有 `SegmentedControl(家庭/个人)`；"个人"分支 ≥2 人加成员切换器（2~4 人 `SegmentedControl`、>4 可滚 chip），改同一指针。**不做两人对比**(二期)。空态文案微调。
- **身体数据/达标/目标**：一律按当前查看人算(`resolveViewing` 的 body)。设置"我的每日热量目标"快捷编辑仍走 `updateSelfBody`(永远改"我")，与查看指针解耦。
- **份额**：语义不变，"关注成员"→"当前查看人"；仍是**单人÷在场和不累加**（看张伟就是张伟份额）；当前查看人当天缺席→share=0 今日卡不显。

## 四、家庭页关注管理 UI（单选星标→多选）
- 星标语义"设为唯一关注"→"加入/移出我关注的人"，**点即切、可多个亮**(去 `clearAllFocus`)；新增 `toggleFocus(id)`。保留星标图标(家庭页"星=我盯的人"直觉成立)。
- **约束至少 1 人**：取消最后一个→snackbar"至少关注一位家人"拒绝。
- **职责划分（推荐）**：**家庭页只管"关注谁"**，"当前看谁"交给今日卡/报告的切换器(天天用)。家庭页低频配置页不塞"在看"切换，避免两处都能切造成困惑。
- 顶部说明更新："关注的家人会出现在今日营养卡和报告里，可关注多位、看时一键切换。忌口按全家合并。非医嘱，仅供参考。"
- **新范式(单选→多选+新切换器)按门禁实现前须 Apple-UX 出精确 dp/组件规范**。

## 五、迁移/兼容（零 schema）
1. 老库唯一 `is_focus=1` 那人 = 天然"关注集合含这一人"(size=1)；指针空→回退到他→**行为 100% 一致、老用户无感**。
2. `setFocus` 保留兼容；新增 `toggleFocus`(加/移·留1)家庭页改调。
3. `ensureInitialized` 建"我"仍 `is_focus=1` 不变。集合空兜底 `isSelf/first` 不崩。

## 六、分期
**MVP（一批·无 schema）**：`is_focus` 多选(`toggleFocus`+家庭页星标多选+留1) + `focusViewingMemberId` 偏好指针 + `resolveViewing` 收口 + 今日卡 ≥2 人切换 chip + 报告个人视角切换器 + 两处共用指针粘性默认 + 1 人时零变化。
**二期**：报告两人对比视图、今日卡关注人 concerns 汇总(谨慎守免责)、关注排序/全部关注。

## 七、⚠️ 拍板项（用户确认前不实现）
1. **产品方向**：确认"多选关注+切换查看"而非"聚合合并"。（核心）
2. **下限=1、不做 0 人全家视角**：确认。
3. **当前查看指针放偏好 JSON、今日卡与报告共用**：确认（免迁移前提；若要两处独立指针则两个 key）。
4. **`is_focus` 多选不改表结构**：确认（决定"逻辑重构"而非"schema 重构"，风险差异大）。
5. **家庭页只管关注、当前查看交给消费页切换器**：确认（职责划分）。
