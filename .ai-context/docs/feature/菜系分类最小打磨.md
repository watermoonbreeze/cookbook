# 菜品菜系分类 · 最小打磨收敛

> 2026-07-16 无人值守。经**多角色验证**（产品经理 + Apple-UX 双角色）+ Google 审查门禁。

## 一、现状盘点（探索）
菜系分类**核心已完成 ~70%**（早前 `eb0580f`/`ab1ca32`）：
- DB `dish.cuisine` 列（默认空）；预设菜 516 道 **100% 有菜系**；`Cuisines.ALL` 集中枚举（家常菜+八大菜系+西餐+其他，11 项）。
- 菜品页"菜系"Tab：左 CuisineRail 竖列 + 右按 cuisine 精确筛选。数据来源页有菜系来源标注（八大菜系公认常识·免责）。
- 底层管道全通（NewDishVM 有 cuisine 字段/setCuisine、Repo 各查询读 cuisine）。

**唯一实质缺口**：自建菜 cuisine 恒空（`ab1ca32` 决策"菜系是预设菜维度、自建菜不纳入"，故新建页无菜系选择器）→ 自建菜在菜系 Tab 选具体菜系**看不到**（可发现性问题）。

## 二、多角色验证结论（产品 + UX 高度一致）
- **不推翻 ab1ca32、不加必填菜系选择器**：让家庭为自家菜手选"川/粤菜"是伪精度必填、制造决策疲劳，违背"少必填"。管道已通，选择器留 backlog 可选增强（日后有反馈再加折叠区横滑 chips，默认家常菜不必填）。
- **主方案=自建菜默认归"家常菜"**（零操作）：家庭菜天然是家常菜，这是**正确默认**非妥协。彻底解决可发现性 + 消除"预设有菜系/自建恒空"的割裂。ab1ca32 本意是"不强迫选"，执行成了"没有菜系"——正确落地是**给合理默认**。
- **CuisineRail 只显"有菜的菜系"**（UX 提）：11 项固定竖列里徽菜4道/西餐1道是"点进去只几道菜"的稀疏死胡同，每点一次是挫败。改动态派生。
- 否决"我的菜/未分类"分组（污染菜系维度）；推荐暂不融入菜系（家庭少按菜系选餐、区分度低）。

## 三、实现（两处最小打磨）
1. **自建菜默认"家常菜"**：
   - `NewDishUiState.cuisine` 默认 `""` → `Cuisines.HOME`（仅影响新建；编辑既有菜走 `d.cuisine` 覆盖不受影响）。
   - **存量回填**：新 SQL `backfillEmptyUserDishCuisine`（`UPDATE dish SET cuisine=:c WHERE source='user' AND cuisine=''`，纯新查询不改表结构→无需迁移；只填空不覆盖、`source='user'` 不误伤预设）；seeder dish 循环前调一次；`SEED_LOGIC_VERSION` v3→v4（红线：seed 逻辑变更让老库跑到）。
2. **CuisineRail 只显有菜的菜系**：DishesVM baseState 从全量 `observed` 派生 `availableCuisines = Cuisines.ALL.filter{有菜}`（按固定顺序），CuisineRail 用它渲染（"全部"恒首）。
