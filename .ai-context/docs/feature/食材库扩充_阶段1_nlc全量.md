## 经验（每步后沉淀）
- **nlc 全量走"分类浏览"而非"按名搜"**：`categoryOne=1..25(有效1,10-25)+pageNum` 遍历即全量·比按 505 个名反查全面（还能发现库里没有的常见食材）。
- **爬取存整行 raw、解析后置**：矿物质列位不稳，先把整行存下来，解析/映射离线做、可反复调，不用重爬（省网络·抗列位变动）。
- **爬虫必带 3 件套**：JSONL append 即写即存 + 已爬 id 跳过(断点续连) + `--max-seconds` 控时——长跑抗断连红线，实测重跑 0 重复。
- **规模化配忌口·关键红线教训**：朴素关键词匹配内脏(肝/肚/心)**误报炸裂**——羊肚菌/牛肝菌(菌藻)、开心果/通心面/夹心酥(含"心")全中招。**必须 nlc 分类过滤(只畜肉/禽肉)+动物前缀**才准。规模化配忌口=**先分类缩范围再关键词**，且只自动"权威确立"类(内脏→痛风avoid/酒→酒精)、ambiguous(肠/海鲜/加工)出抽样核清单交人工，**绝不朴素关键词批量写忌口**(健康红线)。
- **补缺(GI/嘌呤/饱脂)对610低产**：本地 GI/嘌呤参考表仅~30条(西式)·nlc无这三项·USDA需cn_en映射(610中文名未覆盖)→610暂留 pending(用户已同意"补不上留pending")。嘌呤靠属性层(内脏)保痛风安全·非数值填。
- **爬取中间产物 gitignore·候选入git**：raw(`_crawl/`)不入 git(可重爬)；解析后的候选(`candidates/`)入 git(供用户 Gitee 核验 + S9 入库输入)。
- **矿物质列映射靠"已知食材对照"核实**：用库里已有且 nlc 也有的食材(大米↔稻米·Ca/K/Na 三值精确吻合)反推列位，比猜列可靠。中国成分表标准矿物质序=钙磷钾钠镁铁锌硒铜锰。
- **能量自洽当"解析质检"**：批量解析后跑 Atwater 自洽，存疑项若全是干货(纤维高估)=解析对；若出现宏量/kcal 明显不搭=解析列错→回查。本次 10 存疑全干货→解析零错。
- **🔴列映射必须用"极端值食材"交叉验证·别只看一个食材**：nlc 列 [11] 用小麦粉(1.0)/稻米(0.6)看像膳食纤维，实则是**灰分**——魔芋精粉[11]=4.3(真纤维74)、黄豆[11]=4.6(真纤维15)、金华火腿[11]=6.8 才暴露是灰分(真纤维在[13]·稀疏)。**验证列义要挑"该值该极端"的食材**(高纤维的魔芋/黄豆·高胆固醇的牛脑[10]=2447)才能证伪。本次因只用普通食材验证[11]导致 672 纤维全错(灰分当纤维)·体检①的"纤维>碳水物理矛盾"揪出。教训:①核心数值(kcal/宏量/钠钾钙)已用极端值验证故对 ②纤维/胆固醇没验证极端值→错。**物理约束(纤维≤碳水·饱脂≤总脂)是揪列映射错的利器·纳入常规体检**。
