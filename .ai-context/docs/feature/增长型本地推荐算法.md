# 增长型本地推荐算法方案

> [AI生成] 2026-07-14。把现有"库存规则推荐"升级为一套**会成长**的本地推荐机制：
> 纳入营养搭配、用户历史学习、去重，并开放少量**用户轻干预权重**（类音乐 App 的推荐风格）。
> 不需要训练——所有"学习"都是从用户真实数据实时派生的画像，数据越多越准。

## 一、设计理念

三层递进，**规则保证安全（不变）+ 数据驱动个性化（新增）+ 用户轻干预（新增）**：
- 现有 `HealthRuleEngine`「物尽其用 + 忌口红线」核心逻辑保留（见 CLAUDE.md 忌口/份数红线），不推倒。
- 在打分公式上**因子化 + 加权**，新增营养搭配、偏好学习两组因子。
- 权重可由「推荐风格」轻干预切换，用户参与但不强制配置（默认"综合"）。

## 二、打分因子（四组）

在 `HealthRuleEngine.evaluate` 现有加减基础上，抽成**权重表** `RecommendationWeights`，各因子归一后加权：

| 组 | 因子 | 现状/新增 | 默认权重 | 说明 |
|---|---|---|---|---|
| 物尽其用 | 在手主料数 | 现有 | +1.0/味 | 用到库存主料强力靠前（核心，不动） |
| | 调料丰富度 | 现有 | +0.5×占比 | 在手调料越全做法越多 |
| | 库存不足/缺辅料 | 现有 | -0.3 / -0.2/味 | 轻微排后，不挤出 |
| 健康契合 | 调养推荐/限量 | 现有 | +0.6 / -0.4/味 | 利健康靠前、不利靠后 |
| | 忌口 | 现有 | -50（保留+标红） | 红线：保留不隐藏、排最末 |
| **营养搭配** | 与当日/本餐已选的**互补度** | **新增** | +0.8 | 缺蛋白→高蛋白菜加分；当日钠/热量近上限→高钠/高热降分；荤素/主食平衡（复用 NutritionRepository） |
| **偏好学习** | 偏好画像分 | **新增** | +0.6 | 主料/菜系频率 + 菜品复用(preference) + 收藏(dish_favorite) → "这家爱吃什么" |
| 新鲜度 | 最近吃过 | 现有 | -0.5 | 去重降权（现 7 天窗口，可切 1~4 周） |
| | 主料近期重复 | **新增** | -0.3×次 | 避免连着几天同主料 |

排序分层不变：正常菜 → 最近吃过 → 忌口菜，层内按分数降序。

## 三、推荐风格（用户轻干预）

一组**权重预设**，底层因子不变，只切各因子系数。存 `PreferenceKeys.RECOMMEND_STYLE`，默认"综合"。

| 风格 | 调整 | 效果 |
|---|---|---|
| **综合**(默认) | 各因子默认权重 | 均衡 |
| **偏熟悉** | ↑偏好画像(×2)、↓最近惩罚(×0.4) | 多推爱吃/常做 |
| **偏新鲜** | ↑最近惩罚(×2)、↑主料重复惩罚、↓偏好画像(×0.3) | 多推久未吃、尝新搭配 |
| **偏营养** | ↑营养搭配(×1.6)、↑调养推荐(×1.5) | 更冲着均衡达标推 |

UI：AI 推荐页顶部苹果式分段/胶囊选择器（默认综合），选择记偏好、下次记住。守"少操作"：默认合理、不强制配置。

## 四、"会成长"的数据来源（实时派生，非训练）

| 画像 | 来源 | 派生 |
|---|---|---|
| 偏好画像 | MealRecord 近90天 + dish.preference + dish_favorite | 主料/菜系频率、复用/收藏加权 → 每菜偏好分 0~1 |
| 近期营养分布 | 近N天餐食 → NutritionRepository.dishNutrition | 蛋白/脂肪/碳水/纤维/钠… 摄入分布 → 算候选互补度 |
| 主料重复 | 近N天餐食主料 | 主料出现次数 → 重复惩罚 |

数据越多，画像越准。可按天缓存画像，避免每次全量重算。

## 五、分期实施

- **P1 框架**（本期）：`RecommendationWeights` 权重表 + `RecommendationStyle` 枚举与预设；`HealthRuleEngine.evaluate` 因子化（默认权重=现有常量，**行为不变**）+ 新增营养搭配/偏好两个中性因子（无数据时=0，不影响现状）+ 主料重复因子。单测（默认行为不变 + 风格权重生效 + 新因子加分）。**不含 UI、不含画像取数**。
- **P2 成长取数**：`RecommendationDataSource.gather` 补 `preferenceScores`/`nutritionBalanceScores`/`mainRepeatCount`（从 MealRecord/Favorite/NutritionRepository 派生，按天缓存）；接进 evaluate。单测。
- **P3 UI 轻干预**：AI 推荐页「推荐风格」分段选择器 + 存偏好 + 驱动权重；展示"推荐理由"(如"你近7天蛋白偏低"/"你常做")。
- **P4 AI 对齐**：把画像/营养缺口写进 `RecommendationPrompt`，让云端/端侧模型也对齐个性化。

## 六、红线遵守

- 忌口保留+标红+排最末，不隐藏（家庭 app）。调料忌口转做法提示、不剔除菜。
- 忌口/限量只作用非调料食材。
- 健康数据免责：营养为参考整理值。
- 份数/缺料只影响先后、不挤出推荐。
