# 双设备选择性同步方案

> [AI生成] 2026-07-10。承接"双设备局域网同传"(现为整库替换)。目标：可选择同步 菜品/餐食/库存/食材/健康档案/收藏，或全部。

## 现状
- 双设备同传 = 发送完整备份包(`.ckbk`=整库+图片)，接收端**整库替换**。不可选、且覆盖。

## 目标与约束
- **可选择**要同步的数据域；**全部**=整库替换(现状保留)。
- 约束：数据有**引用依赖**，选某域要自动带依赖：
  - 餐食(meal_record→dish_id) → 菜品(dish→ingredient) → 食材
  - 库存(pantry→ingredient) → 食材；收藏(favorite_combo→dish) → 菜品
- **全部=替换**(干净换机)；**选择性=合并**(加/更新到接收端现有数据，不整库覆盖)。

## 机制：结构化 Bundle + 名称匹配合并
- **Bundle 格式**：zip `.ckbksel`：`manifest.json`(schemaVersion+含哪些域) + `data.json`(选中各表行, kotlinx.serialization) + `img/`(被引用图片)。
- **合并策略(按域, ID 重映射)**：
  - **食材(user)**：按 `name` 匹配 → 命中则复用其 id(建 A.id→B.id 映射)、否则插入新行→映射。仅同步 source=user(预设由 seed 生成, 不传)。
  - **菜品(user)**：按 `name` 匹配 → 复用/插入；`dish_ingredient` 的 ingredient_id 经食材映射重映射；dish id 重映射。
  - **库存(pantry)**：按 ingredient_id(经映射)upsert 份数/状态。
  - **餐食(meal_record)**：按 `(date, meal_type_id)` 匹配 → 命中则替换当天该餐的菜(dish 经映射)、否则插入。避免重复同步产生重复餐。
  - **健康档案**：按 crowd_type_id merge。
  - **收藏组合**：按 name(或菜集合)匹配；dish 经映射。
- **不同步**：preference(主题/AI Key, 含本机密钥)、基础/seed 数据(分类/单位/调养规则, 由 seed 生成)。

## 分阶段
1. **P1 引擎地基 + 菜品/食材**(最高价值"分享菜谱")：SyncBundle DTO + 导出(食材+菜品+关联+图片) + 合并(名称匹配+ID重映射) + 单测。
2. **P2 库存 + 健康档案 + 收藏**：各按键合并。
3. **P3 餐食历史**：deps 最重、去重按(date,meal_type)。
4. **P4 UI + 传输接入**：发送前"选择同步内容"多选；沿用局域网 socket / SAF；接收端合并 + 结果提示(新增/更新数)。全部仍走整库替换旧路径。

## 选项用户可见说明（P4 UI 每项都带，让用户懂含义）
- 顶部总说明：**「全部」会覆盖对方数据（适合换新机）；其余为「合并」——只把选中内容加/更新到对方，不动对方其它数据。**
- **全部**：把本机全部数据完整搬到对方并**覆盖**其原有数据。适合换新手机。
- **菜品库（菜谱）**：同步你自建的菜品（含食材/做法/图片）。分享菜谱；同名更新。
- **餐食历史（食历）**：同步吃过/计划的餐食记录（自动带上相关菜品与食材）。
- **库存（家里有啥）**：同步当前在手食材及份数。
- **食材库**：同步你自建的食材（含详情/图片）。
- **健康档案**：同步健康档案配置（关注的人群/病种）。
- **收藏组合**：同步收藏的菜品搭配。

## 风险/注意
- ID 重映射错→引用错乱/丢失：合并全程在一个事务、映射表先建全再插依赖。
- 名称匹配的边界：同名不同物→会合并(可接受, 用户自建同名本就冲突)；大小写/空白 trim 归一。
- 图片：按文件名带；合并时同名覆盖。
- schemaVersion 校验：高版本 bundle 不能导入低版本 App。
