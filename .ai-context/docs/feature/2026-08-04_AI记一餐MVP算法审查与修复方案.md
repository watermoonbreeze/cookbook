# AI记一餐 MVP 算法审查与修复方案

> 2026-08-04 只读会审。结论：当前不可按“健康数据正确”交付；先修 P0，再扩体验。

## P0 阻断项

| ID | 问题 / 证据 | 修复规则 | 验收 |
|---|---|---|---|
| A0-1 | 绝对日期被丢：Rule 未把 `dateHint` 写入 `DayMealJson.date`；多天 AI 锚定会覆盖绝对日期。`TextSegmenter`、`RuleMealParser`、`AiMealInputViewModel` | 新建单一 `DateAnchor`：绝对日期 > 相对词 > 单天星期(最近过去) / 多天计划星期(目标周)。绝对日期永不被周锚点覆盖；校验日历和星期冲突 | 7/1、跨年、2/29、显式日期+周几、多天倒序均落正确日 |
| A0-2 | Flat AI 转换按 `(date_offset, meal_type)` 聚合：同日早餐/午餐被当两天；不同绝对日期默认 offset=0 可合并。`FlatToDayMealConverter` | 先按完整日期标识聚合 Day，再按 meal_type 聚合 Meal；时间/备注冲突给 warning | 同日早+午=1 Day、2 Meal；不同绝对日不合并 |
| A0-3 | `dish_quantity`/unit 在 `MultiDayRecorder→SemanticDish` 丢失；“两碗饭”按一份入库和算营养 | `meal_record_dish` 增 `serving_multiplier`；摄入=`整份×multiplier×eaten_ratio×share`。禁止改全局菜谱克数 | 2份/1份菜的预览、摄入、报告数值严格 2 倍 |
| A0-4 | `SchemaValidator` 未接生产链；非法日期/时间/餐次/比例/数量静默改义或崩溃 | 管道固定：decode→迁移→canonicalize→严格校验→preview。不可修复则 AI→规则降级；可修复必须 warning。限制天/餐/菜/食材数量 | 非法 JSON/日期/比例/数量零写库，确认页可见原因 |
| A0-5 | 有已有餐食仍默认整日删后重写，`hasExisting` 和 warnings 都不显示 | 预览逐日显示“已有 X 餐，将追加”；用户显式确认 MERGE，提供返回修改；显示全部 warnings | 已有记录不再静默改写；跳过菜品可见 |

## P1 正确性与可靠性

| ID | 问题 | 修复 |
|---|---|---|
| A1-1 | commit 注释称原子，实际逐食材/菜/日写，失败留孤儿 | 一次确认使用 DB 总事务；失败全回滚。若暂不能，先实现 commit journal + 幂等清理，不能继续宣称原子 |
| A1-2 | 确认保存可双击重入；保存中仍可关闭 Sheet | `PREVIEW→SAVING` 原子 gate/requestId；保存中禁重复确认，离开二次确认；结果只接受当前 requestId |
| A1-3 | 已有同名菜时忽略本次配料/克数，营养沿用旧菜谱 | 预览明确“复用已有菜谱”；用户选复用/创建变体。中期以 recipeFingerprint 或餐次配料快照决定复用 |
| A1-4 | cookingMethods/tags/description/isMain/unit 等字段中途丢失 | 要么贯通 Preview→commit→DB 并测试，要么从 Prompt/Schema 删除；禁止伪支持 |
| A1-5 | AI 请求、响应、饮食文字写入日志 | Release 只记状态/长度/hash；诊断模式显式开关并脱敏，错误日志不含原文 |
| A1-6 | `大后天` 被“后天”子串抢先命中 | 相对日期词按最长优先的词法器解析；补大后天/上周/跨天同句测试 |
| A1-7 | `eaten_ratio` 预览按整份，提交后才回填 | 预览分开展示“整份估算”与“按实际食用估算”，或统一按摄入显示 |
| A1-8 | AI/规则来源只短暂显示，落库无批次可追溯 | 中期加 `meal_import_batch`（source/parserVersion/inputHash/warnings/createdAt）关联餐记录；原文默认不保存 |

## 实施批次

1. **批一（先止错）**：A0-1~A0-5；DateAnchor、Flat Day 聚合、Schema 校验/预览 warning、冲突确认。
2. **批二（健康数值）**：A0-3；份数数据模型、IntakeCalculator、营养与报告贯通。此批需 DB migration，先给验收合同。
3. **批三（提交可靠）**：A1-1/A1-2/A1-5；总事务、提交 gate、日志脱敏。
4. **批四（菜谱语义）**：A1-3/A1-4/A1-7/A1-8；recipe 版本/快照与字段完整性。

## 必须新增的自动化测试

- DateAnchor 表驱动：绝对/相对/单天星期/多天计划星期、跨年/闰日/冲突。
- Flat 同日多餐和多绝对日期。
- schema 非法值、超限、降级来源与 warning 可见。
- `两碗米饭` 端到端摄入/报告（批二）。
- 已有餐食 MERGE/取消、双击确认、提交失败回滚/重试。
- 括号、多层配料、未闭合括号、大后天。
- AI 新建实体来源、日志不含原始饮食/健康内容。

## 用户可验证

- 批一完成后，用现有真机清单 D6~D15；新增绝对日期/同日早午两例。
- 批二完成后，记“1碗米饭”和“2碗米饭”，报告/营养应严格成倍。
- 批三完成后，在确认键连续点击并强制中断一次，数据库不应出现孤儿 AI 食材/菜或半天记录。
