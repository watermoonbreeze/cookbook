# AI记一餐 MVP 算法审查与修复方案

## 结论

当前不可按“健康数据正确”交付；先完成 P0。

## P0

|项|问题|修复|验收|
|---|---|---|---|
|日期|显式日期被丢，多天锚点覆盖绝对日期|DateAnchor：绝对>相对>单天星期/多天周锚点|跨年、闰日、显式日期、多天倒序正确|

## P1

### 已确认：V2 双阶段解析与健康建议

- **阶段一（餐食草稿）**：AI Prompt 尽量填充时间、餐次、菜名、食材、调料、做法、食材大类和营养元素；`meal-log.v2` 对上述字段均宽松接收，只有菜名必需。AI 显式结果优先，本地只归一、查重、校验和预览；不因“匹配不上库”丢弃语义。
- **阶段二（可选建议）**：先由本机 `HealthSafetyReport` 产生可解释事实；用户本次单独同意后，才发送去标识化的健康摘要与餐食摘要给 AI。AI 建议在确认餐食下方“查看建议”展开，纯展示、退出即清、永不写库/备份/同步/日志/埋点。
- **安全边界**：真实已吃记录始终允许用户确认保存，AI 建议不能阻断；计划/推荐仍执行既有忌口等硬红线。禁发送姓名、ID、原始文本、完整病史、生命体征、报告、用药和历史餐食。
- **降级与诊断**：二阶段失败不影响餐食预览；一阶段失败才规则解析。诊断以会话内 `AiMealAttemptDiagnostic` 提供阶段、脱敏摘要和按需查看的原始返回；`CloudAiRuntime` 禁止记录完整请求/响应。规则解析先支持中文数字日期、显式时间，避免把它们作为菜品。

- 总事务或可恢复幂等：失败不得留孤儿食材/菜或部分天。
- 保存单飞与离开保护：禁止双击并发提交。
- 同名菜复用需说明“沿用已有菜谱”，中期 recipeFingerprint/餐次配料快照。
- cookingMethods、tags、isMain、unit 等字段要么贯通落库，要么从 Schema/Prompt 删除。
- Release 日志不得写原始饮食、prompt、模型响应；只留状态/长度/hash。
- 修正“大后天”长词优先；预览区分整份与实际食用比例营养。

## 批次

1. 批一：日期、Flat 聚合、Validator、warnings/已有记录确认。**真机发现仍有阻断**：当前解析器将 AI 的可选 `null` 字段误判为无效协议，且 `CloudAiRuntime` 仍可能记录完整请求/响应；先修为 `meal-log.v2` 宽松容错与彻底脱敏，再验。
2. 批二：规则降级日期/时间切分、会话内失败诊断、AI 显式食材/调料/做法的保真贯通。
3. 批三：份数数据模型和 IntakeCalculator（需迁移/验收合同）。
4. 批四：本机 `HealthSafetyReport` + 单次同意的 AI 健康建议（纯展示、不可持久化）。
5. 批五：事务、提交互斥、字段完整性/批次追溯。
