# AI记一餐 MVP 算法审查与修复方案

## 结论

当前不可按“健康数据正确”交付；先完成 P0。

## P0

|项|问题|修复|验收|
|---|---|---|---|
|日期|显式日期被丢，多天锚点覆盖绝对日期|DateAnchor：绝对>相对>单天星期/多天周锚点|跨年、闰日、显式日期、多天倒序正确|
|Flat JSON|按日期偏移+餐次分组，同日多餐成多天、跨日可合并|先按完整日期聚 Day，再按餐次聚 Meal|同日早午=1 Day、2 Meal|
|份数|两碗饭/三份菜丢失，营养按一份|meal_record_dish 增 serving_multiplier；摄入=整份×份数×吃完度×成员份额|2份/1份报告严格2倍|
|校验|SchemaValidator未接入，非法输出静默改义/崩溃|decode→迁移→规范化→严格校验→预览；不可修复则规则降级|非法日期/比例/数量零写库且可见原因|
|已有记录|整日重写但无提示|预览显示已有餐食/warnings，用户确认 MERGE|不再静默改写|

## P1

- 总事务或可恢复幂等：失败不得留孤儿食材/菜或部分天。
- 保存单飞与离开保护：禁止双击并发提交。
- 同名菜复用需说明“沿用已有菜谱”，中期 recipeFingerprint/餐次配料快照。
- cookingMethods、tags、isMain、unit 等字段要么贯通落库，要么从 Schema/Prompt 删除。
- Release 日志不得写原始饮食、prompt、模型响应；只留状态/长度/hash。
- 修正“大后天”长词优先；预览区分整份与实际食用比例营养。
