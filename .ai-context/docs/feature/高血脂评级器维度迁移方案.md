## 一、目标与口径

给 `NutritionLevelEvaluator` 加**高血脂(HYPERLIPIDEMIA)负向维度**：当登记高血脂病种、当日饱和脂肪/胆固醇偏高时，温和下调级别+提示。与钠/GI/嘌呤同为负向罚，守免责（仅供参考·非医嘱）。

**权威口径（待核准）**：
- 饱和脂肪：中国居民膳食指南 2022 / 血脂管理指南 2023——饱和脂肪供能 <10%（约 <20g/日，2000kcal 基准）。
- 胆固醇：膳食胆固醇 <300mg/日（一般）/ <200mg/日（高胆固醇血症）。
- **均为定性/建议阈值**，用则标口径来源+免责；缺数据→不触发（同钾/纤维退回口径）。

## 二、Schema 变更（红线：一次改全）

**当前**：`ingredient_nutrition` 无饱和脂肪/胆固醇列（有 fat_g/cholesterol 无）。最新迁移 `24.sqm`。

1. **改 CREATE TABLE**（`Cookbook.sq`）：在 `fat_g` 后追加两列（列序与迁移一致、追加末尾前的合适位置——实际两处都追加到 `purine_mg` 附近保持语义聚集，但**新装走 Schema.create 用 CREATE 的列序**）：
   ```
   saturated_fat_g REAL,   -- 饱和脂肪(g/100g)
   cholesterol_mg REAL,    -- 胆固醇(mg/100g)
   ```
   放在 `calcium_mg` 后、`gi` 前（营养素聚集）。**注意 CREATE 与 ALTER 的列最终集合一致即可，SQLite 加列都在末尾**——为避免混乱，CREATE 也把两列加在**末尾 status 之前**与 ALTER 顺序一致更稳妥。
2. **新建 `25.sqm`**（名=最大24+1）：
   ```
   ALTER TABLE ingredient_nutrition ADD COLUMN saturated_fat_g REAL;
   ALTER TABLE ingredient_nutrition ADD COLUMN cholesterol_mg REAL;
   ```
   REAL 可空、无 DEFAULT（老行为 NULL=缺数据，评级器缺数据不触发，天然安全）。**幂等性**：`ALTER ADD COLUMN` 对全新列安全；不可对已存在列跑（首次迁移，无此问题）。
3. **Schema 版本**：由 `.sqm` 文件数推导（25 个）→ 自动。
