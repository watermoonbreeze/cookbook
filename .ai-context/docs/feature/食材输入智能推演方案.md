# 食材输入智能推演方案 · 待确认

> [AI生成] 2026-07-18 执行队列第7项之①。用户提"食材输入智能推演：输入名称→推食材候选 / 自建按名推分类+营养预填"。
> 先出**方案待确认**，不实现。目标：记菜/加食材时**少打字、少选择**——输入几个字就给候选、自建时按名自动预选分类+预填营养（家庭高频省心）。

## 一、两个场景

1. **已有食材的快速命中（候选建议）**：输入"西红"→候选"西红柿/番茄"，点即用。减少翻分类树。
2. **自建新食材的智能预填**：输入库里没有的名（如"黑毛猪五花"）→自建时**按名自动预选营养大类**、**预填营养**（若能对上近似食材或按大类兜底），用户微调即可保存。

## 二、现有可复用能力（无需从零）

- **按名归一/复用**：`createUserIngredient` 已按去空格名复用已有 id；`selectIngredientIdsByNames` 兼容老库同名多 id。
- **分类推断**：`FoodGroup.classify`（尾词 head-noun 判定：菜/苗/肉/奶/蛋/腐/油 + `NAME_OVERRIDE` 特例）——本会话红线已详列。自建食材编辑区已"按名预选顶层大类"。
- **营养预填**：`ingredient_nutrition.json` 440+ 食材（按名 upsert）；`IngredientEditorDialogs.buildNutrition` 已有营养输入区。
- **拼音检索**：`PinyinIndex.kt`（本项目已提取通用）+ 食材 `pinyin`/`alias` 列。

## 三、方案

### 3.1 候选建议（场景1）
- 输入框下拉**实时候选**：按"名/别名/拼音首字母"匹配已有食材，前 N 条（如 8）。复用 `selectIngredient*`/`PinyinIndex`。
- 已在**选菜品/加食材/库存**入口的搜索基础上增强：无结果时给"＋新建『关键词』"（部分已有，见 IngredientPicker 搜索）。
- 交互复用 `AppSearchField` + 下拉候选行（§九），点候选即选中。

### 3.2 自建智能预填（场景2）
- 用户在自建食材名输入后（失焦/停顿），**按名推演**：
  - **分类**：`FoodGroup.classify(name)` → 预选顶层营养大类（已实现"按名预选"，此项主要是确认覆盖度 + 对新词兜底）。
  - **营养预填（新增点）**：三级兜底——
    1. **近似同名命中**：名去空格/去修饰词后能对上 `ingredient_nutrition` 里某食材（如"黑毛猪五花"→"五花肉"）→ 预填其每 100g 营养，标"参考自 X（可改）"。
    2. **大类均值兜底**：对不上具体食材→按预选大类给一组**保守占位**（如"叶菜类"给低热量高纤维粗值），标"按类别估算·请核对"。
    3. **都不确定**：不预填，只预选分类，留用户填。
  - 全程**预填非强制**：值可改；标注来源与"估算·请核对"（守健康数据免责：非权威、参考整理）。

### 3.3 匹配算法（轻量·端侧）
- 名归一：去空格 + 去常见修饰词（黑毛/土/新鲜/有机/进口/散养…）→ 得"核心名"。
- 核心名精确/后缀匹配 `ingredient_nutrition` 名集（如"五花肉"是"黑毛猪五花肉"的后缀词）→ 命中。
- 纯本地、无联网、无三方；命中不了就退兜底，绝不编造具体数值（免责红线）。

## 四、门禁与风险

- **门禁**：候选下拉/自建预填是交互改动→先 **Apple-UX** 出下拉/预填提示规范；**文案** copywriter 审"估算·请核对/参考自 X"话术；**Google 审** 匹配性能（输入实时匹配防每键全表扫，用索引/预建名表）。
- **免责红线**：预填营养=**参考估算**，必标来源+"请核对"，禁把兜底值当权威；分类推断错了用户可改。
- **风险**：修饰词剥离过度可能误匹配（"椰菜"vs"椰"）→保守，宁可不预填不可错填；沿用 `NAME_OVERRIDE` 特例兜特殊词。
