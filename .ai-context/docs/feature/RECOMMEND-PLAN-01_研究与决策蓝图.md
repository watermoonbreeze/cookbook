# RECOMMEND-PLAN-01：推荐与周计划研究、可复现性与决策门

> 状态：**DECIDED**；SOL 裁决见 `SOL-DECISIONS-20260829.md` §五，不授权改排序权重、学习画像、云端 prompt 或推荐自动写入。
> 覆盖：R6/R2、数据健康-7122、战略会商-9583、K9~K12、J17、8887、A#4/A#6/C#F2。

## 1. 现实基线

| 区域 | 当前事实 | 风险/结论 |
|---|---|---|
| 单餐推荐 | 规则先筛安全集，云端仅在安全集内组合；已有库存、偏好、MMR、多风格、逐菜理由。 | 忌口硬边界不可因“正向健康”或 AI 结果被抵消。 |
| 权重 | `RecommendationStyle` 已有综合/熟悉/新鲜/营养预设；营养风格可对 GI/嘌呤做用户主动选择的软降。 | 新权重必须固定 fixture、同 seed 可复现、可解释；不能把默认行为静默改成“更健康”。 |
| 周计划 | `WeekPlanViewModel` 与 AiPlan 已共用 `WeeklyNutritionLineAggregator` / `NutritionLineAdvisor`。 | 当前输入主要是主料名称，不能被宣传为完整营养或疾病治疗计划；与 R4 历史口径、R3 数据缺失直接相关。 |
| 已吃/未吃 | J17 要求既成历史不被为凑营养线而篡改，但当前营养线本身只作提示。 | 任何“自动补餐”必须先有餐状态机（R6）和明确确认，不可插队。 |

## 2. 执行顺序

| 顺序 | 子批 | 可冻结的最小目标 | 前置/禁止 |
|---|---|---|---|
| R5-A | `RECOMMEND-REPRODUCIBILITY-01` | 固定输入 fixture、排序追踪、分层/权重和理由的一致性测试。 | 不改变权重，不接云端；先证明当前结果可解释。 |
| R5-B | `RECOMMEND-HEALTH-SCOPE-ADR-01` | 正向健康加分、疾病标签菜单与“营养风格”边界的证据/产品 ADR。 | 依赖 R4；不把推荐当医疗建议，不自动排除非忌口食物。 |
| R5-C | `WEEKLY-PLAN-TRUTH-01` | 已吃事实、未吃计划、主料/完整营养数据可用性的模型与展示合同。 | 依赖 R4 的快照决定与 R6 餐状态机；不自动补写计划。 |
| R5-D | `EXPLICIT-PREFERENCE-01` | 用户主动的喜欢/不喜欢/不再推荐入口、存储、解释与关闭。 | 不学习隐式行为，不上传画像，默认关闭或不参与排序。 |
| R5-E | `RECOMMEND-CATALOG-01` | 经证据审校的低脂/低嘌呤/低糖等候选标签。 | 依赖 R3 来源链、R4 健康范围；标签不能替代个体医疗判断。 |

## 3. 不变量

| ID | 必须 | 禁止 |
|---|---|---|
| INV-RP-01 | 先按硬忌口/用户排除分层，再在同层排序；理由可追溯。 | 用任意加分抵消 AVOID 或隐去原因。 |
| INV-RP-02 | 同一 fixture、时间锚、seed 和风格得到相同排序/理由。 | 依赖未记录的随机数、设备时间或云端结果作为唯一排序依据。 |
| INV-RP-03 | 仅在用户明确选择“偏营养”等模式时启用软健康偏好，并说明其影响。 | 静默改变默认推荐或把软降写成疾病禁令。 |
| INV-RP-04 | 周计划区分已吃事实与未吃意图；每项自动建议须用户确认。 | 通过修改历史或自动写计划来凑营养线。 |
| INV-RP-05 | 偏好数据可查看、修改、清除和关闭，并保持本地优先。 | 从浏览/点击等隐式行为秘密训练画像或上云。 |

## 4. 验证合同

- R5-A：覆盖空库存、忌口/限量、同分 tie-break、近期重复、四种风格、GI/嘌呤软降开关、MMR 多样性、理由文本与输入追踪；必须证明权重和、分层优先级与排序 deterministic。
- R5-B：每个健康加分都有来源、适用人群、缺数据降级、用户文案和反例；临床审校前只出 ADR/fixture。
- R5-C：过去、今天、未来各含“已吃/计划/空”场景；营养数据缺失时不显示伪精确线；建议不能影响历史记录或库存。
- R5-D：显式点赞/不喜欢/清除/关闭的纯本地测试；关闭后结果回到固定风格基线。
- R5-E：标签来源、版本、证据级别、撤销/修订、与人工 care 冲突的更严处理；随机抽样可反查原始来源。

## 5. 当前禁止事项

- 不以“家常度”主观字段直接重排 ；先定义数据来源、标注流程、版本和可撤销性。
- 不实施历史餐食隐式学习或模型自更新。
- 不将 NutritionLine 的主料覆盖当成精确营养总量。
- 不让云端生成菜绕过本地安全集、预览与用户确认。
