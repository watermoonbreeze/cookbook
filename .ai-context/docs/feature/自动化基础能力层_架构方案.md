## 1. 目标与范围 🔴

**一句话价值**：给 App 一套"给个名字/半结构语义，就能自动生成**数据完整**（营养/分类/单位/免责俱全）的食材·菜品·餐次·餐食"的地基能力，让 AI 记一餐、分享链接导入等所有上层自动化**共用同一套可靠入库**，而不是各自建半成品。

**In Scope**
- `:shared` 新增 AI 无关的自动生成能力层（4 级：食材→菜品→餐次→餐食）。
- 两阶段 API：`preview`（只读·产完整预览供确认）+ `commit`（落库）。呼应"AI 生成内容必须确认入库"红线。
- 自动生成时**补齐派生数据**：别名归一（K1f）→ 分类（`classify`）→ 营养估算（`NutritionGuesser`·标"估算待核"）→ 单位/默认克数（`SeasoningDefaults`）→ source 标注 → 免责。
- 把现有 `MultiDayRecorder` 重构为本能力层的**适配器**（保持 K1 现有调用不破）。

**Out of Scope**
- 不做 AI 调用本身（AI 只是 `Semantic*` 输入的一个来源，能力层不关心来源）。
- 不做**权威 care/忌口自动断言**（健康红线：忌口是"规则"需权威核实）——新建食材 care 留"待核"，只继承归一命中的库内食材已有 care。
- 不做 UI（预览/确认页由各上层各自实现，消费本层 `*Preview`）。
- 不做营养数值联网核准（估算即估算，标注清楚，后续走数据生产线）。

**数据流图**

```
上层语义源(AI解析/分享解析/手输)
   │  产出 List<SemanticDay>（AI无关的中立结构）
   ▼
DayAutoGenerator.preview(days, today, ctx)  ── 只读·零写库 ──┐
   ├─ 逐天: 日期解析(date/offset)                            │
   ├─ 逐餐: 餐次code→id, 时间解析                            │  下层复用
   ├─ 逐菜: DishAutoGenerator.preview                        │
   │        ├─ dishIdByName 命中→Reuse                       │
   │        └─ 未命中→Create: 逐料 IngredientAutoGenerator.preview
   │              ├─ 别名归一→查已有id→Reuse                 │
   │              └─ 未命中→Create: classify+营养估算+单位+careFlag=PENDING
   ▼                                                          │
AutoGenPreview（完整·含每食材营养估算/每菜热量/新建清单/警告）
   │  → 上层渲染确认页（K1a 复用 DayMealCardView / 分享 ParseSheet）
   ▼  用户确认
DayAutoGenerator.commit(preview, mergeMode)  ── 写库（db.transaction）──
   ├─ 逐新食材: createUserIngredient(categoryId) + upsertNutrition(估算·标注)
   ├─ 逐新菜: saveDish(source, ingredients含默认克数+gramUnit回填)
   └─ saveDayMeals(mergeMode) + backfill eaten_ratio
   ▼
AutoGenResult（准确 created/reused 计数 + 名单 + 警告）
```

**关键设计决策与理由**

| 决策 | 选择 | 理由 | 被否决的替代 |
|---|---|---|---|
| 输入中立化 | 定义 `Semantic*`，不吃 `DayMealJson` | 让 AI/分享/手输共用；能力层不依赖任何一种来源 | 继续吃 `DayMealJson`（锁死 AI 链·D6） |
| 两阶段 | `preview`(只读) + `commit`(写) | 满足"确认入库"红线·上层可先渲染再落库·preview 可单测无副作用 | 单阶段直接写（违可控性·D7） |
| care 不自动断言 | 新建食材 careFlag=PENDING_REVIEW，只继承归一命中库内食材 care | 健康红线：忌口是"规则"须权威核实·纯自动配会误判过度 | 用 `AttributeGuesser` 自动配 care（越健康红线） |
| 营养估算标注 | `NutritionGuesser` 结果全程带 source·缺字段留 null·commit 存"估算"标记 | "0 千卡"红线 + 免责红线·不编造不当权威 | 填 0 补全（放大/失真·越红线） |
| 默认克数 | 缺 quantity 时 `SeasoningDefaults.defaultGramFor` + unitId 回填 gramUnit | 防 unitId=null 小剂量放大红线（盐 3g→180g） | 沿用硬编码 100g（D3·钠/油爆表） |
| 重构而非新起 | `MultiDayRecorder` 降为适配器 | K1 现有调用零破坏·渐进迁移 | 并存两套入库（逻辑漂移） |

## 4. 接口契约 🔴（主力照抄·与合同 §3 API 表面互引）

**AutoGenModels.kt**（字段可空性即红线）

```kotlin
// 中立语义输入（AI/分享/手输统一产出）
data class SemanticIngredient(
    val name: String,
    val quantity: Double? = null,   // null/0 → commit 时用 SeasoningDefaults 兜默认克数
    val unit: String? = null,       // 单位名(如"g""个")·null → 解析默认
    val isMain: Boolean = false,
)
data class SemanticDish(
    val name: String,
    val ingredients: List<SemanticIngredient> = emptyList(), // 空 → 走菜名推演
    val cookingMethods: List<String> = emptyList(),
    val tags: List<String> = emptyList(),
    val description: String = "",
    val specialNote: String = "",
    val eatenRatio: Double? = null, // 餐次维度回填用
    val source: String = "auto",    // "ai"/"link"/"user"·标来源
)
data class SemanticMeal(
    val mealTypeCode: String?,      // "BREAKFAST"等·null→回退午餐
    val mealTime: String? = null,   // "HH:mm"·null→餐次默认时间
    val note: String = "",
    val dishes: List<SemanticDish> = emptyList(),
)
data class SemanticDay(
    val date: String? = null,       // "yyyy-MM-dd"优先
    val dateOffset: Int = 0,        // 相对 today
    val meals: List<SemanticMeal> = emptyList(),
)

// 预览：resolution 明确 Reuse/Create，杜绝计数错误(D5)
enum class ResolveKind { REUSE, CREATE }
data class IngredientPreview(
    val inputName: String,
    val normalizedName: String,     // 别名归一后
    val resolution: ResolveKind,
    val existingId: Long?,          // REUSE 时非空
    val groupLabel: String?,        // classify 大类名·可空
    val categoryId: Long?,          // commit 用
    val nutrition: NutritionGuess,  // 复用现有类型·含 source(Match/Group/None)
    val quantity: Double,           // 已兜默认克数
    val unitId: Long?,              // 已解析(null→saveDish 回填 gramUnit)
    val careFlag: CareFlag,         // 见下
)
enum class CareFlag { INHERITED, PENDING_REVIEW } // 归一命中库内=INHERITED·新建=PENDING
data class DishPreview(
    val inputName: String,
    val resolution: ResolveKind,
    val existingId: Long?,
    val ingredients: List<IngredientPreview>,
    val source: String,
    val estimatedKcal: Double?,     // 由营养估算×克数汇总·全缺料→null(显"营养待完善"非"约0")
)
data class MealPreview(val mealTypeId: Long, val mealTime: String, val note: String, val dishes: List<DishPreview>)
data class DayPreview(val date: LocalDate, val meals: List<MealPreview>, val hasExisting: Boolean)
data class AutoGenPreview(val days: List<DayPreview>, val warnings: List<String>)

data class AutoGenResult(
    val daysSaved: Int, val mealsSaved: Int,
    val dishesCreated: Int, val dishesReused: Int,
    val ingredientsCreated: Int, val ingredientsReused: Int,
    val createdIngredientNames: List<String>,
    val createdDishNames: List<String>,
)
```

**AutoGenContext.kt**：一次性预取——`ingredientNamesWithId`、`nutritionCandidates: List<Pair<String,NutritionGuessValues>>`、`mealTypes`、`gramUnitId`、别名表。由工厂 `suspend fun load(...)` 构建，`preview/commit` 全程复用，防 N+1。

**错误/边界**：空 name 跳过并计 warning；解析失败（日期/餐次）走既有回退（offset/午餐/12:00）；DB 异常由 commit 的 `db.transaction{}` 回滚；preview 全程只读、可安全重算。

**复用关系**：`createUserIngredient`（零改）、`upsertNutrition`（零改）、`saveDish`（零改·其内部已回填 unitId=null→gramUnit）、`NutritionGuesser`/`DishNameIngredientGuesser`/`SeasoningDefaults`/`FoodGroup`（零改）。

## 5. 数据模型 / DB

- **无表结构改动·无 .sqm 迁移**（纯新查询/复用现有写入口）。
- 新增只读查询（若现有 repo 未暴露）：批量取"已有食材名+营养值"供 `NutritionGuesser` 候选、`gramUnit` id。均为 `selectAll*`/单列查询→**无需迁移**（红线：加纯查询不改表不迁移）。
- **新种子文件** `ingredient_aliases.json`（`shared/.../data/seed/`·同 `ingredient_details.json` 免迁移·改内容触发指纹重跑）。
- 备注·营养"估算"标记：主力编码前先查 `IngredientNutrition` 是否有置信度/来源字段；有则存"估算"，无则**约定**——autogen 建的食材 `ingredient.source="ai"/"link"` 即隐含估算，UI 据此显"估算·待核"，**不得**把 autogen 营养当权威展示（列为合同不变量 INV-营养估算）。

## 8. 红线与风险 🔴

| 红线/风险 | 规避 |
|---|---|
| "0 千卡"/营养估算 | commit 必调 `NutritionGuesser`+`upsertNutrition`·缺字段 null·标"估算" |
| unitId=null 小剂量放大 | 缺 quantity 用 `SeasoningDefaults`·unitId 交 saveDish 回填 gramUnit·**单测断言营养不放大** |
| 健康忌口红线 | 新建食材 care=PENDING·不自动断言·只继承归一命中库内 care |
| 食材同名多 id / UNIQUE | 走 `createUserIngredient`（已按去空格名 dedup）+ 先别名归一 |
| 改 data class 字段顺序 | 全用命名参数构造·测试同步 |
| 改 seed 处理逻辑 | 若改入库逻辑影响老库→`SEED_LOGIC_VERSION`+1（本方案主要新增·注意 alias 生效路径） |
| K1 回归 | P3 保 `recordAll` 签名·跑 K1 现有 502 单测 |
