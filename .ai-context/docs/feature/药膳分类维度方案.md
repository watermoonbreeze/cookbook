## ⚠ 一、边界与免责（先定，再谈实现）

中医"食性/四气"（寒/凉/平/温/热）是**传统经验说法**，**非国标、非现代营养学、非医疗诊断**。本项目健康红线是"仅供参考·非医嘱、禁医疗断言、无源不编造"。药膳维度要落地必须守住：

1. **独立维度、不进医疗评级**：食性**只作食材的一个标签/筛选维度**，**绝不接入** `NutritionLevelEvaluator`/`HealthRuleEngine` 的慢病忌口/评级/达标逻辑——不能出现"高血压吃凉性降压"这类断言（红线）。营养/慢病系统保持纯净。
2. **统一标注**：凡展示食性处标"**中医传统说法·参考·非医嘱**"，不写"治疗/调理某病/降火"等医疗承诺；"上火/去火"等口语也需谨慎，倾向中性描述。
3. **来源诚实**：食性数据整理自中医典籍/本草类惯例说法，**标"惯例·非权威核对"**（同嘌呤"非国标"处理），不同典籍有分歧的取常见说法并注明"说法不一"。
4. **可选功能**：默认不打扰（多数家庭用户不需要）；作为**可开启的增强维度**，避免给核心记菜流程加噪。

> 建议：确认前先明确"我们是否要在一款守现代营养免责的 App 里引入中医食性"——两套话语体系并存需清晰隔离，否则易和"仅供参考·非医嘱"定位冲突。**这是最需要你拍板的点。**

## 二、数据模型（若确认做）

- **食性是低基数枚举**（寒/凉/平/温/热，5 值 or 简化凉/温/热/平 4 值）+ 可选"归经/功效"文本。
- **选型 A（推荐·最小侵入）**：`ingredient` 加一列 `tcm_nature TEXT DEFAULT ''`（空=未标）。加列走红线全套（CREATE 同步 + `N.sqm` ALTER 可空 + 所有构造点 + seed 回填只填空 + SEED_LOGIC_VERSION+1）。查询/筛选按该列。
- **选型 B**：独立 `ingredient_tcm` 表（ingredient_id + nature + meridian + effect + ref/review），不动 `ingredient`。更适合带"功效/归经/宜忌"富信息，但多一张表+join。
- 建议：只做"食性标签"→A；要做"药膳功效库"→B。**先 A 起步**。
- **seed**：独立 `ingredient_tcm.json`（同 `ingredient_nutrition.json` 按名 upsert 模式），标 ref/review；数据整理走"惯例·非权威"，分歧标注。
