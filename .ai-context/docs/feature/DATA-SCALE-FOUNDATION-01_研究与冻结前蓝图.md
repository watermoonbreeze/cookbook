# DATA-SCALE-FOUNDATION-01：数据规模基础研究与分批冻结

> 状态：**RESEARCH**；本文件是 R3 唯一分流入口，不授权 seed 或代码变更。  
> 目标：在不伪造健康数据、不破坏老用户 seed 更新与现有读路径的前提下，使食材库可以安全扩大到千/万级。

## 2. 执行顺序与冻结条件

| 顺序 | 子批 | 可做内容 | 冻结前阻断 |
|---|---|---|---|
| R3-A | `INGREDIENT-PAGING-01` | DAO keyset/offset 方案择一、稳定排序、搜索 DB 侧过滤、LazyColumn 续页与 5k 合成基准。 | 先测出现有查询、确认 SQLDelight/索引/排序列；不得先把 5k seed 塞进 App。 |
| R3-B | `VITAMIN-DATA-PIPELINE-01` | 维生素字段 schema/seed/reseed/read model/只读展示贯通。 | 单位、缺失语义、来源/ref、旧库迁移与“是否参与健康评价”必须逐项冻结；默认不参与评级。 |
| R3-C | `DATA-QUALITY-REPORT-01` | 可重跑本地体检、USDA/NLC 差异报告、来源版本、人工审阅结案格式。 | 无外部数据自动落 seed；网络脚本必须限速、缓存和可复现输入。 |
| R3-D | `INGREDIENT-SCALE-IMPORT-01` | 经人工确认的分片导入、映射/care 分类、seed 指纹更新。 | R3-A/B/C 均验收；每条有来源、映射置信与拒绝/留空理由；不能将 USDA 直接等同中国食材。 |
| R3-E | `GENERIC-INGREDIENT-POLICY-01` | “青菜”等泛称代表规则与用户可见提示。 | 需产品+健康数据 ADR；不得伪装成普通 seed 补丁。 |

## 3. 跨批不变量

| ID | 必须 | 禁止 |
|---|---|---|
| INV-DATA-01 | 所有 seed 变更均保留来源、字段单位、置信/审阅结论，并通过 roundtrip 与 shared seed 测试。 | 网络采集或模型猜测直接覆盖 seed。 |
| INV-DATA-02 | 缺失值保持缺失且 UI 能诚实降级。 | 为提高覆盖率填 0 或借用不等价食材。 |
| INV-DATA-03 | 分页排序必须稳定；搜索、下一页和刷新不会重复/漏项。 | 依赖内存全量加载后再裁切。 |
| INV-DATA-04 | 维生素首期只读展示，健康评级/推荐规则不读取它。 | 在没有阈值与免责声明合同前暗中接入医疗/推荐判断。 |
| INV-DATA-05 | 任何外部来源都以版本、时间和映射证据可追溯。 | 以“USDA/NLC”笼统标注而无法定位具体条目。 |

## 4. 子批验证合同（冻结时细化为 L7）

- R3-A：空库、100、1115、5000 条合成数据；相同 sort key 的稳定 tie-break；首/末页、重复加载、搜索改词、旋转恢复；SQL 查询计划无全表重复扫描；Android 单测、Debug 构建与真机滚动帧率/内存证据。
- R3-B：每个维生素的单位与 null round-trip；老库升级/reseed 幂等；同一食材有/无维生素数据的 UI；来源展示；确认营养计算与健康等级结果字节级不变。
- R3-C：相同输入快照重复运行得到同一报告；网络失败不会改 seed；差异阈值和来源版本写入报告；每条 flagged 记录可回到原始来源或明确 SKIP。
- R3-D：小批 dry-run→人工审核→批准清单→正式导入；导入后指纹、roundtrip、seed 验证和分页基准都通过；抽样核查中文名、类别、营养单位、care 缺失处理。
- R3-E：泛称输入的来源、代表范围和用户提示由 ADR 冻结；无证据则解析为待确认名称，不映射到健康裁决。

## 5. 当前禁止事项

不得运行会覆盖 tracked `staging.db`/体检报告的生产线并将时间戳变动当作数据验证；不得把临时 USDA 索引、联网缓存或生成提案提交为生产 seed；不得将 1115→5000 的数量目标置于来源与移动端性能之前。
