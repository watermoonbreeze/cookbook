# 库存份数体系（份数/派生占用/不足提示）

> [AI生成] 2026-07-10 落地。让库存食材带"份数(可做几次菜)"，做菜自动占用、不足灰显、加份数按时间序恢复。

## 统一模型（2026-07-10 定稿，最优）

**一句话**：份数是"结算式余额"——加份数时把库存结算为「当前剩余 + 新加」并从此刻起重新计窗口；缺料/剩余全部按此窗口派生实时算。

- **入库日窗口**：每个在库食材有 `added_at`(最后一次加份数的时刻)。只算 `date >= added_at` 的餐；入库日之前的餐（含很久以前）**完全不参与**（解决"两年前用过还占今天库存"）。
- **加份数=结算**：`serving_count = 当前剩余 + delta`，`added_at = now`。→ 剩0再加3=3；剩3再加2=5（未消耗的3结转，已消耗的不重复计）。为0后重加、续加、出库后重加都正确。
- **剩余** = `serving_count − (入库日起到今天已做的餐数)`；未来计划不减剩余（但会标缺料）。
- **缺料**：把 `[added_at, ∞)` 的餐按时间序对份数排队，超出即不足；入库日到昨天占份数但**不显示**（已吃过），**只今天及未来显示**"缺:X"灰显。加份数后早的先恢复。
- **采购**（仅周期规划）：主料不在库→"采购:X"；在库份数不够→"缺:X"；样式同缺料。只判主料(盐油不标)。
- **库存推荐**：不足也推荐但排后+标；可用份数(剩余)≤0 视为不足。
- **派生、不落库**：现有食历自动覆盖，无需重建餐食。
- 为什么最优：同时满足 做菜自动减/0不消失可续加/加份数按序恢复/历史不占用/为0重加正确/计划不占推荐额度——且无"每天重置"错觉(锚在入库日而非今天)、无重复计入(结算式)。

## 需求与最终模型（用户确认）
- 加入库存时选**份数**=可做几次菜；每道菜按 **1 份**算（预设剂量、自建"适量"都算 1 份）。
- **份数只由用户改**（加/减/出库）；记餐做菜**不改**库存数字。
- **不足是派生算的、不落库**：所有餐食(含计划)里用到某在库食材的菜按时间序(date→meal_time→created_at→sort_order)排队，前 `份数` 个够、其余不足；不足的菜半灰 + "缺:X"；加份数后自动重算、**早的餐先恢复**(7.4先于7.5)。
- **剩余 = max(0, 份数 − 今天及过去占用)**；计划参与排队但**不减剩余、不占推荐额度**。
- **0 份不消失**、可继续加；**手动出库**(status=0, 份数清零)才从库存移除。
- **库存推荐**：不足的**也推荐**，但可用份数≤0 的菜大幅降权排到最后 + 标"⚠库存不足:X"（不过滤）。

## 实现（分 5 阶段）
1. **DB**：`pantry.serving_count INTEGER DEFAULT 0`；迁移 `13.sqm`(v13→v14, ALTER 新列安全)。查询：`insertPantryIfAbsent`+`incrementPantryServings`(续加, 3.18 无 UPSERT 故两步)/`setPantryServings`/`selectPantryServings`/`selectPantryUsageChrono`(时间序)/`selectPantryConsumedUntil`(≤today)；出库清零份数。
2. **派生逻辑**：`shared/pantry/PantryAllocation`(纯, 可测)：按食材分组、时间序排队, rank>份数即不足。`PantryRepository.addServings/setServings/servingCounts/consumedUntilToday`。
3. **餐卡**：`DishMini.shortageIngredients`；`MealRecordRepository.pantryShortages()` 组卡时派生；`DayMealCardView` 缺料菜 alpha0.4 + "缺:X"。
4. **入库 UI**：`IngredientDetailSheet` 份数管理区(未入库选份数入库/已入库 剩余N份+加1份/减/出库)；`IngredientPickerViewModel` addServings/setServings/refreshPantryState(pantryRemaining/pantryServings)。
5. **推荐**：`RecommendationInput.shortageIngredientIds`/`DishCandidate.shortageNames`；`HealthRuleEngine` SHORTAGE_PENALTY 排后+标短料；`RecommendationDataSource`(PANTRY)算可用份数；`AiRecommendViewModel` note 标不足。
