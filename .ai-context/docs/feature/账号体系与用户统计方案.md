## 〇、一句话结论

**"看留存/活跃度"不需要登录账号，只需匿名统计埋点。** 一期先做 **A 方案（匿名统计埋点）** 即可拿到次日/次周留存、DAU/WAU、功能使用频次、推荐采纳率等全部运营指标，对"本地优先隐私招牌"冲击最小、工期最轻、PIPL 合规最简；**完整账号（B·手机号/微信登录）留到二期**（真要上云同步/AI 订阅计费/跨设备资产时再做，即 §9.1 二期起点）。

## 一、破题：看"留存/活跃度"到底需不需要登录账号？

### 1.1 核心认知
留存率本质="同一个安装在 T 日后是否回来"，只需一个**稳定匿名标识**把不同天事件串成时间线，**不需要知道这个人是谁**。登录账号解决的是"跨设备识别同一人/绑付费资产/主动召回"——都是二期诉求，一期一个都用不上。

### 1.2 两条路对比

| 维度 | A. 匿名统计埋点【推荐·一期】 | B. 完整实名账号【二期再做】 |
|---|---|---|
| 算次日/次周留存 | ✅ 能 | ✅ 能（杀鸡用牛刀） |
| 算 DAU/WAU/功能频次/采纳率 | ✅ 全能 | ✅ 全能 |
| 对隐私招牌冲击 | 极小（可关、无健康明细、无身份） | **大**（逼登录=砸隐私底牌） |
| PIPL 复杂度 | 低 | 高（手机号敏感/实名/注销权/出境评估） |
| 工期 | S–M | L |
| 跨设备识别同一人 | ❌（换机=新匿名 ID） | ✅ |
| 承载付费/云同步/召回 | ❌ | ✅（这才是它真价值） |
| 与已定基调契合 | ✅ 完全契合"账号最小化·核心本地无账号" | ⚠️ 一期上=过早过重砸招牌 |

### 1.3 B 方案什么场景才真必需（一期都不成立）
跨设备云同步（一期无·现有双设备同传是局域网直传不依赖账号）、AI 订阅计费防滥用（二期）、主动召回（一期明确不做焦虑召回）、用户资产/上报菜品（本身标注"依赖联网+账号"属二期）。→ **一期上完整账号 = 为不存在的需求提前砸掉现有卖点，不划算。【决策点 1】**

## 二、A 方案详设：一期匿名统计埋点

### 2.1 上报什么事件（对齐 §八 一期 KPI）
原则：**只上报"发生了某类行为一次"的去标识化计数，不上报行为内容**（上报"记了一餐"，绝不上报"记的什么菜/给谁/命中什么忌口"）。

| 事件 | 最小属性（全去标识化） | 支撑指标 |
|---|---|---|
| `app_open` | 时间戳+匿名ID+会话ID | DAU/WAU、留存、会话时长 |
| `first_launch` | 首启标记、App 版本、粗性能档 | 新增、留存队列起点 |
| `meal_logged` | 餐次枚举（早/午/晚/加餐·**不带菜名**） | "记一餐"周活跃频次（核心） |
| `recommend_requested` | 来源枚举（库存/随机/计划/AI）、模式 | 推荐使用率 |
| `recommend_adopted` | 是否采纳 bool、来源枚举 | **推荐采纳率**（核心） |
| `avoid_hit_shown` | 仅"本次出现过忌口标注"的布尔计数（不带病种/菜/食材） | **忌口命中真实场景比例**（核心·见 §四） |
| `feature_used` | 功能区枚举（食材/库存/搜索/报告/计时/周计划…） | 功能频次分布、发现漏斗 |
| `health_profile_set` | 仅布尔"是否设了健康档案"（**绝不带病种/忌口/身体数据**） | 健康档案渗透率 |

→ **【决策点 2】** 事件清单是否按此最小集。

### 2.2 后端选型

| 选项 | 利 | 弊 | 推荐度 |
|---|---|---|---|
| **A. 自建轻量上报服务**（HTTP `/collect` + Postgres/时序库 + Metabase/Grafana） | 数据自控不出境、无三方 SDK 越界采集、最贴隐私招牌、契约最干净 | 要搭+运维后端（M）、看板自配 | **【首选】** |
| B. Firebase Analytics | 免费开箱、留存看板现成 | Google SDK、**数据出境**（PIPL 麻烦）、采集范围不完全可控、与隐私叙事冲突 | 不推荐 |
| C. 友盟/神策等国内三方 | 国内合规成熟、看板强、不出境 | 引入三方 SDK（潜在多余采集需严格关）、"不交三方"叙事被削弱 | 次选（无后端人力时） |

**【推荐】自建（A）**：卖点就是"数据在你手里"，引三方 SDK 会让"我们不采集你数据"打折。无后端人力则退友盟系（C）并严关设备信息采集；**不选 Firebase**（出境）。→ **【决策点 3】**

> **✅ 用户 2026-07-19 定：暂无服务器 → 走第三方 SDK = 友盟+（U-App 统计·免费·境内不出境·留存/活跃/事件看板现成）**。放弃一期自建后端（免运维、当天见看板）。**合规三件套（必做）**：①友盟 SDK **初始化延迟到用户同意之后**再 `init`（非 App 启动即采）②走友盟"合规使用"配置**关闭非必要设备信息/OAID 采集**③隐私政策如实披露"集成友盟 SDK 及采集范围"。二期上账号/云同步时再评估迁自控 BaaS/自建。**排除**：Firebase/GA(出境)、TalkingData(合规风波)、极光/腾讯MTA(采集争议/收缩)。
>
> **工程约定（关键·防越界+可迁移）**：客户端做一层**内部埋点抽象** `Analytics`/`Tracker` 接口，只暴露我们定义的 §2.1 八个业务事件，友盟只是其背后一个实现。好处：①调用点只认业务事件语义、**绝不把健康明细传进去**(代码层杜绝越界) ②以后换友盟↔BaaS↔自建改一处实现即可、不动业务代码 ③"关闭统计"开关在这层统一拦截。选型不锁死、可平滑迁移。

### 2.3 匿名标识与去标识化
- 匿名 ID = **App 首启本地随机 UUID**（不用 IMEI/AndroidID/广告 ID 等可复原身份的硬标识）。
- 只用于串同一安装的留存时间线；**卸载重装即换新 ID**（略微低估长周期留存，换取"绝不可复原到个人"，值得，短期留存不受影响）。
- 上报体不含自由文本/健康明细/精确机型串（只粗分性能档）。→ **【决策点 6】**

### 2.4 首启同意与"关闭统计"开关（PIPL + 不惊扰）
- **首启一句话中性告知**（复用已有 `FeatureGuideScreen` 首启浮层）："为改进产品，App 会匿名统计使用情况（打开几次、用了哪些功能），**不含你记的任何饭菜和健康信息**，可随时在设置里关闭。"
- **【决策点 4】默认策略**：①默认开+透明可关（行为计数属去标识化，多数分析实践默认开·样本大）；②**首启询问"允许匿名使用统计吗？[允许]/[不用]"·默认不勾选**（最强隐私姿态·最贴招牌·样本略少）。**倾向②**，两者都合规。
- **设置常驻开关**：我的→隐私/功能设置→"匿名使用统计"，随时关、关比开易（守 §六 反暗黑）。
- 文案 spawn `copywriter` 审校，不吓唬不诱导（禁"关闭会影响体验"胁迫）。

### 2.5 离线补传 + 不破坏本地优先
- 事件**本地入队**→联网批量补传、失败重试、**永不阻塞本地功能**（没网 App 照常全功能）。
- 轻量低频可合并（会话结束或每 N 条批量发）。
- **透明三件套**：隐私政策列清"上报什么/绝不上报什么"、设置可关、（可选）"看看我们收集了什么"示例页。

## 三、分期设计

```
一期（现在）   A. 匿名统计埋点 —— 只为"看留存活跃"·无登录·可关·核心功能100%无账号
      │  触发=要上云同步 / AI 内置订阅计费（§9.1 二期起点）
      ▼
二期           B. 最小化可选账号 —— 只有想云同步/订阅内置AI/上报贡献的人才登录
              核心本地记菜/推荐/忌口 仍无账号可用（隐私底牌不丢）
              账号承载付费资产/跨设备同步/防滥用计费；匿名统计可平滑并入
```
一期**绝不为统计引入登录**；二期账号是"本地优先+账号增值"非"逼所有人登录"。二期登录方式（微信/手机号）→ **【决策点 7】**（一期不实现）。

## 四、数据边界红线（不可越）
1. **绝不上报健康敏感明细**：病种/忌口项/身体数据/成员信息/菜名/食材名/评级结果——一律不出设备。
2. **只上报去标识化行为频次**：事件枚举+布尔/计数+匿名 UUID+时间戳。`avoid_hit_shown` 只报"忌口被触发过（true/false）"，不带"谁忌什么"。
3. **PIPL 单独同意+最小必要**：告知独立、可拒绝、可撤回；能不收就不收。
4. **对外文案温和不吓唬**（§2.5+文案准则）：中性"改进产品"口径，不制造焦虑、不诱导。
5. **无广告 ID/无设备指纹/无三方数据交换**（§六🔴 不售卖个人健康数据）。

## 五、运营后台"一期留存/活跃看板"最小指标集

| 指标 | 定义 | 为什么看 | 怎么指导产品 |
|---|---|---|---|
| **次日留存 D1** | 首启后第2天回来占比 | 首启/aha 是否成立最快信号 | 低=改 §5.1 首启（aha 前置到零录入看今天吃什么） |
| **次周留存 D7** | 首启后第7天回来占比 | **一期唯一核心 KPI** | 产品是否成立总阀门；分渠道/版本看改动是否抬升 |
| **DAU/WAU + 粘性比** | 日活/周活及比值 | 活跃规模与频度 | 粘性低=想起来才用→强化每日推荐首屏化 |
| **"记一餐"周频次** | 周活人均 `meal_logged` | 核心动作是否成习惯 | 低=记录太麻烦→查创建流程顺手度 |
| **推荐采纳率** | adopted/requested | 推荐是否被信任采用（决策闭环闭没闭） | 低=调算法/风格；分来源看哪种更被采纳 |
| **忌口命中真实场景比例** | `avoid_hit_shown=true` 占比 | 忌口引擎（护城河#2）真被用到吗 | 低=定位是渗透问题还是能力问题 |
| **健康档案渗透率** | `health_profile_set=true` 占比 | 差异化能力被激活前提 | 低=情境处软引导设置（非红点） |
| **功能发现漏斗** | 各 `feature_used` 触达占比 | 高级/低频功能是否被发现 | 无人用=入口太深→情境化发现 |
| （辅）会话时长/深度 | 单次时长与页面数 | 辅判"高效少操作" | 过长=流程啰嗦→找卡点 |

> 看板守线：只看聚合趋势、不盯个人画像；不设"打卡排行/健康分排名"等焦虑运营指标（§5.4）。看板是"知道哪里帮到用户"，不是"催用户"的武器。

## 六、一期 MVP 范围 + 工期 + 依赖
**MVP（一期只做 A）**：①客户端埋点层（本地事件队列+匿名 UUID+§2.1 最小事件集）②上报通道（批量/离线补传/失败重试·异步不阻塞）③首启同意+设置"匿名使用统计"开关 ④后端 `/collect` 接收+存储+最小看板（§五）⑤隐私政策更新+首启文案（copywriter 审校）。

**工期**：客户端埋点+开关+补传 **S–M**；后端+看板（自建）**M** / 三方 SDK **S**；合规文案 **S**。合计 **M**（自建）/ **S–M**（三方）。

**依赖**：**需声明 `INTERNET` 权限**（本地优先 App 现无网络权限·CLAUDE.md 红线：加联网先声明否则 HTTP 静默失败）；一台后端/三方账号；先定隐私政策与同意策略（合规前置）；埋点契约与看板对齐后冻结。
