## 4. Cross-workstream invariants

### INV-BATCH-01 — AF-UEN-01 不得回归
B 修改 `AddDayFoodScreen.kt` 后，embedded 模式仍渲染 `FormBottomBar` 保存 CTA。

### INV-BATCH-02 — AF-UEN-02 不得回归
A/B/C 任意修改后，AI Single/Period 保存 `DONE` 都必须 Snackbar + reset + pop。

### INV-BATCH-03 — 日期业务语义冻结
B 只改变日期选择 UI 与“已有日期可见性”，不得改变 `setDate()` 的：
- occupied → 不切换 + warning；
- empty → 保留当前餐次内容并切日期；
- edit existing → 日期锁定；
- `minSelectableDate` → 原规则保留。

### INV-BATCH-04 — 食历复用不是复制
FoodTimeline 与 AddDayFood 必须调用**同一个共享 Calendar composable**，而不是两份近似实现。

### INV-BATCH-05 — HOME data truth 不泄漏到 AddMeal
C 的 `observeTodayPlusFuture` 改动与 B 的 `observeTimelineDates` 订阅彼此独立；不得为了“共用”把两者错误合并。

## 6. Commit strategy

允许 commit chain，不要求把三项 squash 成一个大 commit。推荐：

1. `docs(blueprint): persist meal ux consolidation arch truth`
2. `fix(uen): make selector switching non-destructive`
3. `feat(meal): reuse timeline calendar for manual date picking`
4. `feat(home): merge today and upcoming meal sections`
5. `test/docs: close meal ux consolidation delivery evidence`
6. `docs(state): hand meal ux consolidation to review`

**禁止 amend/重写已 push 历史。**

## 7. Definition of CODE COMPLETE

CODE 只能宣告 `CODE_COMPLETE / PENDING ARCH REVIEW`，当且仅当：
- A/B/C STEP 全勾销；
- union allowlist 无越界；
- 必需测试/构建通过；
- 不可执行的真机项已准确列为 PENDING，不伪造 PASS；
- `feature_sync_check` 已按项目规则执行并记录；
- 最终状态 `TURN=REVIEW`；
- 所有 commits 已 push。
