# 食材属性标签体系（数值+属性双层的「属性层」结构化）

> [AI生成] 2026-07-22 用户"都要 A+B"。B=把分散的属性判定（HIGH_PURINE 关键词 + 人工 care + 含糖手写）统一为**结构化属性标签 → 声明式映射 care**。目标：加食材只需打属性标签，自动配全 care，不易漏、不冗余、可复用。

## 一、问题（现状痛点）
属性判定分散在三处、各自为政：
- `HIGH_PURINE_KEYWORDS`（关键词兜底·嘌呤）
- `ingredient_care_rules.json`（人工逐条 care·600 条·每食材每病种手写一条）
- 含糖类是我手写的 care（可乐痛风一条+糖尿病一条…冗余）
→ 加食材要人工想"它有哪些属性风险、对哪些病种、什么 level"，**易漏**（如含糖→痛风就漏了很久）、**冗余**（一个"含酒精"要手写痛风+血压多条）。

## 二、方案（seed 时展开·最小侵入·复用现有 care 机制）
**核心：食材打「属性标签」→ 声明式「属性→care」映射表 → seed 时自动展开成 care 规则**（与人工 care 合并·加法·人工优先）。判定/UI/食材详情**全自动复用现有 `IngredientCrowdCare`/care 链路，判定逻辑零改动**。

### 组件
1. **`FoodAttribute` 枚举**（shared/domain·食材固有属性）：
   `CONTAINS_ALCOHOL`(含酒精) / `PROCESSED_FRUCTOSE`(加工浓缩果糖:含糖饮料/糖/果干) / `ADDED_SUGAR`(添加糖) / `TRANS_FAT`(反式脂肪:植脂末/氢化油/起酥) / `ORGAN_HIGH_CHOLESTEROL`(高胆固醇内脏) / `CURED_PROCESSED_MEAT`(腌腊加工肉) / `RICH_BROTH`(浓肉汤) / `HIGH_OXALATE`(高草酸)…
2. **`ATTRIBUTE_CARE_MAP`**（代码常量·声明式映射）：
   `CONTAINS_ALCOHOL → [(GOUT, AVOID), (HYPERTENSION, LIMIT)]`
   `PROCESSED_FRUCTOSE → [(GOUT, LIMIT), (DIABETES, LIMIT)]`
   `TRANS_FAT → [(HYPERLIPIDEMIA, AVOID)]` …每条带 reason 模板 + 权威 ref。
3. **`ingredient_attributes.json`**（seed·食材→属性标签列表）：`{"啤酒":["CONTAINS_ALCOHOL"], "可乐":["PROCESSED_FRUCTOSE"], ...}`
4. **seed 展开**（`PresetDataSeeder`）：对每食材每属性 → 查 map → 生成 care 规则 → `INSERT OR IGNORE`（与人工 care 去重·(ingredient,category) 已存在跳过·**人工 care 优先**）。

### 为什么 seed 展开而非运行时映射
- 复用现有 care/seed/UI/判定链路，`IngredientCrowdCare` **不动**（低风险）
- 属性标签是"care 生成器"，展开后就是普通 care 规则，食材详情/红绿灯自动显示
- 向后兼容：人工 care 保留、属性生成的 care 只补充不覆盖

## 三、迁移策略（渐进·不激进重构）
- **第一步（首版·本次）**：建机制（枚举+map+attributes.json+seed 展开）+ 用**酒精**类验证（`CONTAINS_ALCOHOL` 标签自动生成痛风 avoid+血压 limit·与现有手写 care 一致）→ 证明属性标签能替代手写、生成结果一致。
- **第二步**：含糖类改由 `PROCESSED_FRUCTOSE` 标签生成（去手写冗余）。
- **第三步**：新增类别（反式脂肪/高草酸）随对应食材/档案入库时打标签自动配 care。
- **不动**：现有人工 care（内脏/腌腊等已维护好的）保留，属性标签是补充与未来加食材的标准入口。

## 四、门禁（固化·呼应 CLAUDE.md 双层红线）
加食材必打**属性标签**（有则打）→ seed 自动配 care。属性标签是"数值+属性双层"中**属性层的结构化入口**。
**🔴 新增/调整「属性→care 映射」(`FoodAttributeCare.MAP`) 或给食材打新属性标签前，必须先联网核实权威指南口径**——核实的是**边界**（哪些食材算该属性、哪些不算、对哪些病种、avoid 还是 limit），ref 标指南原文，别凭常识想当然过度。教训：新鲜水果虽含果糖但食养指南2024明确「与痛风无显著相关」→**不打** PROCESSED_FRUCTOSE，限的是含糖饮料/果汁/果葡糖浆/果脯蜜饯。详见 `数据获取脚本化方案.md` 三-B「判定口径必联网核实」。

## 五、风险与守卫
- 属性生成 care 与人工 care 冲突 → seed 去重(人工优先)+ 单测校验生成结果
- 属性标签打错 → 引用完整性单测(食材名在库) + 属性→care 生成快照单测
- 向后兼容 → 老库指纹自重跑；不改判定逻辑；生成的 care 走现有链路
