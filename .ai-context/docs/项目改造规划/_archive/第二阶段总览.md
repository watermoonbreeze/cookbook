# Cookbook Project Graph Phase 2 总实施蓝图 V1.0

## Bootstrap · 从 Draft Model 到可信 Project Truth 数据集

**阶段**：Phase 2
**阶段名称**：Cookbook Bootstrap
**执行模型**：DeepSeek V4 Flash
**架构模式**：分批实施、分批提交、分批审核
**前置阶段**：Phase 1 Model Contract
**最终目标**：建立第一版完整、可信、可追溯的 Cookbook Project Graph 数据
**本阶段不做**：Generated Views / AI自动生命周期 / Git Guard / CI
**Graph mode**：整个 Phase 2 保持 `draft`
**正式激活**：不在 Phase 2 执行

---

# 0. Phase 2 的真正目标

Phase 2 不是：

> 把所有 Markdown 内容复制成 YAML。

Phase 2 的目标是：

> 从 Cookbook 已有代码、状态文档、Bug/Todo、方案、验证清单中重建第一版可信 Project Truth。

最终应满足：

```text
Feature
 ├─ CodeMapping
 ├─ WorkItem
 │   ├─ Bug
 │   ├─ Todo
 │   ├─ Feature Work
 │   └─ Tech / Compliance / Research
 ├─ Plan
 ├─ Verification
 └─ Relation
```

任意当前项目事项都可以通过稳定 ID 关联。

# 4. Truth Source 优先级

这是整个 Phase 2 最重要的迁移规则。

不同事实使用不同 Truth Source。

不能简单规定：

> “最新文件永远正确”。

---

# 4.1 Runtime Fact

例如：

* 文件是否存在；
* 类在哪里；
* Repository 实现；
* 数据结构；
* 实际依赖关系。

优先级：

```text
真实 Code
>
任何文档
```

---

# 4.2 当前项目状态

例如：

* CODE 是否完成；
* ARCH 是否接受；
* 当前是否真机待验；
* WorkItem 当前处于 verifying / parked；
* 当前批次。

优先级：

```text
SESSION_交接
+
BLUEPRINT_STATE
+
最新唯一验证清单
>
专项蓝图当前台账
>
专项待办
>
待办索引
>
07
>
旧项目地图状态描述
```

---

# 4.3 WorkItem 身份与业务范围

例如：

```text
K1g 是什么？
I8 是什么 Bug？
J17 要解决什么？
```

优先：

```text
专项原始定义 / 正式蓝图
>
专项待办
>
待办索引摘要
>
SESSION中的简称
```

SESSION 适合判断：

> 当前状态。

不一定适合作为 WorkItem 完整标题来源。

---

# 4.4 Verification Fact

已有稳定 Verification ID 的语义：

```text
永远以最新唯一验证清单为准。
```

例如：

```text
E-K1I-02
```

不得因为其他文档出现“Build PASS”，重新利用此 ID。

规则：

> Stable ID semantics are immutable.

已有 ID：

不得改变业务含义。

---

# 4.5 Decision Truth

Plan / ADR / 实施蓝图内容：

```text
正式专项蓝图
>
历史草稿
>
待办中的简要说明
```

# 5. 迁移的基本原则

## P2-R01 — Incomplete but Truthful

允许 Graph 暂时不完整。

禁止：

> 为了完整而猜数据。

---

## P2-R02 — No Silent Conflict Resolution

如果两个高优先级 Truth Source 真正矛盾：

不得自行选择其中一个然后不记录。

必须写入：

```text
MIGRATION_CONFLICT
```

并在当前子阶段最终报告中列出。

---

## P2-R03 — Stable ID Preservation

已有：

```text
I*
J*
K*
L*
AF-*
E-*
...
```

一律保留。

禁止重编号。

---

## P2-R04 — No ID Reuse

已有 ID 的语义一旦确认：

永远不能重新分配给别的实体。

---

## P2-R05 — Current State First

Project Graph 是：

> 当前项目结构化记忆。

不是历史档案数据库。

Phase 2 优先迁移：

```text
当前 backlog
当前 ready
当前 in_progress
当前 blocked
当前 verifying
当前 parked
当前重要 recently-completed work
所有当前 required verification
所有与当前 Feature 状态相关的 Plan
```

---

## P2-R06 — 不全量迁移历史坟场

旧待办中已经长期归档、对当前项目没有任何引用的历史完成项：

Phase 2 不要求全部进入 Graph。

例如：

```text
几十个已经关闭多年且没有当前关系的归档事项
```

继续留在历史 Markdown。

这样避免：

```text
Graph越来越大
AI Index浪费Token
历史噪音污染当前状态
```

只有以下历史完成事项需要迁移：

1. 当前 Feature 状态需要它解释；
2. 当前 Plan/Verification 依赖它；
3. 当前 WorkItem 引用了它；
4. 重大架构决定；
5. 当前 SESSION / BLUEPRINT_STATE 明确引用。

```text

正在编码
→ in_progress

明确受外部条件阻塞
→ blocked

→ review
```


# 8.1 Plan 生命周期正式冻结

Plan status 描述：

> Decision / Implementation Artifact 自身生命周期。

与 WorkItem Verification 状态分离。

正式语义：

```text
draft
= 蓝图仍在起草，未获设计接受

reviewing
= 蓝图正在挑战/审核

accepted
= 蓝图已冻结，可实施，但尚未完整实施

implementing
= 已开始按蓝图编码，但蓝图要求的实施步骤尚未全部代码交付

completed
= 蓝图要求的代码/文档实施步骤已经交付并完成设计/架构验收

superseded
= 已被新的 Plan 取代
```

重要：

```text
Plan completed
不等于
WorkItem done
```

例如：

```text
Plan = completed
WorkItem = verifying
Device Verification = pending
```

这是合法且常见的。

---

# 8.2 Phase 1 遗留：PLAN-AI-NDJSON

如果：


```text

```


# 8.5 自动 Test / Build 到底是什么

这是 Phase 1 明确延后的重要问题。

Phase 2 正式冻结：

> 普通构建命令、测试命令的某一次执行结果，默认属于 Observed Fact，不自动成为 Verification Entity。

例如：

```text
./gradlew test
exit=0
```

属于：

```text
Observed
```

不是自动创建：

```text
E-XXXX
```

---

只有满足以下条件才成为 Verification：

1. 蓝图/验收标准明确给它稳定验证语义；
2. 有稳定 Verification ID；
3. 它本身就是一个明确验收项。

因此禁止再次发生：

```text
“Build通过”
→ 抢用 E-K1I-02
```

---

# 8.6 Phase 2 不实现 Observed Store

```text

```

Phase 2 只冻结规则。

不为所有历史 Gradle command 创建节点。

# 11. Source Provenance — Phase 2A 必须补的最小能力

```yaml

  - .ai-context/docs/feature/xxx.md
```

# 11.1 支持实体

增加可选：

```text

WorkItem.source_refs
Plan.source_refs
Verification.source_refs
```

```text
array[string]
```

# 11.2 source_refs 语义

表示：

> 支持该实体身份、状态、计划或验证语义的仓库内权威来源。

不是：

> 把所有提到它的文档都列出来。


```text

```

# 12. Migration Notes

Phase 2 允许新增：

```text
.ai-context/project_graph/migration/
```

仅用于迁移过程。

例如：

```text
PHASE2_CONFLICTS.md
PHASE2_INVENTORY.md
```

它们：

> 不是 Project Truth。

Phase 2 完成后可以保留为迁移审计记录。

不能让未来 AI 默认读取。

# 14. Phase 2 最终验收

Phase 2E 后必须满足：

1. Feature Registry 真实。
2. 每个 Registry Feature 有 Feature shard。
3. CodeMapping 不含虚假路径。
4. 当前重要 WorkItem 均属于 Feature。
5. 无 ID 当前事项已获得稳定 ID。
6. Plan 均关联真实 WorkItem。
7. Plan lifecycle 语义一致。
8. K1g/K1i/L1/K1a 等当前主线状态真实。
9. 最新 Verification 清单全部结构化。
10. Verification ID 无语义复用。
11. Pending/pass 数量与源清单一致。
12. 每个 Verification 有 WorkItem。
13. CurrentWork 与 SESSION 一致。
14. BLUEPRINT extension 与现状一致。
15. 无未处理高优先级 MIGRATION_CONFLICT。
16. Graph tests PASS。
17. pg check PASS。
18. mode 仍为 draft。
19. Phase 3 未开始。
20. 生产行为完全未修改。
