# Cookbook Project Graph — Phase 1 实施指令 V2.0

## 任务性质

本任务是：

> Project Graph Phase 1 — Model Contract。

目标是建立 Project Graph 的基础协议与验证骨架。

本阶段**严禁进行 Cookbook 全量状态迁移**。

完成后必须停止，提交并等待架构复审。

---

# 1. 基准原则

本 Project Graph 遵循：

```text
Code = Runtime Truth

Project Graph = Project State Truth

Plan / ADR = Decision Truth

Generated Markdown = View
```

Project Graph：

```text
AI Maintained
Human Read-Only
```

# 8. Feature

Feature 表示：

> 长期稳定的产品或系统能力。

不是：

* Screen；
* ViewModel；
* Class；
* 临时开发阶段；
* 当前方案。

Feature ID：

```text
F-XXX
```

一旦正式启用应长期稳定。

---

必须结合真实项目重新确认。

> Registry设计 + 少量样例。

必须记录调整理由。

# 17. Relation Model

Relation必须成为正式概念。

至少支持：

```text
belongs_to
implemented_by
verified_by
depends_on
blocks
affects
supersedes
related_to
```

要求：

* source存在；
* target存在；
* 不允许非法自引用；
* depends_on不得形成明显非法循环；
* supersedes语义有方向。

---

# 18. Typed Reference

设计上必须支持：

```text
feature:F-AI-MEAL
work:K1g
plan:PLAN-AI-X
verify:E-X
```

存储格式可以保持简洁：

```yaml
feature: F-AI-MEAL
```

Validator内部可标准化成 Typed Reference。

---

# 19. Declared / Observed / Derived

README和Schema设计必须正式区分：

## Declared

AI维护：

```text
status
feature relation
plan relation
priority
intent
```

## Observed

工具获取：

```text
commit
changed files
test exit code
timestamp
```

## Derived

程序计算：

```text
open bug count
pending verify count
activity
health
affected features
```

必须明确：

> 能 Derive 的值禁止成为需要 AI 手工重复维护的必填字段。

---

# 20. Code Mapping

Feature Schema必须支持：

```yaml
match:
```

例如：

```yaml
match:
  - shared/**/ai/meallog/**
  - androidApp/**/AiMeal*
```

同时支持：

```yaml
code:
  entry:
  ui:
  viewmodel:
  domain:
  data:
  core:
  tests:
  other:
```

所有字段除必要核心外可以是可选。

# 45. 本阶段最终目标

Phase 1不是“把 Project Graph 做出来”。

Phase 1只负责：

> 把 Project Graph 的语言定义正确。

后续几百个项目状态节点都会建立在这个语言上。

因此优先级是：

```text
正确
>
简单
>
可扩展
>
实现速度
```

避免为了未来可能永远不存在的需求过度设计。

最终应得到：

```text
小而稳定的核心Schema
+
清晰的Relation模型
+
可运行Validator
+
少量Proof of Concept
```

而不是一个复杂平台。
