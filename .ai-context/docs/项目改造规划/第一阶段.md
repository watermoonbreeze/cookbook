> Project Graph 第一阶段：基础模型、Schema、ID规则、状态机、关系模型和基础Validator。

# 二、本阶段目标

新增：

```text
.ai-context/project_graph/
```

建立 Project Graph V1 基础结构。

Project Graph 当前必须标记：

```text
mode: draft
```

不得修改现有项目真相优先级。

不得让其他 AI 开始依赖此 Graph。

---

# 三、必须设计并实现

## 1. Schema

必须能够表达：

```text
Project
Feature
WorkItem
Plan
Verification
Relation
CurrentWork
CodeMapping
```

---

## 2. ID规则

必须考虑 Cookbook 已存在：

```text
I*
J*
K*
L*
```

这些 WorkItem ID 必须原样保留。

不得重新编号。

没有稳定ID的事项未来再补。

---

## 3. Feature ID

根据真实 Cookbook 功能体系设计第一版 Feature Registry。

Feature ID必须：

```text
F-XXX
```

语义稳定。

不得按当前临时方案、页面或代码类命名。

Feature代表长期产品能力。

---

## 4. 状态机

实现并文档化：

### WorkItem

```text
backlog
ready
in_progress
blocked
review
verifying
done
parked
cancelled
```

### Plan

```text
draft
reviewing
accepted
implementing
completed
superseded
```

### Verification

```text
pending
pass
fail
blocked
not_required
```

### Feature lifecycle

```text
planned
active
mature
deprecated
```

不要允许自由字符串状态。

---

## 5. Code Mapping

Feature Schema必须支持：

```yaml
match:
```

用于未来：

```text
git diff
→ Feature
```

匹配。

同时支持核心代码路径分类：

```text
entry
ui
viewmodel
domain
data
core
tests
other
```

字段无需全部必填。

---

# 四、推荐目录

可根据实现略调，但必须保持简单：

```text
.ai-context/project_graph/
├── README.md
├── schema.yaml
├── project.yaml
├── features/
└── tools/
```

不要为了架构漂亮增加大量无必要目录。

---

# 五、Validator

第一阶段至少实现基础：

```text
project_graph check
```

命令名称可根据项目实际调整。

必须验证：

1. YAML可解析。
2. Project Graph版本存在。
3. ID唯一。
4. Feature引用存在。
5. WorkItem Feature引用存在。
6. Plan引用存在时必须有效。
7. Verification引用存在时必须有效。
8. depends_on / blocks 不得指向不存在节点。
9. 状态必须属于Schema定义。
10. 禁止明显循环或非法自引用。
11. Feature Code Mapping格式合法。

---
