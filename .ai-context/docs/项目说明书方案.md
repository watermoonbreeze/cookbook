# 通用项目说明书 · 框架规范（方案，待 review）

> [AI生成] 2026-07-17。面向"AI 主导编码、开发者做方向+审核"的新研发模式，定义一套**与具体项目无关、可迁移复用**的项目说明书框架规范。
> 本文件只描述**框架与规范**（分册怎么分、每册装什么、怎么生成与维护），**不含任何具体项目的业务内容**；应用到某项目时才按此规范生成该项目的实际文档。
> 已定基调：① 多分册 + 总索引 ② 落实成可重复运行的技能（通用、可迁移） ③ 项目独有的复杂领域逻辑单列"专属册"、不进通用模板。

---

## 一、目标与使用场景（框架要解决什么）

面向开发者定位上移（定方向 + 审核，不逐行看代码）的场景，说明书须满足三用途：

1. **掌握全貌**：一份文档看懂"有哪些模块、各模块职责、整体架构、当前状态"。
2. **反查定位**：从"界面/行为的某个现象"能反查到它的**操作逻辑、数据来源、代码位置**，据此判断是 **bug 还是需求**。
3. **审核抓手**：核对"实现是否符合既定业务/技术方向"。

## 二、两条分层原则（框架的核心约束）

1. **通用册 vs 专属册分离**
   - **通用册**：架构 / 业务流程 / 界面 / 数据 / 约定 / 对照表——**任何项目都有**，由可复用技能产出，模板不含业务专有词。
   - **专属册**：某项目**独有的复杂领域逻辑/领域知识**（算法口径、行业标准、合规免责等）——**单列成册，不进通用模板**，由该项目自行维护。判据：内容是否可迁移到别的项目，不可迁移即入专属册。
2. **人读优先，非代码搬运**：用业务语言归纳"是什么、为什么、与谁相关"，不粘贴代码；代码位置只在"对照表"里作反查指针。

## 三、通用分册框架（每册装什么，项目无关）

存放约定：`<项目文档根>/项目说明书/`，以 `00_导读与索引` 串联。各册职责固定，内容按应用的项目填充。

| 分册 | 职责（装什么） | 主要服务的用途 |
|---|---|---|
| `00_导读与索引` | 项目一句话定位 + 模块全景 + **"遇到某类问题→看哪册哪节"的快速定位表** + 阅读顺序 + 术语表 | 反查总入口 |
| `01_架构与技术底座` | 分层架构、模块划分、技术栈与版本、构建入口、依赖注入、**通用平台能力清单**（存储/权限/日志/网络/备份/等，按项目实际有什么列什么） | 基础，非业务 |
| `02_业务流程全景` | 逐个主流程一节，统一模板：**入口 → 关键步骤 → 涉及功能 → 技术点 → 与其他流程的关系**。流程清单由应用项目列出 | 业务流程与功能关系 |
| `03_界面与交互` | 页面清单（每页职责/入口/关键状态）+ 交互模式与规范 + 可复用组件清单 + 主题/样式体系 | 界面 UI + UX |
| `04_数据层` | 数据分层（用户生成数据 / 基础预设数据 / 外部参考数据）、持久化结构与关系、配置项、数据生命周期（建/迁移/软删/备份/同步） | 数据层 |
| `06_约定与红线` | 踩坑红线、质量门禁、代码/注释规范、版本管理约定 | 工程约定 |
| `99_功能↔代码↔文档对照表` | 三列：功能/现象 → 关键代码位置(文件:符号) → 文档章节。**把"现象→代码→文档"三者串起来** | 反查核心 |

> 编号留空档（05 等）给"专属册"，使通用册与专属册在同一目录自然排序、又互不污染。

## 四、专属册规范（项目独有逻辑的收纳位）

- 当项目存在**独特且复杂**的领域逻辑/知识（如某类算法、行业标准口径、合规与免责），单列 `NN_<主题>（专属）` 一册。
- 专属册**不由通用技能生成正文**，技能只为它留占位与链接；由项目自身维护，可引用项目内已有的方案/依据文档，做"汇总导读"而非重复正文。
- 通用技能在识别到疑似专属内容时，应**提示单列**，不塞进 `02/04` 等通用册。

## 五、可复用技能设计（落实成通用方法）

**目标**：一条命令扫描当前代码库，(重)生成/刷新**通用册**并保持与代码同步；专属册只留占位。

**技能能力（规范）**：
1. **扫描**：模块与包结构、页面/路由清单、持久化结构与查询、依赖注入、领域层与数据层入口、既有交互/组件规范文档。
2. **生成**：按分册模板填充；清单类（页面/表/流程）自动列全，逻辑描述由 AI 用人读语言归纳。
3. **维护模式**：
   - 全量刷新（结构性变化后重扫重生成通用册）；
   - 增量更新（只刷新指定册/指定流程）；
   - 对照表维护（`99` 随功能增改更新）。
4. **可迁移**：模板零业务词，换项目即用；遇专属内容提示单列。

**触发**：`/项目说明书`（全量）、`/项目说明书 <册号>`（单册）、自然语"更新项目文档"。

**可选加严**：接入提交流程——每完成一个功能，增量更新受影响的一节 + `99` 一行，防文档腐化。

## 六、应用到具体项目的步骤（框架落地流程）

1. 建目录 + `00 导读索引` 骨架 + `99 对照表` 骨架。
2. 先产核心三册看效果：`02 业务流程全景`、`03 界面与交互`、`04 数据层`。
3. 反馈后补齐 `01 / 06`，并按需单列专属册。
4. 将生成/维护固化为可复用技能。
