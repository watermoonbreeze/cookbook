# 通用项目说明书 · 框架规范（方案 v2，待 review）

> [AI生成] 2026-07-17。面向"AI 主导编码、开发者做方向+审核"的新研发模式，定义一套**与具体项目无关、可迁移复用**的项目说明书框架规范。
> 本文件只描述**框架与规范**（分册怎么分、每册装什么、每页怎么写、怎么反查），**不含任何具体项目业务**；应用到某项目时才据此生成该项目实际文档。
> v2 已由 **Apple 信息架构师 + Apple 技术文档设计师** 双角色设计强化。基调：① 多分册+总索引 ② 落实成可重复运行的技能 ③ 项目独有复杂领域逻辑单列"专属册"不进通用模板。

---

## 一、目标与使用场景

面向开发者定位上移（定方向+审核，不逐行看代码），说明书须满足三用途，且**每一册/每一节开头都要点明自己服务哪一种**：

1. **掌握全貌**（learn）：看懂"有哪些模块、各模块职责、整体架构、当前状态"。
2. **反查定位**（solve）：从"界面/行为的某现象"反查到**操作逻辑、数据来源、代码位置**，判断是 **bug 还是需求**。
3. **审核方向**（review）：核对"实现是否符合既定业务/技术方向"，并能查到方向何时、为何而定。

## 二、两条分层原则

1. **通用册 vs 专属册分离**。通用册=架构/流程/界面/数据/诊断/约定/现状/决策——任何项目都有、由技能产出、模板零业务词；专属册=项目**独有且复杂**的领域逻辑/知识（算法口径、行业标准、合规免责）——单列、不进通用模板、人工维护。**判据**：内容"换个项目就不成立"→ 专属。
2. **人读优先，非代码搬运**。用业务语言归纳"是什么、为什么、与谁相关"；代码位置只作反查指针出现在参考层/对照表，正文不嵌代码。

## 三、分册框架（编号 0x=通用骨架 / 2x=专属，物理分区防污染）

存放：`<项目文档根>/项目说明书/`，`00` 串联。**编号前缀固定**（保证任何文件系统/索引排序一致，是寻路的物理基础）。

| 分册 | 心智模式 | 职责（装什么） |
|---|---|---|
| `00_导读与索引` | learn 入口 | 一句话定位 + **模块全景图** + **任务导向阅读路径** + 术语表 + 状态图例（全套唯一） |
| `01_架构与技术底座` | learn | 分层架构、模块划分、技术栈与版本、构建入口、依赖注入、**通用平台能力清单**（按项目实际有什么列） |
| `02_业务流程全景` | learn/solve | 逐主流程一节，统一"流程条目"模板 |
| `03_界面与交互` | learn/solve | 页面清单（统一"页面条目"模板）+ 交互规范 + 可复用组件 + 主题体系 |
| `04_数据层` | learn/solve | 数据分层（用户生成/预设基础/外部参考）、结构与关系、生命周期（建/迁移/软删/备份/同步），统一"数据条目"模板 |
| `05_诊断地图` ★ | **solve 入口（一等公民）** | 反查总入口：现象→逻辑→代码→判据，**≤2 跳 SLA**（见 §四） |
| `06_约定与红线` | 全局 | 踩坑红线、质量门禁、代码/注释规范、版本管理约定 |
| `07_项目现状（活视图）` ★ | learn/review | at-a-glance 健康度：已实现/进行中/待办、已知缺陷、最近变更。**随开发刷新** |
| `08_决策记录（ADR-lite）` ★ | review | 追加式只增不改，每条 背景→选项→决定→影响。支撑"审核方向" |
| `20_<主题>（专属）` | 视内容 | 项目独有复杂逻辑；技能只留摘要卡+页脚占位，正文人工维护 |

> 相比 v1：`99 对照表`升级并入 `05 诊断地图`（以现象为主键，非静态映射）；新增 `07 活视图`、`08 决策记录`；专属册从 `20` 起编号、与通用册视觉分区（不再插空号）。

## 四、诊断地图 `05`（反查一等入口，≤2 跳）

**为什么独立成册**：`00` 是"读文档"入口（learn），`05` 是"救火/审核"入口（solve）——两种心智不同，分开才不互相稀释；诊断是审核者高频动作，须最短路径可达。

**寻路承诺（写进册首）**：从任一现象出发 **≤2 跳**到代码位置或红线条目——第 1 跳进 `05` 分诊台，第 2 跳落到目标行/册节。三层均为统一行模板：

- **层 A · 症状分诊台**：`现象类别 | 典型描述(读者语言) | 首查册·节 | 一句话诊断提示`。现象类别用跨项目通用的症状范式（"某数据算错/某页空白/某操作没反应/某处样式不对"），零术语也能命中。
- **层 B · 现象→链路（核心）**：`现象 | 触发路径 | 涉及流程(02) | 数据来源(04) | 代码位置(文件:符号) | bug/需求判据`。一行串起流程/数据/代码/判据。
- **层 C · 已知坑索引**：`症状特征 | 对应红线条目(06) | 快速验证方法`。

## 五、统一条目模板（一致性=读者的肌肉记忆）

每类内容强制字段模板，技能生成/校验时缺字段即报警。

- **流程条目(02)**：`一句话目的 / 入口 / 前置条件 / 关键步骤(有序·人读) / 涉及页面(→03) / 涉及数据(→04) / 关键技术点 / 关联流程 / 已知坑(→05)`
- **页面条目(03)**：`职责一句话 / 入口路径 / 关键状态(空·加载·错误·正常·无权限) / 主要操作(动词开头) / 复用组件 / 触发流程(→02) / 读写数据(→04)`
- **数据条目(04)**：`属于哪层 / 用途 / 关键字段(语义关键·非全量DDL) / 关系 / 生命周期 / 被谁读写(→02) / 注意事项(→06)`
- **诊断条目(05)**：见 §四三层
- **决策条目(08)**：`标题 | 日期 | 状态(生效/被取代) / 背景 / 选项 / 决定 / 影响(→受影响册)`

## 六、写作与阅读体验规范

**五条统领**（写任何一句话前默念）：清晰>完整 · 以读者为中心 · 渐进披露 · 单一真相源 · 可扫读。

**写作守则清单**（自检）：
- [ ] 开头先"是什么+为什么"，再"怎么样"（**What→Why→How，永不倒装**）
- [ ] 每个模块/流程/页面/功能条目正下方第一行是**「一句话说明」**：`**<名称>** — <是什么>，<为解决什么问题/何时用>`
- [ ] 用"你"称呼读者，主动+现在时；鼓励而非训导
- [ ] 一句一义，删掉可删的词；具体优于抽象
- [ ] 三项以上用列表/表格，不堆进段落（**能结构化的一律表格化**）
- [ ] 术语与术语表、界面、代码实际叫法一致（一物一词）
- [ ] 正文无代码块；实现细节归纳成"行为+口径"，代码位置只在参考层/`05`
- [ ] 事实只写一处，其余**链接**（语义化锚文本），绝不复制粘贴
- [ ] 每个功能/交互条目带一行**「预期行为」**：`<什么条件下 → 什么可观察结果>`（**反查支点**：现象==预期→需求；现象!=预期→bug；须可观测可证伪）
- [ ] 页尾有时效元数据（见 §八）

**标题**：最多三层（`#`册/`##`章/`###`节），标题写有信息量的名词短语，只读标题就能拼出全貌。

## 七、渐进披露（同一文档兼顾速览与深挖）

- **每册顶部 at-a-glance 摘要卡（强制）**：`这册讲什么(一句话) / 服务用途(掌握全貌·反查·审核 勾选) / 装什么(3–5点) / 不装什么(边界·指向别册) / 配套速查(锚链)`。
- **三级信息密度**：`概览层`（一句话说明+心智模型+关系，速览/定位）→ `细节层`（行为规则·状态·口径·边界·为什么这么设计，判 bug/需求）→ `参考层`（`文件:符号`·表结构·配置键·版本，下钻）。概览永远在前；参考层尽量外链 `05`/代码不内嵌。读者读到够用即停。
- **任务导向阅读路径（放 `00`）**：`掌握全貌→00→01→07` / `审核实现→05→目标册→08` / `遇到现象→05 分诊台`。用意图选路替代线性目录。

## 八、时效与可信（AI 生成文档的信任基础）

每册/每节页脚固定元数据条：
```
最后更新：YYYY-MM-DD · 对应代码版本：<commit短哈希/tag/分支> ·
置信度：🟢已核对代码 | 🟡AI推断待核 | 🔴仅规划未实现 · 维护方式：技能生成 | 人工维护
```
- 置信度让审核者一眼分辨可信度；对应代码版本是新鲜度锚（代码版本≫文档记录=可能过时）。
- 变更频繁的册（界面/流程）元数据到**每节**，稳定册到**每册**。技能刷新自动回填时间与版本，置信度默认 🟡、人工核对升 🟢。

## 九、单一真相源与交叉引用

- 同一事实只在其**归属册**权威描述一次（结构→04、流程→02、界面→03、口径→专属册），别处**引用不复制**（复制=文档腐化头号来源）。
- 交叉引用写 `→ 册号·稳定锚`，不写页码/行号。流程↔页面↔数据三者就近双链成闭环。
- `05 诊断地图`是引用汇聚点；`07 现状`/`08 决策`是叶子（被指向、少指出）。
- **状态图例、术语表、时效格式**统一沉淀 `00`，各册引用同一份、不自造。

## 十、可迁移性保证（换项目即用）

1. **占位符协议**：模板字段用 `<...>` 占位（`<流程名>`/`<结构名>`/`<现象>`），规范本体只有占位符，天然零业务，生成时才由扫描结果填充。
2. **0x/2x 编号分区**：通用骨架 0x、专属 2x，从物理上防业务内容渗入通用册。
3. **专属判据**：内容"换个项目就不成立"即判专属，技能只留占位+链接、不生成正文，并提示单列。
4. **诊断现象用症状范式**：`05` 层 A 现象类别用跨项目通用症状（数据算错/页空白/操作无反应），具体业务现象生成时填入。

## 十一、可复用技能设计 `/项目说明书`

**目标**：一条命令扫描代码库，(重)生成/刷新**通用册**并保持与代码同步；专属册只留占位。

- **扫描**：模块与包结构、页面/路由清单、持久化结构与查询、依赖注入、领域/数据层入口、既有交互/组件规范。
- **生成**：按 §五模板与 §十二骨架填充；清单类（页面/表/流程）自动列全，逻辑描述由 AI 用人读语言归纳；页脚元数据自动回填、置信度默认 🟡。
- **诊断地图初稿**：把清单类条目自动铺进 `05` 层 B（数据/代码列可自动填，现象列待人工补），校验每条 ≤2 跳可达。
- **完整性校验**：按 §五模板逐条查缺字段，缺失即在 `07 现状`标"文档待补"（腐化可视化）。
- **维护模式**：全量刷新 / 增量（指定册·流程）/ 诊断表与对照维护。
- **触发**：`/项目说明书`（全量）· `/项目说明书 <册号>`（单册）· 自然语"更新项目文档"。
- **可选加严**：接入提交流程——每完成一个功能，增量更新受影响的一节 + `05` 一行。

## 十三、落地流程

1. 建目录 + `00 导读索引`骨架 + `05 诊断地图`骨架。
2. 先产核心三册看效果：`02 业务流程` `03 界面` `04 数据`。
3. 反馈后补 `01/06/07/08`，按需单列专属册。
4. 生成/维护固化为 `/项目说明书` 技能（全局放 `~/.claude`、可跨项目复用；文档放各项目内）。
