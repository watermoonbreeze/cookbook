- 待查：已连接真机 logcat、截图/输入原文、`AiMealParser`/Rule parser 时间词处理、UI 诊断入口。

## 证据与结论

- 证据：`temp/db/2026-08-04(4).log` 15:47:24 / 15:48:46，DeepSeek HTTP 200 且返回当前 Flat `items` 协议；截图 `pic_1.jpg` 显示规则降级后把“八月十五号”“八月十六号”建为菜。
- AI 失败根因：模型可选文本字段返回 `meal_note: null`、`dish_note: null`；当前 Kotlin `FlatMealItem` 对应字段为非空 `String`，Json decode 因显式 null 失败，再被压缩成“AI 响应无有效结果”。
- 时间/日期成菜根因：`TextSegmenter` 只识别阿拉伯数字日期（如 `8/15`、`8月15日`），不识别中文数字日期“八月十五号”；AI 失败降级后，日期前缀留在 `RuleMealParser` 菜品文本内。
- 安全项：`CloudAiRuntime` 当前仍把完整 prompt 与 HTTP 响应写入本地日志，需改为仅保留脱敏元数据；本次详情需求应使用仅当前页面内存诊断，不以日志为展示来源。
