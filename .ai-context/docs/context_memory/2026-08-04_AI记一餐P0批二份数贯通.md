# AI 记一餐 P0 批二：份数贯通

- 需求：AI 菜品份数需持久化并进入摄入、营养计算；新版本无需兼容旧协议，但数据库历史记录必须安全迁移。
- 级别/模式：深度；用户已授权在 P0 方案下继续。
- 目标链路：Flat `dish_quantity` → `meal_record_dish.serving_multiplier` → 摄入 = 整份营养 × 份数 × eaten_ratio × 成员份额。
- 关键风险：SQLDelight 迁移默认值、已有记录解释为 1 份、共享/成员份额的乘法次序、报告重算与不可重复写入。
- 验收：迁移后旧记录默认 1；两份菜营养严格为一份的两倍；eaten_ratio 与成员份额继续生效；单测、shared 测试、Android 构建、真机验证清单。
- 工作区：`temp/` 的修改和未跟踪 context_memory 文件为历史/本地内容，不属于本批提交范围。
