## AI 推荐页 = 三档（一个页面）
`AiRecommendScreen` 顶部 FilterChip 三档：**库存推荐 / 随机推荐 / 周期计划**。
- 库存/随机：扁平**勾选列表**(每菜名+说明+Checkbox)，底部「确定」回传所选 id（`onPickMeal`）。数据取 `result.candidates`(健康排序,已轮转)top12。
- 周期计划：内嵌 `AiPlanBody`(无 Scaffold)，底栏切「保存为未来N天计划」。
- 独立的 AI_PLAN 路由/我的入口已**移除**(并入本页)。改名：全部「AI 推荐下一餐」→「AI 推荐」。

## 餐次入口(从餐次块进 AI 推荐)
- `AddDayFoodScreen` 每个餐次块内有 AI 推荐图标(顶栏的已移除)。从块进 → `aiRecommendForMeal()`(returnResult=true) → 「选它/确定」→ `savedStateHandle[KEY_AI_PICKED_DISHES]` 回传 → 加到发起的餐次块(`aiTargetBlockId`)，不新开页。从首页进(returnResult=false)则新开加餐页预填。
- **关键 bug 修复**：预填(presetDishIds)在路由里返回时不变，需 `presetApplied` 守卫**只应用一次**，否则返回重载清掉用户新加餐次块。见 `configure(editDate, presetDishIds)`。

## 周期规划(PeriodPlanner + 取数 + AI)
- **规则核心** `PeriodPlanner`(纯函数,7单测)：天数1~30；忌口硬剔除；应季**软优先**(加分,非硬性)；营养维度新颖度；去重(同菜/主料降权)；健康(有档案保≥80%,"选不健康会跌破则强制健康");**每菜随机抖动**(0.5<应季0.8/健康0.6)让每次生成不同。
- **餐次适配(中式)**：`PlanDish.isBreakfast`(菜名含 粥/蛋羹/豆浆/牛奶/燕麦/面/馒头/薯/南瓜/玉米 判定)；早餐档只从早餐菜选，且**软硬搭配**(`breakfastSoft`：偶数位硬/主食、奇数位软/饮，如 紫薯+牛奶)。加了 9 道中式早餐菜(小米粥/水煮蛋/豆浆/蒸蛋羹/燕麦牛奶/阳春面/蒸红薯/蒸紫薯/煮玉米)。**周期规划只早/中/晚**(过滤 BREAKFAST/LUNCH/DINNER)。
- **取数** `RecommendationDataSource.gatherForPlan()`：全库菜→PlanDish(营养/应季标签查询 selectNutritionSeasonTags、健康标记、季节按月份)。
- **AI 优先** `PlanOrchestrator`：`isModelReady()` 则模型排N天(候选标注餐次/营养/应季/利健康,遵膳食指南)→解析校验(id⊆候选,完整)→用AI(🤖)；失败/无key回退规则(📋)。`planDishReason` 共用说明。
- **保存**：`AiPlanViewModel.save()` 逐天 `saveDayMeals(today+dayIndex, drafts)`——**整日替换**(会覆盖那些天已有餐食,注意)。
