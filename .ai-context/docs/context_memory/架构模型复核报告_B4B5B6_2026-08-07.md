**违反**：与 AF-B456-01 同源（双真相源）；B4 蓝图 §2 非目标「语音输入行为变更（快速记/周期记共用既有语音逻辑）」。

**证据**

```kotlin
// AiMealInputViewModel.kt:332-336

    val current = _state.value.inputText.trimEnd()
    val appended = if (current.isBlank()) text else "$current $text"
    invalidateGenerationToInput(appended, _state.value.targetDate)   // 只写 inputText
```

**禁止扩大范围**：不得改 `onVoiceResult` 的拼接分隔符与 `appendText` 的换行策略；不得引入新的语音状态字段。

## 七、写回共享规则的可复用根因（blueprint_protocol §4 要求）

以下两条为跨项目可复用根因，建议写回 `~/.ai-context/GLOBAL.md` 或对应经验分册；其余功能专属事实留在本项目文档。

1. **「重命名/新增状态字段时，必须同步迁移所有写入点，而不只是读取点」**
   本次 AF-01/02 的根因不是"忘了改某一处"，而是**新增了一个与既有字段语义重叠的状态字段**（`quickDraftText` vs `inputText`），却只把**读取方**（`submit()`）切到新字段，写入方（构造器、`onVoiceResult`、`appendText`、`invalidateGenerationToInput`）仍写旧字段。检查动作：新增与既有字段语义重叠的 state 字段时，先 grep 旧字段的**全部写入点**，再决定"派生（计算属性）/ 替换（删旧字段）/ 并存（禁止）"，**并存必须给出同步保证**。

2. **「UI 用计数反推逐项状态 = 隐性索引空间耦合」**
   AF-05 的根因是 UI 拿 `completedSegments`/`failedSegments`/`currentSegmentOrdinal` 三个**标量**去反推每个 item 的状态，而 `ordinal`（业务序号）与 `index`（列表下标）在过滤后不再相等。检查动作：凡"列表逐项状态"，**由数据层直接产出 `List<Status>`**，UI 只做映射；禁止用计数 + 下标比较反推。同类症状：`index < completedCount -> DONE` 这种写法隐含"成功项一定排在失败项前"的错误假设。
