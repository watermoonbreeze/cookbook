## 二、工作规则（当前任务域）

- **写真机验证判据前必须先读代码确认信号可查**：判据只能是①App 界面操作后能亲眼看到的现象，或②`adb logcat`/`AppLogger` 日志文件里能搜到的字样；不能写 App 内部从未暴露的计数（如"Delta 事件次数"）。已写入 `CLAUDE.md`，强制生效。
- **代码 + 已有单测覆盖到位 = 可直接判通过，不必强求真机目测**：这是用户本次现场确立的尺度（针对 E-CFG-03），不等于放松真机验证整体要求——区别是"判据要不要可观测"（必须）vs"验证方式必须是肉眼在真机操作"（有单测兜底时不必），两条规则不矛盾。
- **cookbook 本地 `feature_sync_check.py` 与用户级通用版独立维护，不做回指关联**（沿用上一场会话 D-25 通用化提取时的既定策略）：本次给两边分别加了"待办/缺陷简要清单"能力，是用同一设计思路各自实现了一遍，不是从一份同步到另一份。以后任一份改了想让另一份也有，需要显式做一次移植，不会自动带过去。
- 其余通用规则见 `.ai-context/rules/通用规则.md` + 全局 `~/.ai-context/GLOBAL.md`；架构/协作机制沿用上一场会话确立的 D-25（全景图纵轴 `projectReview/features/` 唯一真相源）。
