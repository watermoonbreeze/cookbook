# 数据驱动界面(UDF)架构审计 · findings 与整改路线（2026-07-21）

> 用户 2026-07-21 确立「数据驱动界面 + Android→Google/iOS→Apple 编码归口」准则后，由 `google_architecture_engineer`(架构符合度) + `google_quality_engineer`(代码质量) **全局审查** codebase 产出。**结论:整体健康**（架构符合度=中偏高·代码质量=高·UDF 系统性遵守·历史坑已收敛）。findings 均**入待办级、不阻断**，此处归档供**逐步专项整改**（非即时改）。

## 一、总体评价
- 22 个主 VM 普遍单一 `MutableStateFlow<UiState>` + 增量 `_state.value.copy(单字段)`，已系统性规避粘性字段丢失/并发写回冲字段；`stateIn(WhileSubscribed).value` 冻结坑规避（toggle 用 hot flow / 读实时 DB）；能力显隐由回调传入决定（非 mode 硬编码）；业务规则沉 `:shared` domain 可单测；三层清晰、无 N+1、无主线程 IO。**踩坑红线沉淀已把多数 UDF 陷阱收敛，代码带防守注释。**

## 二、findings（按价值排序·待专项整改）

### 🟡 系统性·优先
- ✅**F1 已修（`bed5a17`·Google 审无阻断·还修了空态粘性态误重置的潜在 bug）**：mapResult 接收 `prev`、内部 `prev.copy` 只改数据字段，粘性字段源头保留，2 调用点不再手动补。**剩(可选·非阻断)**:补回归守卫单测固化"recommend 清 selectedIds / setMedicinal 保留"契约——但 androidApp **无 VM 测试基建**(需搭源集+mock 5 依赖)，成本不匹配，暂 backlog(契约已由代码注释固化)。原问题↓：
- **F1（质量·复发根源）mapResult 重建 State 靠调用方 `.copy` 补粘性字段**：`AiRecommendViewModel.mapResult` 直接 `return AiRecommendUiState(仅~8字段)`，粘性字段(engineLabel/showNutritionHint/selectedSlot/recommendStyle/recentWindowDays/medicinalFilter)靠 2 处调用方手动链 `.copy` 兜。**防线在调用点非源头**→新增字段/新增调用点忘 copy 就静默丢用户选择(项目历史高频 bug 本体·本 session 加 showNutritionHint 就手动补了 2 处)。**改法**:mapResult **接收 `prev: AiRecommendUiState`**、内部 `prev.copy(仅改数据字段)`，粘性字段天然保留，调用方只设 engineLabel。风险中(用户可见选择丢失·难测)。**范式级根治·优先做**。
- **F-Arch1/2/3（架构·无 VM 页 VM 化专项·D1）**：少数页把业务态+数据访问下沉 Composable。**进度 2026-07-21**：
  - ✅**F-Arch3 `CookModeScreen` 已修**(`354fd1b`·Google 架构审无阻断)：直注 DishRepository→抽薄 `CookModeViewModel.observeDish`(mirror DishDetailViewModel)；index/计时态纯 UI 瞬态按结论保留 Composable。
  - ✅**F-Arch2 `FamilyScreen` 成员编辑区已修(最小修法·Google 架构审)**：**唯一真正越层=`koinInject<IngredientRepository>()` 查名**已移出→`FamilyViewModel.ingredientNamesByIds` + `MemberEditorScreen(onResolveNames=vm::…)` 回调下传(同 careOptions 下传范式)。**未抽完整表单 VM**——准则 A 明确背书"表单本地态作写回单一真相源+hydrated 守卫"(现 ingLoaded 守卫+防数据丢失修复=该范式)，重写风险高收益低，故 20+ 本地态/isDirty 原样保留。**F-Arch2 越层已结案**。

### 🟡 机制/约定
- **F-Arch6（治理）UI 层散落 `koinInject<*Repository>` 缺门禁**：24 Screen 72 处 koinInject/data import(其中 F-Arch1/2/3 是真越层)。**加约定**:「Screen/组件不得注入 Repository」写进 `.ai-context` 规范 + 轻量 grep 门禁扫 `*Screen.kt` 的 `koinInject<*Repository>`(防复发)。
- **F-Arch4（约定二选一）Screen 直注 PreferenceRepository 读 flag**：HomeScreen/DishDetailScreen/NewDishScreen 各在 Composable `observeFlag`。轻量只读但边界渗漏。**二选一定死**:并入 VM UiState / 或明确"只读全局偏好 flag 允许 UI 直取"写进规范(别两可)。
