# 会话快照：库存份数体系（2026-07-10）

> [AI生成] 结论性快照，供跨会话续接。

## 需求（用户确认的最终模型）
库存食材带**份数=可做几次菜**；每道菜按 **1 份**算（预设剂量/自建"适量"都算 1 份）。
核心=**派生占用**：份数只由用户改，做菜不改库存数字；不足是实时按时间序算出来的（所以加份数能让早的餐先恢复，7.4/7.5 例子）。

规则：
- 所有餐食(含计划)用到某在库食材的菜按 date→meal_time→created_at→sort_order 排队，前 `份数` 个够、其余不足；不足菜半灰+"缺:X"。
- 剩余 = max(0, 份数 − 今天及过去占用)；计划参与排队但不减剩余、不占推荐额度。
- 0 份不消失可续加；手动出库(status=0+份数清零)才移除。
- 库存推荐：不足也推荐但大幅降权排后 + 标"⚠库存不足:X"（不过滤）。
