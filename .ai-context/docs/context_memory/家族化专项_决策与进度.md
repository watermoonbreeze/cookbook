## 二、载体路由化的架构阻断（本会话读码发现·关键）
`IngredientPickerScreen` 一体两用：既是**食材 Tab 落地页**（有 nav），又是 `asDialog=true` 的**全屏 Compose Dialog 选择器**（selectionMode，选食材进菜品/餐食）。食材编辑器从两种模式都能打开。
- **阻断**：从 Compose `Dialog{}` 内 push nav 路由会异常；且此时全屏 Dialog 会**遮住** MainScaffold 的统一 Snackbar 宿主（现有代码正因此在 dialog 内用 Toast）。
- **推荐落法**（无人值守·凡拍板用推荐方案）：先抽共享 `IngredientEditorContent`；Tab 入口做真 nav 路由页（得统一 Snackbar）；选择模式内保持原地全屏 surface 复用同一 Content（Snackbar 被遮→Toast 占位·架构限制）。**载体完全统一需先把"选择器本身"路由化（更大重构·易砸核心选食材流程）→ 拆为紧随子批**。
