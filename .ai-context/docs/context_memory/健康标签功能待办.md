# 健康标签功能（待办）

> 更新时间：2026-05-17

## 背景

用户提出：添加菜品时希望能直观看到菜品的健康属性（低/中嘌呤、高糖、高脂等），方便筛选。

## 当前规划现状

- **数据库层**：`food_category.dimension` 已预留 `purine`、`gi` 等维度，`ingredient_nutrient`、`crowd_ingredient`、`dish_crowd` 表已设计，但**全部划到一期**。
- **MVP 阶段**：未包含任何健康维度的表与 UI。
- **界面层**：`界面探讨.md` 的添加菜品弹窗完全没有健康属性展示与筛选入口；待讨论第 4 项只提到荤素/主食分类，未覆盖健康维度。
- **现有 dish_crowd 仅用于"人群风险提示"**（红/黄/绿警告），不是"低嘌呤/高糖"这种客观属性标签——两者诉求不同。

## 已评估的方案（未决策）

### 方案 A：轻量级（建议 MVP 收口）

- 新增 `dish_health_tag` 表，给菜品打"嘌呤等级 / 升糖等级 / 脂肪等级 / 钠等级"等粗粒度标签，手动维护
- 添加菜品弹窗每道菜显示标签 chip：`西红柿炒蛋 [低嘌呤][中糖]`
- 弹窗顶部加按标签筛选
- 成本：2–3 天

### 方案 B：完整版（一期）

- 走食材→营养素→自动推算路线
- 需要食材营养库数据源，工作量大

## 当前决策

**用户回复"暂时不用，先这样"** —— 暂不动 MVP 实施方案与界面探讨文档，保持原规划（健康维度走一期）。

## 后续重新启动的触发条件

- 用户主动提起"健康标签 / 筛选 / 嘌呤糖脂"等关键词
- 进入一期规划时，把方案 A 与方案 B 一并纳入对比决策
- MVP 上线后用户反馈"看不出哪些菜适合慢性病" → 优先回归方案 A
