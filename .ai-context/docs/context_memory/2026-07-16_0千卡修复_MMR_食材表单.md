## 一、预设菜热量为0 根因与修复（fd98ac8）
- **根因**：dishes.json 有 quantity(100%全)，但老库 dish_ingredient 已关联却 quantity/unit_id=NULL（早期 seed 无 quantity），热量按克算=0。原补齐逻辑只补"缺失关联"，对已关联但 NULL 用量的行 `if(ingredientId in linked) return@ing` 跳过 → 永不修。
- **牛肉汤炖白菜豆腐粉丝** 能"删后更新变好"：删=软删(status=0)，selectPresetDishIdByName 只认 status=1 → 当作新菜重插(带 quantity)；**排骨海带汤**未删仍走补齐分支被跳过 → 一直0。
- **修复**：`Cookbook.sq` 加 `fillDishIngredientQuantityIfNull`(仅回填 quantity IS NULL,不覆盖用户,纯新查询免迁移)；`PresetDataSeeder.seedDishes` 补齐分支对已关联配料补空用量；`SEED_LOGIC_VERSION` v2→v3 让老库跑一次。
- **华为真机库(GCL0220212004523)模拟验证**：回填 838 配料行/368 菜；排骨海带汤→排骨400g+海带150g；仅剩 7 道 **user 自建**菜 NULL(seeder 不动用户数据,正确)。
- 用户装新 APK 启动即自动回填(无需手动)。

## 二、MMR 批内多样性重排（01efcbb，算法评审#3.1）
- `RecommendationOrchestrator.diversify()`：取批后按**主料 Jaccard** 贪心 MMR 打散同主料霸屏(库存五花肉→满屏五花肉菜)；**只重排"正常菜层"**，忌口/最近层保持分层末位不动(红线)；纯确定性可测。
- `RecommendationStyle.diversityLambda()`：**仅"偏新鲜"默认开(λ0.6)**，综合/偏熟悉=1.0 关(严格分数序,默认零惊讶、行为不变) → 规避"非严格分数序需拍板"。
- **待拍板**：要不要综合(默认)风格也开 MMR。
- 新增单测(RecommendationOrchestratorTest)：偏新鲜打散、综合保分数序。
