# 2026-08-30 E-IGE 食材编辑营养大类联动 Bug 修复 · 会话快照

> 交接入口见 `SESSION_交接.md`（唯一真相源，本快照为流水细节）。

## 任务

用户报 Bug：**编辑食材时，选择营养大类后下方营养数值不跟随变化**（Checkbox「自动根据营养大类预估」已勾选）；**新建食材时正常**。要求两路径一致。

## 根因（两处叠加）

1. `IngredientEditorDialogs.kt` K7 联动守卫 `if (ingredient != null || ...)` —— 当初设计"仅新建"，编辑态直接 return 不重推。
2. `IngredientPickerScreen.kt` 编辑入口的 `IngredientEditorDialog` 调用**没传 `onGuessNutritionByGroup`**（默认 no-op）——只修守卫不补回调照样不动。

Checkbox 在编辑态照常显示且默认勾选 → UI 承诺与行为不一致即 bug 信号。预设食材编辑页无大类选项（`!isPreset` 分支），不受影响。

## 修复（commit `8de5f7ac`）

- K7 守卫去掉 `ingredient != null`；`groupTouched` 保证只有用户手动切大类才触发（打开页自动预选不误覆盖 DB 值）。
- 编辑入口补传 `onGuessNutritionByGroup`（按名推演/属性推断仍仅新建，编辑改名不自动覆盖既有数据）。
- K7 `LaunchedEffect` key 补 `hydrated`（审查可选3）：编辑态加载窗口内点大类，水合完成后补跑判定不丢重推。
- 「清空预填」编辑态**恢复打开时的 DB 原值**：现取 VM `editorNutrition`（配 `editorIngredientId == ingredient.id` 守卫），**不用瞬态快照**（第一版 `remember` 快照被审查指出旋转即丢——审查建议1 修法①）。新建态清空行为不变。
- banner 标题「已按名字帮你预填」→「已帮你预填营养」（编辑态按大类重推场景原名不准确；副文案已区分 Match/Group 来源）。
