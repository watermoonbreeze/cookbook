> 结论性快照。本轮约 25 个功能/bug，逐个自测+提交+推送，最后 5 轮审核回归 + 逐项审计（全绿）。

## 一、核心红线级发现（务必记住）

- **`DishMini.mainIngredientNames` 长期未被填充**：`DishRepository.buildDishMinis` 与 `MealRecordRepository.buildDishesByMealRecord` 都没设该字段→恒空。依赖它的功能(餐次分类图标 FoodGroup、主食置顶、菜品列表主料副文本)全静默失效。修：新增 SQL `selectMainIngredientNamesByDishIds`(is_main=1)，两处构建都填。**教训：DishMini 派生字段要确认真被填，别假设。**
- **Material3 1.1.2 无 `SelectableDates` API**：DatePicker 无法按日期禁用。需要禁选某些日期时，改在确认回调(setDate)里校验+提示，而非 picker 层禁用。
- **餐次营养只反映实际包含、不做推荐**：用户明确反对"建议再加X"这类推荐(不准确)。FoodGroup.nutritionSummary 只如实归纳已涵盖大类(优质蛋白/主食/蔬菜/水果)，去掉 balanceNote 与推测性 Omega-3。

## 二、餐食编辑状态机（AddMealViewModel，最易错）

多标志协同：`configured / userPickedDate / loadedFromDate / copyFromDate / copyConfigured / isEditingExisting`。三入口互不串味：
- **新增**(空日期)：日期可改；loadedFromDate=null；保存不删旧。
- **编辑既有某天**：加载到既有餐食→isEditingExisting=true→UI 锁日期(不可改)；loadedFromDate=该天；改日期(理论走不到,已锁)才删旧=移动。
- **复制**(configureCopy)：独立 `copyConfigured` 守卫(不被 init 默认 configure 的 configured 抢跑吞掉)；date=**最新餐食日期+1**(非源+1)；minSelectableDate=target(早于此提示不可选)；loadedFromDate=null(不删源)；userPickedDate=true(防返回重组被 configure 覆盖)。
- **F7 选日期不带出**：setDate 不 reload，只把当前餐次改到新日期；占用日期提示不切换；冲突时不置 userPickedDate(避免污染)。

- **首页**：observeTodayPlusFuture 原 LIMIT=2 是行数 bug→取60行 take(2天)完整。
- **底栏**：AiRecommend 保存按钮 navigationBarsPadding 防系统导航栏遮挡。

- **shared 新增**：`domain/StapleFood.kt`(主食判定)、`domain/FoodGroup.kt`(食物大类+emoji+营养,启发式按主料名)。
