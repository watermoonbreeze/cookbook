> [AI生成] 承接 `2026-07-10_库存份数体系.md`。本轮把库存占用模型改到最优并扩大采购覆盖。

## 统一模型（定稿，最优）
份数=**结算式余额** + **入库日窗口**，全部派生实时算、不落库：
- **入库日窗口**：每个在库食材有 `pantry.added_at`(=最后一次加份数时刻, 持久化)。只算 `date >= added_at` 的餐；入库日之前(含很久以前)完全不参与 → 解决"两年前用过还占今天库存"。
- **加份数=结算**：`serving_count = 当前剩余 + delta`, `added_at = now`(`activatePantry` 查询)。→ 剩0再加3=3、剩3再加2=5(未消耗结转、已消耗不重复计)；为0重加/续加/出库重加都对。
- **剩余** = 份数 − 入库日起到今天已做的餐数；未来计划不减剩余(但会标缺料)。`PantryAllocation.remaining()`。
- **缺料**：`[added_at,∞)` 的餐按时间序对份数排队超出即不足；入库日到昨天占份数但不显示(已吃过)，**只今天及未来显示**"缺:X"灰显。`PantryAllocation.shortages(onlyFromDate=today)`。
- **采购**：主料**不在库**→"采:X"。**已覆盖所有餐食卡片**(首页计划/食历, 经 `MealRecordRepository.pantryCardFlags`)+周期规划预览。只判主料(is_main=1, 盐油不标)、只今天及未来、空库存不标。
- 派生 → 现有食历自动覆盖，无需重建餐食。

## 关键实现点
- `PantryAllocation`(纯,可测): `shortages(servings, usages, onlyFromDate)` + `remaining(servings, addedDate, usages, today)`。
- `PantryRepository.addServings`: 先算 `remaining()[id]` 当前剩余, 再 `activatePantry(剩余+delta, now)`(事务)。`remaining()` 窗口化。
- `MealRecordRepository.pantryCardFlags()`: 缺料(selectPantryStock+selectPantryUsageChrono 过滤入库日) + 采购(selectMainIngredientUsageFromDate, 主料不在 pantryIds)。`DishMini` 加 shortageIngredients+purchaseIngredients。
- `DayMealCardView`: 缺/采购菜 alpha0.4 + "采:X"/"缺:X"(LackText)。
- `DateTime.epochSecondsToDate`(epoch→本地日期串, 供窗口比较)。
- 移除 `selectPantryConsumedUntil`/`incrementPantryServings`; 改 `selectPantryStock`(含added_at)/`activatePantry`。
- DB 迁移仍是 `13.sqm`(pantry.serving_count), 本轮无新迁移。
