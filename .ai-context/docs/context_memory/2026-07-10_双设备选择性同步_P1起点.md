# 会话快照：双设备选择性同步（设计定稿 + P1 起点）2026-07-10

> [AI生成] 方案文档 `feature/双设备选择性同步方案.md`。本快照记设计要点 + P1 实现起点(schema/现有方法)，供续接。

## 需求
双设备同传现为**整库替换**(不可选)。要**可选择**同步：菜品/餐食/库存/食材/健康档案/收藏，或全部。**每个选项要带用户说明**(见方案文档"选项用户可见说明")。

## 机制(定稿)
- **全部=整库替换**(现状保留, 换新机)；**选择性=按名称匹配合并 + ID 重映射**(只加/更新到对方, 不动其它)。
- **Bundle**: zip `.ckbksel` = `manifest.json`(schemaVersion+含哪些域) + `data.json`(kotlinx.serialization 各表行) + `img/`(被引用图片)。
- **依赖自动带**：餐食→菜品→食材；库存→食材；收藏→菜品。
- **不同步**：preference(主题/AI Key)、seed/基础数据(分类/单位/调养规则)。
- **合并键**：食材/菜品/标签 按 name；库存 按 ingredient_id(映射后)；餐食 按(date,meal_type_id)；健康档案 按 crowd_type_id；做法/单位 按 name 匹配(seed 假定存在)。

## 分阶段
- **P1(进行中)**: 菜品+食材 导出+合并引擎+单测(分享菜谱, 最高价值)。
- P2: 库存+健康档案+收藏。 P3: 餐食历史。 P4: 选择UI(带说明)+接入 socket/SAF 传输。

## P1 起点(已摸清 schema/方法)
**表**(shared/commonMain/sqldelight/Cookbook.sq)：
- `ingredient`(id,name UNIQUE,alias,pinyin,image_path,thumbnail_path,emoji,default_unit_id,source,created_at,last_referenced_at,status,reason)
- `ingredient_detail`(ingredient_id PK,common_methods,prep_tips,eating_notes,storage_tips,health_note,updated_at,status)
- `ingredient_category`(ingredient_id,category_id) — **P1 暂跳过**(分类合并另议)
- `dish`(id,name,cooking_method_id,preference,special_note,description,image_path,thumbnail_path,source,created_at,updated_at,status)
- `dish_ingredient`(id,dish_id,ingredient_id,quantity,unit_id,is_main,status) UNIQUE(dish_id,ingredient_id)
- `dish_step`(id,dish_id,sort_order,text,image_path,thumbnail_path,...)
- `dish_tag`(id,name UNIQUE,source,...) + `dish_tag_rel`(dish_id,tag_id)
- `dish_cooking_method_rel`(dish_id,cooking_method_id)
- `cooking_method`/`measurement_unit` = seed 基础表(按 name 匹配, 不建)

**现有方法**：
- `DishRepository`: getDishById(完整Dish含ingredients/steps/tags/methods)、saveDish(...)、ensureCookingMethod(name)→id、listCookingMethods。
- `IngredientRepository`: createUserIngredient(name,alias,img,thumb,unit,categoryIds)、saveIngredientDetail、search。
- `PantryRepository`,`HealthProfileRepository`,`FavoriteComboRepository` 供后续阶段。

## P1 计划(下一步做)
1. `shared` `sync/SyncBundle.kt`(@Serializable DTO: version, ingredients[], dishes[])。
2. `SyncExporter`: 采 source=user 的食材(+detail+图片名) + 菜品(+dish_ingredient/steps/tags/methods+图片) → DTO。
3. `SyncImporter`: 事务内 名称匹配 upsert：先食材建 id 映射→再菜品(dish_ingredient/steps/tags/methods 用映射; cooking_method/tag 按 name)。unit_id P1 可置 null。
4. 单测(用 RepositoryTestDatabase 内存库)：导出→导入到另一库→按名合并、ID 重映射正确、重复导入不产生重复。
5. 图片：Bundle 带被引用图片文件名(相对), 合并时释放到 img 目录(androidApp 侧传输时处理)。

## 关键约束
- 合并全程一个事务；映射表先建全再插依赖。
- 名称 trim 归一；同名视为同物(合并)。
- schemaVersion 校验(高版本 bundle 不导入低版本)。
