# 1. 页面节点

本次涉及 3 类页面节点：

```text
P0 = App Main / Root
P1 = UnifiedAddMeal
```

注意：

`Single AI / Single Manual / Period AI / Period Manual`

不是四个 Page，它们是 `P1` 内部四个 Body State。

# 7. Mode 转移规则

## 7.1 Range 事件

```text
EVENT: SELECT_SINGLE_DAY
EVENT: SELECT_PERIOD
```

仅修改：

```text
range
```

禁止修改：

```text
method
```

示例：

```text
SINGLE_DAY + AI
  --SELECT_PERIOD-->
PERIOD + AI
```

```text
SINGLE_DAY + MANUAL
  --SELECT_PERIOD-->
PERIOD + MANUAL
```

---

## 7.2 Method 事件

```text
EVENT: SELECT_AI
EVENT: SELECT_MANUAL
```

仅修改：

```text
method
```

禁止修改：

```text
range
```

示例：

```text
PERIOD + AI
  --SELECT_MANUAL-->
PERIOD + MANUAL
```

---

# 8. Mode 切换不变量

每次 Range / Method 切换必须满足：

```text
NO confirmation
NO back stack push
NO business state reset
NO data discard
```

Mode 切换本质：

```text
P1 内部 UI State 改变
```

不是页面导航。

---

# 9. P1 四个 Body

映射：

```text
SINGLE_DAY + AI
→ SingleAiContent

SINGLE_DAY + MANUAL
→ SingleManualContent

PERIOD + AI
→ PeriodAiContent

PERIOD + MANUAL
→ PeriodManualContent
```

推荐 Host：

```kotlin
when {
    range == SINGLE_DAY && method == AI ->
        SingleAiContent(...)

    range == SINGLE_DAY && method == MANUAL ->
        SingleManualContent(...)

    range == PERIOD && method == AI ->
        PeriodAiContent(...)

    range == PERIOD && method == MANUAL ->
        PeriodManualContent(...)
}
```

---

# 10. 草稿状态

P1 必须逻辑上区分：

```text
Draft A = Single AI
Draft B = Single Manual
Draft C = Period AI
Draft D = Period Manual
```

任何一个 Draft 不得因 Mode 切换被清除。

# 17. P2 保存行为

事件：

```text
EVENT: SAVE_DAY
```

流程：

```text
validate
→ save
→ success
→ popBackStack()
```

返回：

```text
P1
range = PERIOD
method = MANUAL
```

P1 必须刷新相应日期的数据。

---

# 18. P2 Back 行为

## P2 无未保存修改

```text
BACK
→ pop
→ P1 PERIOD + MANUAL
```

## P2 有未保存修改

```text
BACK
→ 子页面 UnsavedChangesGuard
```

如果用户确认丢弃：

```text
pop
→ P1 PERIOD + MANUAL
```

如果取消：

```text
停留 P2
```

---

# 19. P1 Back 行为

事件：

```text
EVENT: BACK
```

先计算：

```text
hasUnsavedChanges
```

## 无 Dirty

```text
P1
→ pop
→ P0
```

## 有 Dirty

```text
P1
→ Unified UnsavedChangesGuard
```

确认丢弃：

```text
pop → P0
```

取消：

```text
留在 P1
```

---

# 20. P1 Dirty 计算

概念：

```kotlin
val hasUnsavedChanges =
    singleAiState.isDirty ||
    singleManualState.isDirty ||
    periodAiState.isDirty ||
    periodManualState.isDirty
```

注意：

Dirty 是“页面是否允许直接退出”的依据。

Dirty 不是“是否允许 Mode 切换”的依据。

```text

        │                                     ▼

│ SINGLE_DAY + AI │                  │   PERIOD + AI   │

┌─────────────────────┐              ┌─────────────────────┐
│ SINGLE_DAY + MANUAL │              │   PERIOD + MANUAL   │

      │
      │ EDIT_DAY(date)
      ▼

      │

      ▼

```

`SingleManualEditor(date)` 是 Navigation State，不是 Mode State。

# 27. Back Stack 不变量

以下必须成立：

## 从主页面点击 `+`

```text
[P0, P1]
```

## 从 Period Manual 编辑某天

```text
[P0, P1, P2]
```

保存后：

```text
[P0, P1]
```

不允许出现：

```text
[P0, P1, P1, P2]
```

或：

```text
[P0, P1(SINGLE_MANUAL), P2]
```

# 28. 推荐 Compose Navigation 边界

NavGraph 注册：

```text
main
unifiedAddMeal
singleManualEditor/{date}
```

不要注册：

```text
singleAi
singleManual
periodAi
periodManual
```

这四个是 `UnifiedAddMeal` 内部 UI State。

---

# 29. 推荐事件接口

概念接口：

```kotlin
sealed interface UnifiedAddMealEvent {
    data class ChangeRange(val range: MealRange) : UnifiedAddMealEvent
    data class ChangeMethod(val method: MealInputMethod) : UnifiedAddMealEvent
    data class EditDay(val date: LocalDate) : UnifiedAddMealEvent
    data object Back : UnifiedAddMealEvent
}
```

不强制必须使用 sealed interface；如果项目已有 MVI/MVVM 事件结构，优先适配现有模式。

但事件语义不得混淆：

```text
ChangeRange != Navigate
ChangeMethod != Navigate
EditDay = Navigate
```

# 30. UI 状态恢复

最低要求：

- Composable 重组不丢状态
- Mode 切换不丢状态
- 子页面 push/pop 后父 Mode 不变

若项目已有 SavedStateHandle / ViewModel 状态恢复机制，应遵循项目现有做法。

本次不要求额外实现“App 被系统杀死后四 Draft 全恢复”，除非现有业务本身已经支持。

---

# 31. Loading 规则

AI Body 的 Loading 属于 Body 内状态。

例如：

```text
Period AI 正在解析周三
```

只影响 Period AI。

不允许：

```text
整个 Unified 页面被全局 Loading 覆盖
```

从而阻止用户切换到手动方式，除非当前业务已有不可中断强约束。

---

# 32. Error 规则

错误归属哪个 Body，就由哪个 Body 展示。

例：

```text
Single AI 解析失败
```

不应破坏：

- Single Manual 草稿
- Period AI 草稿
- Period Manual 状态

# 33. 动画语义

## P0 → P1

属于页面导航。

允许：

```text
push / fade-through
```

## P1 Mode 切换

不属于页面导航。

使用：

```text
Crossfade / short fade
```

## P1 → P2

属于子页面导航。

使用与项目二级页面一致的 push 转场。

# 34. 可访问性与触摸要求

所有可点击控件：

```text
touch target >= 48dp
```

即使视觉高度较小，也要通过 padding 保证点击区域。

Selector 必须具备：

- Selected state
- 可读 label
- TalkBack 可识别选中状态

`+` 必须有明确 contentDescription，例如：

```text
"记录饮食"
```

# 36. 编码模型禁止自行推断的事项

如果源码与本文出现冲突，编码模型不得自行扩大改造范围。

尤其禁止自行决定：

- “四个 Mode 各自做成独立页面更简单”
- “切换时直接重建状态即可”
- “Period Manual 点一天直接把 Range 切成 Single”
- “统一入口顺便收编 AI 智能推荐”
- “用新版 Material3 组件更方便所以升级依赖”
- “删除旧直接入口”
- “把 `+` 仍当成一个 Navigation Item”

这些均视为偏离设计。

# 37. 页面级 Definition of Done

交互层完成必须同时满足：

- P0 → P1 默认路径正确
- P1 2×2 Mode 正确
- Mode 切换无 Back Stack 变化
- 四 Draft 不因切换丢失
- P1 Dirty Guard 检查所有 Draft
- P2 是子导航而非 Mode
- P2 返回后 Parent Mode 保持 Period + Manual
- 明确上下文旧入口绕过 P1
- 所有主要路径 Back Stack 可预测
- 无循环导航
- 无重复统一入口页面入栈
