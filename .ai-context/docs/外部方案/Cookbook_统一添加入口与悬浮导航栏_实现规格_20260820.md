# 0. 文档使用规则

本文件用于约束实现方向，编码模型执行时遵循以下优先级：

1. 本文“已锁定决策 / 不变量 / 禁止事项”
2. 当前项目已有业务语义与数据结构
3. 当前项目已有视觉组件与交互约定
4. 仅在以上都无法决定时，才允许做最小范围实现选择

未经明确授权，不允许因为“实现更方便”而改变本文定义的信息架构、默认路径、返回行为或现有业务语义。

---

# 1. 本次改造目标

本次只解决两个问题：

## 1.1 新建餐食入口统一

将当前分散的四类“新建餐食”场景统一收口到底部 `+`：

- 单天 + AI 快捷
- 单天 + 手动
- 周期 + AI 快捷
- 周期 + 手动

统一入口为一个全屏“记录饮食”工作区。

## 1.2 底部导航栏重构

将当前约 80dp 高的底部 Navigation Bar 改为：

- 56–60dp 高度范围的悬浮胶囊导航
- `+` 从 Navigation Destination 中剥离
- `+` 成为独立悬浮 Action Button
- 保留高频入口的视觉与点击面积

---

# 2. 明确不在范围内

以下内容本次禁止顺带重构：

- 首页布局重构
- AI 智能推荐入口与业务
- AI 解析算法
- 菜品库业务规则
- 编辑历史餐食的业务流程
- 复制某天餐食的业务流程
- AI 推荐结果预填后的业务流程
- 非本次目标所必需的数据层重构
- Material3 版本升级

---

# 3. 已锁定产品模型

统一入口的业务维度是严格的 2×2：

```text
Range:
- SINGLE_DAY
- PERIOD

Method:
- AI
- MANUAL
```

对应内容：

| Range | Method | 复用现有实现 |
|---|---|---|
| SINGLE_DAY | AI | 现有“快速记” |
| SINGLE_DAY | MANUAL | 现有“添加餐食”表单 |
| PERIOD | AI | 现有“周期记” |
| PERIOD | MANUAL | 现有“一周计划” |

实现原则：

> 只增加统一页面壳和状态编排，不重新发明四个业务 Body。

---

# 4. 入口默认行为

底部 `+` 点击后必须直接进入：

```text
UnifiedAddMeal
range = SINGLE_DAY
method = AI
```

禁止：

```text
+ → 弹出选择菜单
+ → BottomSheet
+ → “请选择单天还是周期”
+ → “请选择 AI 还是手动”
```

目标体验：

> 点击 `+` 后，用户已经处于可以开始记录的页面。

---

# 5. 全屏承载约束

AI 文本输入从 `ModalBottomSheet` 迁移到全屏页面。

原因不只是视觉统一，还包括当前 Material3 1.1.2 下 BottomSheet 可编辑文本长按选择/复制/粘贴存在结构性限制。

因此：

- 新统一入口不继续使用 BottomSheet 作为 AI 主承载
- 原 AI Content 可以复用
- BottomSheet 外壳不能作为统一入口的一部分保留

---

# 6. 页面信息架构

统一页面固定结构：

```text
┌────────────────────────────┐
│ ←          记录饮食         │
│                            │
│      [ 单天 | 周期 ]        │
│                            │
│  AI 快捷        手动选择     │
│  ━━━━━                     │
│ ────────────────────────── │
│                            │
│       Current Body         │
│                            │
└────────────────────────────┘
```

# 7. 一级选择：Range

控件：

- 使用项目现有自绘胶囊式二选一控件
- 不引入 Material3 1.2+ `SegmentedButton`

选项：

```text
单天
周期
```

默认：

```text
单天
```

切换规则：

- 切换 Range 时 Method 保持不变
- 不弹确认
- 不清理另一 Range 下的草稿

---

# 8. 二级选择：Method

推荐控件：

```text
AI 快捷        手动选择
━━━━━━
```

实现形式建议为轻量双 Tab，而不是第二排同权重大胶囊 Segmented Control。

原因：

- `Range` 是一级上下文
- `Method` 是二级工作方式
- AI 是默认主路径
- 手动必须始终可见

默认：

```text
AI 快捷
```

切换规则：

- 切换 Method 时 Range 保持不变
- 不弹确认
- 不清理另一 Method 草稿

---

# 9. 页面标题

统一页面标题固定：

```text
记录饮食
```

禁止随模式变化成：

- AI 快捷记一餐
- 添加餐食
- 周期记录
- 一周计划

原因：

> 四个模式属于同一个工作空间，而不是四个不同模块。

# 10. 核心状态模型

禁止优先设计成：

```kotlin
enum class Mode {
    SINGLE_AI,
    SINGLE_MANUAL,
    PERIOD_AI,
    PERIOD_MANUAL
}
```

推荐：

```kotlin
enum class MealRange {
    SINGLE_DAY,
    PERIOD
}

enum class MealInputMethod {
    AI,
    MANUAL
}
```

页面壳状态：

```kotlin
data class UnifiedAddMealUiState(
    val range: MealRange = MealRange.SINGLE_DAY,
    val method: MealInputMethod = MealInputMethod.AI
)
```

---

# 11. 四个 Body 的状态独立性

每个业务 Body 必须拥有独立可恢复状态。

概念结构：

```text
UnifiedAddMealState
├── singleAiState
├── singleManualState
├── periodAiState
└── periodManualState
```

以下行为必须成立：

```text
单天 AI 输入草稿
→ 切单天手动
→ 再切回单天 AI
→ AI 草稿仍存在
```

```text
单天手动已选菜
→ 切周期手动
→ 再切回单天手动
→ 已选菜仍存在
```

切换 Mode 不是销毁当前业务状态。

---

# 12. Dirty 状态不变量

统一页面总 Dirty：

```kotlin
hasUnsavedChanges =
    singleAiDirty ||
    singleManualDirty ||
    periodAiDirty ||
    periodManualDirty
```

规则：

- Range 切换：不拦截
- Method 切换：不拦截
- 离开 UnifiedAddMeal：检查总 Dirty
- Dirty 时复用项目现有 UnsavedChangesGuard
- 不新增另一套确认语义

---

# 13. 四个 Body 的工程拆分

目标结构：

```text
UnifiedAddMealScreen
├── UnifiedAddMealTopBar
├── MealRangeSelector
├── MealMethodSelector
└── AddMealBodyHost
    ├── SingleAiContent
    ├── SingleManualContent
    ├── PeriodAiContent
    └── PeriodManualContent
```

原则：

> Screen/Route 负责导航与页面壳，Content 负责业务 UI。

---

# 14. 现有 Screen 的兼容方式

不要直接删除原 Screen。

应优先抽取 Body：

```kotlin
@Composable
fun ExistingSingleManualScreen(...) {
    ExistingPageScaffold {
        SingleManualContent(...)
    }
}
```

统一入口复用：

```kotlin
@Composable
fun UnifiedAddMealScreen(...) {
    UnifiedScaffold {
        SingleManualContent(...)
    }
}
```

这样可以保证已有直接上下文入口继续工作。

# 15. 四个 Body 允许的最小调整

## 15.1 Single AI

允许：

- 从 BottomSheet 外壳迁移进全屏 Body
- 重新接入全屏焦点/IME
- 评估原“粘贴”补偿按钮是否还需要

禁止：

- 重写 AI 解析业务
- 改变已有结果结构

## 15.2 Single Manual

允许：

- 移除 Body 内原“✨ AI快捷记”入口
- 适配统一页面顶栏占用

禁止：

- 改变添加菜品业务
- 改变保存语义

## 15.3 Period AI

允许：

- 从原 BottomSheet 容器迁出
- 适配统一顶部 Selector

禁止：

- 重写按周 AI 解析流程

## 15.4 Period Manual

允许：

- 去掉与统一页面重复的页面壳
- 将“+安排这天”改成明确子导航事件

禁止：

- 改变周计划已有数据语义

# 16. 特殊导航：Period Manual → Single Manual Editor

该路径必须视为“子页面编辑”，不是模式切换。

正确：

```text
UnifiedAddMeal
range = PERIOD
method = MANUAL
    ↓
点击 周三 +安排这天
    ↓
SingleManualEditor(date = 周三)
    ↓
保存 / 返回
    ↓
popBackStack()
    ↓
UnifiedAddMeal 仍是 PERIOD + MANUAL
```

禁止：

```kotlin
range = SINGLE_DAY
method = MANUAL
```

来模拟该流程。

---

# 17. 明确上下文入口兼容原则

以下入口保持直接到具体业务编辑器：

- 编辑已有某天
- 复制某天到另一天
- AI 智能推荐完成后的预填
- 周计划内编辑某一天

它们不经过 Unified 2×2 选择层。

原因：

> 用户意图已明确时，不增加额外模式选择步骤。

推荐 App 级结构：

```text

├── MainContent

    ├── NavigationCapsule
    └── AddMealSatelliteButton
```

推荐视觉：

```text
┌───────────────────────────┐    ●
│ 首页   食历   菜谱   我的  │    +
└───────────────────────────┘
```

# 19. Navigation Capsule 参数

首版基准：

```text
高度：58dp
左右外边距：16dp
底部外边距：12dp + navigationBars inset
圆角：29dp
Elevation：6dp
```

普通 Item：

```text
Icon：22dp
Label：11sp
Icon-label gap：2dp
```

允许在真实视觉回归中 ±2dp 微调，但不得突破：

```text
Navigation Capsule 高度 > 60dp
```

除非经过重新评审。

---

# 20. 独立 `+` 参数

首版基准：

```text
按钮尺寸：56dp × 56dp
圆角/圆形半径：28dp
Elevation：8dp
与 Capsule 水平间距：12dp
```

要求：

- 不跟随 Navigation Capsule 等比缩小
- 必须具有至少 48dp 可点击区域
- 推荐使用主题主色（terracotta）
- 图标使用高对比前景色

---

# 21. 系统栏与沉浸式约束

项目为 edge-to-edge。

Floating Bottom Bar 必须显式处理：

```text
navigationBars inset
```

要求：

- 不使用固定 bottom padding 假设所有设备导航栏一致
- 胶囊和 `+` 都不能被手势条/三键导航覆盖
- 内容区域底部 padding 必须考虑悬浮栏实际占用高度

---

# 22. Compose 技术约束

当前：

```text
Material3 1.1.2
```

因此：

- 不使用 `SegmentedButton`
- 不使用新版 Floating Navigation 组件假设
- 不升级 Material3 解决 UI 问题

推荐自绘：

```kotlin
Box {
    MainContent()

    Row(
        modifier = Modifier
            .align(Alignment.BottomCenter)
            .navigationBarsPadding()
    ) {
        Surface(/* capsule */) { ... }
        Surface(/* plus */) { ... }
    }
}
```

具体实现应复用项目 Theme Token，不硬编码颜色值。

# 23. 动画规范

## `+` → Unified

使用简单全屏 Navigation transition。

建议：

- fade / horizontal push
- 150–250ms 级别
- 不做复杂 hero 动画

## Mode 切换

属于同页状态切换，不属于页面导航。

建议：

```text
Crossfade
```

或短 fade。

禁止：

- 将四个 Mode 分别做成 Nav Destination
- 每次切换导致完整 back stack 变化

# 25. 实现不变量

编码完成后以下必须全部成立：

1. `+` 点击后直接进入 Single + AI。
2. 不再通过 BottomSheet 承载统一 AI 入口。
3. Single/Period 切换不会丢草稿。
4. AI/Manual 切换不会丢草稿。
5. 切换模式不会弹离开确认。
6. 退出 Unified 页面才检查总 Dirty。
7. Period Manual → 某天编辑不会改变父 Mode。
8. 子编辑返回后仍处于 Period + Manual。
9. 已有明确上下文入口不被强制导向 Unified。
10. AI 智能推荐入口不受影响。
11. Navigation Capsule 高度目标 56–60dp。
12. `+` 是独立 Action，不是 Navigation Item。
13. 系统导航栏安全区正确。
14. 深浅主题均可用。
15. Material3 版本不升级。

---

# 26. 禁止事项

编码模型不得：

- 为了统一而复制四份业务实现
- 把四个 Mode 设计为四个独立 Nav Destination
- 在切换模式时主动清空另一模式状态
- 在切换 Range/Method 时弹“是否放弃”
- 将 Period Manual → Single Manual 实现成父 Mode 切换
- 顺带重写 AI 业务
- 顺带重写 Weekly Plan 数据模型
- 升级 Material3
- 将 AI 智能推荐合并进 `+`
- 将 `+` 重新塞回 Navigation Capsule 内部
- 用固定底部 padding 代替系统 inset 处理

# 28. 完成定义（Definition of Done）

本功能只有同时满足以下条件才视为完成：

- 新统一入口正式接管底部 `+`
- 四个旧业务 Body 无复制复用
- 原明确上下文入口无功能回归
- Period Manual 子导航闭环正确
- 模式切换草稿可恢复
- Dirty Guard 层级正确
- Floating Navigation 在系统 Insets 下稳定
- 浅色 / 深色可用
- 关键交互测试通过
- 不引入 Material3 版本升级
