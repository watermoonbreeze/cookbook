# 问题与踩坑

## Codex 自动任务编排容易停留在“引用文档”

[2026-05-24]
- 只在 `~/.codex/AGENTS.md` 写“流程定义：workflow_auto_orchestration.md”不够，模型可能把它当参考文档，而不是强制入口。
- 必须在全局入口写清楚：开发类任务开始前先执行阶段0评估，输出任务类型、深度、模式和智能体分派表。
- DEV 角色不是 Codex 内建 agent 名称，需要显式映射到 `multi_agent_v1.spawn_agent`：
- 分析/方案/审核类角色用 `explorer`，实现/测试落地类角色用 `worker`。
- 标准/深度任务如果有多智能体工具但没有真实分派，应视为流程偏差，必须暂停并修正流程后再继续。

## 任务前上下文快照不能只靠收尾保存

[2026-05-30]
- 原规则只要求“重要任务节点后保存上下文”，没有把“任务开始前保存上下文”写成入口门禁。
- 结果是执行任务时容易只在结束后保存，用户看不到任务前状态被固定下来。
- 修正方式：阶段0任务编排声明后，阶段1分析或任何实质操作前，先写 `.codex/docs/context_memory/yyyy-MM-dd_pretask_<任务短名>.md`。
- 快照内容必须包含最新需求、模式/级别、计划分派、已知状态、预计涉及文件、风险和待验证项。
- 纯问答不执行命令、不改文件、不做项目决策时可不写，但必须明确说明原因。

## Codex 与 Claude Code slash command 差异

[2026-05-24]
- `.codex/commands/zongjie.md` 已存在，不代表 Codex 客户端会注册裸 `/zongjie`。
- 用户输入 `/zongjie` 时，Codex UI/CLI 可能先拦截并提示“没有这个命令”，消息不会进入模型。
- 可行替代：
  - 直接输入普通文本“执行 zongjie / 总结经验”。
  - 用 Codex plugin 的 `commands/` 暴露命令，通常以 `/插件名:命令名` 使用。
- 已创建个人插件 `personal-workflow` 并安装 `personal-workflow@personal`，但新命令通常需要新开会话才会加载。

## IngredientPicker 跨列表选择问题

[2026-05-24]
- 原 `confirmSelected()` 只从当前 `ingredients` 列表筛选，用户跨搜索/分类选择后可能丢失之前选中的食材。
- 修复方式：在 `IngredientPickerUiState` 中维护 `selectedIngredients`，确认时直接返回该列表。
- 同时新增 `excludeIngredientIds`，避免已经加入菜品的食材再次展示。

## Android app label 回退包名

[2026-05-24]
- Manifest 未设置 `android:label` 且无 `app_name` 资源时，安装后可能显示包名/默认名。
- 修复方式：新增 `res/values/strings.xml`，设置 `app_name=CookBook`，并在 `application` 和 launcher `activity` 上引用。

## DatePicker 默认日期偏移

[2026-05-24]
- Material3 `DatePicker` 的 `selectedDateMillis` 语义更接近 UTC 日期毫秒。
- 如果用本地时区 `atStartOfDayIn(TimeZone.currentSystemDefault())` 初始化，在东八区等时区可能出现默认显示前一天的问题。
- 修复方式：用 UTC 零点毫秒初始化和解析，例如 `Instant.parse("${date}T00:00:00Z")`，确认时也按 UTC date 读取。

## 图片 URI 展示与持久化

[2026-05-24]
- 拍照返回的 URI 写入 `image_path` 后，界面不会自动显示真实图片，必须有统一解码组件读取 `content://` 或文件路径。
- 仅显示“图片1/图片2”会让用户误以为照片没有保存；图片选择区应展示真实缩略图。
- 相册返回的 `content://` 不能长期依赖临时授权；拍照 cache 原图也存在被清理风险。
- 处理方式：图片选择后立即在后台压缩并复制到 `filesDir/images/`，`image_path` 只保存压缩后的私有文件路径。
- 列表和详情不要直接解码原图；压缩图目标控制在 10KB 内，点击图片时再用弹框展示较大尺寸预览。

## 预设/自建食材权限

[2026-05-24]
- 用户明确规则：预设食材不可编辑、不可删除；自建食材才可编辑/删除。
- UI 需要给明显提示，避免用户不知道哪些能长按：
- 预设：不显示编辑图标，不弹长按菜单。
- 自建：显示可长按的图标提示，长按弹出编辑/删除菜单。
- 权限规则不能只写在 UI；SQL 的 update/delete 也要限制 `source='user'`，防止误操作。
- 删除自建食材不能只 `DELETE ingredient`；必须先处理 `dish_ingredient` 关联，否则可能外键失败或留下孤儿关联。

## 食历前插分页跳动

[2026-05-24]
- 食历顶部加载历史会在列表头部前插 7 天，若提前发布 `prependCount`，UI 会在旧列表上消费锚点，等新数据回来后仍然跳动。
- 正确做法：ViewModel 等新窗口数据返回后再发布 `prependCount`，UI 消费后调用 `consumePrependCount()`。
- 加载历史和计划必须共用 `loading` 门禁，避免两端加载互相取消 Flow 订阅。

## 阶段性性能优化边界

[2026-05-25]
- 无人值守做架构优化时，优先选择不改 schema、不引入新依赖、可编译验证的优化。
- Repository 层列表组装容易出现 N+1：菜品标签、烹饪方式、餐食记录下菜品都应按批次预取。
- 保存餐食和保存菜品要用 `db.transaction` 包裹主表、关联表和喜爱度更新，避免 Flow 收到半完成状态。
- 食历窗口裁剪会改变“滑过日期是否保留”的体验，不能和低风险性能优化混在一起悄悄落地。
- 当前工程没有 `:shared:allTests` 任务，shared 验证使用 `./gradlew :shared:testDebugUnitTest`；如果后续新增 multiplatform 测试任务，再更新命令文档。

## 食历真实日期分页

[2026-05-25]
- 食历“总数”不能按连续自然日计算，否则无餐食日期也会生成空 item。
- 正确数据源是 `meal_record` 的 `DISTINCT date`，列表按日期正序显示。
- 默认定位优先级：今天有餐食 -> 未来最近有餐食日期 -> 最大餐食日期。
- 顶部加载历史和底部加载计划，每次都加载 7 个“有餐食日期”，不是 7 个自然日。
- 日历标记要用全量有餐食日期集合，日期范围也必须来自全量最早/最晚餐食日期，不随当前分页窗口变化。

## Navigation query 参数编辑态丢失

[2026-05-30]
- 菜品详情点击编辑进入了新建菜品，根因是 `NEW_DISH` 使用 query 参数时，当前 Navigation 配置下 `dishId` 解析不稳定。
- 修复方式：把 `newdish?dishId={dishId}&importDishId={importDishId}` 改为路径参数 `newdish/{dishId}/{importDishId}`。
- 对编辑/复制这种必须可靠传递 id 的路由，优先使用路径参数；query 参数更适合可选搜索条件。

## SQLDelight schema 变更必须配套迁移

[2026-05-30]
- 新增 `dish_cooking_method_rel` 后，老安装包升级启动会崩溃：`SQLiteException: no such table: dish_cooking_method_rel`。
- 只改 `Cookbook.sq` 只能影响新建数据库；已安装用户必须新增 `.sqm` 迁移文件。
- 修复方式：在 `shared/src/commonMain/sqldelight/.../1.sqm` 创建新表，并从旧字段 `dish.cooking_method_id` 回填关联数据。
- 经验：任何 schema 变更完成后都要检查 `shared/src/commonMain/sqldelight` 下是否需要新增/更新迁移，并跑 `:shared:generateCommonMainCookbookDatabaseInterface`。

## SQLDelight 迁移文件必须同步提升 version

[2026-06-03]
- 报错：`SQLiteException: Can't downgrade database from version 2 to 1`。
- 根因：已有 `1.sqm` 表示 v1 -> v2 迁移，但 `shared/build.gradle.kts` 未配置 `version = 2`，导致当前包仍按 DB version 1 打开。
- SQLite 不允许从设备已有 version 2 降到 version 1，不能通过清库作为修复方案。
- 修复方式：在 `sqldelight.databases.create("CookbookDatabase")` 中显式设置 `version = 2`。
- 经验：每新增一个 `.sqm` 迁移文件，都要同步检查 SQLDelight `version` 是否等于目标 schema 版本；版本只能升不能降。

## Compose 页面复用导致编辑态串状态

[2026-05-30]
- 菜品详情点击编辑仍可能显示成新建，不能只检查路由参数是否传对，还要检查页面 ViewModel 是否复用旧表单状态。
- `NewDishScreen` 里分散使用多个 `LaunchedEffect` 分别加载编辑/导入，容易出现新建、编辑、导入互相覆盖。
- 修复方式：在 `NewDishViewModel.start(editId, importId)` 统一入口，先重置表单状态，再按“编辑优先、导入其次、新建为空”加载。
- 经验：编辑页标题、保存 id、表单数据必须来自同一个入口状态；保存完成的 `done=true` 也要在再次进入时清掉。

## Kotlin daemon + 中文路径问题

[2026-05-30]
- Gradle 编译时 Kotlin daemon 偶发连接失败，fallback 编译会把中文路径错误转义成 `/Users/sxd/Documents/u5DE5u4F5C/...`，导致大量 “source file not found”。
- 这类报错不一定是源码问题；先执行 `./gradlew --stop` 停掉 daemon，再复跑构建。
- 如果复跑后进入正常 Kotlin/SQLDelight 类型错误，再按真实源码问题处理。

## 菜品列表返回不刷新

[2026-06-03]
- 添加菜品后返回菜品页不刷新，根因是列表使用一次性 `searchDishes("")` 结果，未持续观察数据库变化。[AI生成]
- 修复方式：空关键词场景使用 `dishRepo.observeAllDishes()` 的 Flow 作为主列表；搜索关键词非空时仍走一次性搜索。[AI生成]
- 从新建/编辑返回时在 `ON_RESUME` 主动 `refresh()`，并给 Tab 列表增加下拉刷新入口，保证用户手动可恢复最新状态。[AI生成]

## 编辑页标题正确但表单为空

[2026-06-03]
- 标题显示“编辑菜品”只能说明路由 id 已传入，不能说明详情数据已成功加载。[AI生成]
- `loadForEdit()` 不能静默忽略 `getDishById()` 返回 null 或异常，否则用户看到的是空表单并误以为编辑功能失效。[AI生成]
- 修复方式：编辑/导入入口增加 `loading/errorMessage` 状态，加载成功后一次性回填表单，失败时禁用保存并显示错误提示。[AI生成]

## 图片字段新增后必须保持索引一致

[2026-06-03]
- `image_path` 和 `thumbnail_path` 都使用 `|` 分隔多图时，删除图片必须按索引同步删除，不能用路径去重或只删原图字段。[AI生成]
- 图片展示优先走缩略图，预览再加载原图；保存时要同时生成两个文件并一起回写数据库。[AI生成]
- SQLDelight 新增字段后，`insert`、`update`、查询映射、seed 插入参数都必须同步调整，否则会出现编译错误或运行时数据缺失。[AI生成]

## 公共 sdCard 目录必须先授权再建库

[2026-06-03]
- 如果目标是 `/sdcard/cookbook/...`，不能在 `Application.onCreate()` 里提前 seed 或读取偏好，否则数据库会在权限门禁前被创建。[AI生成]
- 正确流程：`MainActivity` 先判断/申请外部存储权限 -> 授权后迁移旧 app 专属 `cookbook` 目录 -> 创建 `/sdcard/cookbook/db` 和 `/sdcard/cookbook/img` -> 再加载主题、数据库和 HomeScreen。[AI生成]
- Android 11+ 写 sdCard 根目录需要 `MANAGE_EXTERNAL_STORAGE`，运行时普通读写权限不够；必须跳系统“所有文件访问权限”设置页。[AI生成]
- 数据库和图片路径必须统一从 `CookbookStorage` 获取，不要各模块各自 fallback 到 app 专属目录，否则用户会看到 db/img 不在指定目录。[AI生成]

## SQLDelight 非空字段遇到旧库 NULL 会崩溃

[2026-06-03]
- 闪退日志 `CookbookQueries$selectAllIngredients` 内 `cursor.getString(...)!!`，通常表示旧库中某个声明非空的 TEXT 字段实际为 NULL。[AI生成]
- 只给新字段 `DEFAULT ''` 不能修复已存在的异常旧数据；查询层要用 `COALESCE` 兜底，启动 seed 时也要执行一次 NULL 清洗。[AI生成]
- 改 `SELECT *` 为显式 `COALESCE` 后，SQLDelight 会生成自定义查询结果类型，Repository 需要用显式 mapper，不再套用表实体扩展函数。[AI生成]
