# 问题与踩坑

## Codex 自动任务编排容易停留在“引用文档”

[2026-05-24]
- 只在 `~/.codex/AGENTS.md` 写“流程定义：workflow_auto_orchestration.md”不够，模型可能把它当参考文档，而不是强制入口。
- 必须在全局入口写清楚：开发类任务开始前先执行阶段0评估，输出任务类型、深度、模式和智能体分派表。
- DEV 角色不是 Codex 内建 agent 名称，需要显式映射到 `multi_agent_v1.spawn_agent`：
- 分析/方案/审核类角色用 `explorer`，实现/测试落地类角色用 `worker`。
- 标准/深度任务如果有多智能体工具但没有真实分派，应视为流程偏差，必须暂停并修正流程后再继续。

## Codex 与 Claude Code slash command 差异

[2026-05-24]
- `.codex/commands/zongjie.md` 已存在，不代表 Codex 客户端会注册裸 `/zongjie`。
- 用户输入 `/zongjie` 时，Codex UI/CLI 可能先拦截并提示“没有这个命令”，消息不会进入模型。
- 可行替代：
  - 直接输入普通文本“执行 zongjie / 总结经验”。
  - 用 Codex plugin 的 `commands/` 暴露命令，通常以 `/插件名:命令名` 使用。
- 已创建个人插件 `personal-workflow` 并安装 `personal-workflow@personal`，但新命令通常需要新开会话才会加载。

## IngredientPicker 跨列表选择问题

[2026-05-24]
- 原 `confirmSelected()` 只从当前 `ingredients` 列表筛选，用户跨搜索/分类选择后可能丢失之前选中的食材。
- 修复方式：在 `IngredientPickerUiState` 中维护 `selectedIngredients`，确认时直接返回该列表。
- 同时新增 `excludeIngredientIds`，避免已经加入菜品的食材再次展示。

## Android app label 回退包名

[2026-05-24]
- Manifest 未设置 `android:label` 且无 `app_name` 资源时，安装后可能显示包名/默认名。
- 修复方式：新增 `res/values/strings.xml`，设置 `app_name=CookBook`，并在 `application` 和 launcher `activity` 上引用。

## DatePicker 默认日期偏移

[2026-05-24]
- Material3 `DatePicker` 的 `selectedDateMillis` 语义更接近 UTC 日期毫秒。
- 如果用本地时区 `atStartOfDayIn(TimeZone.currentSystemDefault())` 初始化，在东八区等时区可能出现默认显示前一天的问题。
- 修复方式：用 UTC 零点毫秒初始化和解析，例如 `Instant.parse("${date}T00:00:00Z")`，确认时也按 UTC date 读取。

## 图片 URI 展示与持久化

[2026-05-24]
- 拍照返回的 URI 写入 `image_path` 后，界面不会自动显示真实图片，必须有统一解码组件读取 `content://` 或文件路径。
- 仅显示“图片1/图片2”会让用户误以为照片没有保存；图片选择区应展示真实缩略图。
- 相册返回的 `content://` 不能长期依赖临时授权；拍照 cache 原图也存在被清理风险。
- 处理方式：图片选择后立即在后台压缩并复制到 `filesDir/images/`，`image_path` 只保存压缩后的私有文件路径。
- 列表和详情不要直接解码原图；压缩图目标控制在 10KB 内，点击图片时再用弹框展示较大尺寸预览。

## 预设/自建食材权限

[2026-05-24]
- 用户明确规则：预设食材不可编辑、不可删除；自建食材才可编辑/删除。
- UI 需要给明显提示，避免用户不知道哪些能长按：
- 预设：不显示编辑图标，不弹长按菜单。
- 自建：显示可长按的图标提示，长按弹出编辑/删除菜单。
- 权限规则不能只写在 UI；SQL 的 update/delete 也要限制 `source='user'`，防止误操作。
- 删除自建食材不能只 `DELETE ingredient`；必须先处理 `dish_ingredient` 关联，否则可能外键失败或留下孤儿关联。

## 食历前插分页跳动

[2026-05-24]
- 食历顶部加载历史会在列表头部前插 7 天，若提前发布 `prependCount`，UI 会在旧列表上消费锚点，等新数据回来后仍然跳动。
- 正确做法：ViewModel 等新窗口数据返回后再发布 `prependCount`，UI 消费后调用 `consumePrependCount()`。
- 加载历史和计划必须共用 `loading` 门禁，避免两端加载互相取消 Flow 订阅。

## 阶段性性能优化边界

[2026-05-25]
- 无人值守做架构优化时，优先选择不改 schema、不引入新依赖、可编译验证的优化。
- Repository 层列表组装容易出现 N+1：菜品标签、烹饪方式、餐食记录下菜品都应按批次预取。
- 保存餐食和保存菜品要用 `db.transaction` 包裹主表、关联表和喜爱度更新，避免 Flow 收到半完成状态。
- 食历窗口裁剪会改变“滑过日期是否保留”的体验，不能和低风险性能优化混在一起悄悄落地。
- 当前工程没有 `:shared:allTests` 任务，shared 验证使用 `./gradlew :shared:testDebugUnitTest`；如果后续新增 multiplatform 测试任务，再更新命令文档。

## 食历真实日期分页

[2026-05-25]
- 食历“总数”不能按连续自然日计算，否则无餐食日期也会生成空 item。
- 正确数据源是 `meal_record` 的 `DISTINCT date`，列表按日期正序显示。
- 默认定位优先级：今天有餐食 -> 未来最近有餐食日期 -> 最大餐食日期。
- 顶部加载历史和底部加载计划，每次都加载 7 个“有餐食日期”，不是 7 个自然日。
- 日历标记要用全量有餐食日期集合，日期范围也必须来自全量最早/最晚餐食日期，不随当前分页窗口变化。
