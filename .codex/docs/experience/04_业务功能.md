# 业务功能

## 添加/编辑餐食

[2026-05-24]
- 添加餐食页不应按“每次只添加一餐”设计；用户目标是一次创建/编辑一天的餐食。
- UI 状态使用 `MealBlockUiState` 列表表达一天内多个餐食模块，每个模块包含：餐次、用餐时间、菜品列表、备注。
- 保存某天餐食采用“整日覆盖”策略：先删除该日期旧的 `meal_record_dish` 和 `meal_record`，再写入当前模块列表，避免同一天重复叠加。
- 进入添加餐食页时，如果指定日期已有餐食，需要直接回填为可编辑模块；没有数据时默认创建“早餐”模块。
- 固定餐次自动带出默认时间；`加餐` 这类非固定餐次不带默认时间，必须由用户手动选择。
- 首页计划卡片和食历卡片的编辑入口都跳转同一个添加/编辑餐食页，保持编辑体验一致。

## 图片与多图字段

[2026-05-24]
- 菜品/食材多图复用 `image_path` 和 `thumbnail_path` 字段，用 `|` 分隔多个图片路径，最多 3 张。[AI修改]
- `image_path` 保存原图文件路径，`thumbnail_path` 保存对应缩略图文件路径；两者按相同索引一一对应。[AI修改]
- 图片默认落到 `/sdcard/cookbook/img/`，文件名格式为 `yyyyMMddHHmmssS.jpg`；缩略图为 `yyyyMMddHHmmssS_thum.jpg`。[AI修改]
- Android 系统限制公共根目录写入时，回退到 app 专属外部目录下的 `cookbook/img/`，避免因为存储权限导致拍照保存失败。[AI修改]
- 所有列表和封面默认展示 `thumbnail_path` 第一张；点击图片预览时先展示缩略图，再异步加载 `image_path` 原图，形成从模糊到清晰的效果。[AI修改]
- 缩略图压缩目标约 5KB，最大不超过 10KB；原图按较大尺寸压缩保存，避免列表直接解码大图。[AI修改]

## 菜品喜爱度

[2026-05-24]
- `dish.preference` 使用 `INTEGER` / Kotlin `Int` 累加，避免 `REAL/Double` 小数精度问题。
- 喜爱度总分上限 1000；每次菜品添加到餐食记录中，累加 1。
- 星级展示为 5 颗星，每颗 200 分，即 `preference / 200.0`。
- 用户可见文案统一为“喜爱/喜爱度”，不再显示旧“热度”或 `/1000` 总数。

## 食历分页与定位

[2026-05-24]
- 食历使用连续自然日窗口，不只展示有餐食记录的日期；无记录日期也返回空卡，方便定位当天。
- 默认窗口为最近一周：`today-6` 到 `today`，进入页面后定位到当天。
- 日期按正序展示：上方历史，下方计划；手指上滑看未来计划，下拉看更早历史。
- 顶部加载历史、底部加载计划，每次扩展 7 个自然日。
- 顶部前插历史日期后必须通过 `prependCount` 保持滚动锚点，避免列表跳动。

## 添加餐食默认日期

[2026-05-24]
- 新建餐食入口不再固定今天：先查已有餐食最大日期。
- 无记录或最大日期早于今天：默认今天。
- 最大日期为今天或未来：默认最大日期 + 1。
- 编辑入口指定日期优先，不能被新建默认日期逻辑覆盖。

## 食材权限规则

[2026-05-24]
- 食材按 `source` 区分权限：
- `source='preset'`：预设食材，不可编辑、不可删除，UI 不做明显文字标记。
- `source='user'`：用户自建食材，可编辑、可删除，UI 显示可长按的图标提示。
- UI 层和 Repository/SQL 层都需要限制该规则，不能只靠界面隐藏按钮。
- 删除用户自建食材前必须二次确认；删除时先清理 `dish_ingredient` 关联，再删除食材本身，失败要提示用户。

## 菜品食材分类

[2026-05-24]
- 新增/编辑菜品和菜品详情暂不展示“主料”标识。
- 新添加到菜品的食材默认 `isMain=false`；`dish_ingredient.is_main` 字段暂保留，后续做原料/调味料分类时再统一迁移。
