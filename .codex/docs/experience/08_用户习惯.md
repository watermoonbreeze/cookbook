# 用户习惯

## 沟通风格

[2026-05-14]
- 用户倾向于先提出大致想法，然后让 AI 细化方案
- 喜欢分轮次确认，逐步完善设计（如数据库方案经历三轮讨论）
- 关注设计的实用性，倾向于简洁自然的方案（如用时间排序替代数字排序）

## 设计偏好

[2026-05-14]
- 偏好"表结构先建全，UI 按阶段暴露"的渐进式策略
- 重视数据来源区分（preset vs user），方便后续管理
- 倾向于把逻辑放在业务层而非数据库约束层（如菜名+标签唯一性）
- [2026-05-30] UI 控件希望有稳定“沟通名称”，例如菜品Block、菜品Item、餐食卡片、通用搜索栏、食材卡，后续修改时优先用这些名称定位。
- [2026-05-30] 用户倾向少边框、多色块和投影；固定高度输入控件要确保文字完整显示。

## 文档管理

[2026-05-14]
- 要求设计文档统一存放在 `.codex/docs/` 下管理
- 临时文件放 temp/codex/，稳定后迁移到 .codex/docs/feature/

## 流程要求

[2026-05-24]
- 用户要求“严谨流程模式”：先确认依据，再按小步实现，最后构建验证并记录上下文。
- 用户重视代码风格和技术架构统一，要求不同开发者接手也能保持一致。
- 新增或修改功能时应优先查项目规范、feature 文档、context memory，再动代码。
- 用户明确要求自动任务编排不能只由主线程“口头模拟”；标准/深度任务必须真实分派对应 DEV 角色智能体。
- 任务开始前必须先说明任务类型、执行深度、交互模式和智能体分派表；常规模式下方案阶段完成后要等用户确认再进入实现。
- 如果当前 Codex 会话没有可用多智能体工具，必须主动说明“流程降级”，不能假装已经分派智能体。

## Codex / Claude 双模式偏好

[2026-05-24]
- 用户希望 Codex 尽量保留 Claude Code 的工作习惯，例如 `/zongjie`、`/fansi`、`/myinit`。
- 需要明确区分：Claude 侧配置不作为 Codex 运行时依赖；Codex 侧应维护自己的 `AGENTS.md`、`.codex/`、plugin/commands。
- 对于 Codex 不能裸注册的 slash command，可通过普通文本触发或个人 plugin 命名空间命令替代。
