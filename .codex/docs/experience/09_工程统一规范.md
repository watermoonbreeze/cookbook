# 工程统一规范

> 更新时间：2026-05-24。所有 Codex 后续开发默认遵守本规范；如与更具体的 feature 文档冲突，以用户最新确认和 feature 文档为准，并同步更新本规范。

## 一、跨平台架构边界

- `:shared` 只放跨平台 Domain/Data：model、repository、SQLDelight、seed、expect/actual platform adapter。
- `:androidApp` 只放 Android UI：Compose Screen、ViewModel、Navigation、Theme、Android DI。
- `iosApp/` 只放 iOS UI：SwiftUI View、iOS navigation、iOS presentation state。
- 业务规则优先沉到 `shared`；平台 UI 只做展示、输入收集、页面状态编排。
- 平台能力必须走 `expect/actual`，不要让 Android/iOS API 泄漏到 `commonMain`。

## 二、Android UI 规范

- Android 使用 Jetpack Compose + Material Design 3；所有颜色从 `MaterialTheme.colorScheme` 或 `ExtendedColorsHolder` 取。
- 页面按功能包拆分：`home/`、`timeline/`、`dishes/`、`addmeal/`、`newdish/`、`picker/`、`mine/`。
- 每个业务页面优先采用 `Screen + ViewModel + UiState` 形态；`Screen` 不直接访问 Repository。
- 可复用 UI 放 `ui/component/`，不要在页面内复制通用行、卡片、空状态、评分、标签等组件。
- Android 交互遵循 Material3：`TopAppBar`、`NavigationBar`、`FloatingActionButton`、`Dialog(usePlatformDefaultWidth=false)`。
- 主题语义：[AI修改] Primary=暖杏主操作/选中态/主按钮，Secondary=辅助色/默认图标/弱交互，Tertiary=价格/热销/推荐等小面积强调，Background=页面根背景，Surface=白底内容卡片，SurfaceVariant/SecondaryContainer=浅底分组区块。
- 不硬编码一套新配色；新增状态色先扩展 `ExtendedColors`，再在组件中引用。
- [AI修改] 暖杏主题规范禁止脏色叠加和高饱和大面积铺底；圆角按卡片/弹窗 16dp、按钮/输入框 12dp、列表/标签 8dp、角标 4dp 执行。

## 三、iOS UI 规范

- iOS 使用 SwiftUI 和系统原生控件风格，避免照搬 Android Material 组件。
- iOS 页面结构应映射同一业务能力，但保留 iOS 导航、列表、表单、Sheet 的原生体验。
- iOS 只调用 shared framework 暴露的业务能力，不重复实现 Repository 或数据库规则。
- iOS 主题遵循系统 Dynamic Type、Light/Dark、safe area 与原生 spacing；视觉语义与 Android 保持一致，不要求像素一致。

## 四、数据库规范

- schema 唯一来源是 `shared/src/commonMain/sqldelight/com/sxdbsm/cookbook/db/Cookbook.sq`。
- 数据库结构变更必须同步 `.codex/docs/feature/数据库设计方案.md` 和相关上下文记忆。
- SQLite/SQLDelight 方言能力有限时，优先保持行为等价；不能使用的 SQL 能力用 Repository 层补齐，并记录原因。
- 表字段的来源统一用 `source='preset'|'user'`；用户只能编辑/删除 user 数据。
- 查询命名保持动词语义：`select...`、`insert...`、`update...`、`delete...`，不要混用业务口语命名。

## 五、代码风格

- Kotlin 文件按 package/import/model/ViewModel/Composable/helper 的局部顺序组织，避免无关重排。
- 状态对象使用不可变 `data class UiState`；ViewModel 内用 `MutableStateFlow`，对外暴露 `StateFlow`。
- Repository 暴露 `Flow<T>` 或 suspend 方法；UI 不直接操作 SQLDelight query。
- Composable 参数顺序：业务入参、回调、`vm: XxxViewModel = koinViewModel()`。
- 命名保持领域语言统一：Dish、Ingredient、MealRecord、MealType、HealthProfile，不新增同义词。
- 注释只解释复杂业务决策或平台限制，不写重复代码含义的注释。

## 六、开发流程

- 开始改动前先读取 `AGENTS.md`、相关 `.codex/docs/feature/` 与 `.codex/docs/context_memory/`。
- 先完成最小闭环，再补非阻塞体验；每次改动尽量只覆盖一个业务目标。
- 改 UI 时优先复用既有组件和主题，不引入新设计体系。
- 改数据库或 shared 行为后必须跑对应 Gradle 构建/测试；Android UI 改动至少跑 `./gradlew :androidApp:assembleDebug`。
- 重要阶段完成后，在 `.codex/docs/context_memory/` 写一份 100 行以内的结论记录。
