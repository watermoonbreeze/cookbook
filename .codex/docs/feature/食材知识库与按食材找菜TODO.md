## 二、产品目标

1. 食材页支持按不同维度浏览：常规、营养、慢病、自定义。
2. 食材筛选支持跨维度组合：分类、营养标签、慢病建议、来源、最近使用。
3. 食材详情能够解释“是什么、属于哪些类、适合哪些人、怎么处理/怎么做”。
4. 用户选择手头食材后，可以查“能做什么菜”。
5. 后续 AI 只负责生成候选和解释，最终推荐仍由本地菜品库和健康规则校验。

## 四、数据模型规划

### 4.1 当前可复用

- `ingredient`：食材主表。
- `food_category`：分类/维度树，`dimension` 区分 general、nutrition、gi、purine、sodium、fat、crowd 等。
- `ingredient_category`：食材与多个分类的多对多关系。
- `crowd_type`：慢病/人群类型。
- `crowd_ingredient`：某类人群对某食材的 recommend/limit/avoid 规则。
- `dish_ingredient`：菜品与食材关联，是“按食材找菜”的基础。
- `dish_cooking_method_rel`：可用于按做法筛选。
- `dish_step`：可用于菜品详情展示具体步骤。

### 4.2 一期建议新增

| 表/字段 | 用途 | 优先级 |
|---|---|---|
| `ingredient_detail` | 食材做法建议、处理建议、存储建议、注意事项、备注 | P1 |
| `ingredient_category` 编辑能力增强 | 一个食材可在编辑时绑定多个分类/标签 | P0 |
| `ingredient_filter_query` 不落库 | UI 层筛选条件对象，转 SQL 查询 | P0 |

`ingredient_detail` 建议字段：

- `ingredient_id`
- `cook_tips`：常见做法/适合烹饪方式
- `prep_tips`：处理建议，如焯水、去皮、少油少盐
- `storage_tips`：保存方式
- `health_note`：通用健康说明
- `source`
- `updated_at`
- `status`

### 4.3 二期再新增

| 表 | 用途 | 说明 |
|---|---|---|
| `nutrient` | 营养素定义 | 钙、铁、钠、钾、蛋白质、脂肪、碳水、嘌呤等。 |
| `ingredient_nutrient` | 每 100g/100ml 含量 | 必须有可靠来源和单位，不能让 AI 凭空生成。 |
| `ingredient_substitute` | 食材替代关系 | 用于“缺一种也能做”和 AI 换一换。 |

## 六、按食材找菜 TODO

### 目标

用户选择手头已有食材，例如 `青椒 + 鸡胸肉`，系统推荐可以做的菜。

### P0：规则版找菜

- [ ] 食材页支持多选食材。
- [ ] 底部操作条显示：`已选 N 个食材 / 找菜`。
- [ ] 新增“可做菜品”结果页或弹层。
- [ ] 根据 `dish_ingredient` 查询包含任意已选食材的菜品。
- [ ] 计算匹配食材、缺少食材、匹配比例。
- [ ] 结果按匹配度排序。

结果分组：

- `食材齐全`：菜品所需食材都已选中。
- `差 1 样`：缺少一个关键食材。
- `可替换/部分匹配`：只匹配部分食材，作为低优先级候选。

### P1：筛选增强

- [ ] 支持按烹饪方式筛选：炒、蒸、煮、炖、凉拌等。
- [ ] 支持按慢病规则过滤：避免推荐明显禁忌食材组合。
- [ ] 支持按喜爱度/最近做过排序。
- [ ] 支持“一键加入今日菜单”。
- [ ] 支持“缺少食材”提示，点击可加入采购清单（采购清单为后续功能）。

### P2：智能推荐版

- [ ] 基于已有食材和菜品库，AI 推荐 3 个候选菜。
- [ ] AI 可生成新菜草案：菜名、食材、烹饪方式、操作步骤。
- [ ] 所有 AI 结果必须经本地规则校验，并由用户确认后保存。
- [ ] 禁止 AI 直接写数据库或直接给医疗结论。

## 八、推荐执行顺序

1. 调整食材页结构：顶部 Tab + 当前维度左侧树。
2. 做食材详情面板，先展示已有分类和慢病规则。
3. 增强食材编辑：支持多分类绑定。
4. 做筛选面板：分类/营养/慢病/来源。
5. 做按食材找菜规则版。
6. 扩充 seed：补齐文档中的常规分类、营养标签和四类慢病规则。
7. 再接 AI：先 AI 新建菜品草案，再 AI 食材找菜/下一餐推荐。

## 九、暂不做

- 暂不直接录入精确营养素数值，除非有稳定来源。
- 暂不支持 13 类慢病全量细规则，先做当前项目已有 4 类。
- 暂不让 AI 直接判定“能不能吃”，只能解释本地规则。
- 暂不自动生成采购清单，可在“缺少食材”能力稳定后补。
