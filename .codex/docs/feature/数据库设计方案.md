# 数据库设计方案（细化版）

> 最后更新：2026-05-21（第五轮：热度规则改为自动累加 0-100；删除 meal_record.rating；新增 dish 热度触发器）

## 一、设计思路

### 与 MVP 方案的对比

| 维度 | MVP 原方案 | 新方案 |
|------|-----------|--------|
| 菜品 | 只有名称+分类 | 拆分为**菜品（菜单表）+ 食材 + 配料关联**，支持详细材料记录 |
| 菜品区分 | name 唯一 | name 允许重复，通过**标签**区分同名菜品（如"西红柿炒蛋 [少盐]"） |
| 食材 | 无 | 独立食材表，支持分类、微量元素、人群禁忌 |
| 人群健康 | 无（规划在一期） | 提前设计人群分类、食材-人群关联，预留风险提示能力 |
| 分类体系 | 菜品一个 category 字段 | 独立分类表，支持多维度、多对多 |
| 数据来源 | 无区分 | 所有表加 `source` 字段，区分预设/用户数据 |
| 餐序 | 早/中/晚 3 个 | 6 个固定餐序 + 用户自定义加餐，按 sort_order 排列 |
| 每餐记录 | meal + meal_dish | 食谱表（meal_record）关联菜单表 |

### 核心关系

```
食材(ingredient) ←──配料表(dish_ingredient)──→ 菜品(dish) ←── 标签(dish_tag_rel → dish_tag)
     │                                            │
     ├── 食物分类(food_category)                   ├── 烹饪方式(cooking_method)
     ├── 微量元素(ingredient_nutrient)             ├── 适应人群(dish_crowd)
     └── 人群禁忌(crowd_ingredient)               └── 每餐记录(meal_record_dish)
                                                        │
                                                   食谱记录(meal_record)
```

## 二、完整表设计

### 2.1 字典/基础表

#### `cooking_method` — 烹饪方式表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| name | TEXT NOT NULL | 烹饪方式名称（炒、蒸、煮、炖、烤、凉拌、煎、炸...） |
| source | TEXT NOT NULL DEFAULT 'preset' | 数据来源：preset=预设，user=用户添加 |
| created_at | INTEGER NOT NULL | 创建时间戳 |

#### `crowd_type` — 人群分类表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| name | TEXT NOT NULL | 人群名称（高血压、糖尿病、高血脂、痛风、肾病...） |
| description | TEXT DEFAULT '' | 简要说明 |
| source | TEXT NOT NULL DEFAULT 'preset' | preset / user |
| created_at | INTEGER NOT NULL | 创建时间戳 |

#### `measurement_unit` — 计量单位表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| name | TEXT NOT NULL | 单位名称（克、两、斤、毫升、个、片、勺、适量...） |
| source | TEXT NOT NULL DEFAULT 'preset' | preset / user |

### 2.2 食材体系

#### `ingredient` — 食材表

所有的食材都在这里，是整个系统的基础数据。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| name | TEXT NOT NULL UNIQUE | 食材名称（鸡蛋、西红柿、五花肉、大米...） |
| alias | TEXT DEFAULT '' | 别名，用于搜索（如"番茄"匹配"西红柿"），多个用逗号分隔 |
| pinyin | TEXT DEFAULT '' | 拼音（如"xihongshi"），用于排序与首字母搜索 |
| image_path | TEXT DEFAULT '' | 食材图片本地路径，食材选择弹框展示用 |
| default_unit_id | INTEGER | 默认计量单位（外键 → measurement_unit） |
| source | TEXT NOT NULL DEFAULT 'preset' | preset / user |
| created_at | INTEGER NOT NULL | 创建时间戳 |

#### `food_category` — 食物分类表

一种食材可从不同维度分类（如：鸡蛋 → 蛋类、优质蛋白、低嘌呤食物）。**食材选择弹框左侧分类树**的数据来源也是本表。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| name | TEXT NOT NULL | 分类名称 |
| dimension | TEXT NOT NULL DEFAULT 'general' | 分类维度（general=常规、nutrition=营养、purine=嘌呤、gi=升糖指数、crowd=人群关联...） |
| parent_id | INTEGER | 父分类 ID（支持层级，如 肉类→猪肉类），NULL 表示顶级 |
| crowd_type_id | INTEGER | 可空外键 → crowd_type。**非空时**表示该叶子分类的食材列表走 `crowd_ingredient` 查询（高血压/糖尿病等人群推荐食材）；为空时走 `ingredient_category` 查询 |
| sort_order | INTEGER NOT NULL DEFAULT 0 | 同级分类的显示顺序 |
| icon | TEXT DEFAULT '' | 分类图标（资源名或本地路径，左侧导航前置图标） |
| source | TEXT NOT NULL DEFAULT 'preset' | preset / user |
| created_at | INTEGER NOT NULL | 创建时间戳 |

> **左侧分类树结构示例**（预置数据）：
> - 主食（dimension=general） → 米类 / 面类 / 粗粮
> - 蔬菜（dimension=general） → 叶菜 / 根茎 / 瓜茄
> - 肉类（dimension=general） → 猪牛羊 / 禽类
> - 水产（dimension=general）
> - 蛋奶豆（dimension=general）
> - 调味料（dimension=general）
> - 健康饮食（dimension=nutrition） → 低嘌呤 / 低 Gi / 低糖 / 低脂 / 低钠
> - 人群分类（dimension=crowd） → 高血压(crowd_type_id=1) / 糖尿病(=2) / 高血脂(=3) / 高尿酸(=4)
>
> **判断一级分类能否展二级**：UI 直接判断 `SELECT COUNT(*) FROM food_category WHERE parent_id = ?` 是否大于 0，不需要额外字段。

#### `ingredient_category` — 食材-分类关联表（多对多）

| 字段 | 类型 | 说明 |
|------|------|------|
| ingredient_id | INTEGER NOT NULL | 外键 → ingredient |
| category_id | INTEGER NOT NULL | 外键 → food_category |
| PRIMARY KEY | (ingredient_id, category_id) | 联合主键 |

#### `nutrient` — 微量元素/营养素定义表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| name | TEXT NOT NULL | 营养素名称（钾、钠、钙、铁、锌、维生素C、嘌呤...） |
| unit | TEXT NOT NULL | 度量单位（mg、g、μg...） |

#### `ingredient_nutrient` — 食材-营养素关联表

每种食材含有的各种营养素含量（每 100g）。

| 字段 | 类型 | 说明 |
|------|------|------|
| ingredient_id | INTEGER NOT NULL | 外键 → ingredient |
| nutrient_id | INTEGER NOT NULL | 外键 → nutrient |
| amount_per_100g | REAL NOT NULL | 每 100g 含量 |
| source | TEXT NOT NULL DEFAULT 'preset' | preset / user |
| PRIMARY KEY | (ingredient_id, nutrient_id) | 联合主键 |

#### `crowd_ingredient` — 人群-食材关联表

标记特定人群对特定食材的建议（推荐/限量/禁忌）。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| crowd_id | INTEGER NOT NULL | 外键 → crowd_type |
| ingredient_id | INTEGER NOT NULL | 外键 → ingredient |
| advice_level | TEXT NOT NULL | 建议级别：recommend=推荐、limit=限量、avoid=禁忌 |
| reason | TEXT DEFAULT '' | 原因说明（如"高钠，升血压"） |
| daily_limit | REAL | 每日限量（克），limit 级别时有值 |
| source | TEXT NOT NULL DEFAULT 'preset' | preset / user |
| UNIQUE | (crowd_id, ingredient_id) | 同一人群+食材不重复 |

### 2.3 菜品体系

#### `dish` — 菜品表

一道菜的完整信息。**name 允许重复**，同名菜品通过标签区分。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| name | TEXT NOT NULL | 菜名（西红柿炒蛋、清蒸鲈鱼...），允许重复 |
| cooking_method_id | INTEGER | 外键 → cooking_method（主要烹饪方式） |
| preference | REAL NOT NULL DEFAULT 0.0 | **热度**（0-100 分，自动累加，不由用户手动设置）。每次该菜品被添加到 `meal_record_dish` 时由触发器 `+0.1`，上限 100。UI 显示为 5 颗星，每颗星 20 分 |
| special_note | TEXT DEFAULT '' | 特殊处理说明（如"少盐"、"去皮"） |
| description | TEXT DEFAULT '' | 菜品说明 |
| image_path | TEXT DEFAULT '' | 图片本地路径 |
| source | TEXT NOT NULL DEFAULT 'user' | preset / user |
| created_at | INTEGER NOT NULL | 创建时间戳 |
| updated_at | INTEGER NOT NULL | 更新时间戳 |

> **同名菜品处理**：用户新增菜品时，如果 dish 表中已存在同名菜品，弹框展示已有菜品信息（标签、配料、烹饪方式），让用户选择：a) 直接复用已有菜品 b) 基于已有修改后另存 c) 全新创建（建议附加不同标签以区分）。

> **热度（preference）规则（2026-05-21）**：
> - 范围 0-100 分；5 颗星 × 20 分/颗
> - **每次该菜品被添加到 `meal_record_dish` 时，由触发器 `trg_dish_popularity_after_insert` 自动 +0.1**
> - 上限 100（满分约需 1000 次添加，实际不会触达）
> - **删除 meal_record_dish 不扣回热度**（保留历史热度，避免清空记录后热度归零；如需扣回可后续增加 AFTER DELETE 触发器）
> - **UI 上用户不可手动设置/编辑**；新建菜品 Activity 不暴露此字段
> - **HomeScreen 热门 / DishesScreen 热度横滑**直接按 preference DESC + name ASC 取前 N 个（不限时间窗口，不限次数阈值）

#### `dish_tag` — 菜品标签表

用于区分同名菜品的灵活标签（如"少盐版"、"妈妈做法"、"快手版"、"家常"等）。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| name | TEXT NOT NULL UNIQUE | 标签名称 |
| source | TEXT NOT NULL DEFAULT 'user' | preset / user |
| created_at | INTEGER NOT NULL | 创建时间戳 |

#### `dish_tag_rel` — 菜品-标签关联表（多对多）

| 字段 | 类型 | 说明 |
|------|------|------|
| dish_id | INTEGER NOT NULL | 外键 → dish |
| tag_id | INTEGER NOT NULL | 外键 → dish_tag |
| PRIMARY KEY | (dish_id, tag_id) | 联合主键 |

> **唯一性约束**：菜名本身不做唯一约束，但同一个"菜名 + 标签组合"在业务层保证不重复。搜索菜品时，展示格式为"西红柿炒蛋 [少盐] [快手]"，方便用户区分。

#### `dish_ingredient` — 配料表（菜品-食材关联）

一道菜需要哪些食材、用量。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| dish_id | INTEGER NOT NULL | 外键 → dish |
| ingredient_id | INTEGER NOT NULL | 外键 → ingredient |
| quantity | REAL | 用量数值（NULL 表示"适量"） |
| unit_id | INTEGER | 外键 → measurement_unit |
| is_main | INTEGER NOT NULL DEFAULT 1 | 1=主料，0=辅料/调料 |
| UNIQUE | (dish_id, ingredient_id) | 同一菜品同一食材不重复 |

#### `dish_crowd` — 菜品-适应人群关联表

| 字段 | 类型 | 说明 |
|------|------|------|
| dish_id | INTEGER NOT NULL | 外键 → dish |
| crowd_id | INTEGER NOT NULL | 外键 → crowd_type |
| suitability | TEXT NOT NULL DEFAULT 'suitable' | suitable=适合、caution=注意、avoid=不宜 |
| PRIMARY KEY | (dish_id, crowd_id) | 联合主键 |

> **说明**：菜品的适应人群可以手动指定，也可以根据配料中食材的 `crowd_ingredient` 关系**自动推算**（取最严格的级别）。两种方式并存，手动指定优先级更高。

### 2.4 每餐记录（食谱）

#### `meal_type` — 餐序类型表

6 个固定餐序 + 用户可自定义加餐。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| code | TEXT NOT NULL UNIQUE | 餐序编码 |
| name | TEXT NOT NULL | 显示名称 |
| default_time | TEXT NOT NULL | 默认时间 HH:mm（用于排序和显示，用户可在设置中修改） |
| is_fixed | INTEGER NOT NULL DEFAULT 1 | 1=固定餐序（不可删除），0=用户自定义加餐 |
| source | TEXT NOT NULL DEFAULT 'preset' | preset / user |

**预设数据**：

| code | name | default_time | is_fixed |
|------|------|-------------|----------|
| BREAKFAST | 早餐 | 07:30 | 1 |
| MORNING_SNACK | 上午餐 | 10:00 | 1 |
| LUNCH | 中餐 | 12:00 | 1 |
| AFTERNOON_SNACK | 下午餐 | 15:00 | 1 |
| DINNER | 晚餐 | 18:30 | 1 |
| NIGHT_SNACK | 宵夜 | 21:30 | 1 |

> **时间排序机制**：所有餐序都有一个时间值，一天中的餐食按时间 `HH:mm` 自然排序。固定餐序的时间可在设置中修改（如有人习惯 6 点吃早餐）。用户添加加餐时必须选择时间，选完后自动按时间归位到正确的顺序中，无需额外的排序转换逻辑。

#### `meal_record` — 食谱/每餐记录表

记录每天每餐吃了什么。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| date | TEXT NOT NULL | 日期 yyyy-MM-dd |
| meal_type_id | INTEGER NOT NULL | 外键 → meal_type（餐序） |
| meal_time | TEXT NOT NULL | 用餐时间 HH:mm（固定餐序取 default_time，加餐由用户选择） |
| note | TEXT NOT NULL DEFAULT '' | 备注 |
| created_at | INTEGER NOT NULL | 创建时间戳 |

> **说明**：去掉了 `UNIQUE(date, meal_type)` 约束。固定餐序在业务层保证每天每种最多一条；加餐（is_fixed=0）可以有多条。查询一天的餐食按 `meal_time` 排序，时间天然有序，无需额外排序字段。

#### `meal_record_dish` — 每餐-菜品关联表

| 字段 | 类型 | 说明 |
|------|------|------|
| meal_record_id | INTEGER NOT NULL | 外键 → meal_record |
| dish_id | INTEGER NOT NULL | 外键 → dish |
| sort_order | INTEGER NOT NULL DEFAULT 0 | 排序序号 |
| PRIMARY KEY | (meal_record_id, dish_id) | 联合主键 |

> **核心交互**：用户记录每餐时输入菜名 → 系统自动匹配已有菜品 → 如果有同名菜品，弹框展示已有菜品信息（标签、配料、烹饪方式），用户可选择复用或新建。

### 2.6 用户偏好与档案（2026-05-19 新增，应用架构升级触发）

#### `user_preferences` — 用户偏好键值表

跨平台一致的偏好存储（替代 Android DataStore / iOS NSUserDefaults），便于备份/恢复一并迁移。

| 字段 | 类型 | 说明 |
|------|------|------|
| key | TEXT PK | 偏好键（theme_mode、home_recent_count 等） |
| value | TEXT NOT NULL | 值（统一字符串存储，业务层解析） |
| updated_at | INTEGER NOT NULL | 更新时间戳 |

**MVP 预置键**：
- `theme_mode`: `system` / `light` / `dark`（默认 `system`）
- `home_recent_count`: `6`（HomeScreen 最近菜品数）
- `home_popular_count`: `6`（HomeScreen 热门菜品数）
- `home_popular_days`: `30`（热门统计窗口）
- `home_popular_threshold`: `3`（热门最少次数）

#### `user_health_profile` — 个人健康档案（人群标签）

用户在 MineScreen 选择的所属人群标签，多对一关系。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| crowd_type_id | INTEGER NOT NULL | 外键 → crowd_type |
| enabled | INTEGER NOT NULL DEFAULT 1 | 1=启用、0=软删（保留历史） |
| created_at | INTEGER NOT NULL | 创建时间戳 |
| UNIQUE | (crowd_type_id) | 同一人群不重复 |

**用法**：
- 用户多选人群（高血压/糖尿病/...），每选一项 INSERT 一行
- IngredientPickerScreen 默认查询 `WHERE crowd_type_id IN (SELECT crowd_type_id FROM user_health_profile WHERE enabled=1)`，自动给角标
- `enabled=0` 允许保留历史档案（用户改主意时可撤销）

## 四、source 字段规范

所有需要区分数据来源的表统一使用 `source` 字段：

| 值 | 含义 | 说明 |
|----|------|------|
| `preset` | 预设数据 | APP 内置，首次安装或更新时填充 |
| `user` | 用户添加 | 用户手动创建的数据 |

**查询便利性**：
- 展示时：默认显示全部（preset + user）
- 管理时：用户只能编辑/删除 source='user' 的数据
- 预设数据更新：APP 升级时可安全更新 source='preset' 的记录，不影响用户数据

## 五、核心业务场景的数据流

### 场景 1：用户记录一餐

```
用户输入"西红柿炒蛋"
  → 搜索 dish 表（name LIKE '%西红柿炒蛋%'）
  → 找到匹配 → 展示已有菜品信息（配料、烹饪方式）
     → 用户选择"就是这个" → 直接关联到 meal_record_dish
     → 用户选择"新建一个" → 创建新 dish 记录
  → 未找到 → 快速创建（仅填菜名，配料等信息后续补充）
```

### 场景 2：菜名关联 — 相同菜名智能带出

```
用户输入菜名 → 实时搜索 dish 表
  → 精确匹配：直接展示该菜品详情（配料列表、烹饪方式、适应人群）
  → 模糊匹配：展示候选列表，每项显示"菜名 | 主要食材 | 烹饪方式"
  → 用户可选择：
     a) 复用已有菜品（直接引用，不复制）
     b) 基于已有菜品修改（复制一份，修改后保存为新菜品）
     c) 全新创建
```

### 场景 3：食材关联 — 通过食材反查菜品

```
用户想知道"鸡蛋能做什么菜"
  → 查 dish_ingredient 表，找到所有包含"鸡蛋"的 dish_id
  → 展示菜品列表

用户想知道"这道菜用了什么食材"
  → 查 dish_ingredient 表，找到该 dish_id 的所有食材
  → 展示食材列表及用量
```

### 场景 4：人群风险提示（一期功能，但表结构提前预留）

```
用户设置了"高血压"标签
  → 添加菜品时，查该菜品的所有食材
  → 逐个检查 crowd_ingredient 表
  → 如果存在 advice_level='avoid' → 红色警告
  → 如果存在 advice_level='limit' → 黄色提醒
  → 否则 → 绿色安全
```

## 七 bis、食材选择弹框的查询逻辑

新建菜品 Activity 内嵌的"食材选择 Fragment 弹框"按用户在左侧选中的分类节点，**三种查询路径**：

```sql
-- ① 全部（UI 内置项，不入表）
SELECT * FROM ingredient ORDER BY pinyin ASC;

-- ② 普通分类（dimension=general/nutrition 等，crowd_type_id IS NULL）
SELECT i.*
  FROM ingredient i
  JOIN ingredient_category ic ON i.id = ic.ingredient_id
 WHERE ic.category_id = :categoryId
 ORDER BY i.pinyin ASC;

-- ③ 人群分类（dimension=crowd 且 crowd_type_id 非空）
SELECT i.*, ci.advice_level, ci.reason, ci.daily_limit
  FROM ingredient i
  JOIN crowd_ingredient ci ON i.id = ci.ingredient_id
 WHERE ci.crowd_id = :crowdTypeId
 ORDER BY
   CASE ci.advice_level WHEN 'recommend' THEN 1 WHEN 'limit' THEN 2 WHEN 'avoid' THEN 3 END,
   i.pinyin ASC;
-- advice_level 用于在食材卡片上加角标：recommend=绿✓、limit=橙⚠、avoid=红✕
```

UI 侧判断走哪种：根据当前选中 `food_category` 节点的 `crowd_type_id` 是否为空。

## 十、本地备份与恢复实现方案（2026-05-19 新增）

### 设计思路

**不引入数据库元数据表**，文件系统直接管理：
- 备份 = 复制当前 `.db / .db-wal / .db-shm` 三个文件到指定目录
- 备份元数据 = 文件名（时间戳）+ 文件系统的 size/mtime
- 优势：简单、不会出现"DB 中有记录但备份文件被删了"的不一致
- KISS 原则

### 跨平台契约（shared 模块）

```kotlin
expect class BackupManager {
    suspend fun createBackup(): BackupInfo
    suspend fun listBackups(): List<BackupInfo>
    suspend fun restoreFromBackup(file: String)
    suspend fun deleteBackup(file: String)
}

data class BackupInfo(
    val fileName: String,           // backup_20260519_233015.db
    val createdAt: Instant,
    val sizeBytes: Long,
)
```

### Android 实现要点（androidMain）

```kotlin
actual class BackupManager(
    private val context: Context,
    private val driver: SqlDriver,
) {
    private val dbName = "cookbook.db"
    private val backupDir get() = File(context.getExternalFilesDir(null), "backups").apply { mkdirs() }
    private val currentDb get() = context.getDatabasePath(dbName)

    actual suspend fun createBackup(): BackupInfo {
        val timestamp = ...
        val target = File(backupDir, "backup_$timestamp.db")
        // 复制 .db / .db-wal / .db-shm
        driver.execute(null, "PRAGMA wal_checkpoint(FULL)", 0)   // 先 checkpoint
        currentDb.copyTo(target, overwrite = true)
        File(currentDb.path + "-wal").takeIf { it.exists() }?.copyTo(File(target.path + "-wal"))
        File(currentDb.path + "-shm").takeIf { it.exists() }?.copyTo(File(target.path + "-shm"))

        // 保留最近 5 个，超过删旧
        pruneOldBackups(keep = 5)
        return BackupInfo(target.name, Instant.now(), target.length())
    }

    actual suspend fun restoreFromBackup(file: String) {
        driver.close()  // 必须先关闭 SQLDelight Driver
        File(backupDir, file).copyTo(currentDb, overwrite = true)
        File(backupDir, "$file-wal").takeIf { it.exists() }?.copyTo(File(currentDb.path + "-wal"), overwrite = true)
        File(backupDir, "$file-shm").takeIf { it.exists() }?.copyTo(File(currentDb.path + "-shm"), overwrite = true)
        // Koin 重启 DataModule
        appRestart()  // 或弹"恢复成功，请重启应用"
    }
}
```

### iOS 实现（一期）

iosMain 通过 `NSFileManager` 实现，路径走 `NSDocumentDirectory/backups/`。

### MVP 限制

- 仅手动触发（用户在 MineScreen 点 [立即备份]）
- 自动保留最近 5 个备份，超过自动清理最旧
- 不做定时自动备份（一期再说）
- 不做云备份（二期，配合上云触发条件）
